Test guard (#9730): `tests/key_dir_bind_guard_9730.rs` lexes every tracked Rust file and refuses any spelling of the key-dir environment variable, its constant, the `test_key_dir` sandbox module or `armed_sandbox` outside an allowed site. An allowed site names one file, one item path (each item with the `#[cfg(..)]` written on it, the module path from the crate root, and a cfg'd statement, field or arm inside the item) and one kind of use (read, write, child-process env or plain use), so a write inside an allowed reader, a `#[cfg(not(test))]` copy of an allowed test item and a new product caller of the sandbox are each red. `include!` and `#[path]` targets are scanned as Rust, doc-comment code blocks are scanned as doctests, and every tracked non-Rust file that mentions the names needs a `NON_RUST` row by exact path and mention count. The table sizes and a whole-tree wall-clock ceiling are pinned. The files of the `cargo_skip` set (any `.md`, `docs/`, `scripts/ci/tests/`) are judged in Python by `scripts/ci/tests/test_key_dir_name_mentions_9730.py` with the same decode, unescape, count and written-out rows, because a change to only such a file skips cargo and the ledger gate runs the Python test on every change; the Rust guard leaves exactly that domain to it. Forms the lexer cannot see are listed as known-green rows and tracked in #9786; the run-time check is #9861.
