### Security

- **[http] the monitoring routes are metered by the shared auth-failure backoff**
  ([#4068](https://github.com/alphaonedev/ai-memory-mcp/issues/4068)). The outer
  monitoring gate authenticated `/api/v1/monitoring/{status,metrics}` itself and
  `api_key_auth` exempts those paths, but that check neither consulted nor updated the
  per-source `AuthFailurePolicy`: failed monitoring credentials were never counted and a
  source already backed off elsewhere was not refused there. The same gate's
  `unresolved_transport_principal` refusal (health-only scopes configured) was unmetered
  too. Both now use the same policy instance through the shared `transport` funnels: a
  backed-off source is refused `429` + `Retry-After` before any key is compared (a correct
  key included, and the scope refusal is not reachable as a key oracle during backoff),
  every failure is recorded against the one per-source budget, and a key-based success
  resets it. Monitoring scope and TLS enforcement are unchanged, and the public legacy
  `/api/v1/health` liveness probe is never backed off. Pinned by
  `tests/monitoring_auth_backoff_4068.rs`.
