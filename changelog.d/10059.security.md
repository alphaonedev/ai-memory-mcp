### Security

- **[federation] One shared source for the peer list and the outbound scope under the
  enterprise-federation posture**
  ([#10059](https://github.com/alphaonedev/ai-memory-mcp/issues/10059)). The new key
  `AI_MEMORY_FED_QUORUM_PEERS` holds the comma-separated https peer URLs. Under the posture
  `serve`, `sync-daemon` and a fresh `doctor --posture enterprise-federation` parse it, and
  `AI_MEMORY_FED_PEER_OUTBOUND_SCOPE`, through one function, so check #23 judges exactly the peers
  the daemon is bound to and can pass on a fresh process. The daemon refuses boot when the key is
  absent, empty, malformed or over its cap, when `--quorum-peers` / `--peers` names a different
  peer set, or when a scope key names no peer of it; each refusal names the key and the fix. A
  bound boot prints a `sha256:` digest of the source (no credential), and check #23 prints the
  same digest with the note that an edit applies only after a restart. A doctor without the posture
  signal FAILs check #23. Outside the posture the key is not read and nothing changes. Upgrade
  note: a deployment that ran under the posture with `--quorum-peers` alone sets the key to the same
  value before upgrading.
