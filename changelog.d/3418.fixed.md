Per-agent HTTP api-key enrollment no longer requires a daemon restart, and is
reachable on both backends. The enrolled `sha256(token) -> agent_id` map was
captured once at boot, so a dynamically-minted fleet could not be key-bound
without restarting the data tier per enrollment — and, worse, a REVOKED key kept
authenticating until that restart. The map is now a live registry the daemon
re-reads from the configured backend on a bounded cadence
(`AI_MEMORY_AGENT_KEY_REFRESH_SECS`, default 15s; `0` restores the previous
restart-required behaviour and says so at boot). A failed refresh keeps the last
known enrolled set rather than disarming the identity gate. `agents
bind-api-key` / `revoke-api-key` gain an explicit `--store-url`, so enrolling on
the certified postgres tier is discoverable from `--help` instead of only
through the non-argv env channel, and `doctor` now reports the refresh window
and warns that its enrolled-key count is read from local sqlite when a postgres
store-url is configured.
