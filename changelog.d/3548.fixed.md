**Recall names content attestation apart from link attestation, and
surfaces the confidence claim beside its tier (#3548).** Verbose-provenance
recall rows carry `content_attestation` (the memory's OWN write attestation,
from `metadata.attest_level`) and `link_attestation` (the strongest incident
EDGE attestation) as distinct fields, same vocabulary as before (`signed_peer`
> `curator_derived` > `self_signed` > `unsigned_caller`). Previously the
single `provenance_tier` derived from the incident edge yet read like a
property of the memory — an unsigned row reached through one peer-signed
link reported `signed_peer`. `provenance_tier` is kept as a DEPRECATED alias
of `link_attestation` for one release (removed in v1.0.1). Rows also carry
`confidence_value` (the raw stored `confidence`) beside `confidence_tier`,
and `confidence_tier` is documented as NUMERIC-ONLY in v1.0.0: it thresholds
the value and does not consult `confidence_source`, so a caller-asserted
`1.0` and an engine-measured `1.0` both read `confirmed`; the raw value and
its source now travel with the tier so a consumer can tell them apart.
Redefining `confirmed` to require provenance or corroboration is deferred to
v1.0.1 with the crossroads vote.
