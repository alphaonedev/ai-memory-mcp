**Optional sender idempotency key on `memory_notify` (#8487).**
`memory_notify`, `POST /api/v1/notify` and `ai-memory notify --idempotency-key`
take an optional `idempotency_key` (1-128 bytes of `A-Za-z0-9._:-`). A retry
with the same key and content returns the first delivery's id with
`dedup_hit: true` and writes, charges and wakes nothing; the same key with
different content is a typed conflict (HTTP 409, MCP error) naming the original
id; an invalid key is refused before any quota charge or write and is never
echoed. The key is scoped to the server-resolved sender and the recipient.
Schema **v101** adds the `notify_dedup` table on both backends; the inbox row
and its dedup row commit in one transaction. Without a key behaviour is
unchanged, and every response now carries `dedup_hit: false`.
