**SQLite no longer corrupts its full-text index when an `_agents` registration row is written (#8341, #9259, #9260).** The schema v97 triggers that kept a registration row's `agent_pubkey` / `pubkey_bound_at` mirrors equal to the open `agent_pubkey_history` row rewrote the row's content in a nested `UPDATE` after `memories_fts` had already indexed it, so the external-content FTS5 index fell out of step with its table and the next delete or `integrity-check` failed with `SQLITE_CORRUPT_VTAB` (267). Schema v102 drops those triggers: every Rust write funnel now writes the authoritative projection itself, in the same write transaction, and new RAISE(ABORT) guards refuse any write that does not carry it instead of rewriting it. The migration reconciles every drifted registration row, installs the guards and rebuilds `memories_fts` in one transaction (idempotent; postgres only stamps the version, since its v97 trigger is a BEFORE trigger and its `tsv` column is generated from the stored row). A same-key rebind now keeps the ledger's `bound_at` instead of writing the rebind time (#9259), and a bound registration row whose content is not a JSON object is refused with an exact error naming the repair, `register_agent` (#9260).
