**`[logging].rotation = "never"` now refuses to start. Use `"external"` if
another tool rotates the file.** With `never`, nothing bounded the log file:
ai-memory didn't rotate it and nothing else was declared to. The file sink now
accepts three answers to "who bounds this file?":

- `minutely`, `hourly` or `daily` (the default): ai-memory does. It keeps at
  most `max_files` files and deletes the oldest.
- `external` (new): your rotator (logrotate, newsyslog, …) does. ai-memory
  writes one file and never rotates or deletes it. It doesn't reopen a
  renamed file, so use copy-and-truncate or restart the process after
  rotating. `ai-memory doctor` reports the sink as externally bounded.
- `never`: nobody does. Every command except `doctor` now exits with code 78
  and names the two alternatives. If you had `rotation = "never"`, change it
  to `"external"` (logrotate owns the file) or to a period.

**`[logging].max_size_mb` is reported as not enforced.** The file sink
rotates by time only, and nothing ever read `max_size_mb`. Setting it now logs
a warning at start-up, and `ai-memory doctor` shows it as `NOT ENFORCED` in a
new `Log retention (#3652)` section. Use a shorter `rotation` period for a
tighter bound. `retention_days` deletes nothing. It only sets the age at which
`ai-memory logs archive` compresses a file.

**The curator and sync systemd units now log to the journal.**
`scripts/install-batman-active.sh` and `scripts/templates/ai-memory-sync.service`
used to append the service's output to `~/.local/state/ai-memory/log/curator.log`
and `sync.log`. Nothing rotated those files, so they grew without limit. The
units now use `StandardOutput=journal` and `StandardError=journal`, so journald
applies its own rotation and retention (`SystemMaxUse=`, `MaxRetentionSec=` in
`journald.conf`). Read the output with
`journalctl --user -u ai-memory-curator` or `journalctl --user -u ai-memory-sync.service`.
An existing unit file is not rewritten; to switch an installed unit, edit those two
lines and run `systemctl --user daemon-reload`. The old log files are left in place
for you to remove.

**The macOS launchd plists keep only stderr.** The curator, sync, wake-hub,
wake-hub-refresh and watch plists no longer set `StandardOutPath`, so launchd
discards stdout. launchd opens the stderr file once and never rotates or
reopens it: truncate or remove it only while the job is stopped. On macOS,
enable the `[logging]` file sink. It is the bounded owner there, and with it
the stderr file receives only start-up refusals and at most one sink-failure
message per minute. launchd does not send a service's output to the unified
log; the documentation used to say it did.

**Don't rotate the audit evidence files.** `audit.log` and the
`forensic-<date>.jsonl` files are hash chains that ai-memory names itself. An
external rename or copy-and-truncate breaks the chain, and `ai-memory audit
verify` reports where. That break is left visible on purpose. Recovery after
an external rotation is a new chain.
