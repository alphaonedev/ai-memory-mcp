**The curator and sync systemd units now log to the journal.**
`scripts/install-batman-active.sh` and `scripts/templates/ai-memory-sync.service`
used to append the service's output to `~/.local/state/ai-memory/log/curator.log`
and `sync.log`. Nothing rotated those files, so they grew without limit. The
units now use `StandardOutput=journal` and `StandardError=journal`, so journald
applies its own rotation and retention (`SystemMaxUse=`, `MaxRetentionSec=` in
`journald.conf`). Read the output with
`journalctl --user -u ai-memory-curator` or `journalctl --user -u ai-memory-sync.service`.
An existing unit file is not rewritten; to switch an installed unit, edit those two
lines and run `systemctl --user daemon-reload`. The old log files are left in place
for you to remove.

The logging documentation now states the rotation and retention contract:

- The `[logging]` file sink rotates by time and keeps `max_files` files.
- `max_size_mb` is not enforced.
- `retention_days` only sets when `ai-memory logs archive` compresses files.
- On macOS, launchd does not send a service's output to the unified log.
