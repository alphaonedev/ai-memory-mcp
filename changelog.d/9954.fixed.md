**`doctor --posture enterprise-federation` check 10 passes only on a pin file the
runtime loads.** The `AI_MEMORY_FED_PEER_FINGERPRINTS` row used to pass when the
named file existed. It now parses the file with the same loader the outbound
pinning verifier uses, and passes only when that loader returns a non-empty pin
set; the row's `actual` reads `<path>: N host(s), M pin(s)`. A pass proves the
file loads; it does not prove that each host key can match a peer's server name
(issue 9989).

**What it costs you.** A pin file that the row passed before and that the
daemon could not use now fails the row, with the loader's exact reason: an
empty, whitespace-only or comment-only file, a malformed line, a directory, a
FIFO or other non-regular file, a dangling symlink, a file that is not UTF-8,
and a file over 65536 bytes (`PEER_FP_FILE_MAX_BYTES`). The outbound peer
client and `ai-memory sync` refuse the same files at start-up, and a FIFO no
longer blocks them.

**Remedy.** Write one `<host> <sha256-hex>` line per pinned peer certificate
into a regular file under the cap, then rerun the posture check.
