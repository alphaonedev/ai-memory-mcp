**`--pre-apply` rejects `branches` together with `branches-ignore` (#6438, carrier gate #6143, #6232 follow-up).** GitHub treats a workflow whose `on.pull_request` carries both filters as invalid, so it runs for no pull request. `trigger_covers` in `scripts/check_carrier_ruleset_live.py` evaluated `branches` and returned true. It now returns false when both keys are present, so the precondition fails before the ruleset `POST` instead of leaving the carrier unmergeable.
