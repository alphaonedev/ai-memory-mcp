Repeated HTTP authentication failures now back the source off. `api_key_auth`
counted nothing before, so a single address could present wrong keys forever
at whatever rate the daemon answered; admission control bounds concurrency,
not attempts over time. After 10 rejected keys a source gets `429` with
`Retry-After` for 1 s, doubling per further rejection up to 300 s, and while
it lasts the right key is refused too, so a guesser learns nothing. A success
does not reset the count, so a caller holding one valid key cannot interleave
guesses at another; 15 minutes without a rejection does. The source is the TCP
peer (IPv6 by /64); behind a same-host proxy it is the rightmost
`X-Forwarded-For` hop the proxy appended, and a remote peer's
`X-Forwarded-For` is never read. `/health` and the mTLS federation paths are
never refused. New counters `ai_memory_auth_failures_total` and
`ai_memory_auth_backoff_refusals_total`. `AI_MEMORY_AUTH_FAILURE_BACKOFF=0`
turns it off.
