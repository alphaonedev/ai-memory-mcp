PostgreSQL graph queries use `(depth, target_id, relation, path)` ordering before the row cap on relational and AGE engines; identical candidate sets produce the same bounded page. Explicit `C` collation can reorder target IDs on non-`C` installations, so upgrades may change capped pages. SQLite retains its separate temporal ordering. See [the PostgreSQL graph ordering contract](docs/postgres-graph-order.md).
