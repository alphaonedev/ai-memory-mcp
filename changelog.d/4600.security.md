### Security

- `ai-memory schema-init` now resolves its store URL through the same ladder as `serve` (`AI_MEMORY_STORE_URL_FILE`, a 0600 file, then `AI_MEMORY_STORE_URL`, then the `--store-url` flag), so the database password no longer has to appear on the command line. With no channel set it fails closed with a message naming all three. The Postgres deployment docs and the `schema-init` examples in the CLI reference use the file form, and the allowlist entry for `schema-init` in `scripts/check-docs-no-argv-secrets.py` is gone. (#4600)
- `ai-memory migrate` gains `--from-url-file PATH` and `--to-url-file PATH`, so a Postgres URL with a password no longer has to ride argv (`/proc/<pid>/cmdline`, `ps auxww`). Each side takes exactly one of the plain flag or its file flag; both, or neither, fails at parse time. The file is read through the same single-open, owner-only (`0600`) check as `AI_MEMORY_STORE_URL_FILE`; `AI_MEMORY_STORE_URL_FILE_ALLOW_LAX_PERMS` is the only opt-out. `migrate` never reads `AI_MEMORY_STORE_URL` / `AI_MEMORY_STORE_URL_FILE`, so a stale exported variable cannot redirect a bulk write, and an explicit flag is never overridden. A credential-bearing `--from` / `--to` still works and logs a warning per side naming the file flag. The Postgres migration guide, CLI reference, DigitalOcean runbook and the federation repro script use the file form, with CI and Kubernetes examples. (#4600, 5-agent vote 4d3ea1c5)
