### Security

- `ai-memory schema-init` now resolves its store URL through the same ladder as `serve` (`AI_MEMORY_STORE_URL_FILE`, a 0600 file, then `AI_MEMORY_STORE_URL`, then the `--store-url` flag), so the database password no longer has to appear on the command line. With no channel set it fails closed with a message naming all three. The Postgres deployment docs and the `schema-init` examples in the CLI reference use the file form, and the allowlist entry for `schema-init` in `scripts/check-docs-no-argv-secrets.py` is gone. (#4600)
- `ai-memory migrate` gains `--from-url-file PATH` and `--to-url-file PATH`, so a Postgres URL with a password no longer has to ride argv (`/proc/<pid>/cmdline`, `ps auxww`). Each side takes exactly one of the plain flag or its file flag; both, or neither, fails at parse time. The file is read through the same single-open, owner-only (`0600`) check as `AI_MEMORY_STORE_URL_FILE`; `AI_MEMORY_STORE_URL_FILE_ALLOW_LAX_PERMS` is the only opt-out. `migrate` never reads `AI_MEMORY_STORE_URL` / `AI_MEMORY_STORE_URL_FILE`, so a stale exported variable cannot redirect a bulk write, and an explicit flag is never overridden. A credential-bearing `--from` / `--to` still works and prints a warning to stderr per side naming the file flag (never the URL). The Postgres migration guide, CLI reference, DigitalOcean runbook and the federation repro script use the file form, with CI and Kubernetes examples. (#4600, 5-agent vote 4d3ea1c5)
- `ai-memory quarantine` and `ai-memory recover-previous-session` resolve the store URL through the file and env channels as well (`AI_MEMORY_STORE_URL_FILE`, then `AI_MEMORY_STORE_URL`, then `--store-url`, a group/world-readable or empty file refused). Before, both read only the `--store-url` flag, so a Postgres URL held in a 0600 file was ignored and the verb ran against the local SQLite `--db` instead. `scripts/check-docs-no-argv-secrets.py` now also flags a credentialed `migrate --from` / `--to` argument, and the hive provisioning script hands `schema-init` a 0600 URL file and gives the PostgreSQL superuser and role passwords to `docker run` / `psql` through 0600 files (`--env-file`, a `\set` include) instead of argv. The boot and MCP warnings for a refused inference-egress target print the endpoint origin only, never the configured URL with its userinfo or query. (#4600)
- On the one-shot writers `schema-init`, `quarantine` and `recover-previous-session`, an explicit `--store-url` that differs from a set `AI_MEMORY_STORE_URL_FILE` or `AI_MEMORY_STORE_URL` is now refused with an error naming the disagreeing channel names (never a URL or a credential), instead of being silently overridden by the channel, so a write can no longer reach a store the operator did not name. The same URL on the flag and a channel is accepted, and with no flag the file-then-env order is unchanged. `serve` and the other daemon verbs keep the documented precedence (#9202). A credential-bearing `--store-url` on these three verbs now prints its warning to stderr (they install no console log subscriber, so the earlier log-only warning was dropped); the warning names the flag and the file channel, never the URL. `scripts/check-docs-no-argv-secrets.py` also flags an empty-user password (`scheme://:pw@`) and a libpq `password=` / `sslpassword=` query key, the two shapes `url_carries_credentials` treats as credentials. (#4600)
