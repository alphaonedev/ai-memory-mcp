**Store-opening unit tests in `storage::connection` no longer race the passphrase seeder (#6582).** `check_trigger_rejects_bad_tier_insert` and twelve sibling tests called `open()` outside the passphrase window while another test held a live seed, so about half of `cargo test --lib storage::connection` runs failed with the sqlcipher refusal. Each now enters `no_passphrase_guard()`; the two tests that already hold the environment lock are unchanged. Test-only change.
