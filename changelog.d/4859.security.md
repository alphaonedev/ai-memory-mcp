### Security

- `scripts/check-docs-no-argv-secrets.py` now flags `psql -v`/`--set`/`--variable` password assignments wherever `psql` appears on the line: at line start, after a path, after a semicolon, or inside a command substitution. (#4859, #4817, #4808)
- The same gate now reads the psql segment the way the shell does (quotes and backslashes removed) and flags any `psql -v` variable whose name contains pass, secret, token, key, cred, pw or auth, with no locator-suffix or redaction-token exemption. A `psql` word the shell spells with backslashes or quotes (`\psql`, `p\sql`, `ps''ql`, `"ps"ql`) is normalised to `psql` before both psql rules run, a short-flag cluster may carry digits ahead of `v` (`-1v`, `-0v`, `-Xq1v`), a non-ASCII `-v` name is flagged, and a `-v` value with a `$` followed by a secret-like token (`x=$PGPASSWORD`, `x=${PG_PW}`) is flagged under any name; 20 further red self-test probes (4 for #5481, 8 for #5482, 8 for #5483): 19 spellings passed the gate before, and the 20th pins the backslash-inside-name step. The name is everything before the first `=` (psql accepts digits anywhere and non-ASCII bytes), a `-v` operand whose name part holds a shell expansion or substitution, or that is only an expansion, is flagged because a text gate cannot decide it, and `run_psql` / `my-psql` wrapper heads are scanned; 27 spellings that passed are now red self-test probes (13 for #5399, 14 for #5448). Stated limits a text gate cannot decide: options passed through an array or another variable (#5398); a secret held in a variable with a neutral name and passed under a neutral name (`x=$A`, with `A` assigned from a secret on another line); a literal secret under a neutral name (`-v x=hunter2`); and a command substitution value with a space (`x=$(cat /run/pw)`), which is read only to its first space. (#5399, #5448, #5481, #5482, #5483)
- `deploy/hive-1461/provision/20_pg_age.sh` builds the image with `-f` and an empty context directory, so the CA key and the secret files are never sent to the docker daemon. (#5401)
- `scripts/postgres-droplet-reinit.sh` runs the pg_dump backup with `sslmode=verify-full` and a pinned local CA (`PG_DUMP_SSLROOTCERT`) written into the `-d` connection string, which libpq ranks above `PGSSLMODE`, `PGSSLROOTCERT` and a `PGSERVICE` file; `PGSERVICE` and `PGSERVICEFILE` are unset first, `PG_PRIMARY_DB` must be a lower-case plain identifier (`[a-z_][a-z0-9_]*`; the unquoted DROP and CREATE fold case while the dump name does not, #5484), `PG_PORT` must be a port number from 1 to 65535 and the backup connection string and the local DROP and CREATE psql calls use it (#5454), and the script refuses with exit 7 before the backup when the CA is unusable or, with `AI_MEMORY_SSH_HOST` set, `PG_DUMP_SSLROOTCERT` is unset. (#5402, #5449, #5450, #5454, #5484)
- `ai-memory --db <path> curator` opens the explicit database on every store-backed arm (`--rollback-last`, `--prune-reports`, `--reflect`, `--once`), not only the sweep. (#5218)
