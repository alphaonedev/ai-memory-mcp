### Security

- `scripts/check-docs-no-argv-secrets.py` now flags `psql -v`/`--set`/`--variable` password assignments wherever `psql` appears on the line: at line start, after a path, after a semicolon, or inside a command substitution. (#4859, #4817, #4808)
- The same gate now reads the psql segment the way the shell does (quotes and backslashes removed) and flags any `psql -v` variable whose name contains pass, secret, token, key, cred, pw or auth, with no locator-suffix or redaction-token exemption. A `psql` word the shell spells with backslashes or quotes (`\psql`, `p\sql`, `ps''ql`, `"ps"ql`) is normalised to `psql` before both psql rules run, a short-flag cluster may carry digits ahead of `v` (`-1v`, `-0v`, `-Xq1v`), a non-ASCII `-v` name is flagged, and a `-v` value with a `$` followed by a secret-like token (`x=$PGPASSWORD`, `x=${PG_PW}`) is flagged under any name; 23 red self-test probes (4 for #5481, 10 for #5482, 9 for #5483) and 8 green ones (1, 4 and 3), counted by name in the self-test tables; a hit on a line that starts with `psql` is now reported on that line, not the line before it (#5485). The name is everything before the first `=` (psql accepts digits anywhere and non-ASCII bytes), a `-v` operand whose name part holds a shell expansion or substitution, or that is only an expansion, is flagged because a text gate cannot decide it, and `run_psql` / `my-psql` wrapper heads are scanned; 27 spellings that passed are now red self-test probes (13 for #5399, 14 for #5448). Stated limits a text gate cannot decide: options passed through an array or another variable (#5398); a secret held in a variable with a neutral name and passed under a neutral name (`x=$A`, with `A` assigned from a secret on another line); a literal secret under a neutral name (`-v x=hunter2`). (#5399, #5448, #5481, #5482, #5483, #5485)
- Round 7 of the same gate (#5512, #5513, #5514, #5516): every shell word of a psql head and of a psql option is resolved to the word the shell passes (quotes, backslashes, backslash-newline, ANSI-C `$'..'` escapes and empty substitutions removed), so `ps$'q'l`, `$'ps\x71l'`, `ps$()ql`, `$'-v'` and `$'\x2dv'` are read as `psql` and `-v`; a word that still holds an expansion, glob or brace and carries at least two literal letters that could be letters of `psql` (`ps$(printf q)l`, `p[s]ql`, and in a script file `*sql`) is refused as `[psql-undecidable-word]` (in a prose file a word that opens with a glob is not refused by this rule; a word with one literal letter or none, and a command substitution that is the head, are handled by the round-8 rule below), and an option word that opens like a psql option and then holds an expansion (`-$o`, `-X$o`, `--s$x`) is refused as `[psql-undecidable-option]`, while `-h"$HOST"`, `-d "$DB"` and `-U"$USER_NAME"` stay clean. A backtick command substitution in a `-v` value is read like `$(...)`, a substitution is one word whatever spaces it holds (`x=$(cat /run/pw)`), and a value is read from its first `$` or backtick so `x=pw$ROWS` stays clean. The psql segment ends at its own command (a newline, an unquoted `;`, `|` or `&` that is not `2>&1` or `&>`, or the close of the quote, parenthesis or backtick that holds it), so a repeated or continued command is one hit, on its own line, with the offending option in the snippet. Red self-test probes added: 25 for #5512, 10 for #5513 and 7 for #5514 (counted by name in the self-test tables), plus 21 segment probes for #5516, of which 13 want a hit and 8 (5516-09 to 5516-16) assert that there is no hit. (#5512, #5513, #5514, #5516)
- Round 8 of the same gate (#5556, #5557, #5558, #5559): the gate stopped guessing whether an unresolved first word spells `psql`: a command whose first word is not fully literal (any expansion, command substitution, backtick span, glob, brace, ANSI-C or locale quoting) has its credential-shaped `-v`, `--set` or `--variable` operands flagged, in every file type including fenced blocks, indented blocks and inline code in prose, so `"$(command -v psql)" -v pw="$PG_PW"`, `p$X -v pw=...` and `${X}l -v pw=...` are flagged. A quoted string or backtick span that holds a space is read as a command string, and the long-option pattern accepts only true prefixes of `--variable`, so `--variant` is not read as a psql option. Red self-test probes added: 47 (23 for #5556, 14 for #5557, 10 for #5558), plus 5 line-number probes and 12 clean probes; a probe that asserts no hit is counted as a clean case, not a red one (#5559). How a command's head is found was replaced in round 9 below. (#5556, #5557, #5558, #5559)
- Round 9 of the same gate (#5593, #5594, #5595): the proof obligation is inverted. A credential-shaped `-v`, `--set` or `--variable` operand is clean only when the gate proves that its command has a fully literal head that is not `psql`; every other command is flagged, with no cap on the number of words read. Command starts come from a shell tokenisation: a newline, `;`, `|`, `|&`, `&`, `&&`, `||`, `(` and `)`, the inside of `$(..)`, backticks, `<(..)`, `>(..)` and `${..}`, and a quoted word that holds a command string; nesting deeper than 8 levels is never clean. Before the head the gate skips assignments (any number), redirections with their target (an fd number or `{name}` prefix included), the keywords `!`, `{`, `}`, `if`, `then`, `elif`, `else`, `while`, `until`, `do`, `done`, `fi` and `esac`, `coproc` (and `coproc NAME {`), list numbers and document markers (`-`, `+`, `$`, `#`, `%`, `RUN`, `CMD`, `ENTRYPOINT`, a word ending in `:`, a unit `Exec*=` key). `case`, `for`, `select`, `function` and `in` are not modelled and their command is flagged. The wrappers `env`, `nice`, `nohup`, `timeout`, `stdbuf`, `setsid`, `taskset`, `ionice`, `chrt`, `flock`, `chroot`, `sudo`, `doas`, `exec`, `command`, `builtin` and `time` are followed through their exact option grammar and number of positional operands (for example `timeout` and `taskset` take 1, `chrt`, `flock` and `chroot` take 1, `env` takes 0); an unknown option or a non-literal word in an option or operand position is flagged. `sh`, `bash`, `dash`, `zsh`, `ksh`, `mksh`, `ash`, `yash` and `posh` are followed into a literal `-c` string; a non-literal `-c` string is flagged. Programs that run their arguments in a way the gate does not model (`eval`, `xargs`, `ssh`, `docker`, `kubectl`, `su`, `runuser`, `nsenter`, `unshare`, `systemd-run`, `watch`, `find`, `parallel` and 69 others) are flagged. `command -v` and `command -V` run nothing and are clean. Operand shape (#5594): psql's operand is `NAME=VALUE`, and psql rejects a name that holds a colon, so under a head that is not literally `psql` an operand whose first literal colon stands before any literal `=` (a docker or compose mount `SRC:DST`, `"$SECRET_DIR:/s"`) is not read as a psql variable; `pw=$A:$B` and `pw=$PG_PW:x` stay flagged. Whole-repo false-positive cost: the inverted rule alone hit 16 lines (13 `command -v` lookups and 3 docker mounts); with the two narrowings it hits 0, with no allow entry added. Red self-test probes added: 123 (115 for #5593, including the eight reproducers and 39 mutation pins, and 8 for #5594) and clean probes 35 (26 for #5593, 9 for #5594), each run as a script, a prose file and a fenced block. The self-test at this tip runs 978 red and 331 green cases. Stated limits of this rule: a literal program that is not in the wrapper or runner lists and runs its arguments as a command is read as clean; an HTML tag in prose such as `<code>` is read as a redirection and its target; in a prose file a literal first word such as `Run` makes the command clean (a literal `psql` anywhere on the line is still caught by the psql rules above). A `#` is not read as a comment, so text after it is still checked. (#5593, #5594, #5595)
