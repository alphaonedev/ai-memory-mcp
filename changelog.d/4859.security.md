### Security

- `scripts/check-docs-no-argv-secrets.py` now flags `psql -v`/`--set`/`--variable` password assignments wherever `psql` appears on the line: at line start, after a path, after a semicolon, or inside a command substitution. (#4859, #4817, #4808)
- The same gate now reads the psql segment the way the shell does (quotes and backslashes removed) and flags any `psql -v` variable whose name contains pass, secret, token, key, cred, pw or auth, with no locator-suffix or redaction-token exemption. A `psql` word the shell spells with backslashes or quotes (`\psql`, `p\sql`, `ps''ql`, `"ps"ql`) is normalised to `psql` before both psql rules run, a short-flag cluster may carry digits ahead of `v` (`-1v`, `-0v`, `-Xq1v`), a non-ASCII `-v` name is flagged, and a `-v` value with a `$` followed by a secret-like token (`x=$PGPASSWORD`, `x=${PG_PW}`) is flagged under any name; 23 red self-test probes (4 for #5481, 10 for #5482, 9 for #5483) and 8 green ones (1, 4 and 3), counted by name in the self-test tables; a hit on a line that starts with `psql` is now reported on that line, not the line before it (#5485). The name is everything before the first `=` (psql accepts digits anywhere and non-ASCII bytes), a `-v` operand whose name part holds a shell expansion or substitution, or that is only an expansion, is flagged because a text gate cannot decide it, and `run_psql` / `my-psql` wrapper heads are scanned; 27 spellings that passed are now red self-test probes (13 for #5399, 14 for #5448). Stated limits a text gate cannot decide: options passed through an array or another variable (#5398); a secret held in a variable with a neutral name and passed under a neutral name (`x=$A`, with `A` assigned from a secret on another line); a literal secret under a neutral name (`-v x=hunter2`). (#5399, #5448, #5481, #5482, #5483, #5485)
- Round 7 of the same gate (#5512, #5513, #5514, #5516): every shell word of a psql head and of a psql option is resolved to the word the shell passes (quotes, backslashes, backslash-newline, ANSI-C `$'..'` escapes and empty substitutions removed), so `ps$'q'l`, `$'ps\x71l'`, `ps$()ql`, `$'-v'` and `$'\x2dv'` are read as `psql` and `-v`; a word that still holds an expansion, glob or brace and could spell `psql` (`ps$(printf q)l`, `p[s]ql`, and in a script file `*sql`) is refused as `[psql-undecidable-word]`, and an option word that opens like a psql option and then holds an expansion (`-$o`, `-X$o`, `--s$x`) is refused as `[psql-undecidable-option]`, while `-h"$HOST"`, `-d "$DB"` and `-U"$USER_NAME"` stay clean. A backtick command substitution in a `-v` value is read like `$(...)`, a substitution is one word whatever spaces it holds (`x=$(cat /run/pw)`), and a value is read from its first `$` or backtick so `x=pw$ROWS` stays clean. The psql segment ends at its own command (a newline, an unquoted `;`, `|` or `&` that is not `2>&1` or `&>`, or the close of the quote, parenthesis or backtick that holds it), so a repeated or continued command is one hit, on its own line, with the offending option in the snippet. Red self-test probes added: 25 for #5512, 10 for #5513 and 7 for #5514 (counted by name in the self-test tables), plus 21 segment probes for #5516; the self-test at this tip runs 518 red and 197 green cases (each name runs per file type). (#5512, #5513, #5514, #5516)
- `deploy/hive-1461/provision/20_pg_age.sh` builds the image with `-f` and an empty context directory, so the CA key and the secret files are never sent to the docker daemon. (#5401)
- `scripts/postgres-droplet-reinit.sh` runs the pg_dump backup with `sslmode=verify-full` and a pinned local CA (`PG_DUMP_SSLROOTCERT`) written into the `-d` connection string, which libpq ranks above `PGSSLMODE`, `PGSSLROOTCERT` and a `PGSERVICE` file; `PGSERVICE` and `PGSERVICEFILE` are unset first, `PG_PRIMARY_DB` must be a lower-case plain identifier (`[a-z_][a-z0-9_]*`; the unquoted DROP and CREATE fold case while the dump name does not, #5484), `PG_PORT` must be a port number from 1 to 65535 and the backup connection string and the local DROP and CREATE psql calls use it (#5454), and the script refuses with exit 7 before the backup when the CA is unusable or, with `AI_MEMORY_SSH_HOST` set, `PG_DUMP_SSLROOTCERT` is unset. (#5402, #5449, #5450, #5454, #5484)
