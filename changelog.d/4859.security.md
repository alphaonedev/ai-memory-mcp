### Security

- `scripts/check-docs-no-argv-secrets.py` now flags `psql -v`/`--set`/`--variable` password assignments wherever `psql` appears on the line: at line start, after a path, after a semicolon, or inside a command substitution. (#4859, #4817, #4808)
- The same gate now reads the psql segment the way the shell does (quotes and backslashes removed) and flags any `psql -v` variable whose name contains pass, secret, token, key, cred, pw or auth, with no locator-suffix or redaction-token exemption. A `psql` word the shell spells with backslashes or quotes (`\psql`, `p\sql`, `ps''ql`, `"ps"ql`) is normalised to `psql` before both psql rules run, a short-flag cluster may carry digits ahead of `v` (`-1v`, `-0v`, `-Xq1v`), a non-ASCII `-v` name is flagged, and a `-v` value with a `$` followed by a secret-like token (`x=$PGPASSWORD`, `x=${PG_PW}`) is flagged under any name; 23 red self-test probes (4 for #5481, 10 for #5482, 9 for #5483) and 8 green ones (1, 4 and 3), counted by name in the self-test tables; a hit on a line that starts with `psql` is now reported on that line, not the line before it (#5485). The name is everything before the first `=` (psql accepts digits anywhere and non-ASCII bytes), a `-v` operand whose name part holds a shell expansion or substitution, or that is only an expansion, is flagged because a text gate cannot decide it, and `run_psql` / `my-psql` wrapper heads are scanned; 27 spellings that passed are now red self-test probes (13 for #5399, 14 for #5448). Stated limits a text gate cannot decide: options passed through an array or another variable (#5398); a secret held in a variable with a neutral name and passed under a neutral name (`x=$A`, with `A` assigned from a secret on another line); a literal secret under a neutral name (`-v x=hunter2`). (#5399, #5448, #5481, #5482, #5483, #5485)
- Round 7 of the same gate (#5512, #5513, #5514, #5516): every shell word of a psql head and of a psql option is resolved to the word the shell passes (quotes, backslashes, backslash-newline, ANSI-C `$'..'` escapes and empty substitutions removed), so `ps$'q'l`, `$'ps\x71l'`, `ps$()ql`, `$'-v'` and `$'\x2dv'` are read as `psql` and `-v`; a word that still holds an expansion, glob or brace and carries at least two literal letters that could be letters of `psql` (`ps$(printf q)l`, `p[s]ql`, and in a script file `*sql`) is refused as `[psql-undecidable-word]` (in a prose file a word that opens with a glob is not refused by this rule; a word with one literal letter or none, and a command substitution that is the head, are handled by the round-8 rule below), and an option word that opens like a psql option and then holds an expansion (`-$o`, `-X$o`, `--s$x`) is refused as `[psql-undecidable-option]`, while `-h"$HOST"`, `-d "$DB"` and `-U"$USER_NAME"` stay clean. A backtick command substitution in a `-v` value is read like `$(...)`, a substitution is one word whatever spaces it holds (`x=$(cat /run/pw)`), and a value is read from its first `$` or backtick so `x=pw$ROWS` stays clean. The psql segment ends at its own command (a newline, an unquoted `;`, `|` or `&` that is not `2>&1` or `&>`, or the close of the quote, parenthesis or backtick that holds it), so a repeated or continued command is one hit, on its own line, with the offending option in the snippet. Red self-test probes added: 25 for #5512, 10 for #5513 and 7 for #5514 (counted by name in the self-test tables), plus 21 segment probes for #5516, of which 13 want a hit and 8 (5516-09 to 5516-16) assert that there is no hit. (#5512, #5513, #5514, #5516)
- Round 8 of the same gate (#5556, #5557, #5558, #5559): the gate no longer guesses whether an unresolved first word spells `psql`. When the first word of a command (after assignments, options and redirections, and after the wrappers `env`, `command`, `exec`, `sudo`, `doas`, `time`, `nohup`, `eval` and similar) is not fully literal, whatever it holds (any expansion, command substitution, backtick span, glob, brace, ANSI-C or locale quoting, with any number of literal letters, none or one included), the rest of that command is read as `psql` argv and a `-v`, `--set` or `--variable` operand that the gate already calls credential-shaped is flagged. The rule is the same in every file type, including fenced blocks, indented blocks and inline code in prose, and a command substitution or backtick span that is itself the head no longer ends the segment, so `"$(command -v psql)" -v pw="$PG_PW"`, `p$X -v pw=...` and `${X}l -v pw=...` are flagged. A quoted string or backtick span that holds a space is read as a command string. The long-option pattern accepts only true prefixes of `--variable`, so an unrelated tool option such as `--variant` is not read as a psql option. Whole-repo false-positive cost: 0 hits at this tip (a first draft hit 20 lines, all removed by the two narrowings above). Red self-test probes added: 47 (23 for #5556, 14 for #5557, 10 for #5558), each run as a prose file and as a script, plus 5 line-number probes, 11 clean probes (each run per file type) and 1 prose-only clean probe; a probe that asserts no hit is now counted as a clean case, not a red one (#5559). The self-test at this tip runs 609 red and 228 green cases. Stated limits of this rule: a first word that is fully literal and is not `psql` (`docker`, `foo`) is a different command and is not read; a non-literal word after such a literal word is an argument, not a head; a head with no credential `-v` operand is not flagged by this rule (a script file still refuses an undecidable psql-like word, a prose file does not); an option and its argument written as separate words is skipped as a pair, so `sudo -E true $X -v pw=...` reads `$X` as a head. (#5556, #5557, #5558, #5559)
