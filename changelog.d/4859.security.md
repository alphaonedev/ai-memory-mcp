### Security

- `scripts/check-docs-no-argv-secrets.py` now flags `psql -v`/`--set`/`--variable` password assignments wherever `psql` appears on the line: at line start, after a path, after a semicolon, or inside a command substitution. (#4859, #4817, #4808)
- The same gate now reads the psql segment the way the shell does (quotes and backslashes removed) and flags any `psql -v` variable whose name contains pass, secret, token, key, cred, pw or auth, with no locator-suffix or redaction-token exemption. The name is everything before the first `=` (psql accepts digits anywhere and non-ASCII bytes), a `-v` operand whose name part holds a shell expansion or substitution, or that is only an expansion, is flagged because a text gate cannot decide it, and `run_psql` / `my-psql` wrapper heads are scanned; 23 spellings that passed are now red self-test probes (13 for #5399, 10 for #5448). The array-form limit is #5398. (#5399, #5448)
- `deploy/hive-1461/provision/20_pg_age.sh` builds the image with `-f` and an empty context directory, so the CA key and the secret files are never sent to the docker daemon. (#5401)
- `scripts/postgres-droplet-reinit.sh` runs the pg_dump backup with `sslmode=verify-full` and a pinned local CA (`PG_DUMP_SSLROOTCERT`) written into the `-d` connection string, which libpq ranks above `PGSSLMODE`, `PGSSLROOTCERT` and a `PGSERVICE` file; `PGSERVICE` and `PGSERVICEFILE` are unset first, `PG_PRIMARY_DB` must be a plain identifier, and the script refuses with exit 7 before the backup when the CA is unusable or, with `AI_MEMORY_SSH_HOST` set, `PG_DUMP_SSLROOTCERT` is unset. (#5402, #5449, #5450)
- `ai-memory --db <path> curator` opens the explicit database on every store-backed arm (`--rollback-last`, `--prune-reports`, `--reflect`, `--once`), not only the sweep. (#5218)
