**`touch_many` refuses a read-only connection instead of answering `Ok(0)` (#5882, WP-FAULT #6051).**
A connection with `PRAGMA query_only = ON` (the WAL read-pool posture, or a
scope that made the handle read-only) now gets the typed
`storage::TouchRefusedReadOnly` error and nothing is written; the pragma read
itself propagates its error instead of assuming a writable connection. The
return value is `ids.len()` on success, as the doc comment always said. The
only production caller (`SqliteStore::touch_after_recall`) runs on the writer
connection and logs the refusal at WARN.
