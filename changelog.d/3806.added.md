**Calibration harness for the `[decision]` provider slot** — the evidence half
of #3806, folded into the #3564 / #3570 harness family rather than standing up
a second one. `tests/decision_calibration/` computes Brier, expected
calibration error over ten fixed bins, and the reliability curve those
summarise, deterministically under one named seed, from preregistered held-out
sets whose sha256 digests are committed in
`tests/fixtures/decision-calibration/MANIFEST.sha256` **before** any result
exists. Two independent readers verify that manifest — the Rust harness and
`scripts/evidence/decision-calibration.sh` with the system sha256 tool — and a
fixture that changed, vanished, or was added unlisted is RED in both: a
held-out set cannot be grown, trimmed, or re-pointed after seeing the numbers.
Every seam publishes the ALWAYS-ABSTAIN null baseline (no scored items, so its
ECE is **absent**, never a flattering `0.0`) and an ORACLE positive baseline on
the SAME set, so a provider's figure is never read in a vacuum; the per-seam
gate carries a coverage floor beside its ECE ceiling precisely because ECE
alone is gamed by abstaining. A deliberately overconfident fixture
(`synthesis_verdict.miscalibrated.jsonl`, ECE 0.295 against a 0.10 ceiling)
MUST fail the ECE arm for the report to be `PASS` — a gate that cannot go red
gates nothing. Reports render from a closed vocabulary (every string is a Rust
enum token, a fixed literal, a digest, or a preregistered filename; a line
carrying a free-text field is refused, not ignored) and carry `source_commit`
plus the manifest digest, so any number traces to both the tree and the
held-out set that produced it. The producer writes a bound evidence bundle that
`scripts/check-evidence-bundle.sh` validates. Test-only: nothing lands in a
production path. Customer guide: `docs/decision-calibration.md`.
