**`[llm]` inference clients refuse proxies and redirects outside the `allow`
posture (#4193).** Under `AI_MEMORY_INFERENCE_EGRESS=loopback-only` (and
`deny`, for the clients a CLI verb still builds) the chat and embedding
clients honoured `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` and followed
redirects: a process-wide proxy variable routed a loopback-admitted call —
bearer token plus memory content — through an off-host proxy the posture
never admitted, and a 307/308 from the admitted endpoint re-POSTed the prompt
to an origin the gate never checked. Only the `internal-only` pin (#3822)
disabled both. Every inference client is now built through one posture-aware
composition point (`llm::egress_policy::inference_client_builder`): `allow`
is byte-identical legacy; every other posture builds with
`redirect::Policy::none()` and `.no_proxy()`. Pinned by
`tests/inference_egress_proxy_redirect_4193.rs` (RED on the pre-fix tree: a
307 was followed and an environment proxy received the probe under
`loopback-only`; each leg has an `allow` control) and by env-free cells
beside the policy that inject the proxy on the builder.
