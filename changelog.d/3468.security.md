`ai-memory wake-hub` now admits a hello only against a scoped
`a2a-hub/join/v1` delegation, replacing the deny-all placeholder #3467 shipped
(EPIC #3466).

A delegation is a short-lived certificate minted by an agent's **enrolled** key
(`ai-memory identity delegate --scope a2a-hub`) that authorises exactly one
freshly-generated key to present a hello at one named hub as that agent — and
nothing else. It is a NEW signing domain, `ai-memory/a2a-hub-join/v1`, with an
explicit `scope` element, deliberately not `SUBKEY_CERT_V1_DOMAIN`: that tag
carries no scope field and already means "may mint `agent_attested` writes", so
a hub credential minted under it would turn a compromise of a content-free wake
LISTENER into forged, durably-attested history. The minted bundle carries the
delegated private key and never the enrolled `.priv`.

The hub holds only public material — a derived allowlist cache of enrolled keys,
loaded 0600 — and performs no live revocation lookup, so a bounded expiry IS the
revocation mechanism and an over-long window is refused rather than clamped. An
**unproven** root (a `legacy_unproven` binding predating #3464's proof of
possession, or any `bind_authority` this build does not recognise) may not mint a
delegation at all: allowing it would reopen the #3464 defect exactly one
delegation hop out.

Fail-closed throughout. An empty or over-long `claimed_agent_id` is refused
before any key lookup (`Frame::decode` deliberately admits an empty `from` on a
hello, so the id must die at the identity gate rather than reach a map lookup as
an attacker-chosen key). The delegation must name this agent, this hub and this
hello key, so it is neither portable across hubs nor usable by a holder of the
bytes who lacks the key. Every refusal is one `401 unauthorized` on the wire —
"unknown agent", "bad signature" and "unproven root" are indistinguishable to a
peer — while the specific reason is logged. Configuring an allowlist that cannot
be loaded is a refusal to start, not a silent fall back to deny-all, and
`wake-hub --posture` now reports the verifier a configuration actually installs
(`deny-all` or `delegation/v1`) from one shared definition, so the JSON and human
renderings cannot drift from the runtime.

Also hardened from the #3467 review: the accept loop now runs
credentials -> authorize -> permit, so a peer that fails the kernel-credential
gate is dropped in silence — no connection permit consumed and not one byte
written, where previously a hub at its ceiling answered an unauthorized peer
with a `507` before looking at who it was.

Wire: the handshake frame class (`hello`/`join`/`depart`/`subscribe`/
`unsubscribe`) grows from 1024 to 1536 bytes to carry the delegation. The routed
classes are unchanged — a `wake` still cannot exceed 256 bytes — so the fan-out
memory envelope did not move.
