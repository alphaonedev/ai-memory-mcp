**The postgres transit-encryption floor now decides on the options the driver will use.** The floor read the store URL as raw text, while the driver matches keys case-sensitively, honours the `ssl-mode` alias, percent-decodes keys, drops tab and newline characters, ignores the fragment and falls back to `PGSSLMODE`; a URL could pass the floor and still connect with `disable`, `prefer` or `require`. `floored_connect_options` now refuses unless the PARSED options carry `sslmode=verify-full` on a TCP host, so the store, `doctor` and the CLI reads can no longer disagree with the driver (#4434).
