**The postgres transit-encryption floor now decides on the options the driver will use.** The floor read the store URL as raw text, while the driver matches keys case-sensitively, honours the `ssl-mode` alias, percent-decodes keys, drops tab and newline characters, ignores the fragment and falls back to `PGSSLMODE`; a URL could pass the floor and still connect with `disable`, `prefer` or `require`. `floored_connect_options` now refuses unless the PARSED options carry `sslmode=verify-full` on a TCP host, so the store, `doctor` and the CLI reads can no longer disagree with the driver (#4434). A binary built without `sal-postgres` (the release configuration) cannot verify the driver's sslmode, so `doctor`'s Transit section now reports a postgres store URL as unverifiable (REFUSES at boot) and posture check #15 fails, instead of claiming a pin. A URL whose host key the driver does not recognise (an upper-case `HOST=`) is refused because the driver would dial a different host than the URL names (#4434).
