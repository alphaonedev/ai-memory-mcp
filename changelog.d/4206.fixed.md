A federation push that folds into a local row by `(title, namespace)` no longer overwrites that row's text without a recovery copy. When the inbound row wins the newer-wins tiebreak and its text differs from the stored text, the title-slot upsert (SQLite `insert_if_newer`, PostgreSQL `apply_remote_memory`) first snapshots the local row into `archived_memories` with `archive_reason = federation_merge`, in the same write transaction, keyed by the local id. This is the snapshot the same-id merge lane already takes (#1773/#3961). A losing inbound archives nothing. A no-change replay (the same text with a newer timestamp) leaves the earlier snapshot in place, because the comparison is made on plaintext before sealing. On SQLite the federation upsert now always runs under one `BEGIN IMMEDIATE` when it owns the connection. On PostgreSQL the title-slot pre-image probe (advisory lock plus `FOR UPDATE`, filtered to the live title slot) now runs on every apply rather than only when the append-only spine is armed (#4206).
