Gate `memory_pending_reject` on approver eligibility. Rejecting a queued
governance action had no approver check at all, so any tenant — including the
requester, whom `memory_pending_approve` explicitly refuses — could veto any
tenant's pending action and, with `remember`, write a synthetic deny rule off
the back of it. Approve and reject now run the SAME eligibility predicate
(self-decision refusal, named-approver equality, registered-agent requirement)
under the same posture, so the two can no longer disagree, and a refused veto
leaves the pending action untouched and is attributed in the governance audit
chain to the resolved caller rather than to a wire-supplied `agent_id`.
