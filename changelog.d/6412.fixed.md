The sharded-suite lib Postgres gate now follows callers of a Postgres helper by resolved module path instead of by bare name (#6412): `use` imports (plain, aliased, group, glob) and `crate`/`self`/`super` qualifiers are resolved, string literals and comments are ignored, and a function passed by name without a call counts. A same-named unrelated function or method no longer counts as a Postgres site, and an aliased import or a by-name pass can no longer slip past the gate; on the real tree this surfaced one previously missed by-name site (`.or_else(postgres_url)`), already covered by the `store::postgres` prefix. A helper that is itself an impl/trait method is still matched by name (fail closed).
