The sharded-suite lib Postgres gate now finds callers of a Postgres helper as the union of two passes (#6412, #6425; 5-agent vote (4d3ea1c5), 4-1 for the union design). Misses fixed: the by-name pass (the original `name(` matcher, kept unchanged and never filtered), aliases (`use ... as x`, alias of alias), re-exports (`pub use`, glob re-exports, `use super::*` in `mod tests`, transitively with a cycle guard) and `macro_rules!` bodies (a macro whose body names the URL or any helper by bare name, alias or path records every invoking test as well as its own module, #6425); on the real tree this surfaced one previously missed site (`.or_else(postgres_url)`, a function passed by name), already covered by the `store::postgres` prefix. Lexical false positives dropped: strings and raw strings, comments (including nested block comments), char literals, `.name(` method calls and `.name` field access of a free-fn helper, and the definition token itself. Same-named free functions remain an over-match by design (fail closed): no module, shadowing, `#[cfg]` or namespace reasoning decides an exclusion, and the union is add-only over the 674a893c8 matcher except for those lexical drops: sites(tip) is a superset of sites(base) over every fixture class, the 34 + 20 review probes plus the `..helper()` fixtures, and the real tree (verified, and pinned by one invariant test whose oracle shares the method-call predicate with the tool). Only a single-dot receiver (`x.name(`) is a method call: a struct-update base (`S { n: 1, ..name() }`) and a range (`0..name().len()`) are call sites (review r3 #6460). A resolver exception fails the step red; there is no silent fallback. A helper that is itself an impl/trait method is still matched by name (fail closed).
