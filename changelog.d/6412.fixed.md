The sharded-suite lib Postgres gate now follows callers of a Postgres helper by resolved module path instead of by bare name (#6412): `use` imports (plain, aliased, group, glob, `pub use` re-exports) and `crate`/`self`/`super` qualifiers are resolved transitively with a cycle guard, so `mod tests { use super::*; }` sees what its parent imports (plain, glob or aliased) and a `use` of a re-export reaches the helper; string literals and comments are ignored, and a function passed by name without a call counts. A same-named different item defined in the same module, a same-named method call, and a path that provably leaves the crate no longer count as a Postgres site; a name the resolver cannot prove is a different item counts as the helper (fail closed, as the bare-name matcher did). A `macro_rules!` whose body names the URL or calls a helper (transitively through other macros) records every invoking test as well as its own module (#6425). On the real tree this surfaced one previously missed by-name site (`.or_else(postgres_url)`), already covered by the `store::postgres` prefix. A helper that is itself an impl/trait method is still matched by name (fail closed).
