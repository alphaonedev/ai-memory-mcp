**Cert-expiry gate escapes control characters in printed names (#6175).**
`scripts/check_cert_expiry.py` printed names that a pull request controls (watched
federation-wire paths, workflow file names in `GUARD SHADOW` lines, the
`Rule-Change-Approved-By` value, banner text and git error output) verbatim. A newline or
carriage return in such a name started a new step-log line, and the Actions runner reads a
line that begins with `::` (after trimming leading whitespace) as a workflow command, so a
change could inject forged annotations or other commands into the gate's log; the verdict
exit code was never affected. Every such name now goes through `log_safe()`, which escapes
backslash, C0 and C1 control characters, DEL, U+2028 and U+2029 (`\x0a`, `\u2028`, ...), in
both the required `pull_request` job and the trusted job. New self-test cells plant a
watched path, a workflow file name and an approval trailer that carry a forged `::error` and
require them to be shown escaped with no log line read as a workflow command. Round 3: the
file name in the oversized-blob and blob-read errors is escaped too, the `(fail-closed)` suffix
is no longer doubled, and cells pin the U+2028 / C1 escapes and the `%` escape in the
`::warning` annotation. Refs #6140.
