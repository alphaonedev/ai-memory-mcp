**An interrupted gate self-test no longer strands probe files in the tree (#4292).** Six `scripts/check-*.sh` self-tests have to plant probe files inside the repository, because the gate under test scans `src/` or `tests/`. Four of them removed their probes only on the normal path, with no trap: `check-test-env-lock.sh`, `check-test-stdin-reads.sh`, `check-create-extension-allowlist.sh` and `check-vendor-literals.sh`. A disk that filled, a `^C` or a CI cancel stranded the probes. A stranded `src/` probe then failed other gates: on 2026-09-30 it turned the #3838 landing gate's `check-cert-removal-proof.sh --self-test` red on a clean change. A fifth gate, `check-const-name-literals.sh`, cleaned up but, trapping EXIT only, let an interrupted run finish and exit 0. All five now use one shared helper, `scripts/lib/selftest-probes.sh`. It removes every registered probe on EXIT, INT or TERM and stops a running gate child. It then re-raises INT/TERM, so an interrupted self-test dies of the signal and never reads as a pass. The long gate run is waited for in the background, so a SIGTERM is acted on at once rather than after the whole gate run, which a CI cancel's SIGKILL would cut short. `scripts/test/test-gate-selftest-interrupt-cleanup.sh`, run in CI, interrupts all six self-tests with SIGINT and SIGTERM once a probe appears. It requires `git status` to be unchanged and a non-zero exit. On the pre-fix scripts it failed 9 of 12 runs. `check-const-name-literals.sh` also gains the "probe already exists: refuse (exit 2)" guard the others had, so it no longer overwrites and then deletes a file already at its probe path. The same test now plants a file at every probe path each of the six self-tests declares, and requires exit 2 with the file left byte-identical.
