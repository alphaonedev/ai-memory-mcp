### Fixed

- **[ci-gate] `check-hardcoded-literals.sh` returned a different verdict on
  macOS than on Linux, because BSD `uniq` groups lines by LOCALE COLLATION
  rather than by bytes**
  ([#3537](https://github.com/alphaonedev/ai-memory-mcp/issues/3537)).
  Gate-script change only; no product behaviour and no baseline content is
  altered. The gate decides a literal's identity with `sort | uniq -c`, and
  BSD/macOS `uniq` compares lines through the locale collation. In
  `en_US.UTF-8` a run of U+2500 BOX DRAWINGS LIGHT HORIZONTAL collates as
  ignorable, so the 89-, 81- and 109-character box rules in `src/bench.rs`
  (x2) and `src/bench_relevance.rs` (x1) — three DISTINCT literals with ONE
  production site each — folded into a single group and were reported as
  `+3 (baseline 0)`, failing the gate for the bare published tip. GNU `uniq`
  compares bytes, so on the Linux push gate the same three literals stayed
  three count-1 entries, below `DUP_THRESHOLD`, and correctly never entered
  the frozen baseline.
  - The mis-grouping was not merely a false positive: it attributed one
    literal's sites to a DIFFERENT literal's key. With the `--self-test`
    probes planted, the pre-fix script reported `+6` for a literal that
    occurs 3 times, having absorbed three unrelated box rules into that
    key's count. A ratchet gate whose counts can be charged to the wrong
    key cannot be trusted to hold a shared baseline.
  - The whole pipeline (`grep`, `awk`, `sort`, `uniq` and bash's own pattern
    matching) is now pinned to `LC_ALL=C`, which is the byte-exact semantics
    the shipped baseline already encodes — `LC_ALL=C` alone makes the macOS
    host reproduce the Linux verdict on the unmodified tree.
  - The same pin fixes a LATENT divergence of the same class in `MIN_LEN`:
    one-true-awk `length()` counts BYTES (243 for that 81-character rule)
    while gawk in a UTF-8 locale counts CHARACTERS (81), so the threshold
    meant two different things per host. Under `LC_ALL=C` gawk, mawk,
    one-true-awk and BSD awk all make `length()` byte length. Byte length is
    the fail-closed choice — bytes >= chars, so the byte test admits a
    SUPERSET of the character test and the gate can only ever catch more,
    never fewer, duplicated magic strings — and on the tree the baseline was
    frozen from, the two measures select an identical literal set, so no
    existing baseline entry is reinterpreted. The chosen semantics is stated
    in a PORTABILITY / DETERMINISM CONTRACT block at the top of the script.
  - `--self-test` is now the anti-regression proof rather than a single
    liveness check. It plants three probes and runs the gate once per awk
    installed on the host (`awk`, `gawk`, `mawk`, `nawk`, `/usr/bin/*`,
    de-duplicated by resolved path, absent ones reported by name), requiring
    a BYTE-IDENTICAL violation set from every one: **A** the existing
    `gate-probe-magic-string-xyz` triplicate, which must stay red; **B** the
    #3537 shape — three U+2500 rules of DIFFERENT lengths with one site each,
    which must NOT be reported (it is reported on the pre-fix script); and
    **C** a 4-character / 12-byte multibyte literal on 3 sites, which must be
    reported and so pins the byte-length reading of `MIN_LEN`. Probe bytes are
    written with octal escapes so they are exact regardless of the ambient
    locale, and the planted files are removed by an `EXIT`/`INT`/`TERM` trap
    so a killed run cannot leave a contrived `.rs` under `src/`.
  - The self-test now re-enters the gate through `"${BASH}"` instead of the
    shebang. `#!/usr/bin/env bash` resolves to whatever bash is first on
    `PATH`, so with `/usr/bin` ahead of the homebrew prefix the child ran
    under stock bash 3.2, died on the existing `bash >= 4` guard, and the
    self-test reported a phantom failure. The shebang itself is unchanged.
