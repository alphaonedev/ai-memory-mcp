**Every stdio MCP write tool is sealed by the session signer (#10012, #10010).** With
`AI_MEMORY_MCP_SIGNING_KEY_FILE` loaded (#9926), every connection the `ai-memory mcp`
process opens is armed with a write-seal funnel: a memory row a tool inserts for the
session agent in this call, or changes when its prior seal is the session's own and
intact, is signed with the session key and lands `agent_attested`, whichever tool wrote
it (`memory_update`, `memory_capture_turn`, `memory_notify` and the rest no longer land
`claimed`, `self_signed` or with no level). The session signs only bytes it wrote: a row
whose stored seal does not verify is refused in both modes with `ATTESTATION_FAILED:
mcp session signer (#10012): stored seal does not verify; refusing to re-sign (row
<id>)`, a write that changes bytes another agent's verifying seal covers is refused in
both modes, and an unsigned row the session did not seal is left as written (refused
under strict mode, with the row named).
The `derived_from` links of `memory_consolidate` and `memory_offload` blobs are signed
by the session key too; `memory_kg_invalidate` re-signs a link only when its stored
signature verifies with the session key, and refuses a tampered link, a link signed by
another agent and (under strict mode) an unsigned link or one with no observer.
Under `AI_MEMORY_REQUIRE_AGENT_ATTESTATION=1` a write the session cannot seal, such as
a `memory_share` or `memory_agent_register` row owned by another agent, is refused with
an exact `ATTESTATION_FAILED: mcp session signer (#10012)` reason and nothing is stored.
The session never signs for another agent. With the variable unset nothing changes.
