### Security

- **[wake-hub] The packaged refresher's root hand-off no longer follows a symlinked source (CWE-59) and is now atomic**
  ([#3971](https://github.com/alphaonedev/ai-memory-mcp/issues/3971), from
  [#3637](https://github.com/alphaonedev/ai-memory-mcp/issues/3637) M4).
  `ai-memory-wake-hub-refresh.service` ran `ExecStartPost=+/usr/bin/install … /var/lib/ai-memory/hub-allow.json
  /run/ai-memory-hub/hub-allow.json` as root. The source directory is writable by the `ai-memory` uid and
  `install(1)` dereferences its source, so the less-privileged writer chose what root read; `install(1)` also
  unlinks and re-creates the destination, so the hub could find no snapshot mid-copy. The unit now runs
  `ai-memory wake-hub --publish-snapshot SRC --allowlist DEST` under `env -i`, a packaging-internal mode
  (stable argument shape and exit codes `0`/`1`/`2`, unstable output text). It walks both parent directories
  from `/` with `O_NOFOLLOW`, refuses unless the source directory belongs to a non-root uid, the destination
  directory to a different uid and neither is group- or world-writable, proves the source through `fstat` on
  its own descriptor (regular, one link, `0600`, owned by its directory's owner, at most 1 MiB; a FIFO is
  refused without blocking), validates it with the hub's own reader, and publishes through an `O_EXCL` temp
  file handed to the destination's owner at `0600`, `fsync`, `renameat` and a directory `fsync`. The mode is
  the first action of `main` after argument parsing: it opens no config, store, key, log or socket, and no
  environment variable changes it. Every refusal names its reason, exits `1` and publishes nothing.
  A CI step proves the hand-off as real root across two uids. **Operators with a customised refresher unit
  must replace their `install` line** with the shipped `ExecStartPost=`.
