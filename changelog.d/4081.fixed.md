Fix #4081: Postgres `GET /api/v1/subscriptions` returns documented `null`
dispatch/failure counters when persistence is unavailable, instead of
fabricating zeros after real deliveries. A counter UPDATE matching no
subscription now reports a `dispatch_counter` bookkeeping failure on both
backends. SQLite continues to expose persisted counts. Regression tests
cover missing rows, acknowledged plus failed SQLite counters, and real
Postgres-backed HTTPS deliveries followed by the owner-visible listing.
