### Security

- **[authz] `set_namespace_standard` may no longer REPLACE another tenant's
  bound governance standard**
  ([#3758](https://github.com/alphaonedev/ai-memory-mcp/issues/3758)). The
  SET funnels (HTTP `POST /api/v1/namespaces` + `/namespaces/{ns}/standard`,
  MCP `memory_namespace_set_standard`, both SAL adapters) authorized the
  memory BEING bound and the declared parent — never the standard CURRENTLY
  bound — so any caller could overwrite another tenant's policy with a memory
  of their own (a governance-config takeover) while being refused to clear
  it. SET now runs the same predicate CLEAR uses
  (`visibility::namespace_standard_mutation_admission`, one decision for both
  ops, both backends), at the HTTP funnel before any write and inside the
  adapter's upsert transaction; a foreign named owner is refused with the
  #3407 closed shape (403 `NOT_OWNER`, `namespace` echoed, owner never
  named). The owner still replaces her own standard, an unbound namespace
  binds for anyone, and a severed / dangling binding remains the SET repair
  path (CLEAR still refuses it, #2545). `MemoryStore::set_namespace_standard`
  now honours its `CallerContext` on both adapters.
