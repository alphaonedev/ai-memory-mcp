**Test-env hygiene: one `$HOME` mutex, a helper-blind census closed, five
victim tests moved to their own process, an unconditional refusal leg, and a
structural test-only identity seam (#3523).**

`src/**/*.rs` compiles into ONE `cargo test --lib` binary whose `#[test]`
functions run in PARALLEL THREADS, so a process-global environment write is
both unsound (rust-1.98 UNSAFE-01/03) and globally VISIBLE. Five independent
holes in that containment are closed.

**1 — ONE `$HOME` mutex, not two.** `crate::test_support::env_lock()` declared
its own `static LOCK: OnceLock<Mutex<()>>`, so the crate held TWO independent
mutexes over exactly the same process-global environment table: this one
(taken by `log_paths`, `encryption`, `daemon_runtime`) and
`crate::config::test_env_lock()` (taken by `config`, `reranker`, `egress`,
`security_profile`, `cli::commands::config`, `recover::transcript_paths`,
`enterprise_federation_posture`). Holding either excluded only its own users,
so a `log_paths` test setting `HOME` and a `config` test reading
`~/.config/ai-memory/config.toml` could run at literally the same instant —
the identical per-module-mutex defect `$HOME` already suffered three times
(#1998 -> #2115 -> #2127); this was its fourth. `test_support::env_lock()` now
DELEGATES to `config::test_env_lock()`, which acquires the one
`config::test_env_mutex()`. **Both names survive, so no call site moved.**
Pinned twice, deliberately complementary: `tests/env_lock_singleton_gate_3523.rs`
walks the source (neither entry point declares a mutex; a census over the
`env_lock` family caps who may own one), and
`test_support::tests::the_two_env_lock_paths_are_one_mutex_3523` pins it by
OBSERVATION — holding one wrapper, a PROBE THREAD must fail to `try_lock()`
the other, which a source walk cannot see and a correctly-spelled delegate
that resolved elsewhere would still pass.

**2 — `check-test-env-lock.sh` arm (e).** Arm (d) (#3475) counts LITERAL
`set_var(` / `remove_var(` LINES per file, so an env write routed through a
CROSS-FILE helper is invisible to it: the file spells neither verb, its count
stays 0, and it can be absent from the arm (d) baseline entirely.
`src/log_paths.rs` (73 helper-routed writes) and `src/encryption/mod.rs`
appear in that baseline **not at all**. The new arm (e) is a sibling per-file
census over the cross-file helpers (`test_support::EnvGuard`,
`identity::agent_id_env_set_guard` / `_unset_guard`, and the two
security-posture installers) against its OWN baseline, so the #3475 baseline
stays byte-identical. `identity::test_key_dir::install` / `::arm` and
`cli::test_utils::ensure_no_config_env` are DOCUMENTED-EXEMPT: both write a
fixed, isolation-PRESERVING value and are near-mandatory boilerplate, so
counting them would fire on almost every added test while catching nothing an
operator would act on. The script header enumerates every `set_var` wrapper in
`src/` and classifies each (file-local — already ratcheted by arm (d) via its
own definition line — vs cross-file counted vs cross-file exempt), so the
exemptions are decisions rather than oversights. `--self-test` plants a
helper-routed write that spells neither verb (invisible to arms (a)-(d) by
construction) and requires arm (e) to catch it, alongside a NEAR-MISS probe
using the exempt fixture that must be SPARED.

**3 — the five `*_3387` cases run in their own process.** They pass an
EXPLICIT caller and assert an existence-hiding REFUSAL plus ZERO egress, which
makes them exactly the #3517 VICTIM shape: a sibling installing
`AI_MEMORY_AGENT_ID` steers every concurrent reader, and a refusal assertion
that starts passing for the wrong reason is worse than one that fails.
Serializing the mutators cannot help — the victims are READERS that take no
lock. Per the #3475 pattern they moved to `tests/detect_contradiction_3387.rs`
(its own binary, its own process), BYTE-FOR-BYTE apart from three mechanical
rewrites: `crate::` -> `ai_memory::`, the de-indent, and the call through a
`cfg`-gated public wrapper that forwards its four arguments verbatim. Every
assertion is unchanged.

**4 — a STRUCTURAL, test-only injection seam for the caller principal
(product change; see the security note).** Until now the ONLY way a test could
influence `identity::resolve_agent_id` / `resolve_read_visibility_caller` was
to write `AI_MEMORY_AGENT_ID` into the PROCESS environment — the write that
causes the #3475 / #3517 class. `identity::test_agent_id::AgentIdOverride`
replaces it with a THREAD-LOCAL override consulted by the one new
`agent_id_env()` chokepoint the three resolvers now read through. A value
installed on one test thread is invisible to every other BY CONSTRUCTION: no
lock, no window, no way to steer a sibling.

*Security note.* The seam is `#[cfg(any(test, feature = "test-support"))]` —
STRUCTURAL, not a runtime flag: under `cargo build --release` (default
features) neither the module nor the line that consults it is compiled, and
`agent_id_env()` is exactly `std::env::var(ENV_AGENT_ID)`. That alone is not
sufficient, and #3516 is why: the self dev-dependency unifies `test-support`
into every `cargo test` build INCLUDING the `ai-memory` BIN, so there the
module IS compiled. It is inert there because the thread-local defaults to
`None` (an unarmed process is byte-identical to one without the seam) and
because nothing production-side arms it.
`tests/agent_id_seam_structural_3523.rs` asserts BOTH by source walk — the
`cfg` gate on each half, and the absence of any arming call site anywhere in
`src/` outside the defining file — plus the runtime behaviour (the override
reaches the resolver, restores on drop, and does NOT cross a thread boundary),
so a `cfg`-gated module nothing consults cannot pass vacuously. Documented
bound: the override deliberately does not cross `spawn_blocking` or a runtime
worker; a test whose handler runs on another thread must pass an EXPLICIT
caller.

**5 — the auto-atomise refusal leg is unconditional.**
`db::GOVERNANCE_PRE_WRITE` is a process-wide `OnceLock`, and
`test_auto_atomise_refused_memory_not_atomised` installed its hook inside its
own body and then SOFT-SKIPPED the load-bearing assertion when the insert
succeeded. That made `a refused write must never reach the auto-atomise
funnel` conditional on TEST ORDERING, which libtest does not promise. The hook
is now installed by `test_guard()` — the entry gate every case in this binary
takes — so whichever case runs first arms it, and the refusal leg asserts
unconditionally in every ordering; a success is now a hard failure naming the
one-shot rather than a silent skip. The hook is discriminating (it refuses
only `refused-`-prefixed titles), so no other case's behaviour changes.
