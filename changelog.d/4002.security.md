### Security

- **[docs][identity] The published TOFU recipe pins the daemon identity, not
  the signature bytes** ([#4002](https://github.com/alphaonedev/ai-memory-mcp/issues/4002)).
  The NSA-CSI mapping (Markdown and HTML) and the `mcp::server_identity`
  module doc told clients to capture the `ai_memory_identity` signature on
  first connect and refuse any later connect presenting a different one. The
  signature covers `signed_at`, which the daemon takes fresh on every
  `initialize`, so the bytes change on every connect and a client following
  the recipe rejects every legitimate reconnect (or turns the check off). The
  recipe now says: verify the envelope, pin `public_key` + `daemon_id`,
  verify each later envelope's signature against the pinned key, and treat a
  key change as rotation requiring explicit approval. Pinned by
  `tests/mcp_initialize_server_signing.rs::tofu_pin_is_the_identity_not_the_signature_bytes_4002`
  and `tests/fit_docs_b_false_claims_4000_4009.rs`.
