**Forensic governance log: no plaintext action content, and decision rows are opt-in (#3647).**

The signed forensic log (`<audit dir>/forensic-YYYY-MM-DD.jsonl`) used to store every governed agent action in full: shell commands, process arguments, custom payloads and recall queries, along with the rule's reason text. That applied to refused actions too. It also started on every boot, whatever `audit.enabled` said. Anything secret in a command therefore ended up as a second plaintext copy in the log and in wherever the log is shipped or backed up.

What changes for operators:

- **Governance decision rows now need `audit.enabled = true`.** They cover agent actions, admin operations, approvals, archive/purge, namespace standards and capability grants. The default config no longer writes them. If your SIEM tails these rows, add `[audit]` with `enabled = true` to `config.toml` and restart.
- **Integrity rows are still written by default.** These are the truncation watermark behind `verify-audit-trail`, open-time rollback evidence, and the unverified-restore record. The forensic directory is still created on every boot, so tamper detection works without any configuration.
- **Rows no longer carry request content.** An agent action is recorded as actor, action kind, rule id and outcome, plus `content_mac`: an HMAC-SHA256 of the action and decision, keyed from the daemon's signing key. Free text in other rows (reasons, error messages, memory titles) is recorded the same way. Actor, rule and identifier fields are kept as written only when they look like identifiers and carry no credential; anything else becomes a commitment. Without a daemon key the commitment is written as `withheld:unsigned` and no hash is stored, because an unkeyed hash of a short command could be confirmed by guessing.
- **Consumers that read `payload.action`, `payload.decision_detail` or free-text `reason` fields must switch** to the identity and outcome fields. With the daemon key, `ai_memory::governance::audit::forensic_commitment` recomputes a commitment so you can check a row against content you already hold.
- **Existing log files are not rewritten.** They still verify with `ai-memory audit verify --since <YYYY-MM-DD>`.
- **`audit.redact_content = false` is refused.** It turns off decision rows and prints a boot diagnostic, rather than being quietly ignored. Integrity rows are unaffected.
