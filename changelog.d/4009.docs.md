### Documentation

- **The v1.0.0 release notes no longer say the abort-after-commit harness
  proves power-cut durability**
  ([#4009](https://github.com/alphaonedev/ai-memory-mcp/issues/4009)). The
  `AI_MEMORY_DB_SYNCHRONOUS` entry said `FULL`/`EXTRA` make an acknowledged
  write survive a power cut and that the `AI_MEMORY_TEST_ABORT_AFTER_COMMIT`
  harness "proves it". The harness calls `std::process::abort()`, which leaves
  the OS page cache intact; `PERFORMANCE.md` already marks real power-cut
  durability NOT proven. The entry (and the `CLAUDE.md` row for the harness
  knob, which said it simulates "a power cut") now say the harness proves crash
  consistency across an unclean process exit and that power-cut fsync
  behaviour is not yet evidenced (#3561). Docs only; pinned by
  `tests/fit_docs_b_false_claims_4000_4009.rs`.
