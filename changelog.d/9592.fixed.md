**CI: the linux-fed enterprise-fed serial shard runs its integration binaries on per-binary Postgres clones in one step (#9592).**
The per-binary isolation wrapper (#6383) was off on every leg, so the serial
shard ran every Postgres test binary one after another on one shared
database. Per `3-agent vote (71472661)` (decision A, step-scoped opt-in), the
flag is now `1` in exactly one place: the step `Serial shard isolated binaries
(linux-fed enterprise-fed, issue 9592)`. "Run tests" defers the serial shard's
`--test` binaries to that step, which runs them through
`scripts/ci/pg_isolate_serial_step.py`: each on its own clone of an age+vector
template, eight at a time, with the residual binaries alone on the shared
database after the pool drains, and in-binary `--test-threads=1` unchanged.
The wrapper's admission re-reads the connection budget on every acquire and
reserves the sessions of every binary in flight, and the binaries with a
cluster-global operation or a wall-time assert (the audit in
`scripts/ci/pg_isolate_cluster_audit.py`) are on the residual list, so neither
defect of PR 8230 returns. The step fails closed on a missing log, a zero-test
binary (no test line at all, whatever the result line says), a log whose ok,
FAILED and ignored test lines differ from the totals of its real (last)
result line, any test filtered out, a second result line outside a
captured-output body, a log without its `current_database` evidence line, two binaries on
one database, a skip print, a clone failure and any clone or
template left after teardown; the always() cleanup tears a cancelled run down
again. `scripts/ci/pg_isolate_parity.py` compares the per-test ok, failed and
ignored outcomes with the serial path. The repository variable
`CI_PG_ISOLATE_OFF` (`1`/`true`/`on`, any case; any value other than those
and `0`/`false`/`off`/empty is red) selects the exact serial path. One
completion ledger in `$RUNNER_TEMP` ties the halves together: "Run tests"
writes the deferred list and the mode, the isolated step writes the run id
before its first clone and one row per binary when green, and the always()
Cleanup step (which now runs the isolation cleanup first and carries its exit
code on every path) is red unless the ledger matches the list and no clone is
left. The isolated step runs inside the #7914 host semaphore, never on a fork
pull request, redacts its per-binary logs before the upload, is red on any
skip print and checks each binary's ignored test names against `--list --ignored`.
The re-cut (PR 9841) adds three changes. The log parse strips ANSI colour
codes first, because ci.yml sets `CARGO_TERM_COLOR=always` and the coloured
`Running` line matched nothing, so every deferred binary was "missing".
`pg_health_probe_constant_cost_2617` and `pg_record_stop_write_gate_ttl_3276`
are residual by design (a clone starts empty and un-migrated: the first needs
rows other binaries wrote, the second needs its first write inside a window
the migration ladder uses up), pinned by
`scripts/ci/tests/test_pg_isolate_residual_by_design_9592.py`. A binary whose
every test is `#[ignore]` is accounted instead of "zero tests": one rule,
`evidence_reason` in `scripts/ci/pg_isolate_parity.py`, used by the parity
checker and the step alike, holds it to one test line per ignored test, the
exact totals, nothing filtered out and the same ignored names as its own
`--list --ignored`.
The invariant checker's G1 allows that one site and is red on a second one,
on an expression-valued `env:` and on a script that writes the flag to
`GITHUB_ENV`; G7, G8 and G10-G14 check the step wiring. Tests:
