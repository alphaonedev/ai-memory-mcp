**A SQLite database is created or moved to schema v103 only with the daemon key (#10145, #10155).**
The v103 agent cutover marker on SQLite is now signed by the daemon key (`daemon` keypair in the
key directory). Opening a SQLite database that needs to be created or moved to v103 provisions
that key first; when no usable key can be had (generation disabled, only one key half present,
the halves do not match, no key directory, or an unusable key directory) the open is refused
with `daemon key missing: <cause>` before any byte is written: no file is created, the database,
its directory and the key directory stay byte-identical, and no half key is healed. A database
already at v103 opens without the key. The stored format has no keyless variant. The binary
before this change still opens a database this change refused, because the refused database was
not touched. The postgres adapter still writes the v103 marker unsigned.
