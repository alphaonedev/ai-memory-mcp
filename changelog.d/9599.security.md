**Secret screen: every detector runs in time linear in the screened text (#9599).**
The prefix detectors (`github_pat_`, `ghp_`, `sk-`, `xai-`, `Bearer`), the AWS
access-key detector and the JWT detector re-scanned the rest of a token run,
and the prefix detectors rebuilt the entropy histogram over it, for every
candidate they rejected, so a field near the content cap with many candidates
in one long run cost time quadratic in its length on the write, import and
federation receive paths. Each detector now keeps its per-run state (the run
end, an incremental suffix histogram, the dot offsets of the run) and reuses it
for every later candidate in the same run; the AWS check reads only the fixed
16-byte window after the prefix. Every candidate is still judged on its own
full token, so the screen detects exactly what it detected before, including a
secret that follows a rejected candidate in the same run. PEM blocks and the
fast-path checks were already linear. Tests:
`src/secret_screen_linear_9599_tests.rs` (an op-count ceiling per input byte
at the content cap and at 128 KiB, a doubling bound, and a differential check
against the previous detectors over a generated corpus with multi-byte text).
