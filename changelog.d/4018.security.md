**The inference-egress gate reads the target host with the HTTP client's own
parser (#4018).** Under `loopback-only` and `internal-only` the admission
check extracted the host from the configured base URL with a hand-rolled
authority parser (authority bounded at the first `/`, `?` or `#`, host taken
after the last `@`). The request is sent by reqwest, whose WHATWG `Url`
parser also ends a special scheme's authority at a backslash, so the two
could name different hosts for one string: `https://evil.example\@127.0.0.1/v1`
was admitted as loopback (and, under `internal-only`, pinned on `127.0.0.1`)
while the client connected to `evil.example`. Memory content could leave the
host with the gate reporting compliance. Admission, the loopback predicate
and the resolve-then-pin now all read the host from one `reqwest::Url` parse
(`egress::admitted_host`), the pinned port is that parse's explicit or
scheme-default port, and the request URL is built from the same parse
(#3742). A target reqwest could never send to — no scheme, a non-http(s)
scheme, no host — is refused instead of admitted (a scheme-less
`localhost:11434` is no longer treated as loopback). Pinned by
`tests/egress_admission_parser_4018.rs` on a table of disagreeing shapes
(RED on the pre-fix tree: `loopback-only` admitted the backslash shape and
`internal-only` pinned a host the client never contacts), with presence
controls on the same hosts spelled unambiguously.
