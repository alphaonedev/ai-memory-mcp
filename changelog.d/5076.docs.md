**Docs: the PgBouncer prepared-statement caveat (enterprise guide §5.6.6) names all three failure modes (#5076).**

`sqlx-postgres` 0.8.6 names prepared statements `sqlx_s_<n>` from a
per-client-connection counter, so on a shared server connection a
statement can be missing, collide (`already exists`), or execute another
client's same-named statement. The guide now states that
`max_prepared_statements > 0` (PgBouncer ≥ 1.21) is mandatory wherever
server connections are shared between clients, and no longer claims the
adapter avoids named prepared statements.
