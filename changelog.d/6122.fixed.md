**Integration tests no longer leak sqlite `-wal`/`-shm` side files (#6122).**
About 200 integration suites bound a WAL-mode sqlite database to a
`tempfile::NamedTempFile` and dropped the handle before the router/store that
owned the connections; SQLite does not delete the `-wal` once the main file
has moved, so every such test orphaned `.tmp*-wal` / `.tmp*-shm` in `TMPDIR`
(`http_source_uri_query`: 12 orphans per run, now 0). The suites now use
`tests/common/sqlite_tempfile.rs::SqliteTempFile`, a drop-in owner that removes
the `-wal`, `-shm` and `-journal` siblings. `tests/tmp_leak_guard_6122.rs`
pins the behaviour and holds two ceilings: (1) zero files anywhere under
`tests/` (recursive) that pair a raw `NamedTempFile` with a sqlite open
(`db::open`, `SqliteStore::open`, `storage::open`, `storage::open_read_only`,
`open_db` or `Connection::open`); (2) a falling per-file ceiling on
`std::mem::forget` of a temp handle (68 pre-existing files, migration tracked
in #6458; a new site fails). The `embedding_space_boot_maintenance_2167_daemon_pg`
suite no longer forgets its scratch handles. Test-only change; no production
code touched.
