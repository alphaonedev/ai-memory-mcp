**Integration tests no longer leak sqlite `-wal`/`-shm` side files (#6122).**
About 200 integration suites bound a WAL-mode sqlite database to a
`tempfile::NamedTempFile` and dropped the handle before the router/store that
owned the connections; SQLite does not delete the `-wal` once the main file
has moved, so every such test orphaned `.tmp*-wal` / `.tmp*-shm` in `TMPDIR`
(`http_source_uri_query`: 12 orphans per run, now 0). The suites now use
`tests/common/sqlite_tempfile.rs::SqliteTempFile`, a drop-in owner that removes
the `-wal`, `-shm` and `-journal` siblings. `tests/tmp_leak_guard_6122.rs`
pins the behaviour and holds two ceilings: (1) zero files anywhere under
`tests/` (recursive) that pair a raw `NamedTempFile` (also built through
`tempfile::Builder`) with a sqlite open (`db::open`, `SqliteStore::open`,
`storage::open`, `storage::open_read_only`, `open_db`, `open_with_flags`,
`Connection::open`, including aliased `use ... as` and bare imported forms); (2) an exact per-file pin on
`std::mem::forget` of a temp handle (qualified, bare-imported or aliased calls),
and zero use of `ManuallyDrop::new(`, `Box::leak(`, `.into_path()`,
`.into_temp_path()` or `.keep()` in files that hold a temp handle (68 pre-existing files, 78 sites, migration
tracked in #6458): a new site, a count that fell without its entry being
lowered, or an entry for a file that is gone fails, and the table total and
file count are pinned too, so the ceiling only falls. The scan itself fails closed on any symlink under `tests/` (file or
directory), naming the one offending path, and on any unreadable or non-UTF-8
source. The `embedding_space_boot_maintenance_2167_daemon_pg`
suite no longer forgets its scratch handles. Test-only change; no production
code touched.
