### Fixed

- **[security][fail-open] The coordination lease `holder` was an
  unauthenticated caller-asserted string — any co-located agent could release,
  renew or steal another agent's lease**
  ([#3361](https://github.com/alphaonedev/ai-memory-mcp/issues/3361)).
  A lease is the ownership primitive of the coordination substrate, yet
  `memory_lease_acquire` / `_renew` / `_release` read `holder` with
  `require_str` alone. `memory_lease_get` PUBLISHES the current holder, so
  reading `ai:alice` and replaying that string into `memory_lease_release`
  returned `released: true` for a caller that never held the lease — and the
  same trick renewed or re-acquired it. The value was also never run through
  `validate_agent_id`, so spaces, control characters and reserved internal
  sentinels landed in the `coordination_audit` identity fields (log injection)
  and wedged `claimed_by`-bound transitions, which *do* validate.
  - `holder` is now resolved through `identity::resolve_governance_subject` —
    the same control #3171/#3363 applied to every other caller-asserted
    principal, and the direct analogue of #2996's `signal_send.from_agent`
    bind. The wire value is ALWAYS wire-strict-validated
    (`validate_agent_id`), in both postures; under the MULTI-TENANT posture
    (`AI_MEMORY_AGENT_ID` set) it is BOUND to the resolved caller and a
    `holder` naming anyone else is REFUSED.
  - Under the SINGLE-OPERATOR default (`AI_MEMORY_AGENT_ID` unset) the holder
    remains the *validated wire value*: with no configured identity the
    substrate cannot distinguish one local caller from another, so binding
    would be a no-op by construction rather than a control. This is the
    accepted, deliberate posture — identical to what #3363 shipped for the
    other caller-asserted principals — and it means zero-config coordination
    with a worker label such as `w1` is byte-identical to before, except that
    a malformed label is now refused rather than persisted. An operator who
    needs enforced lease ownership sets `AI_MEMORY_AGENT_ID` per agent, which
    is the same switch that engages every other multi-tenant gate.
  - Scope: the lease acquire/renew/release wire surface is MCP-stdio only and
    structurally sqlite-local (there is no HTTP lease route and no
    postgres-reachable lease-mutation surface — see the #2513 reachability
    note on `store::MemoryStore::lease_acquire`), so there is no second
    backend to keep in parity here.
  - The `memory_lease_renew` / `memory_lease_release` tool docs no longer
    advertise `holder` as an unauthenticated coordination token.
  - Regression pins for BOTH directions: DENIED — a non-holder cannot
    release, renew or re-acquire another agent's lease under the multi-tenant
    posture, and the victim's lease survives the refusal; a holder carrying
    spaces / control characters / `..` / a reserved sentinel is refused in
    EVERY posture and mints no lease. ALLOWED — an agent still acquires,
    renews and releases its OWN lease, and the single-operator worker-label
    flow still works.
