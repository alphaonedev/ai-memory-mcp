**Behaviour change: an audit trail whose tail cannot be read now stops `ai-memory` from starting.**
When `[audit].enabled = true` and the existing audit trail cannot be read to
continue its hash chain (the file cannot be opened or read, it holds bytes that
are not UTF-8, or its last record is torn or corrupt), every `ai-memory`
command now exits with code 78 and a message naming the trail and the error;
`ai-memory doctor` still runs. Before this, the error was discarded and a new
chain was appended at genesis into the same file, forking it silently: every
later event was written, but none could be verified. A missing or empty trail
still starts a fresh chain as before. To recover, repair or move the trail
(`ai-memory audit verify` reports where it breaks), or set
`[audit].enabled = false` (#4190).
