### Fixed

- **P0 hotfix: the #3355 test key-directory guard no longer leaks into the
  shipped `ai-memory` binary**
  ([#3516](https://github.com/alphaonedev/ai-memory-mcp/issues/3516)).
  `Cargo.toml` carries a self dev-dependency
  (`ai-memory = { path = ".", features = ["test-support"] }`), so every
  `cargo test` unifies `test-support` into the whole build — including the
  `ai-memory` BIN compiled for the integration tests, which overwrites
  `target/{debug,release}/ai-memory`. The guard was gated on
  `cfg(any(test, feature = "test-support"))`, so any binary produced in a
  target where `cargo test` had run panicked with
  `#3355 test key directory resolves under HOME` whenever the key directory
  resolved under HOME — the DEFAULT operator location
  (`~/.config/ai-memory/keys`) — and silently substituted a temporary sandbox
  for the operator's key store when no override was set. The `Batman Mode
  acceptance gate` (`cargo build --release` → `cargo test --release` → run
  `target/release/ai-memory`) failed on the published head for exactly this.
  The guard is now armed per PROCESS, never by feature unification: `cfg(test)`
  for the crate's own unit tests, a call to `identity::test_key_dir::install()`
  for integration tests, or the `AI_MEMORY_TEST_KEY_GUARD` marker that
  `install()` exports so child processes of an armed test stay guarded. An
  operator binary or a CI step carries none of the three, so both halves of the
  guard are inert there and the production `dirs::config_dir()` key store is
  resolved as intended. #3355's isolation for test processes is unchanged.
- **`pg_register_agent_then_list` matches the #3398 registration contract**
  ([#3516](https://github.com/alphaonedev/ai-memory-mcp/issues/3516)).
  `POST /api/v1/agents` UPSERTS the roster row, so #3398 routed a
  cross-register (`body.agent_id != caller`) through `require_admin`. The
  fake-postgres branch suite still registered as an ANONYMOUS caller and took
  the new — correct — `403 {"error":"admin role required"}`, reddening the
  coverage workflow. The happy leg now drives the pg branch through the admin
  context the #3303 lineage test uses, and a new DENIED twin
  (`pg_register_agent_cross_register_requires_admin_3398`) pins the exact
  refusal wire shape for a plain tenant caller. Test-only: the gate itself is
  unchanged.
