**Carrier-ruleset verifier names only an exact match as the `PUT` target (#6436, carrier gate #6143).** `judge_one` in `scripts/check_carrier_ruleset_live.py` reported a live ruleset as matching when its `include` carried extra patterns (`~ALL`, `~DEFAULT_BRANCH`, `release/*`), when it carried extra rule types, or when a context was repeated (one copy unpinned), and printed it as the ruleset the promotion `PUT` targets, which replaces the whole ruleset body. A match now needs the payload name, exactly the two carrier include patterns, `exclude == []`, exactly the payload's rule types and no repeated context; two matching rulesets are reported as ambiguous. `docs/ci/CARRIER-BRANCH-GATES.md` takes the `PUT` id from the `POST` response confirmed by `GET rulesets/<id>`, never from a CI log.
