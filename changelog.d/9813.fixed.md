CI guard tests no longer import PyYAML (#9813): `scripts/ci/tests/test_ci_progress_notice_9430.py`, `test_ci_tainted_job_boundary.py` and `test_pgbouncer_smoke_compose_4734.py` read workflow and compose files with the shared standard-library reader (`workflow_text.read_document` / `read_all_steps`, built on `taint_boundary.parse_yaml`), so they load on a fleet node that has no PyYAML. The reader refuses every form it cannot parse (a tab in indentation, a duplicate key, a tag or anchor, a multi-line quoted scalar, an empty file, a missing or non-UTF-8 file, an unreadable document shape) with `WorkflowReadError` naming the file and, for a parse refusal, the line; no guard skips or substitutes a default. `scripts/ci/tests/test_workflow_text_yaml_9813.py` pins each refusal and value, and `scripts/ci/tests/test_ci_stdlib_imports_9813.py` is the class guard: every module under `scripts/` imports only the standard library or a repository module, with an empty third-party allow table. `scripts/ci/tests/test_ci_tainted_job_boundary.py` keeps its parity cell, now checked against the independent line reader instead of PyYAML, and runs it instead of skipping when PyYAML is absent.
