CLI `notify` / `subscribe` / `unsubscribe` / `list-subscriptions` / `inbox`
honor the global `--agent-id` (and `AI_MEMORY_AGENT_ID`) as the sender/owner.

FX-C3 wired those verbs through the MCP handlers with `mcp_client = None`, so
`resolve_agent_id` fell through to `host:<hostname>`: notify stamped the wrong
sender, the subscribe registration gate evaluated the wrong principal, and
`inbox --agent-id X` read any agent's inbox (the MCP twin's #3356 ownership
gate was never passed a caller). The CLI now resolves the caller first and
feeds it into the same as-sender / as-caller funnels HTTP already uses
(`handle_notify_as_sender`, plus subscribe-family twins that return
`MemoryError` so QUAL-6 does not grow). A subcommand `inbox --agent-id`
that disagrees with the resolved caller is refused.
