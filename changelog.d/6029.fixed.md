The append-only scratch janitor (`scripts/clear-append-only-scratch.py`) no longer leaves a widened mode on an inode that gained a second link after the Linux leg pinned it (#6029). The link count is read again from the pin after the widen; a regular file with more than one link gets the mode the walk found put back through the same pin, and is refused as a shared inode, so a name outside the scratch tree never keeps the widened mode.
