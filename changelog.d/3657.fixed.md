**The wake sink's counters now reach `/metrics` (#3657).** `install_uds` /
`install_in_process` returned the installed sink's counters (wakes seen,
delivered, written, coalesced, hints shed, and every drop by cause) but
`serve` discarded the handle, so the only readers were library tests: an
operator could not tell a quiet fleet from a hub that silently stopped
waking anyone. The installer now parks the one installed sink's handle in
`wake_sink::installed_sink_metrics`, and a scrape-time collector renders it
as `ai_memory_wake_sink_active` plus
`ai_memory_wake_sink_{wakes_seen,delivered,written,coalesced,meta_shed}_total`
and `ai_memory_wake_sink_dropped_total{cause}` (closed label set: `unknown`,
`overflow`, `unaddressable`, `unencodable`, `transport_full`, `hub_down`,
`bus_lagged`). The counters are rendered only while a sink is installed; with
none the gauge reads `0` and nothing else is exposed. The sink stays the only
writer; the scrape loads its atomics. See docs/wake-hub.md §"Degrade, never
corrupt" and the `/metrics` table in docs/API_REFERENCE.md.
