**`check_cert_expiry.py`: a re-bind is not a re-issue while the certification is EXPIRED or VOID
(#6774).** Rule B counted any change of the banner as a re-issue or voiding record, so a change that only
set or changed the bound SHA on the Binds-to line, with STATUS still EXPIRED, let a federation-wire change
pass without an amendment record (#3899 forbids re-binding without re-measurement). While the range-start
STATUS is EXPIRED or VOID and STATUS does not change, a Binds-to line that sets or changes a bound SHA now
takes the amendment route and is refused there; dropping the bound SHA (the #6116 record) withdraws the
live bind and still counts. That drop is one-shot: it exists only while the base still carries a bound
SHA under EXPIRED, it vanishes once promotion 6 lands (release then carries no bound SHA), and the drop is
still held to the append-only ledger. #6877 tightens the rule to the literal form after promotion 6
(3-agent vote 6def5ab6). Regression: self-test cells `6124-b1`, `6124-b4` (a bound SHA set again after the
drop) and `6124-b5` (a drop that deletes a record), all RED, and the controls `6124-b2` (EXPIRED -> VOID)
and `6124-b3` (bound SHA dropped), both GREEN.
