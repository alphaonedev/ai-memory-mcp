The janitor's scan-time shared-inode refusal is now pinned by behaviour on both platforms (#5936). On Linux a second name removed between the scan and the widen step is still refused by the scan's own check, which reads the walk's `lstat`; on macOS a hard-linked, append-only file behind mode `0o000` is refused for its second name, not for its flag, so the report never tells the operator to clear a flag on an inode that also lives outside the scratch tree, and a later run leaves the shared inode untouched. The earlier statement that removing the scan's refusal changes no behaviour was wrong and is retracted.
