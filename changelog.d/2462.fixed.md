**Fixed: v54 expiry backfill emits canonical micros+`Z`; sqlite TTL floors self-heal legacy offsets (#2462, #2463).**

The v54 tier-default-expiry backfill wrote `strftime(...+00:00)` with no
fractional seconds — two axes off the canonical `YYYY-MM-DDTHH:MM:SS.ffffffZ`
rendering — and was correct only because v87's `normalize_expiry_rows` ran
later. It now stamps `created_at + tier-default TTL` through
`validate::render_canonical_utc`, independently of that heal.

The sqlite `touch` / `touch_many` / `fold_recall_accesses` funnels no longer
apply the #1596 floor with SQL `MAX()` (a byte comparison). They read the
stored `expires_at`, compare instants via `later_expiry_canonical`, and write
the later value already canonical, so a legacy `+09:00` rendering cannot void
a strictly later floor. NULL expiry stays NULL; unparseable bytes pass through
(fail-safe). Postgres is unchanged: `expires_at` is `TIMESTAMPTZ` and
`GREATEST` already compares instants.
