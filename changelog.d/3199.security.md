**Breaking:** backup manifests are signed with the operator key, and
`restore` refuses what that key did not vouch for. Before, a manifest was a
sha256 of its snapshot written beside it, so anyone who could write the
backup directory could replace both files and have them restored.

`backup` now signs the manifest with the operator key (the key that signs
governance rules; `ai-memory rules keygen` creates it). The signed bytes
cover the snapshot's file name, sha256, size, creation time, backend,
schema version and memory count. `restore` verifies them against the
operator public key it resolves itself (`AI_MEMORY_OPERATOR_PUBKEY`, else
the key directory), never a key the manifest carries, and then decides only
from the verified payload. A signature that does not verify is refused with
no override, and a signed backup cannot be renamed to pass for another.

- An unsigned manifest (every pre-v1.0.0 backup) is refused unless you pass
  the new `--allow-unsigned-manifest`. A manifest-less `.bak` /
  `.pre-restore` / `.pre-repair` file needs `--skip-verify`. Both WARN,
  record a `backup_restore_unverified` audit event, and are refused under
  `asi-hard`. **Take a fresh backup right after upgrading.**
- `restore --from <dir>` needs `--snapshot <id>` or the new `--latest`
  (the newest backup by its signed creation time; a candidate whose
  signature fails makes it refuse). The modification-time pick is removed.
- Under `asi-hard`, `backup` refuses before writing anything when the
  operator signing key is missing, no operator public key resolves, or
  the two do not match. Under the standard posture a host without the key
  writes an unsigned manifest and WARNs.
- `doctor --posture enterprise-federation` gains a backup-signing check;
  the certified posture now has 21 checks.
- `restore --json` reports `manifest_verification` and `audit_sink`;
  `backup --json` reports `signed`.

Manifests stay beside their snapshots: with the signature checked against
a key resolved out of band, their location adds no integrity. See
SECURITY.md ("Backup and restore trust model") and `docs/CLI_REFERENCE.md`
("Signed manifests"), which also gives the `asi-hard` procedure for a
legacy or manifest-less file. Restoring an unsigned or legacy backup is
not certified.
