### Fixed

- **[data-integrity][federation] Postgres did not round-trip the attested
  `created_at`, so a signed write's `write_signature` could no longer be
  re-derived from the row — federation re-verification of pg-authored rows
  dropped them**
  ([#3422](https://github.com/alphaonedev/ai-memory-mcp/issues/3422)).
  `SignableWrite` (`src/identity/sign.rs`) commits to `created_at` as TEXT, and
  every re-verification rebuilds the envelope from the **persisted row**: the
  store gate, and `federation_receive::apply_inbound_write_attestation` on a
  relayed row. SQLite keeps `created_at` in a `TEXT` column and returns the
  attested string unchanged; postgres keeps it in `TIMESTAMPTZ` (microsecond
  int8) and re-renders the readback through `DateTime::<Utc>::to_rfc3339()`. A
  write attested with `…Z`, with a non-UTC offset, or with chrono's own 9-digit
  `Utc::now().to_rfc3339()` nanosecond rendering therefore came back out of
  postgres with **different bytes** — a different canonical-CBOR pre-image and
  an Ed25519 signature that could never be re-derived again. The receiver read
  the author's genuine signature as FORGED and **skipped the row**: silent,
  unrecoverable loss of a row the peer sent correctly.
  - **The control (fail closed, #3279/#3281 form).** A single canonicalizer,
    `identity::attest::canonicalize_attested_created_at`, defines the ONE
    storage-stable rendering — parse RFC3339 → UTC → truncate to microseconds →
    `to_rfc3339()` (`+00:00`, `AutoSi` fractional digits). That is *exactly*
    what the postgres readback emits, so a string equal to its own canonical
    form is a fixpoint of both backends. Every funnel that puts a `created_at`
    inside a signed envelope now gates on it:
    - `attest::prepare_signed_store` (the v1 signed-store funnel shared by MCP
      `memory_store`, `POST /api/v1/memories`, and both bulk paths) and
      `attest_v2::adopt_created_at` (the v2 positional envelope) **REFUSE** a
      non-canonical `created_at`, naming the exact string to sign (the caller's
      raw bytes are never reflected back into the 4xx envelope);
    - `attest::sign_memory_write` **refuses to mint** a signature over a
      `created_at` the storage layer cannot return byte-for-byte — a signature
      that reads FORGED at every receiver is strictly worse than no signature,
      since the receive path drops the row instead of landing it `claimed`;
    - `cli::store` and `storage::consolidate` stamp
      `attest::now_attestable_rfc3339()`, so a row that will be signed (or
      self-attested on read-back by the federated-consolidate path) is born
      signable on both backends.
  - **Wire-contract tightening.** A signed store whose `created_at` is not the
    canonical rendering is now a `400` naming the canonical string, where it
    previously landed a row whose signature was unverifiable on postgres. Both
    shipped SDK signers already emitted the `+00:00` form; they now
    canonicalize explicitly (`canonicalize_created_at` in
    `sdk/python/ai_memory/attestation.py`, `canonicalizeCreatedAt` in
    `sdk/typescript/src/attestation.ts`), applied to `rfc3339_now()` /
    `rfc3339Now()` and to any caller-supplied stamp in `attestation_fields` /
    `attestationFields` — so the SDKs sign exactly what the server stores.
    No golden or conformance vector changed: `sdk/fixtures/write_attestation_vector.json`
    already pins the canonical `2026-07-28T12:00:00+00:00`.
  - **Not fixed, by design:** rows already persisted on postgres with a
    non-canonical attested `created_at` stay unverifiable (the original signed
    bytes are unrecoverable). They degrade to `claimed`; the control prevents
    new ones. Verifier leniency over "equivalent renderings" was rejected — it
    would enlarge the accepted pre-image set by hand-enumerated pattern, which
    the charter forbids.
  - Regression coverage for the DENIED and the ALLOWED path on BOTH backends:
    `tests/attested_created_at_roundtrip_3422.rs` (sqlite round-trip +
    re-derivation, funnel/signer refusals, and — against a live cluster —
    the postgres round-trip plus a demonstration that a `…Z` stamp does not
    survive `TIMESTAMPTZ`), plus
    `federation_receive::tests::pg_authored_row_reverifies_after_the_timestamptz_round_trip_3422`,
    canonicalizer unit tests in `identity::attest`, and SDK suites in both
    languages.
