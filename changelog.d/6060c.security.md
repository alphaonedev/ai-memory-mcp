### Security

- **[sdk-python] The CA-path rule and the owner-only credential readers also read macOS extended ACLs**
  ([#6934](https://github.com/alphaonedev/ai-memory-mcp/issues/6934), umbrella
  [#6060](https://github.com/alphaonedev/ai-memory-mcp/issues/6060), round 8, CWE-732).
  A `chmod +a "everyone allow add_file,delete_child"` entry let another account replace a CA under a `0755`
  directory, and an `allow read` entry let another account read a `0600` key; the mode bits showed neither.
  A CA file or any directory on the path with a foreign ACL write, append, delete, delete_child, writesecurity or
  chown right is refused, an owner-only credential file with a foreign ACL read right is refused, and an ACL that
  cannot be read is a typed refusal. Deny entries and entries for you or root are ignored. The check uses
  `ctypes` on the platform C library only (no new dependency). Upgrade note: a CA bundle or credential file whose
  macOS ACL names another principal is now refused; `chmod -N <path>` clears it.
  The opened CA file is checked with `fstat` on its descriptor, the path is walked again after the open and must end
  at that inode, and a file or directory that vanishes mid-check raises `ValueError`, also from the `fstat`
  ([#6829](https://github.com/alphaonedev/ai-memory-mcp/issues/6829)). The wake bundle reader names only the
  exception class when a bundle is not JSON ([#6936](https://github.com/alphaonedev/ai-memory-mcp/issues/6936)),
  and the owner-only readers do the same for non-UTF-8 text
  ([#6963](https://github.com/alphaonedev/ai-memory-mcp/issues/6963)). Regression tests:
  `sdk/python/tests/test_acl_6934.py`, `sdk/python/tests/test_tls_ca_path_6060_r8.py`,
  `sdk/python/tests/test_owned_readers_6963_r8.py`, `sdk/python/tests/test_wake_bundle_typed_6936.py`.
