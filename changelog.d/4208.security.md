Federation route-OUT dequarantine-on-attest (#1948) now releases a quarantined row only when the row actually stored is the exact signed unit this node verified, on both backends. Before, a validly signed but OLDER push for the row's own id lost the newer-wins merge, left the local never-attested content on the row, and still released it from quarantine. The check and the release now run under one write lock (sqlite `BEGIN IMMEDIATE`, postgres `FOR UPDATE`); a push whose content did not win leaves the row quarantined for an operator release (#4208, residual of #3901).
