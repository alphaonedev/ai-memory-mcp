Federation route-OUT dequarantine-on-attest (#1948) now releases a quarantined row only when the row actually stored carries the signed content this node verified, on both backends. "Signed content" is content, title, namespace, memory kind and author; `created_at` and the signature key are deliberately excluded (the merge keeps the local genesis instant and may keep either side's signature metadata), so this is not a byte-exact match of the whole unit. Before, a validly signed but OLDER push for the row's own id lost the newer-wins merge, left the local never-attested content on the row, and still released it from quarantine. The release primitives also require the incoming row to be `agent_attested` themselves rather than trusting the caller. The check and the release run under one write lock (sqlite `BEGIN IMMEDIATE`, postgres `FOR UPDATE`); a push whose content did not win leaves the row quarantined for an operator release (#4208, residual of #3901).
