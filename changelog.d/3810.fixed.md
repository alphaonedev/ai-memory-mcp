`kg_query` ordering is now deterministic before the row cap: sqlite keeps its temporal key `(depth, COALESCE(valid_from, created_at), created_at)` and appends the tie-break `(target_id, relation, path)`, so its public order is unchanged and only former ties are resolved; the postgres recursive CTE and AGE use the total key `(depth, target_id, relation, path)` in byte order, so a tied group straddling the cap keeps the same edge on every run (#3810, #3893).
