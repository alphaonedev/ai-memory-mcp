Self-hosted macOS CI legs no longer fail in `actions/checkout` with `EPERM` on a leftover append-only `.local-runs/.tmp*/audit/audit.log` (#5657). A pre-checkout step (`scripts/clear-append-only-scratch.py`, pinned byte-identical to its inline workflow copies) clears the append-only bit on the dead scratch tree only; the live audit-log flag in `src/audit.rs` is unchanged. The janitor descends by directory descriptor with `O_NOFOLLOW|O_DIRECTORY` and verifies each reopen against the scanned inode, so the descent cannot be redirected out of the scratch tree by a symlink or a directory swapped underneath it. A permission-blocked mode it owns is widened and restored rather than reported, so a leftover that `actions/checkout` would have cleaned by itself never reds a leg; the widen never follows a symlink and is put back on every exit from the open, including the refusal of a swapped entry and a reopen that fails (#5812, #5813). On Linux it is bound to the inode that was scanned - pinned with `O_PATH|O_NOFOLLOW`, identity-checked before anything changes, and applied through `/proc/self/fd`; on macOS, which has no `O_PATH`, it is `fchmodat(AT_SYMLINK_NOFOLLOW)` by name, which does not follow a symlink but is not bound to the scanned inode either (narrowing that leg is tracked as #5852); where neither is available it is refused outright; and it fails closed on anything it could not prove unlinkable - a surviving `uchg`/immutable flag, a flag state it could not read, a multiply-linked flagged inode, a flagged symlink, or an inode owned by another user. The suite that pins all of this builds no fixture it cannot remove and restores every mode it narrows when a run is cancelled, so the self-test cannot wedge the runner it exists to unblock (#5814).
