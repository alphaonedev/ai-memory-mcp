### Security

- **[skills] A promoted skill keeps the narrowest scope of its sources, and callers cannot forge it**
  ([#8832](https://github.com/alphaonedev/ai-memory-mcp/issues/8832)). A skill promoted from a
  reflection could republish private or other-team source content to every agent. Promotion now
  binds the narrowest source scope and the promoting principal under `metadata._visibility` (a
  `team`, `unit` or `org` source in another namespace narrows to `private`), the binding is part of
  the skill digest only when present (rows registered before this change verify unchanged), and
  every read funnel applies the memory visibility predicate to it. A caller who may not read a skill
  gets `skill not found: <id>`, also when the row is damaged, so no integrity text discloses the
  row. `memory_skill_register` (MCP, CLI and `POST /api/v1/skill`) runs one shared check on the
  final stored and digested metadata (3-agent vote (71472661) B 3-0, conditions B-1..B-14): a
  top-level `_visibility` is accepted only when it is exactly the shape promotion stamps for the
  authenticated registering principal, its scope is a canonical scope token that principal is a
  member of in the namespace, and the principal is resolved (an anonymous, host-default or reserved
  identity owns no binding). Every other key beginning with `_` at any depth, a malformed binding,
  an invalid or non-member scope and a binding for another principal are refused, each with its own
  exact message, and a bound register may not supersede a current skill of the same namespace and
  name that is not bound to the same principal. The HTTP route returns the typed `code`:
  `AGENT_ID_MISMATCH` (403), `IDENTITY_REQUIRED` (403), `CONFLICT` (409) or `VALIDATION_FAILED`
  (400). `memory_skill_export`
  keeps the binding and strips the other reserved keys, and the CLI read verbs refuse a set but
  shape-invalid `AI_MEMORY_AGENT_ID` (exit 2) instead of reading as the local operator.
  `tests/skill_scope_integrity_8832_8834.rs` pins each refusal text.
- **[skills] Narrowing: a promoted skill no longer re-registers under a different principal**
  ([#8832](https://github.com/alphaonedev/ai-memory-mcp/issues/8832)). The cross-node
  identical-digest guarantee still holds for every unbound skill and for a promoted skill
  registered by the principal that promoted it. A different principal is refused with
  `metadata '_visibility' is bound to a different principal; remove the '_visibility' binding and
  register the skill as your own (its digest then differs from the exported digest), or register it
  as the principal that promoted it`; the message never names the other principal. The default
  agent id is host-derived and differs per host, so a cross-host round trip sets
  `AI_MEMORY_AGENT_ID` to the promoting principal. Before this change that registration was accepted and the foreign
  binding was trusted as written.
