### Security

- **[governance] `network_request` host rules match the canonical host, not
  its byte spelling** ([#4300](https://github.com/alphaonedev/ai-memory-mcp/issues/4300)).
  The rule `host` glob was compared byte-for-byte with the evaluated host, so a
  `refuse`/`escalate` rule for `evil.example.com` did not apply to
  `EVIL.example.com`, `evil.example.com.`, a Unicode spelling of an A-label
  host, or a non-canonical IP literal (a silent fail-open). Both the rule
  pattern and the evaluated host now pass through one shared function
  (`governance::host`): ASCII-lowercase, exactly one trailing root dot removed,
  IDNA to the A-label, WHATWG dotted-quad IPv4 and bracketed compressed IPv6,
  and rejection of empty labels, labels over 63 bytes, hosts over 253 bytes and
  whitespace/control/NUL characters. A host that cannot be canonicalised is
  never allowed by default: it matches every blocking (`refuse`/`escalate`)
  `network_request` rule and no `warn`/`log` rule. A rule pattern that cannot be
  canonicalised is rejected by `rules add` and is inert (fails closed) when it
  is already stored. Wildcards are unchanged: `*` spans any run of characters
  including dots, so `*.example.com` matches a subdomain at any depth but not
  the bare apex. Rules are stored only in SQLite (Postgres ships no
  `governance_rules` table), so there is one evaluation funnel.
