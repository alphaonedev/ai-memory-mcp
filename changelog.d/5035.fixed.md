### Fixed

- The #2445 schema-ahead guard now holds for the lifetime of a connection, not only when it is opened. Previously a long-lived daemon kept writing after a newer binary migrated its database, and callers saw a raw `ON CONFLICT clause does not match any PRIMARY KEY or UNIQUE constraint` error (or, worse, wrote rows into tables whose shape it did not know). On SQLite every gated write (`record_stop::gate_storage_conn`, which also fences MCP `tools/call`) re-reads `schema_version` with one cached statement; on Postgres the #3276 record-stop refresh winner re-reads `MAX(schema_version)` once per `RECORD_STOP_REFRESH_TTL_MS` window and every write evaluates the cached version. A schema that moved ahead is refused with the typed `SCHEMA_AHEAD_OF_BINARY` error (HTTP 503, MCP error text, `StoreError::SchemaAheadOfBinary` on both SAL adapters); reads keep working. The refusal names no file path. The exact-version `AI_MEMORY_ALLOW_SCHEMA_AHEAD` hatch still authorises writes, and a poisoned stamp is refused even under a matching hatch. (#5035)
