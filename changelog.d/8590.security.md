### Security

- **[identity] Mapped client certificates satisfy enforced identity gates**
  ([#8590](https://github.com/alphaonedev/ai-memory-mcp/issues/8590), umbrella
  [#8493](https://github.com/alphaonedev/ai-memory-mcp/issues/8493)). A verified,
  active client-certificate binding matching the effective caller now satisfies
  the `KeyAuthenticated` gate category on IDOR and admin routes, including when
  the request presents the shared transport key. Certificate provenance comes
  from the TLS acceptor's typed request context and remains `client_cert` in
  authority/audit records. Admin allowlisting still applies. Missing, disabled,
  unmapped or mismatched certificate context grants no identity authority;
  conflicting certificate/key principals are refused under certificate
  `enforce` and served as the certificate's principal under `warn`. Per-agent
  key fallback and the gate activation rule for zero enrolled keys are
  unchanged. The enforced identity refusal now names both supported credentials.
