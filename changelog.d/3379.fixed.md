Close a cross-tenant exfiltration primitive in `memory_share`: the source
memory is now resolved through the same caller-scoped visibility funnel
`memory_get` uses, on all three surfaces (MCP, `POST /api/v1/share`, and the
`share` CLI verb). Previously the source was read through the unfiltered
by-id resolver with no caller threaded at all, so any agent could name another
agent's `scope=private` id and mint a full copy of its title and content into
`_shared/<victim>-><anyone>/` — a row the same caller is told "not found" about
by `memory_get`. A source that exists but is not visible to the caller now
refuses with the identical message an absent id produces, so the surface cannot
be used as a presence oracle, and the share decision is chained into the
forensic audit trail against the resolved caller. The HTTP route also gained
the per-agent-key identity gate so a shared-transport-key caller cannot forge
`X-Agent-Id` to share a victim's rows. The single-operator default
(`AI_MEMORY_AGENT_ID` unset) is unchanged.
