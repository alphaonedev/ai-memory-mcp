`ai-memory backup` (and therefore the scheduled `ai-memory-backup.timer`) never migrates the database it copies: it opens the source through the unmigrated egress funnel (`db::open_unmigrated`, #2445), so a newer binary on disk cannot upgrade a live primary under a still-running older daemon. The manifest still records the observed schema version. The backup unit's write grant stays `ReadWritePaths=/var/lib/ai-memory` (this is a loosening of that unit's hardening versus the pre-#4080 read-only database path, needed for the SQLite WAL/SHM sidecars and the backups directory).
