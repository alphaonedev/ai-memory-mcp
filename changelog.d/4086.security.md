Audit events lost at the TAIL of the flat audit trail just before a restart are no longer invisible. An event is numbered before it is written; a restart used to resume numbering from the last event WRITTEN, so the numbers of events lost to a failed write after that point were reused and `audit verify` (#4021) saw no gap, while the #3975 failure counter died with the process. The trail now keeps a sequence high-water mark next to it (`audit.log.seq`): a failed write records its sequence number there durably before the failure is reported (an in-place fixed-width overwrite, so it works on the full disk that lost the event), a restart resumes from `max(trail tail, high-water)` and prints the lost range on stderr, and `verify` reports numbers past the last written line as a gap even before the next write. A high-water file that exists but is unreadable or out of range refuses `init` (and so boot, #3651) and fails `verify` rather than being guessed around; a missing one is created. The audit sequence counter can no longer overflow (#4086).
