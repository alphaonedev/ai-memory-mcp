**`log_safe_problems` no longer swallows a source-read failure in a silent `except` (#7989).** The unicodedata
check wrapped `inspect.getsource` in `except (OSError, TypeError): pass`, which CodeQL flagged as
`py/empty-except` (alert 586) and which let an escaper with no readable source skip the check. The handler now
names the exception and reports a problem when the source cannot be read. Proof:
`case_7989_unreadable_escaper_source` feeds an exec-built escaper (OSError) and a builtin (TypeError) and fails
on the old code with an empty problem list.
