**zip-extract guard catches build-time generated modules (#7310).** A `mod name;` whose file is not where cargo looks (`name.rs` / `name/mod.rs` beside a crate root, a `mod.rs` or any file loaded through `#[path]`, under `<stem>/` for any other file) fails; a `cfg_attr(.., path = ..)` module is not exempt, only an unconditional `#[path]` is. Every target `src_path` in `cargo metadata` (inline-table, array and auto-discovered forms included, for the root and each local package) is a crate root, is scanned, and fails when it has no file on disk (only a build step could create it); so does a manifest-declared path or build script with no file. Build scripts are scanned with their string bodies kept (comments still masked).
