**zip-extract guard catches build-time generated modules (#7310).** A `mod name;` whose file is not where cargo looks fails. The base is resolved per load, as rustc does: a crate root, a `mod.rs` or a file loaded through `#[path]` looks for `name.rs` / `name/mod.rs` beside itself, any plain `mod x;` load of a file looks under `<stem>/`; a file loaded both ways (`mod a;` plus `#[path = "a.rs"]`) must satisfy both bases, and a `path =` key inside a cfg predicate loads nothing. Only an unconditional `#[path]` exempts a `mod`; a `cfg_attr(.., path = ..)` module is not exempt. Every declared module file is scanned wherever it resolves, including outside `src/` (every existing `name.rs` / `name/mod.rs` candidate is queued). Every target `src_path` in `cargo metadata` (inline-table, array and auto-discovered forms included, for the root and each local package) is a crate root, is scanned, and fails when it has no file on disk (only a build step could create it); a local package with no `targets` in the metadata is a tool error (rc 2); so does a manifest-declared path or build script with no file. Build scripts are scanned with their string bodies kept (comments still masked).
