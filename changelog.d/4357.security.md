**`POST /api/v1/memory_reflect` on a PostgreSQL daemon now honours the namespace's `require_approval_above_depth` approval gate (#4357, CWE-862).** The L1-8 gate was read only by the SQLite/MCP reflect handler, so a reflection above the operator-configured depth threshold was applied immediately on PostgreSQL instead of being parked as a pending action. The threshold is now resolved backend-blind through a new `MemoryStore::resolve_require_approval_above_depth` trait method whose per-level decision is one shared function used by both backends (leaf-first, a leaf policy that omits the field ends the walk, an out-of-range threshold fails closed to 0). A reflection above the threshold is queued (202, same body fields as the SQLite wire shape, threshold never echoed) and never written; a resolver or queue failure refuses the reflect. The default trait implementation fails loudly rather than skipping the gate. A queued `reflect` pending could also not be executed on PostgreSQL (no `reflect` arm in `execute_pending_action`); approval now replays the reflection through the same payload decoder the SQLite executor uses. Pinned by `tests/issue_4357_reflect_approval_gate_parity.rs` on both backends, including a same-request parity cell.
