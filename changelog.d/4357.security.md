**`POST /api/v1/memory_reflect` on a PostgreSQL daemon now honours the namespace's `require_approval_above_depth` approval gate (#4357, CWE-862).** The L1-8 gate was read only by the SQLite/MCP reflect handler, so a reflection above the operator-configured depth threshold was applied immediately on PostgreSQL instead of being parked as a pending action. The threshold is now resolved backend-blind through a new `MemoryStore::resolve_require_approval_above_depth` trait method whose per-level decision is one shared function used by both backends (leaf-first-wins, #2542: an explicit value at the nearest level decides; a well-formed policy that omits the field means no gate and ends the walk; an explicit null or a missing standard keeps walking; a corrupt level keeps walking; a chain that passed a corrupt level and found no explicit value anywhere requires approval rather than skipping the gate; an out-of-range threshold fails closed to 0). A reflection above the threshold is queued (202, same body fields as the SQLite wire shape, threshold never echoed) and never written; a resolver or queue failure refuses the reflect. The default trait implementation fails loudly rather than skipping the gate. A queued `reflect` pending could also not be executed on PostgreSQL (no `reflect` arm in `execute_pending_action`); approval now replays the reflection as the requester's tenant through the trait `reflect`, so source visibility, title-slot admission, the why_trace gate and the attestation posture re-apply at execute time. A caller-supplied `attest_level` is scrubbed before queueing, and global-strict attestation refuses before queueing, as on SQLite. Documented gap: under leaf-first-wins a child standard that omits the field escapes the parent's gate; that is safe only once #4356 (the ancestor-owner bind gate, PR #4367) lands, since until then any caller can bind the first standard at a child namespace. Follow-ups: #4394 and #4398 (malformed threshold values), the curator reflection pass, and the 202 versus 200 status nit. Pinned by `tests/issue_4357_reflect_approval_gate_parity.rs` on both backends, including a same-request parity cell.
