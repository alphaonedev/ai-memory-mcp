**A pull request that changes only documentation no test reads no longer spends the cert-postgres-age, postgres-ignored and token-budget runs (#9683).** Each of the three jobs now opens with one `Docs-only short-circuit (#9683)` step (`.github/actions/docs-only-gate`, `scripts/ci/impact/docs_only_gate.py`). It judges the whole pull request, from the base sha to the checked-out merge ref, with the allowlist coverage already uses (`rules.json` `cargo_skip` docs globs minus every never-skip and test-read glob), so a Markdown file under `.github/` or `scripts/ci/` and a doc a test or `include_str!` reads still count as code. The decider and its rules are read from the base commit, never from the pull request. The diff is read as NUL-separated data with named exits (full run, docs only, unreadable). Only the docs-only exit skips work: a push, merge queue or other event, a main, develop or release base, a missing base, an empty, unreadable or over-bound diff, and any error run the job in full. The jobs, their names, conditions and required contexts are unchanged; only the steps after the gate are guarded, and the always()/failure() cleanup steps still run. CodeQL and the coverage c8 gates keep their full runs: a skipped analysis would leave the head without a scan, and the c8 gates read docs.
