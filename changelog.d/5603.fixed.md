The enterprise-federation cert-expiry gate (`scripts/check-cert-expiry.sh`) no longer exits 0 "N/A" when it cannot decide its range (#5603). It takes its range only from `scripts/ci-commit-range.py` (the same closed-world helper as the count-assertion gate, #5579): `pull_request` runs merge-base(base, head)..head; `merge_group` runs `merge_group.base_sha..head_sha`; `push` runs `before..sha` only when `before` is a full, non-zero, 40-char lowercase sha that resolves to a commit. An all-zero, empty, malformed or unreachable `before`, a `merge_group` without `base_sha`, an unknown event, or a helper refusal is a red job, never a skip. The refusal names its cause (creation push or force-push of a protected branch, or a missing merge_group base) and says the next ordinary push produces a comparable range; such a run is red and a re-run cannot turn it green. The workflow now passes the six event inputs to the gate, and `cert-expiry-gate` is added to the helper's static workflow pin (checked by mutants of the workflow and the script). The required-contexts lists are unchanged. 5-agent vote (4d3ea1c5).
