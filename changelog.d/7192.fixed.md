### Fixed

- **[cli] `AI_MEMORY_NO_CONFIG=1` still created `config.toml` in the caller's HOME**
  ([#7192](https://github.com/alphaonedev/ai-memory-mcp/issues/7192),
  regression of [#3606](https://github.com/alphaonedev/ai-memory-mcp/issues/3606)).

  [#3603](https://github.com/alphaonedev/ai-memory-mcp/issues/3603) silenced the
  config-path WARNs under the escape hatch but left the boot-time
  `AppConfig::write_default_if_missing()` call in `src/main.rs` unguarded, so
  every `AI_MEMORY_NO_CONFIG=1` child (hermetic scripts and gates included)
  still wrote `~/.config/ai-memory/config.toml`, which persists across jobs on a
  self-hosted runner.

  `main` now skips the default writer under a truthy `AI_MEMORY_NO_CONFIG`,
  the same predicate `AppConfig::load` uses. A failure to create the config
  directory or file is now reported on stderr instead of being discarded.
