**LLM and embedding request URLs keep the base URL's query string after the
path (#3742).** Every OpenAI-compatible and Ollama request URL was built by
string concatenation, `format!("{base_url}/<path>")`. A configured base URL
that carries a query string — Azure OpenAI's `?api-version=2024-02-01` is the
common real case — had the path appended after the query
(`…/v1?api-version=2024-02-01/chat/completions`): the request went to the
wrong resource and the query value was corrupted. One helper,
`llm::join_api_path`, now parses the base with the client's own URL parser,
appends the path to the URL's path (one trailing slash trimmed) and keeps
the query and fragment in place; every request site in the client (chat,
generate, embed, models probe, model pull, tags) and both `doctor`
reachability probes use it. A base URL the parser rejects falls back to the
plain join so the eventual send error still names what was configured.
Pinned by `tests/api_url_join_3742.rs` (RED on the pre-fix tree: the probe,
the embed and the Ollama tags request all landed on an unmatched route) and
the unit cells beside the helper; the #3667 doctor pin is tightened back to
the full `/v1/models` probe path it was originally written for.
