**The AWS burst cloud-init memory template now provisions a daemon that starts (#4616, #4619, #4635-#4637, #4639-#4641, #4638, #4642).** `infra/aws-gpu-burst/cloud-init-memory.yaml.tpl` installs PostgreSQL 18 from PGDG with pgvector and Apache AGE built from source at pinned commits (a fetched commit that does not match the pin stops the script), mints a Postgres server certificate on the node and requires `sslmode=verify-full` in the store URL (the connect funnel applies that floor to a TCP postgres DSN, src/store/postgres/dsn.rs:213-283), writes a per-node API key and a self-signed listener TLS pair on the node, and runs `serve --host --port --tls-cert --tls-key`. The tarball is checked against the required `ai_memory_image_sha256` before it is extracted. The role password is percent-decoded and SQL-quoted from the DSN. Both memory templates create `/etc/ai-memory` mode 0700 in `bootcmd`, so the store-URL file has no window for another UID. The `--tls-cert`/`--tls-key` pair is the operator-PKI path of `resolve_tls_material` (src/daemon_runtime.rs:6226-6232); a serve with no flags is not refused for the default shape (it mints a local-CA certificate, :6163-6225). New gate `scripts/check-cloud-init-serve-flags.py` (job `cloud-init-serve-flags-gate` in `c8-precheck.yml`) fails on a serve flag that is not a `ServeArgs` field, a missing `--tls-cert`/`--tls-key`, an unpinned git fetch, a store URL without `sslmode=verify-full` (the do-hive gap is recorded in a shrink-only list), or a non-ASCII byte. The do-hive template is not fully covered: its PgBouncer TLS hop and tarball digest are tracked separately.
