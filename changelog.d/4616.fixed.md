**The AWS burst cloud-init memory template now provisions a daemon that starts (#4616, #4619, #4635-#4642, #4660, #4665, #4666, #4695-#4698, #4703).** `infra/aws-gpu-burst/cloud-init-memory.yaml.tpl` installs PostgreSQL 18 from PGDG with pgvector and Apache AGE built from source at pinned commits (a fetched commit that does not match the pin stops the script), mints a Postgres CA and server certificate on the node and requires `sslmode=verify-full` in the store URL (the connect funnel applies that floor to a TCP postgres DSN, src/store/postgres/dsn.rs:213-283), writes a per-node API key and a self-signed listener TLS pair on the node, and runs `serve --host --port --tls-cert --tls-key`. The CA private key is created in a root-only work directory on `/run` and removed when the script exits, so only the CA certificate stays in `/etc/ai-memory/tls` (#4666); the script stops before writing the key unless `/run` is tmpfs and no swap device is active (#4698). The tarball is checked against the required `ai_memory_image_sha256` before it is extracted, is extracted into a root-only staging directory, the member must be a regular file and not a symlink (#4697), and it is installed as root-owned `/usr/local/lib/ai-memory/bin/ai-memory`, outside the service user's home, so the service user can neither write nor rename it aside (#4665, #4696). Root no longer walks the service-owned home with `chown`; it checks the home owner, and the service user writes its own config (#4695). `infra/aws-gpu-burst/main.tf` passes the rendered template through `user_data_base64 = base64gzip(...)`: rendered with a versioned URL and a 64-hex digest it is 18,362 bytes, over the 16,384-byte EC2 limit, and 9,032 bytes after gzip and base64 (#4703). `infra/aws-gpu-burst/spawn.sh apply` refuses to run without `TF_VAR_ai_memory_image_url` and `TF_VAR_ai_memory_image_sha256` (`spawn.sh plan` does not check them; terraform then stops on the missing required variables); both are required terraform variables, and `main.tf` has no default tarball URL and refuses a URL that is not https, is empty, holds percent-encoding, or contains `/releases/latest` in any letter case (#4660). The role password is percent-decoded and SQL-quoted from the DSN. Both memory templates create `/etc/ai-memory` mode 0700 in `bootcmd`, so the store-URL file has no window for another UID. The `--tls-cert`/`--tls-key` pair is the operator-PKI path of `resolve_tls_material` (src/daemon_runtime.rs:6226-6232); a serve with no flags is not refused for the default shape (it mints a local-CA certificate, :6163-6225). `main.tf` also refuses an image URL with any character other than letters, digits and `. _ ~ / -` after `https://` (#4787) and requires IMDSv2 (`http_tokens = "required"`) on every instance (#4789); the PGDG signing key is checked against a pinned sha256 before apt trusts it (#4790); the provision script refuses the CHANGEME placeholder password (#4788).

**`scripts/check-cloud-init-serve-flags.py` is a fail-closed token allowlist (#4657, #4682-#4685, #4687-#4689, #4693; 5-agent vote (4d3ea1c5)).** Threat model: the gate stops honest drift in the two cloud-init memory templates. Every script, heredoc, unit and structural line, and every data line that names a fetch, credential or daemon token (triggers are case-insensitive and percent-decoded), must match an exact, whitespace-normalised entry in `scripts/qc-allowlists/cloud-init-token-allow.txt` (398 entries, 37 shared by both templates). It does not claim to stop an author who both hides a token and edits the gate or its allowlist; that is left to review of the allowlist diff. Per template and context the approved lines must be the allowlist entries in file order and count, so a moved, repeated or reordered approved line fails (#4784). A malformed, non-normalised or stale entry, or one listed both as allowed and pending, fails, and an empty allowlist or an empty scan fails closed. Known defects are listed, not approved, in `scripts/qc-allowlists/cloud-init-token-pending.txt` (10 entries: in do-hive, the store URL without `verify-full` on the PgBouncer hop, the role password lines and the unverified tarball download tracked by #4671, and the daemon binary and bootstrap script inside the service home tracked by #4712; in aws-gpu-burst, the CHANGEME placeholder store URL tracked by #4610, which the provision script refuses at boot, #4788). The template must start with exactly `#cloud-config` and use only LF line breaks (#4785, #4786). `scripts/regen-cloud-init-token-allow.py <repo-root>` rewrites the allowlist in template order; any new, moved, repeated or removed line in the approved sequence is listed and the file is left unchanged unless `--accept-new` is given, and the diff is reviewed like any allowlist change (#4831, #4885). A companion rule, applied also to heredoc bodies and unit `Exec*=` commands (#4793), refuses `eval`, a glob as the command word (#4795), a decoder (base64, xxd, openssl) feeding a shell, ANSI-C quoting, and a `$` or command substitution in command position. Validators refuse, even on a listed line, any sslmode other than exactly `verify-full`, a password outside `/etc/ai-memory/store-url`, `--store-url` in any quoting, `AI_MEMORY_STORE_URL=`, `PGPASSWORD`, a lax-permission opt-out, a store-url mode other than 0600, `curl ... || true` or a download piped into a shell or tar, and a unit binary in the service user's home. The rendered user-data must fit the provider limit or be gzip-compressed by main.tf (#4703). The pattern rules the allowlist replaces are deleted; the ASCII, serve-present, ServeArgs-flag and TLS-flag rules stay. Its self-test flags 194 red probes (every round-1, round-2 and round-3 review probe included), keeps 7 green probes clean, raises 10 form faults and turns all 398 allowlist entries red when each is mutated.
