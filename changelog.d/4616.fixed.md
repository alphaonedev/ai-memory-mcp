**The AWS burst cloud-init memory template now provisions a daemon that starts (#4616, #4619, #4635-#4642, #4660, #4665, #4666, #4695-#4698, #4703).** `infra/aws-gpu-burst/cloud-init-memory.yaml.tpl` installs PostgreSQL 18 from PGDG with pgvector and Apache AGE built from source at pinned commits (a fetched commit that does not match the pin stops the script), mints a Postgres CA and server certificate on the node and requires `sslmode=verify-full` in the store URL (the connect funnel applies that floor to a TCP postgres DSN, src/store/postgres/dsn.rs:213-283), writes a per-node API key and a self-signed listener TLS pair on the node, and runs `serve --host --port --tls-cert --tls-key`. The CA private key is created in a root-only work directory on `/run` and removed when the script exits, so only the CA certificate stays in `/etc/ai-memory/tls` (#4666); the script stops before writing the key unless `/run` is tmpfs and no swap device is active (#4698). The tarball is checked against the required `ai_memory_image_sha256` before it is extracted, is extracted into a root-only staging directory, the member must be a regular file and not a symlink (#4697), and it is installed as root-owned `/usr/local/lib/ai-memory/bin/ai-memory`, outside the service user's home, so the service user can neither write nor rename it aside (#4665, #4696). Root no longer walks the service-owned home with `chown`; it checks the home owner, and the service user writes its own config (#4695). `infra/aws-gpu-burst/main.tf` passes the rendered template through `user_data_base64 = base64gzip(...)`: rendered with a versioned URL and a 64-hex digest it is 18,362 bytes, over the 16,384-byte EC2 limit, and 9,032 bytes after gzip and base64 (#4703). `infra/aws-gpu-burst/spawn.sh apply` refuses to run without `TF_VAR_ai_memory_image_url` and `TF_VAR_ai_memory_image_sha256` (`spawn.sh plan` does not check them; terraform then stops on the missing required variables); both are required terraform variables, and `main.tf` has no default tarball URL and refuses a URL that is not https, is empty, holds percent-encoding, or contains `/releases/latest` in any letter case (#4660). The role password is percent-decoded and SQL-quoted from the DSN. Both memory templates create `/etc/ai-memory` mode 0700 in `bootcmd`, so the store-URL file has no window for another UID. The `--tls-cert`/`--tls-key` pair is the operator-PKI path of `resolve_tls_material` (src/daemon_runtime.rs:6226-6232); a serve with no flags is not refused for the default shape (it mints a local-CA certificate, :6163-6225). `main.tf` also refuses an image URL with any character other than letters, digits and `. _ ~ / -` after `https://` (#4787) and requires IMDSv2 (`http_tokens = "required"`) on every instance (#4789); the PGDG signing key is checked against a pinned sha256 before apt trusts it (#4790); the provision script refuses the CHANGEME placeholder password (#4788).

**`scripts/check-cloud-init-serve-flags.py` is a fail-closed token allowlist (#4657, #4682-#4685, #4687-#4689, #4693; 5-agent vote (4d3ea1c5)).** Threat model: the gate stops honest drift in the two cloud-init memory templates. Every script, heredoc, unit and structural line, and every data line that names a fetch, credential or daemon token (triggers are case-insensitive and percent-decoded), must match an exact entry after normalisation, in which only whitespace outside quotes collapses and a kept line break is written as U+23CE (#5097) in `scripts/qc-allowlists/cloud-init-token-allow.txt` (398 entries, 37 shared by both templates). It does not claim to stop an author who both hides a token and edits the gate or its allowlist; that is left to review of the allowlist diff. Per template and context the approved lines must be the allowlist entries in file order and count, so a moved, repeated or reordered approved line fails (#4784). A malformed, non-normalised or stale entry, or one listed both as allowed and pending, fails, and an empty allowlist or an empty scan fails closed. Known defects are listed, not approved, in `scripts/qc-allowlists/cloud-init-token-pending.txt` (10 entries: in do-hive, the store URL without `verify-full` on the PgBouncer hop, the role password lines and the unverified tarball download tracked by #4671, and the daemon binary and bootstrap script inside the service home tracked by #4712; in aws-gpu-burst, the CHANGEME placeholder store URL tracked by #4610, which the provision script refuses at boot, #4788). Each tracker heading in the pending list must be one of #4610, #4671 and #4712, and the pending count per tracker may not exceed 1, 6 and 3, so a known defect cannot be parked under a new or malformed tracker (#5098). The template must start with exactly `#cloud-config` and use only LF line breaks (#4785, #4786). `scripts/regen-cloud-init-token-allow.py <repo-root>` rewrites the allowlist in template order; any new, moved, repeated or removed line in the approved sequence is listed and the file is left unchanged unless `--accept-new` is given, and the diff is reviewed like any allowlist change (#4831, #4885). Regen refuses (exit 1, file unchanged) when a template or list fails to load or a pending entry no longer matches a template line (a pending entry for both templates must match each, #5222), so a fixed or stale pending line is not moved into the allowlist (#5116). A companion rule, applied also to heredoc bodies and unit `Exec*=` commands (#4793), refuses `eval`, a glob as the command word (#4795), a decoder (base64, xxd, openssl) feeding a shell, ANSI-C quoting, and a `$` or command substitution in command position. Validators refuse, even on a listed line, any sslmode other than exactly `verify-full`, a password outside `/etc/ai-memory/store-url`, `--store-url` in any quoting, `AI_MEMORY_STORE_URL=`, `PGPASSWORD`, a lax-permission opt-out, a store-url mode other than 0600, `curl ... || true` or a download piped into a shell or tar, and a unit binary in the service user's home. The rendered user-data must fit the provider limit or be gzip-compressed by main.tf (#4703). The pattern rules the allowlist replaces are deleted; the ASCII, serve-present, ServeArgs-flag and TLS-flag rules stay. Before the ai-memory subcommand the gate reads a closed grammar (#4837, #4966-#4971, #4998, copying the closed-world precedent of memories d517ebcd and 19497ef6): an option value is green only as a bare literal of `[A-Za-z0-9_./:@%+=,-]` with no leading `~` or as one double-quoted word of those characters and plain `$NAME`/`${NAME}` shell variables, and the subcommand only as a bare literal, so a terraform interpolation (quoted or not), a `%{ }` directive, an array, a `${X:-..}` operator, a glob, a brace or a tilde is red; the terraform placeholder holds a control character that the gate refuses in a template, so no shell variable can forge it; a word naming the ai-memory binary must be the command word or an operand of a command that never runs it, so an unknown wrapper (taskset, doas, `time -p`, unshare, prlimit, numactl, setpriv) or a copy of the binary to another name is red, while a data-home directory such as /etc/ai-memory is not taken for the binary; and a write_files block or heredoc body is data only when it has no execute bit, lives under /etc/ai-memory, /opt/ai-memory/.config/ai-memory or /etc/pgbouncer, and no statement runs its path, a glob for it or a parent directory, otherwise its lines are checked as script lines. The binary is also tracked through a data-home parent path (#5092), a terraform value in a redirection target before the subcommand (#5099), a renamed copy built by glob, brace, tar or find (#5093), a variable alias or operator expansion (#5094; an operand that is not exactly a plain $NAME or ${NAME} of a resolved name, an indirect, array, glob or nameref value, and a value built by an append are red, #5173, #5174, #5219), an extended glob (#5220), a tar rename carried in TAR_OPTIONS (#5221), a data-file use spelled by a relative, normalised or globbed path (#5095), or by a variable whose values pass the 64-variant expansion cap, which then names every path (#5139), and a copy of a data file, which is not a safe read (#5096). Its self-test flags 405 red probes (every review probe from rounds 1 to 13 included, and each of those forms, #5100, #5323-#5330, #5356), keeps 29 green probes clean, raises 14 form faults and turns all 398 allowlist entries red when each is mutated. Not every check has a pin: the mutants that disable the declare-word poison, the option-word poison and the IFS collapse in the value map survive because another check already refuses each form (built_name refuses an expanded name or option; a poisoned IFS makes every split name unknown to R4), and the PR records each surviving mutant by name. Rule R5 now keeps every literal a name is assigned even when the name is also a `read` target (#5356, 5-agent vote 4d3ea1c5), so a use before a later `read`, a use after a `read` that may not run and a `read` in a pipeline subshell are all red. The remaining gap: a value loaded at run time, as in `read F < /etc/x`, is unknown to the gate, and a bare `"$F"` use is skipped by design (#5139). A failing self-test probe prints its hit count, up to 3 hits whole and, for R5, the use that made a data-home file read as script (#5385).

Its header states what it does not claim (runtime-assembled arguments, SQL literals in `psql -c`). `infra/pgbouncer/smoke-test.sh`, `coverage.yml` and `publish-ci-image.yml` now pass the database password through the docker client environment (#4694).
