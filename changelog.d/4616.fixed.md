**The AWS burst cloud-init memory template now provisions a daemon that starts (#4616, #4619, #4635-#4642, #4660, #4665, #4666).** `infra/aws-gpu-burst/cloud-init-memory.yaml.tpl` installs PostgreSQL 18 from PGDG with pgvector and Apache AGE built from source at pinned commits (a fetched commit that does not match the pin stops the script), mints a Postgres CA and server certificate on the node and requires `sslmode=verify-full` in the store URL (the connect funnel applies that floor to a TCP postgres DSN, src/store/postgres/dsn.rs:213-283), writes a per-node API key and a self-signed listener TLS pair on the node, and runs `serve --host --port --tls-cert --tls-key`. The CA private key is created in a root-only work directory on tmpfs and removed when the script exits, so only the CA certificate stays in `/etc/ai-memory/tls` (#4666). The tarball is checked against the required `ai_memory_image_sha256` before it is extracted, is extracted into a root-only staging directory, and is installed as a root-owned `/opt/ai-memory/bin/ai-memory` that the service user cannot write (#4665). `infra/aws-gpu-burst/spawn.sh apply` refuses to run without `TF_VAR_ai_memory_image_url` and `TF_VAR_ai_memory_image_sha256`, and both are required terraform variables; `main.tf` has no default tarball URL and refuses a `/releases/latest/` URL (#4660). The role password is percent-decoded and SQL-quoted from the DSN. Both memory templates create `/etc/ai-memory` mode 0700 in `bootcmd`, so the store-URL file has no window for another UID. The `--tls-cert`/`--tls-key` pair is the operator-PKI path of `resolve_tls_material` (src/daemon_runtime.rs:6226-6232); a serve with no flags is not refused for the default shape (it mints a local-CA certificate, :6163-6225). New gate `scripts/check-cloud-init-serve-flags.py` (job `cloud-init-serve-flags-gate` in `c8-precheck.yml`) enforces seven rules on the memory templates: pure ASCII; an `ExecStart` that runs `ai-memory serve`; every serve flag is a `ServeArgs` long flag; both TLS flags present; `sslmode=verify-full` on each postgres URL (the do-hive gap is recorded in a shrink-only list); the store URL reaches the daemon only through `AI_MEMORY_STORE_URL_FILE` (no `--store-url`, no `AI_MEMORY_STORE_URL=`, no password in a unit); and every plain git command is inside the one fetch_pinned, called with a 40-hex *_COMMIT that it verifies by rev-parse. Its self-test runs 49 red probes and 11 green probes. `scripts/check-docs-no-argv-secrets.py` now also flags a `password=` query parameter and a credential postgres URL on the argv of a command in a shell-like file (#4663). The do-hive template is not fully covered: its PgBouncer TLS hop and tarball digest are tracked separately.
