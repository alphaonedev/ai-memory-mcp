**An audit event lost on its first byte is no longer invisible after a crash (#4299).** The #4086 sequence high-water was written only after a write failed. An event whose write failed on the first byte (a full disk), with the process dying before that mark write, left nothing in the trail and nothing in the mark, so `audit verify` read clean. Each event's number is now written to the mark AHEAD of its append (in place, no fsync), under the trail's exclusive lock, and made durable only if the write fails. Any process death between numbering an event and writing it now leaves the number on disk, and `verify` reports it as a gap; after ordinary writes the mark equals the last line, so there is no false alarm. The write-ahead is not fsynced because the trail lines are not either (a per-event fsync would stall every audited operation), so a power loss can still drop the newest lines and their mark together; that limit is documented. `audit verify` now takes a shared lock on the trail, so a write in progress is waited out rather than reported. If the write-ahead itself fails, the event is still written and stderr says so. Decided by a 5-agent vote (3-2).
