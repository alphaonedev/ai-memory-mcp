**The lab probe matcher no longer writes outside the lab scratch directory, cannot be replaced by the caller, and a verdict it cannot record fails the run (#5197, #5586, #5646, #5647, #5648, #5649, #5662, #5663, #5664, #5709, #5739, #5740, #5741, #5744, #5745, #5742, #5743).** The bash matcher read its log through a here-string, which spills a large value to a temp file under `$TMPDIR` (`/tmp` when unset), so a large probe log wrote outside the lab scratch directory. Six rounds of in-shell guards then closed one shadowing route at a time (a function, exported function, alias, `enable -n`, PATH file or hash for `command`, `builtin`, `type`, `return`, `exec`, `source` and their neighbours; trace options and DEBUG, RETURN and ERR traps; `BASH_ENV`, `SHELLOPTS`, `CDPATH` and other start variables), and each left the next, because in bash every command name a guard calls can be rebound by the caller. The bash lab (`run.sh`, `lib/common.sh`, `lib/posture.sh`) is replaced by one Python program, `infra/federation-lab/run.py` (#5815), which closes the class rather than each route:

- The matcher is `probe_verdict`, a pure function of the log bytes read with the builtin `open`: no here-string, pipe, child shell or temp file (#5197, #5586). It returns `detected`, `not-detected`, or `refused: <reason>` when the log cannot be read. `probe_report` turns only `detected` into a PASS row; every other verdict prints a FAIL row naming it (#5664).
- Nothing the caller defines can replace the matcher (#5646, #5647, #5648, #5649, #5662, #5740, #5741, #5744). Before it imports anything but `sys`, `run.py` refuses to start (exit 78, one `run.py: REFUSED:` line naming each reason) unless the interpreter was started isolated (`-I`) on a script file, with no `-c`, `-m` or stdin entry; no `-i`, `-O`, `-v`, `-b`, `-d`, `-x`, `-W` or `-X` option other than `frozen_modules=on|off`; no replaced builtin it calls (`open`, `__import__` and eighteen more, compared by identity); no replaced `sys.excepthook`, `displayhook`, `unraisablehook` or `breakpointhook`; and no `LD_*` or `DYLD_*` variable. `-I` makes the interpreter ignore every `PYTHON*` variable and the user site directory. A start with `-I` but without `-S` re-executes itself once with `-I -S`, so no `.pth` file or `sitecustomize` of the installation runs, and then the stock import machinery, `sys.path` entries under the installation prefix only (never the script directory, `""` or `.`) and a standard-library origin for every loaded module are required too.
- A trace, profile or `sys.monitoring` hook is refused at start (#5663, #5742).
- The probe block must record exactly one verdict: `probe_guarded` counts the ledger before and after the block and prints one FAIL line naming #5739 for a block that raised, recorded none or recorded two (#5739). The exit code is 0 only when at least one PASS and no FAIL were recorded and the summary and every output stream were written; an interrupt exits 130 or 143 after the daemons are stopped.
- `PORT_A`, `PORT_B` and `CORPUS_ROWS` are read by a positive parse: a plain decimal from 1 to 65533 (room for `PORT_B + 2`) or from 1 to 999999999, no sign, space, underscore, leading zero or non-ASCII digit; anything else exits 2 (#5745).
- Self-test scratch comes from one helper, `scratch_dir`, which returns an absolute physical directory under `$TMPDIR` made absolute, or the current directory when `TMPDIR` is unset; a leg pins that it is the only scratch maker in `run.py` (#5709, #5743).

`--posture-selftest` pins each of these with a named leg: every matcher case (including a log with 200000 lines before the refusal, a missing log and a directory), every probe-block outcome, every exit path, every port and row spelling, and the start-state controls and refusals, each run as a child interpreter. Three legs pin the bars this round was held to: a verdict that cannot be recorded exits non-zero; code injected at interpreter start that changes the matcher result (a `sitecustomize` or `usercustomize` that replaces `open`, a driver that replaces `open` before running the file) is refused; and a name or module that replaces one the matcher uses (an injected global `open`, a replaced `re` in `sys.modules`, an import hook) is refused. Stated limits: code that runs inside the interpreter before line 1 (an already-loaded preload library, an audit hook, a modified installation) can forge any check; the `python3` on `PATH` and its installation are trusted; Python 3.9 has no `sys.orig_argv`, so there the entry check rests on `__file__`, `__spec__` and `sys.argv[0]`. The self-test was run on CPython 3.12 on Linux only; no other Python version and no macOS host was run.
