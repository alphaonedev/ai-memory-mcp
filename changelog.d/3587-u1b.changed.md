CLI `resolve` now archives the older loser atomically on SQLite and PostgreSQL, preserving priority and confidence. Hardened owner authority or an allowlisted `--as-admin` identity is required; refusals are audited. Generic MCP `memory_link(supersedes)` continues to link two live rows.

**Compatibility — `ai-memory resolve` behaves differently after upgrade.** Two changes can break an existing script:

- It now refuses unless the command runs as the owner of the losing memory. Before, it ran for anyone. Set `AI_MEMORY_AGENT_ID` to the agent that wrote the older memory, or run it from an identity on the admin allowlist with `--as-admin`. A refusal exits non-zero with `supersession refused: <reason>` (for example `UnauthenticatedPrincipal` or `OwnerMismatch`), changes nothing, and is recorded in the audit log.
- The losing memory is moved to the archive (`archive_reason = superseded`) instead of staying live with priority 1 and confidence 0.1. It no longer appears in `list`, `search` or `recall`. Restore it with `ai-memory archive restore <id>` if you need it back.
