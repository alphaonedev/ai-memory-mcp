`ai-memory wake-hub` — a same-host, **content-free** agent wake plane over a
0600 Unix domain socket with kernel-attested peer credentials (`SO_PEERCRED` on
Linux, `LOCAL_PEERPID` + `getpeereid` on macOS; the hub asserts at start-up that
the platform actually supplies a peer pid and REFUSES to start if it does not).
Recipients learn "you have inbox row X" in about a millisecond instead of on
their next three-minute poll (EPIC #3466, design authority: the rust-a2a v2
adjusted plan from the 2x3 adversarial vote).

The hub carries **no message bodies**, structurally: the v1 protocol has no
`request` / `reply` / `notify` kinds at all — their wire numbers are refused by
name so a client built against the pre-vote draft fails closed with a legible
error instead of having its body silently routed. The largest routed payload is
a 256-byte hint of `{inbox_row_id, namespace, sender, digest,
seq_high_watermark}`. The ai-memory inbox row remains the durable record and the
<=60 s backstop poll remains the guarantee, so losing the hub degrades wake
LATENCY and nothing else. It opens no database on either backend.

Everything is bounded in BYTES, not frames — the four defects the adversarial
vote found in the original spec: per-recipient queues carry a byte cap as well
as a frame cap, a hub-wide egress byte budget caps them all, a topic wake is
charged one extra token per additional recipient against the sender's 500/s
burst-2000 bucket (so fan-out amplification is visible to the limiter meant to
bound it), and `RLIMIT_NOFILE` is raised and the connection ceiling derived from
what was actually granted at start-up (macOS's 256-fd default lands `EMFILE` at
exactly the 256-agent design target, so it is now a reported clamp rather than a
discovery under load). Offline state is a coalesced set — count, a bounded id
set, and a `lagged` marker obliging a catch-up read — never a payload ring, and
an entry is only ever created for an agent that has completed a handshake, so a
forged destination cannot mint one. Overflow answers the SENDER with `507`; it
is never a silent drop.

Identity verification is a trait boundary and the shipped verifier **refuses
every hello** until the scoped `a2a-hub/join/v1` delegation lands in #3468.
There is deliberately no CLI flag that substitutes a permissive one. Every
identity refusal collapses to a single `401 unauthorized` on the wire so a peer
cannot distinguish "unknown agent" from "bad signature" by probing, and the
handshake signature covers a domain-separated, length-prefixed transcript bound
to the hub id, a per-connection challenge nonce, the claimed agent id and the
asserted topic set.
