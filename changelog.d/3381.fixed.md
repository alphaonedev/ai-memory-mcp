Require caller-scoped read visibility and mutation ownership before
`memory_auto_tag` sends stored content to the model. Persist tags through the
same permission, governance, and audit funnel as `memory_update`, preserving
the caller and returning pending approval responses when required. Invalid
configured MCP identities fail closed. Substrate rows are withheld on both
MCP and HTTP because neither auto-tag request accepts a namespace selector.

`POST /api/v1/auto_tag` checks per-agent identity binding and applies the same
substrate-aware read predicate on SQLite and PostgreSQL. It generates tags
without persisting them; readable collective rows remain available through
this read-only surface. Ordinary rows retain the MCP single-operator posture
when no identity is configured. An identified caller cannot auto-tag an
unowned private row merely because the legacy mutation rule would allow it.
