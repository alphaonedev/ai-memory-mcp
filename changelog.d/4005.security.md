### Security

- **[mcp][schema] `memory_subscribe` no longer advertises plaintext loopback
  webhooks or unsigned delivery** ([#4005](https://github.com/alphaonedev/ai-memory-mcp/issues/4005)).
  The tool's `docs` and its `url` / `secret` property descriptions (served by
  the verbose `memory_capabilities` drilldown) said "https URL (http only for
  loopback)" and "HMAC secret. Omit for unsigned." The server refuses both:
  `subscriptions::validate_url` rejects every `http` URL, loopback included
  (#3705), and registration is refused when neither a per-subscription secret
  nor the server-wide `[hooks.subscription] hmac_secret` is set
  (R3-S1.HMAC). The text now states what is enforced, including that loopback
  also needs `[subscriptions] allow_loopback_webhooks = true`. Behaviour is
  unchanged (the enforced behaviour is the safer one). Pinned by
  `tests/c2_tool_docs_field.rs::memory_subscribe_schema_text_matches_server_enforcement_4005`.
