**CI: external-PR operator-approval gate judges every event and fails closed on a merge queue (#6117, #6227, #6229).**

`scripts/check_external_pr_approval.py` replaces the inline step of the `external-pr-operator-approval-gate` job in `c8-precheck.yml`. On `pull_request` it judges the event's PR; on `push` the open PRs whose head is the run sha; on `merge_group` the PR named by `merge_group.head_ref` (#6227), whose ref sha must equal `merge_group.base_sha`, the queue commit's parent (#6325; #6242 stays open for the residual below), and only when the base branch's `merge_queue` rule has `max_entries_to_merge` equal to 1 so no queued PR goes unjudged (#6229). Exit 0 passes, exit 1 means the operator approval is missing, exit 2 means the verdict cannot be established (API error, malformed payload, unreadable rule); an interrupt kills the in-flight `gh` and the gate dies of the delivered signal. Cases are pinned in `scripts/ci/tests/test_check_external_pr_approval_6117.py`. The gate still judges the PR's current head, which may differ from the head that was queued; that residual is tracked in #6242 and is not closed here.
