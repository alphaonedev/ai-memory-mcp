**The External-PR operator-approval gate now judges push and merge-queue runs (#6117, #6193).**
The required context `External-PR operator-approval gate (author outside team
=> @alphaonedev review)` answered every non-`pull_request` event "not
applicable (pass)". Once `chain/**` pushes ran the workflow, a push run could
post a passing check of that name on an external PR's head sha beside the
failing PR run. The gate is now `scripts/check_external_pr_approval.py`
(self-tested in the job): on `pull_request` it judges the event's PR; on any
other event it lists the open PRs whose head is the run's sha and applies the
same rule to each (no such PR: pass). An API error, unparsable page or
malformed entry fails the job. The checkout that supplies the script uses
`persist-credentials: false`. A PR opened after a push run already judged its
sha is tracked in #6213.
