**CI: the shard progress notice of `ci.yml` no longer echoes raw test-log text into a workflow command (#9430).**
The `Run tests (impact-aware)` heartbeat printed `::notice::[#6344] progress | ...` with the last line of
each shard log (text a pull request controls) put in raw, so a carriage return or other line break in a test's
output ended the notice and the runner parsed the rest as a new command (`::warning::`, `::add-mask::`,
`::stop-commands::`, `##[...]`). The notice is now built by `scripts/ci/workflow_annotation.py`
(`render` escapes each log tail once, `annotation` writes the one line), so no line break, `%`, `::` or `##[`
of a shard log tail reaches the runner through the progress notice; the visible text differs only in escaped
bytes. The same step still prints the full raw shard logs after the heartbeat; that print is #9433. Test:
`scripts/ci/tests/test_ci_progress_notice_9430.py` (runs the step's heartbeat over a hostile corpus).
Bytes: `cut -b1-90` keeps the first 90 bytes of each tail on GNU, uutils (the ubuntu-26.04 runner) and BSD cut
in every locale (`cut -c` cuts characters on uutils and BSD in a UTF-8 locale), so a tail can end inside a UTF-8
character or hold any byte; the notice is one valid UTF-8 line in every locale (a byte that is not part of a
whole character shows as `\udcXX`). The interpreter runs with `python3 -I`, so `PYTHONPATH`, the user site and
their `sitecustomize` / `usercustomize` hooks are ignored and the working directory is not on `sys.path` (the
call adds only `scripts/ci`). A failed notice call (python3 exits non-zero, is killed,
is missing, or stdout is closed) is reported on stderr, and that report is itself `|| true`, so with stderr
closed too no failure of the notice ends the heartbeat loop (`set -e` is live in that subshell) or changes
the step result.
