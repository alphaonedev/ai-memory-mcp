### Security

- **[errors] `POST /api/v1/skill/{id}/promote` no longer returns store or driver
  text in its 400 body, and keeps first-party refusal text**
  ([#6115](https://github.com/alphaonedev/ai-memory-mcp/issues/6115),
  [#6125](https://github.com/alphaonedev/ai-memory-mcp/issues/6125)).
  The failure body is now rendered by the same classifier the MCP tool
  `memory_skill_promote_from_reflection` uses (`mcp_foreign_err`), so HTTP and
  MCP callers get the same text for the same input.
  - **Own text is preserved.** A bad skill name, a description over 1024
    characters, a minimum-depth refusal and the 404 `reflection not found: <id>`
    body reach the caller unchanged.
  - **Foreign text is withheld.** A database, filesystem or encoding failure
    (SQL fragments, DSNs, filesystem paths) is replaced by its class constant
    (`internal storage error`, `filesystem operation failed`,
    `encoding operation failed`); the detail goes to the operator log only.
  - Upgrade note: a client that string-matched a promote 400 body should match
    the typed refusal text or the status code. HTTP status codes are unchanged
    (404 for a missing or hidden reflection, 400 otherwise).
