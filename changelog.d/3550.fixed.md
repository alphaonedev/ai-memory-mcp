`ai-memory restore` now removes the old database's `-wal`, `-shm` and
`-journal` before it publishes the replacement, and refuses the restore if
one cannot be removed. Previously they were removed after the swap and a
failure only warned, so a daemon starting in that window could replay the
old WAL into the restored database. The restore also keeps its exclusive
lock from the liveness check through the swap, runs every check on the
staged copy it actually publishes, fsyncs the directory before and after
the rename, and reports the result as `durable_publish` in `--json`
(`asi-hard` refuses a publish it cannot make durable). Once the swap is
durable it invalidates the replaced, unlinked file, so a process that
opened the database mid-restore fails instead of writing beside the
restored one. The restored file keeps the permissions of the database it
replaces, not the snapshot's.

`restore` now only replaces a database it can lock and checkpoint. A
target it cannot open read-write or lock (not a database, damaged, or
encrypted and opened without its key), or whose WAL it cannot fully fold,
is refused and left untouched; previously the first two were warned about
and replaced anyway, which let a restore run as the wrong user or without
the passphrase overwrite a database a daemon was writing. For a damaged
database, move it and its sidecars aside and restore into the empty
target. Into an empty target the restore publishes with a hard link, so a
database that appears there meanwhile is never replaced, and a leftover
`-wal` beside a missing database is moved into the rollback set instead
of deleted. A symlinked `--db` restores the database it points at.

New `restore --snapshot <name>` selects a snapshot inside a `--from`
directory. Without it the newest file by modification time is used, with a
warning and `selected_by: "mtime"` in `--json`; `asi-hard` refuses that
fallback. `docs/production-deployment.md` gains the PostgreSQL recovery
procedure (`pg_dump` and point-in-time recovery), since `restore` is
SQLite-only (#3550).
