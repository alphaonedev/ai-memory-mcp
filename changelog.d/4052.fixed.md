**#4052 — B7 parity slicer no longer credits a following function's gate.** `fn_body_has_gate` in
`tests/record_stop_structural_b7.rs` used its own function boundary. It ended a body only at
`\n    async fn ` or `\npub fn `, and it found the target with a prefix `find("fn <name>")`. So an
ungated sqlite/pg parity target followed by a gated indented sync fn or a `pub(self)` fn read as
gated, and `fn foo_v2` could stand in for `fn foo`. Every B7 slicer (main scanner, `#3934` core,
parity) now uses one boundary routine, `fn_spans`, built on `is_fn_start`, with exact name matching.
The parity side fails closed: every same-named definition must be gated, and an absent function
counts as ungated. New red-first test: `b7_parity_slicer_does_not_borrow_a_following_gate_4052`.

**R4-G2 follow-up — a gate counts only when the target function itself calls it.** The shared
boundary now ends a function at its real closing brace, matched on a copy of the source with comments
and string/char literals blanked. `extern "C" fn` is recognised as a function start. A gate counts only
as a call (`marker(` or `marker::<`) in the function's own code, not in a nested helper, a comment, a
string, or a following `const`. A `<marker>_*` wrapper counts only when its own body calls a gate. The
SAL primitive `store::record_stop::gate_flag` joins the markers. Write SQL outside every function is
reported instead of dropped. Before this, replacing a real `self.gate_record_stop().await?` with
`// TODO: self.gate_record_stop().await?;` left the whole-tree gate green. New test:
`b7_gate_must_be_called_by_the_target_itself_r4_g2`.
