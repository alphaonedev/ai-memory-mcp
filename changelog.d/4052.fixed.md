**#4052 — B7 parity slicer no longer credits a following function's gate.** `fn_body_has_gate` in
`tests/record_stop_structural_b7.rs` used its own function boundary. It ended a body only at
`\n    async fn ` or `\npub fn `, and it found the target with a prefix `find("fn <name>")`. So an
ungated sqlite/pg parity target followed by a gated indented sync fn or a `pub(self)` fn read as
gated, and `fn foo_v2` could stand in for `fn foo`. Every B7 slicer (main scanner, `#3934` core,
parity) now uses one boundary routine, `fn_spans`, built on `is_fn_start`, with exact name matching.
The parity side fails closed: every same-named definition must be gated, and an absent function
counts as ungated. New red-first test: `b7_parity_slicer_does_not_borrow_a_following_gate_4052`.
