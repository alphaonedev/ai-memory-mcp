**#3500 — release notes document the v97 legacy-agent-key precondition and remedy.**

`docs/v1.0.0/release-notes.md` said "v90–v97 are additive". v97 also
backfills and can rewrite `_agents` registration rows, and it refuses the
upgrade (a bare `CHECK constraint failed`, no agent named) when a canonical
registration row holds a malformed legacy `agent_pubkey` — reachable only on
a database poisoned before #3362. A new "Before upgrading — v97 and legacy
agent keys" section gives the precondition, a read-only SQLite query that
lists the rows the rung would refuse, and the remedy
(`ai-memory agents revoke-key --agent-id <id>` on the pre-v97 binary, after a
backup). The fail-closed migration is unchanged; the pre-flight probe that
names the offending agents stays v1.1.0.
