`admit_attested_write` — the #3419 admit-once ledger primitive — is now
record-stop gated on both backends. It runs *before* the memory write, so an
ungated admission under an active record stop consumed the signed envelope's
fingerprint while the write itself was refused downstream: when the operator
lifted the stop and the caller legitimately resubmitted the same body, the
ledger answered `Replay` and a genuine write was lost. A control meant to
prevent duplicates was destroying originals.

The refusal is fail-closed and writes no ledger row, so the envelope stays
fresh for after the stop, and the write path maps it to the same
`503 ATTESTATION_FAILED` as the ledger-unavailable arm. The #3419
record-before-store ordering is unchanged for every other case — it is the
right fail-closed direction against a crash, where a spent envelope beats an
admitted replay; a record stop is different in kind, being predictable,
operator-initiated and indefinitely long. No B7 allowlist exemption was taken:
that allowlist is for writes that must proceed during a stop, and this one must
not.
