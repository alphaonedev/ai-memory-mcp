**The signed-events ledger is never silently unsigned (#3354, write path).**
A fresh store whose resolved agent id had no signing key wrote every
`signed_events` row `attest_level=unsigned` behind a debug-level log — a
ledger claiming a guarantee it did not provide. The boot funnel now ENSURES
the resolved id's signing key before the first row (loaded when present,
generated when absent — automatic generation is not automatic trust: the
key signs this node's own ledger and binds nothing elsewhere), so the ledger
is signed from row one on sqlite and postgres alike. A ledger-writing verb
whose key cannot be ensured (an unwritable key directory) refuses to start,
naming `ai-memory identity generate --agent-id <id>`; read-only and
remediation verbs (`doctor`, `stats`, `recall`, the `verify-*` family, …)
stay reachable. `doctor` is untouched (its masking was already fixed); the
epoch-seal / re-anchor ask for an existing unsigned prefix stays at #3479.
