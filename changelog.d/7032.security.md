**[release][supply-chain] The payload check is as strict on every sibling path as on the first one (#7032, umbrella #6062).**
The #7018 / #7019 checks were strict on one path of several pairs and weaker on
its sibling: rpm payloads took xz and bzip2 where deb members are gzip only, the
rpm lead and signature header were not read while the main header was
allowlisted, the rpm NAME was not compared as the deb `Package` is, a regular
file named with a trailing `/` was normalised to the binary's path, the
`--verify-dist` file names were never compared with the package version,
release and architecture (nor the deb with the rpm), and the two-build proof
derived workspace B's remap prefix from a symlinked path. Now every compressed
member must be gzip; the lead must be a version 3.0 binary package with a
header signature whose name is `ai-memory-<version>-<release>`; the signature
header must carry exactly nfpm's tags with the main header's SHA-256 and the
package and payload sizes; the rpm NAME must be `ai-memory`; regular-file names
ending in `/` are refused; each package's metadata must match its file name and
the deb and rpm must be one version for one architecture; and both proof
workspaces are resolved before the remap. Regression: the `7032 ...` packer
self-test cases.
