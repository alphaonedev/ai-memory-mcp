Attribute a reflection written through `POST /api/v1/memory_reflect` to the
authenticated caller on SQLite as well as PostgreSQL. The caller identity was
resolved header-authoritatively only on the PostgreSQL branch, so on SQLite the
reflection was owned by the daemon host principal: the request returned 200 with
an id that the caller then could not read back or list. The owner rule now lives
at one site both backends reach. `reflects_on` edges written by the PostgreSQL
reflect path are also signed with the active keypair, matching SQLite, instead of
always landing unsigned.
