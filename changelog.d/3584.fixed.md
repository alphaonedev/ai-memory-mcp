### Fixed

- **[test-isolation] `identity::test_key_dir::install()` now neutralises an
  ambient `AI_MEMORY_KEY_DIR`**
  ([#3584](https://github.com/alphaonedev/ai-memory-mcp/issues/3584)).
  Product behaviour is unchanged: an explicit `AI_MEMORY_KEY_DIR` still beats
  the derived default. The gap was that the *test isolation helper* left that
  override standing, so a harness that exported `AI_MEMORY_KEY_DIR` made
  `tests/key_dir_isolation_3355.rs::shared_helper_isolates_x25519_and_ed25519_writes`
  compare the sandbox path against the harness path. `install()` now points
  `AI_MEMORY_KEY_DIR` at the sandbox it created (EnvGuard snapshot/restore
  on the process-lifetime bind, OWNERSHIP-24/25) so a test that asked for
  isolation cannot observe an ambient override. Denied pin: ambient
  `AI_MEMORY_KEY_DIR` set → helper still isolates. The subprocess
  `env_remove("AI_MEMORY_KEY_DIR")` pin is unchanged. Call sites of
  `install()` stay documented-exempt from env-lock arm (e); the helper
  file's own `set_var` lines count in arm (d). The #3516 unmarked-binary
  doctor pin now asserts "no #3355 panic" rather than exit 0: #3411 made
  doctor read-only, so a missing db is CRITICAL (exit 2) and that is
  operator-correct, independent of the key-dir guard.
