**SQLite `PRAGMA integrity_check` no longer answers for a file it did not
fully examine (#3510, extending the #3508 hotfix).** A verdict of `ok`
stopped meaning "every page in this file was checked": SQLite builds the
check's root-page list from the schema's table hash, every schema object
with no root page of its own — a `VIEW`, a `VIRTUAL TABLE` — contributes
root page **0**, and `btree.c` reads a leading zero as a PARTIAL check,
skipping BOTH the freelist scan AND the every-page-referenced pass while
still returning `ok` (bundled SQLite 3.46.0: `pragma.c`
`if( HasRowid(pTab) ) aRoot[++cnt] = pTab->tnum;` feeding
`if( aRoot[0]==0 ){ bPartial = 1; … }`). The schema v98
`inbox_namespace_aliases` view (#3401) put a zero-root entry at the head
of the ai-memory schema; `memories_fts` is an older one, so any future
view or virtual table can re-trigger it.

- **One implementation, structurally pinned.** The #3508 page-accounting
  control moves out of `src/cli/backup.rs` into the shared
  `storage::sqlite_integrity` module — Result-typed, no `unwrap`, and
  fail-closed: it distinguishes "this database is NOT sound" from "this
  build could not COMPLETE the check", and never reports the second as a
  pass. `tests/sqlite_integrity_call_site_gate_3510.rs` walks
  `src/**/*.rs` and fails any product `PRAGMA integrity_check` outside
  that module, so a future surface cannot re-acquire the fail-open by
  reaching for the raw pragma.
- **The power-loss durability claim is now real.** The post-crash
  no-corruption assertion in `src/recover/durability.rs`
  (`tests/power_loss_durability.rs`) asked the bare pragma, so on a v98
  schema it could report "no corruption" without ever looking for the
  unreferenced pages a torn write is most likely to leave. It routes
  through the shared helper, and the harness asserts on
  `integrity_verdict` so a failure names the unaccounted pages.
- **The `auto_vacuum` branch is a real check, not an invisible WARN.**
  It previously degraded to a `tracing::warn!` no CLI surface subscribes
  to. Pointer-map pages are now counted exactly — derived from
  `ptrmapPageno` in the bundled amalgamation (`nPagesPerMapPage =
  (pBt->usableSize/5)+1`, with the pending-byte group shifted one page
  later), with the per-page reserved-byte count read through
  `sqlite3_file_control(SQLITE_FCNTL_RESERVE_BYTES)` so the arithmetic is
  exact on the SQLCipher bundle too. An unreadable geometry REFUSES.
- **`restore` says what it checked.** When the page census is what
  covered the staged file, the operator sees
  `Verified all N pages of … (b-tree … + freelist … + pointer-map … +
  pending-byte …)` on their own output — stderr under `--json`, so the
  envelope stays a single machine-readable document.
- **A migration-ladder proof, not just a census.** The new gate also
  builds a freshly migrated database, constructs the exact damage the
  partial check skips, and asserts the verdict is a refusal — measured
  against SQLite's OBSERVED verdict, so a future SQLite that restores the
  full pass still passes.

`storage::fts_integrity_check` (the FTS5 index-vs-table command) is a
different mechanism, is not affected by this hazard, and is unchanged.
