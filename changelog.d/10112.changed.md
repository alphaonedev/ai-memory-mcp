- **`ai-memory identity recover` now requires a signing arm holding
  `K_new.priv` inside `--key-dir` and archives the retired `K_old` under the
  trust anchor (#10112, Option B, vote `V1-RECOVER-REBIND-ATTEST`).** Guardian
  M-of-N signatures are verified against the committed quorum (read from any
  prior signed lineage record, never from CLI arguments) before any write; the
  `agent_lineage` insert, `agent_pubkey_history` append, `_agents` update, and
  `#10040`-format `row_attestations` row signed by `K_new` commit in one SQLite
  transaction at a single shared timestamp `ts`, followed by an atomic
  staged+fsynced anchor swap archiving `K_old` to `<agent>.pub.<ts>` and
  installing `K_new` as `<agent>.{pub,priv}`, then advancing the anchored seal.
  A verify-only arm (`--verify-only`), a missing `K_new.priv`, a mismatch with
  `--successor-pubkey`, or a quorum shortfall is refused preflight with zero
  database or anchor changes; the PostgreSQL path refuses unattested recovery
  rebinds with the same named refusal (`REFUSE_RECOVERY_VERIFY_ONLY`). Row
  attestation stored bytes and `#10040` verifier rules remain byte-identical.
