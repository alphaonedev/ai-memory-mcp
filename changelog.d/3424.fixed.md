`POST /api/v1/kg/query` and `POST /api/v1/check_duplicate` now answer with one
wire shape on both backends.

`kg/query` documents a nine-field row. The sqlite branch projected all nine; the
postgres branch hand-built a four-field object, dropping `title`,
`target_namespace`, `valid_from`, `valid_until` and `observed_by`. The root
cause was one layer down — the SAL row type `store::KgQueryRow` carried only
those four fields, so the data never reached the handler and the sqlite adapter
was discarding five values it already had. `KgQueryRow` now mirrors
`models::KgQueryNode` field-for-field, and both postgres traversal paths (AGE
Cypher and the relational CTE) return the traversal skeleton which a single
shared hydration step fills before either traversal returns — so the two paths
cannot project different shapes, and the existing AGE↔CTE parity contract now
covers nine fields instead of four.

`check_duplicate` renamed `nearest.similarity` to `score` on the postgres
branch, skipped the display rounding the contract specifies, and put the
`is_duplicate` **boolean** in `suggested_merge`, where a consumer expects the id
to merge into.

Both routes now have exactly one projection function each, called from both
branches, so a field can only be added, renamed or dropped in one place.

Hydration uses the full `(source_id, target_id, relation)` edge key so parallel
relations retain their own validity window and observer. Seeded native
PostgreSQL tests cover allowed/denied responses and wire parity; AGE/CTE
fixtures now use typed AGE parameters and matching timestamps so those
comparisons execute instead of silently skipping.
