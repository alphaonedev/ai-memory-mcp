### Security

- **[sdk-python] The Python SDK verifies TLS or refuses to build, and reads its trust anchors once, from paths only their owner can change**
  ([#3840](https://github.com/alphaonedev/ai-memory-mcp/issues/3840), umbrella
  [#6060](https://github.com/alphaonedev/ai-memory-mcp/issues/6060), CWE-295).
  `AiMemoryClient` / `AsyncAiMemoryClient` accept `verify=` as exactly `None`,
  `True`, the path of an existing CA bundle file or hashed CA directory, or an
  exact `ssl.SSLContext` that is `CERT_REQUIRED` with `check_hostname` on, no
  relaxing verify flag (#6375), no cipher suite without server authentication
  (#6305) and no replaced handshake attribute (#6363). `verify=False`, an
  empty or blank path, a subclass such as `truststore.SSLContext`, and every
  other value raise `ValueError` at construction.
  A caller-supplied context is re-checked before every request (#6249, #6378),
  and after every TLS handshake, direct, through an `http://` or `https://`
  CONNECT proxy, or over SOCKS, the session must belong to that context, name
  the request host and be inside its validity dates before the first request
  byte (and the `X-API-Key` header) is written (#6349, #6350, #6375, #6376); a
  response-side backstop refuses what a skipped trace would miss (#6360). The
  check is installed inside every transport, after all request event hooks,
  so a later hook cannot remove it, and a client whose transports cannot be
  wrapped is refused (#6537).
  A CA path is resolved component by component and read ONCE, at construction,
  into a context the SDK builds: a certificate added to a hashed directory
  later is never trusted, and a CA file or any directory the path passes
  through (an ancestor, the holder of a symlink, or an ancestor of a link's
  target) that its group or others can write, or that belongs to a user other
  than you or root, is refused, except a sticky directory whose entry belongs
  to you or root (#6248, #6269, #6377, #6559, #6653, #6654; 3-agent vote
  (6def5ab6)). A FIFO or other non-regular entry is refused without blocking
  (#6307). `ca.pem/` (a trailing separator on a file) is refused (#6690).
  Under `verify=None` / `True`, `SSL_CERT_FILE` (else `SSL_CERT_DIR`, an empty
  value counting as unset, as httpx does) is read the same way at
  construction (#6538).
  Upgrade note: these used to be accepted and now raise `ValueError` when the
  client is built: `verify=False`; a non-exact or weakened `SSLContext`; a CA
  path or `SSL_CERT_FILE` / `SSL_CERT_DIR` value that is missing, of the wrong
  kind, or writable by its group or others (on httpx 0.27 a missing
  `SSL_CERT_FILE` used to fall back to certifi silently); and a CA path that
  passes through a directory that is shared-writable and not sticky, or owned
  by another non-root user, for example a bundle under Homebrew's
  `/opt/homebrew/etc` (`drwxrwxr-x`). Each message names the directory, its
  owner and mode, and the remedy (`chmod go-w`, `chown`, or a private copy). Regression tests: `sdk/python/tests/test_verify_false_3840.py`,
  `sdk/python/tests/test_tls_session_6060_r5.py`, `sdk/python/swarm/tests/test_tls_config.py`.
