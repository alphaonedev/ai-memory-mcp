### Fixed

- **[cli] `AI_MEMORY_NO_CONFIG=1` still wrote the config-path WARN to stderr**
  ([#3603](https://github.com/alphaonedev/ai-memory-mcp/issues/3603)).

  `AppConfig::config_path()` emitted its one-shot config-path WARNs
  (shadowed Library config and Library-only config on macOS; the #3002
  legacy-root fallback elsewhere) whenever the WARN-bearing shape existed on
  disk, even with the escape hatch set. `main` resolves that path for
  `write_default_if_missing` on every boot, so on a host carrying both
  `~/.config/ai-memory/config.toml` and
  `~/Library/Application Support/ai-memory/config.toml`, every
  `AI_MEMORY_NO_CONFIG=1` child printed "loading the DOCUMENTED config …
  a second config exists …" and broke quiet-success contracts such as
  `ai-memory capture-turn --quiet` (`tests/capture_turn_cli_3587.rs`).

  Under a truthy `AI_MEMORY_NO_CONFIG` no config file is consulted, so these
  WARNs are no longer emitted. The resolved path is unchanged, so doctor's
  `config_path` fact, `ai-memory config check|migrate` and
  `write_default_if_missing` name the same file as before. Without the
  escape hatch the WARNs fire exactly as before.
