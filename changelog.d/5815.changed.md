**The laptop federation lab is one Python program, `infra/federation-lab/run.py`, and proves its own start state (#5815, fixes #5756 and #5757).** The bash lab (`run.sh`, `lib/common.sh`, `lib/posture.sh`) could not see code that ran in its own shell before line 1 (a `BASH_ENV` file that unsets itself, #5757), and under `bash -n`, `bash -t` or an exported `SHELLOPTS=noexec` it exited 0 with no output, so a vacuous run read as a pass (#5756). `run.py` runs under `python3 -I -S` (its first line), proves that start state before it imports anything but `sys`, and exits 78 with one `run.py: REFUSED:` line naming each reason otherwise; a lab run exits 0 only when it recorded at least one PASS and no FAIL and wrote its summary and every output stream, so no interpreter mode turns a run that did nothing into a pass. The flags (`--bin`, `--signer`, `--corpus-db`, `--corpus-ns`, `--corpus-rows`, `--recall-query`, `--port-a`, `--port-b`, `--keep`, `--no-caveat-probe`, `--probe-mutation`, `--posture-selftest`, `--help`), the environment overrides (`BIN`, `SIGNER`, `PORT_A`, `PORT_B`, `CORPUS_ROWS`, `RUST_LOG`, `NO_COLOR`), the exit codes 0, 1 and 2, and the PASS and FAIL rows are the bash lab's; a green run on the same binary printed the same eighteen PASS rows. Changes a user sees:

- Run it as `./run.py` or `python3 -I -S run.py`; a plain `python3 run.py` is refused (exit 78), because without `-I` the interpreter runs `PYTHON*` variables and the user site directory before the program can check anything.
- Prerequisites are `python3` 3.9 or later, `openssl` and `bash` (for the prior-art certificate generator). `curl` is no longer used: HTTPS and mutual TLS go through the standard library. `jq` and `sqlite3` are needed only with `--corpus-db`, where `tools/make-local-slice.sh` uses them (#5816 ports that tool).
- Every child process gets an argument list, an absolute program path and an allowlisted environment (no caller variable reaches a node, the probe or a tool); a `RUST_LOG` that is not a plain filter spelling is replaced by the lab default.
- `CORPUS_ROWS` (and `--corpus-rows`) is validated on every run, not only with `--corpus-db`.
- `SIGINT` and `SIGTERM` stop the daemons, remove `run/` (absent `--keep`) and exit 130 or 143, in every window: while a daemon is being started, between the start and its registration, while the handlers are installed and while cleanup runs; a cleanup that cannot finish exits non-zero with a named line (#5946).
- `./run.py` works only through `env -S` (its first line is `#!/usr/bin/env -S python3 -I -S`); where `env -S` is missing use `python3 -I -S run.py` (#5940).
- `--help` exits 1 when the usage text cannot be written.
- The crypto step now points the reader at step 7, where N1 asserts the same-CA unpinned refusal; the bash lab said step 6 (#5817).

The `--posture-selftest` legs grew from the bash posture checks to cover the start state, every exit path, the matcher, the jq-equivalent readers (compared with jq 1.6 running the bash lab's own filters on 38 inputs: no difference) and the input parsers. Stated limits: the self-test and a full lab run (18 PASS) were measured on CPython 3.12.3 and 3.9.25 on Linux; no other Python version, no macOS host and no docker lab was run.
