**The coverage job repairs a mismatched PostgreSQL 16 package set before the tests run (#9235).** `apt-get install postgresql-16-pgvector` inside the running `pg-age` container can upgrade `postgresql-16` underneath the postmaster started from the image's older binary, and the old postmaster then cannot load the new `plpgsql.so`, so every Postgres test panicked with `BackendUnavailable`. The trigger is the pgdg package build (first seen with `postgresql-16-pgvector` 0.8.7-1.pgdg13+2), not the hosted runner image. `.github/workflows/coverage.yml` now restarts the container after the install and runs `scripts/ci/pg_env_preflight.py`, which probes `plpgsql`, `vector` and `age` and fails the job with one `PG-ENV <reason>` class line on a package mismatch; `scripts/ci/check_pg_preflight_workflows.py` pins the step in CI. No coverage threshold, test selection or product code changes.
