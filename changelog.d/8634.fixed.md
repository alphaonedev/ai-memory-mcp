**CI: self-hosted runners prune their own stale `TMPDIR` at job start (#8634).**
Tests leave databases, WAL files and backups under the runner `TMPDIR`, and
nothing removed them: on one node four runner directories held 771 GB and a GA
test job was refused at the disk floor. `scripts/ci/prune_runner_tmp.py` now
removes direct entries of the runner's own `TMPDIR` whose mtime is older than
one day (a symlink is unlinked, never followed; a sibling runner directory is
never touched). The directory is proven by file identity to be
`<confirmed runner root>/runner-<digits>` (one confirmed root per node, no
override flag), opened once, and removed through that descriptor with an
iterative walk that never enters another device and never recurses. Input it
cannot prove ends in a named refusal: a `::warning` annotation, nothing deleted,
and the job continues; an unexpected error fails the job; a failure on one entry
is counted, not fatal. Names in the log are escaped. The composite action
`.github/actions/prune-runner-tmp` runs it as the step right after checkout in
every self-hosted job. Tests: `scripts/ci/tests/test_prune_runner_tmp_8634.py`.
