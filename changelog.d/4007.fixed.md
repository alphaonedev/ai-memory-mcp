### Fixed

- **[data-integrity] An invalid `--tier` on `store` / `update` is now refused
  before the database is opened**
  ([#4007](https://github.com/alphaonedev/ai-memory-mcp/issues/4007)).
  `docs/CLI_REFERENCE.md` promised the #3130 tier refusal "happens before the
  database is opened, so nothing is deleted". For SQLite `store` it did not:
  `store` ran `db::open`, then `db::gc_if_needed` — which archives, or with
  `archive_on_gc=false` erases, every expired row and commits — and only then
  parsed the tier, so a refused command could remove expired rows. `update`
  also opened (creating or migrating) the database before its parse. Both
  verbs now parse the tier first, which makes the documented guarantee true;
  the reference now also states the MCP-tool half precisely. Live rows were
  never affected. Pinned by `tests/cli_tier_refused_before_db_open_4007.rs`.
