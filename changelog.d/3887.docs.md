**#3887 — postgres AGE guide no longer scopes KG staleness to `deferred` mode.**

`docs/postgres-age-guide.md` said only `deferred` mode has a staleness
window for `kg_query` / `kg_timeline`. On the default `sync` mode an AGE
runtime failure during a link write commits the relational row and records a
`kg_projection_outbox` row instead of failing, and the readers fall back to
the CTE only on an AGE *error* — so a healthy-but-behind projection returns
`Ok` with edges missing. The guide now says so for both modes, describes the
drainer's retry/quarantine behaviour, and names the metrics that show the
lag. No code change; CTE routing on outbox depth stays tracked in #3887.
