**Trusted cert-expiry gate re-fetches a stale or missing merge ref before failing (#6176).**
`pull_request_target` does not wait for GitHub to build the pull request's test merge, and a
conflicted pull request has none, so the trusted cert-expiry job could fail closed on a
correct pull request because the fetched `refs/pull/N/merge` was stale or absent (a false
red; a stale merge commit was always refused, so no false green was possible). The job now
passes `--pr-number` and `scripts/check_cert_expiry.py --trusted` fetches the merge ref
itself, re-fetching it after each of four fixed sleeps (5, 10, 20 and 30 seconds, five
attempts at most) until its second parent is the pull request head. After the last attempt
it fails closed with an `::error` annotation that names the stale or missing ref and the
remedy (resolve the conflict, or push or sync the branch, and re-run). Following the #6163
precedent, the workflow no longer has a fetch step at all: the base copy of the gate also
fetches `refs/pull/N/head` itself as git objects, from a `--pr-number` that must match
`[1-9][0-9]{0,9}` (ASCII) and is checked before any git call, and the
`check-claude-md-size.py` pin refuses `git fetch`, `git pull` and `pr checkout` in the
workflow. Refs #6140, #6163.
