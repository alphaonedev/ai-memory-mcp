**`--pre-apply` fails closed on branch patterns using `?`, `+` or `[...]` (#6437, carrier gate #6143, #6232 follow-up).** `_glob` in `scripts/check_carrier_ruleset_live.py` translated `**` and `*` and escaped every other character, so a `!` negation written with `?`, `+` or a character class never matched and `trigger_covers` kept reporting the carrier as covered while GitHub would not run the workflow. A pattern, or a flow-list line, using those characters is now unsupported and `trigger_covers` returns false, so the precondition fails before the ruleset `POST`.
