Gate the remaining pending-reject surfaces on approver eligibility. #3388
closed the MCP tool; the HTTP `POST /api/v1/pending/{id}/reject` route (both
the SQLite and the PostgreSQL branch), the HMAC-signed `/approvals/decide`
deny arm (both branches), and the `ai-memory pending reject` CLI command still
reached the raw structural transition, so any principal — including the
requester, whom approve refuses — could veto any other tenant's queued action.
All of them now run the same eligibility rules approve runs, which have moved
to a single backend-agnostic predicate that the SQLite substrate and the
PostgreSQL adapter both call, so the two backends and the two decisions cannot
drift apart. Federation replay of a peer's already-gated decision is
deliberately unchanged.
