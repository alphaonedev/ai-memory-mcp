### Documentation

- **[http] the approval handler's rustdoc states the contract the code enforces**
  ([#4073](https://github.com/alphaonedev/ai-memory-mcp/issues/4073)). The module and
  verifier docs of `src/handlers/approvals.rs` gave the approval HMAC preimage as a two-part
  timestamp-and-body string (the verifier binds `<unix_ts>.<METHOD>.<pending_id>.<body>`, so
  a client following them was refused `401`), and the visibility docs promised `host:`
  subscribers a see-everything SSE feed that the predicate and the handshake both deny. Both
  now match the code and `docs/k10-sse-approvals.md`; no behaviour changed. The docs are
  executable: `tests/approval_doc_contract_4073.rs` extracts every documented signing recipe
  and requires the real verifier to accept it, keeps the two-part preimage rejected, and ties
  the documented `host:` rule to the predicate's host denial.
