**Server-side signing for stdio MCP writes (#9926).** A new environment variable,
`AI_MEMORY_MCP_SIGNING_KEY_FILE`, names the session agent's 32-byte Ed25519 secret
key for `ai-memory mcp`. The file is read once at boot with `O_NOFOLLOW` and must
be a regular file owned by the effective user, mode `0600` or stricter, and exactly
32 bytes. Its public half must equal the key bound to `AI_MEMORY_AGENT_ID`. If any
check fails, or a federation forward URL is configured, the server refuses to start
with an exact reason.

When the key is loaded, the session agent's `memory_store` without a caller
signature, `memory_reflect`, `memory_consolidate` and `memory_entity_register` are
signed server-side, verified against the bound key and admitted once, so they land
`agent_attested` under `AI_MEMORY_REQUIRE_AGENT_ATTESTATION=1`. A signing failure
refuses the write instead of downgrading it to `claimed`. A caller-supplied
signature takes precedence. With the variable unset, behaviour is unchanged. See
`docs/attestation.md` (Recipe 3) and `docs/CLI_REFERENCE.md`.
