### Security

- **[ci] Pull-request bytes no longer reach the CI runner log as workflow commands**
  ([#9433](https://github.com/alphaonedev/ai-memory-mcp/issues/9433),
  [#9434](https://github.com/alphaonedev/ai-memory-mcp/issues/9434)). Several `ci.yml` steps
  printed text a pull request controls (changed file names, the cargo_skip reason derived from
  them, the PR-tree selector log and the shard logs that PR-run tests write) straight to the runner
  log, where a line starting with `::` or containing `##[` is read as a workflow command. The
  cargo_skip notice now passes the reason through `scripts/ci/workflow_annotation.py` taken from the
  trusted merge-base tree, never the workspace copy, and prints a fixed notice when that escaper does
  not run. The changed-file list and each shard log are printed only between
  `::stop-commands::<token>` and `::<token>::`, with a 128-bit token from the kernel CSPRNG made in
  the step right before each block and never shown before it; without a token the text is not
  printed and the step result is unchanged. The first 200 lines of the selector log are printed
  with every `::` and `##[` spaced apart and a final newline added. The enterprise-fed database name is now cut to 59 bytes
  by Python, since `cut -c` counts characters on uutils and bytes on GNU.
