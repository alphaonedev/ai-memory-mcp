**Postgres federation merge keeps a recoverable copy of what it overwrites (#3961, the postgres half of #1773).** A same-id federation merge where the remote wins the LWW tiebreak now archives the PRE-MERGE row under `archive_reason = 'federation_merge'` inside the merge's own transaction on postgres, exactly as sqlite always has, so `archive restore` and `undo-edit` have something to restore from on both backends. Before this, `PostgresStore::merge_inbound` overwrote the row with no snapshot while its own comment claimed one existed. The reason is one named constant (`ARCHIVE_REASON_FEDERATION_MERGE`) on both backends, and the snapshot SQL is one statement shared with the in-place-edit snapshots, so the archive-parity column set cannot drift. Pinned by `tests/pg_merge_snapshot_3961.rs` (the pre-merge content is archived under that reason, a repeated merge keeps one snapshot, and a merge that overwrote nothing writes none).
