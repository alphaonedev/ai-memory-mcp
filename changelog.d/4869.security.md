### Security

- **[ci] Closed-world gate against credentials on a process argv in executable files**
  ([#4869](https://github.com/alphaonedev/ai-memory-mcp/issues/4869)). The denylist gate
  `scripts/check-docs-no-argv-secrets.py` missed a new argv form in every review round. The new
  gate `scripts/check-exec-secret-argv.py` (precedent 19497ef6, fail-closed allowlist, the form
  of `check-cloud-init-serve-flags.py`) scans shell scripts, workflow `run:` steps, compose
  command/entrypoint/healthcheck, Dockerfile instructions, systemd `Exec` lines and Makefile
  recipes, joins continuations into logical lines, and treats any line that names a secret-like
  thing as red unless it is listed in `scripts/qc-allowlists/exec-secret-argv-allow.txt` (keyed
  by file, normalised line text and count) or in `exec-secret-argv-pending.txt` (a credential on
  an argv today, each pending entry tied to an open issue). Markdown fences and html `pre` blocks
  are checked in prose mode, where nothing can be allowed, only pending. On this branch it scans
  357 executable and 1049 prose files, 910 triggered lines: 794 allow entries (811 lines) and 95
  pending entries (99 lines). `scripts/regen-exec-secret-argv-allow.py` in its default mode
  adds nothing and deletes nothing; only `--prune` deletes, adding needs `--accept-new` and a
  reason or issue (plus `--match <regex>` when it would take more than one new key at once, and
  `--retag` always needs `--match`), and it refuses
  denylist-flagged lines, lines the prose rules flag, and any line that is pending.
  The denylist gate `check-docs-no-argv-secrets.py` passes
  (0 argv credentials, 276 red and 176 green self-test cases) and stays scanned by the new gate.
  A line that was pending at the merge base cannot be approved by a list edit, also after an
  edit elsewhere in its file, a rename, a prune followed by an accept-new run, or an edit that
  leaves the line at least 80 percent similar to it (`EDITED_PENDING_RATIO`). An allow entry that
  is new or changed cannot approve a line whose text is pending in any file, so copying a pending
  line into a file that allows it and then moving it is refused. A base that cannot be read is a
  fault, a base without the list files is not. In CI a missing or unresolvable merge base is a fault on every event (pull
  request, merge group, push); outside CI the gate says the merge-base rule was not evaluated.
  Round 5 (decision B of the 5-agent vote 4d3ea1c5, memory bf29bdb2-4a7a-4926-91e9-8be4bdaff702):
  the allow list is frozen for every file that had a pending row at the merge base. No allow entry
  may be added or raised in such a file, also when the same change removes the pending row; the
  regen tool refuses the same for `--accept-new` (#5298). There is no override flag. At this tip
  that is 40 files holding 95 pending rows (99 lines); their 126 existing allow entries are not
  judged again, only a new or raised entry is refused. The only release is #4929 Part 1 (judge the
  value, not the spelling), which replaces the spelling rules and the freeze. A pending row that an
  earlier change removed cannot come back as an allow entry with its exact text: the gate scans the
  whole history, in every file at every path, with no rename detection (#5500: git
  detected a rename of the pending list onto the allow list path and hid a removal; a delete plus an
  add over-collects and fails closed, and a row the same diff adds back unchanged under the pending
  list path is netted, so a pure rename of the list names nothing). Every merge commit is diffed
  against each of its parents, so a row dropped in a merge, an evil merge or an octopus merge is seen
  (#5463). Every git read of the gate goes through one funnel with a closed environment
  (a short allowlist plus pins): replace refs are off (`GIT_NO_REPLACE_OBJECTS`, #5581; before this
  round only the history log ignored them) and so are grafts (`GIT_GRAFT_FILE` is the null device, #5503), and
  system and global config are the null device. A once-per-repo proof reads the config with scopes
  and the gate exits 2 if any system or global row is still visible. The history log reads text for
  every path (a -diff attribute cannot hide rows) and forces UTF-8 (a UTF-16 log encoding made the
  scan return nothing). A self-test leg refuses a process start outside the funnel for the forms named below.
  Every line-terminator and trailing-whitespace form of a row (CRLF, a lone CR, VT, FF, FS, GS, RS,
  NEL, LS, PS, blanks) is read as the row by the base and history readers, and the tip refuses any
  such byte in either list, so a row cannot be hidden from a rule by its line ending (#5501). A shallow or unreadable
  history, and a committed row that no scanned commit ever added, is a fault that says how to fetch
  full history (#5299; the CI job already uses `fetch-depth: 0`). Known
  limit: a respelling of a removed row, or one split across two changes, is not caught here (a row
  moved unchanged into another file is named: the row text is what the scan keeps, #5505), which is why #5298 is Refs and not Fixes; #4929
  Part 1 closes it, not this round. The credential grammars also read every prefix of wget
  `--execute` (#5293), every `-e` and `--execute` option of a wget command up to its pipe, semicolon or ampersand (#5682), and a backtick word in a credential header, a wget long password option, and
  the sshpass, redis-cli, mysql-family and curl `--cert` arms (#5304). mysql-family arm (#5583, closed world since round 9, #5631): a word that names a mysql or mariadb
  client (mysql, mysqldump, mysqlslap, mysql_upgrade, mariadb-dump, ...; a head in any letter case is read
  when it ends in .exe) in command position is read word by word, and a token counts as clean only when the
  gate positively recognises it; every other token is reported. Command position means: the path has a bin,
  sbin or libexec directory or starts with ./ ../ ~/ or a dollar sign, or there is no path; no earlier word
  of the same command is a verb such as install, start, cat or echo; the name is not an all-capital
  environment variable such as MYSQL_ROOT_PASSWORD. The reader skips quotes, redirects and env assignments,
  and stops at an unquoted pipe, semicolon, newline, ampersand or unmatched closing parenthesis or quote.
  Recognised and clean: a short letter that takes no value or a known value (-u, -h, -P, -S, ...) with
  its value, in a group or alone, and a long option from a table of the options of the ten 5.7.24 clients
  (with the loose-, skip-, enable-, disable- and maximum- prefixes, dash or underscore, and unique
  abbreviations that no password option shares a prefix with). Reported: -p glued to an expansion or followed by
  an expansion, in a group (-Bp"$P"), alone or as a whole quoted word ("-p$P"); --password and its
  abbreviations, also quoted or in a group; an option or short letter that is not in the table when its value or the next word is or holds an
  expansion (-D "$DB", -e "select $X", --pager="$X"; with a literal value it is clean); an operand that starts
  with an expansion before a -- terminator (after one it is a plain operand); an operand that follows a word that is a
  prefix of password or old-password. Stated limits: the tables are a measured sample of the ten clients
  mysql, mysqladmin, mysqlbinlog, mysqlcheck, mysqldump, mysqlimport, mysqlpump, mysqlshow, mysqlslap and
  mysql_upgrade of MySQL 5.7.24, run on the build node (all ten present, every unique prefix of --password
  rejected, -p glued accepted), not a list of every client or version, and an option of a newer or different
  client is unknown to the table, so it is reported only when its value holds an expansion; the MariaDB unique-prefix rule rests on mysys/my_getopt.c
  of 10.11 (source, not executed) and is reported fail closed; a path head without a bin, sbin or libexec
  directory (#5831), a head that is only a package or echo operand, a head after an option value that
  equals a verb (#5829), an all-capital head (#5830), a head split by quotes or a backslash (#5832), a
  parameter-default head (#5833), a password inside a mysqlsh URI operand (#5834), and a head in a
  spelling that is not mysql or mariadb is not read; a single-quoted dollar sign counts as an expansion (reported, the
  conservative side); a literal value that is not an expansion (-pLITERAL) is the concern of the other
  arms, not of this one; an abbreviation shared by options of different kinds is reported.
  Round 9 also moved the repo-local config into the funnel: every git call runs with core.fsmonitor=false
  and core.hooksPath=/dev/null (#5633), so a repo-local fsmonitor command is not run, and the history
  readers use git show --no-textconv. The self-test leg for process starts is an AST check that names the
  forms it refuses (the name subprocess or os used as a value, an alias, getattr, vars, globals, eval, exec,
  __import__, importlib beyond importlib.util, an import of pty, ctypes, multiprocessing or asyncio, a
  sys.modules lookup, an os spawn, exec or fork name) outside the git funnel (#5632); a process name built
  from strings at run time is not seen, so it is a regression guard and not a security boundary.
  Round 10: one verb rule holds for every head, also a head in a quoted payload (ssh, sh -c) after a
  wrapper such as sudo, exec, timeout or an env assignment (#5820); when a command substitution that
  prints a mysql head is itself the command word (command -v, which, type -P), the words after its
  closing parenthesis are read (#5821; v=$(...), x$(...) and an echo operand stay clean). The funnel now also turns off every program git could start while it
  reads history: log.showSignature=false and gpg.program, gpg.openpgp.program, gpg.x509.program and
  gpg.ssh.program set to the null device (#5822), so a signed commit does not run a repo-local
  verifier, and GIT_ALLOW_PROTOCOL is empty (#5823), so a partial clone cannot fetch a missing blob

  repo-configured program runs in the git funnel (6c835151) holds for the verifier and transport programs
  too. advice.graftFileDeprecated=false keeps git's graft hint out of a fault message, so a fault
  names its reason (#5846). Corrections: the comment over the mysql arm said a head is read after
  any path; it is read only under the path rule above (#5824). The funnel comment said the blob
  reads pass --no-ext-diff; only the history log does, and the blob reads pass --no-textconv (#5825).
