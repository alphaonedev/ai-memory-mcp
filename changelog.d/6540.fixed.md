**A lost escalated write is reported on stderr even when no log subscriber is installed (#6540, #6541).** The #6132 dedupe marked a leaked escalation as reported after a `tracing::error!` that reaches no sink on CLI paths without a subscriber, so the thread-exit line was skipped and the loss went unreported. The stale-frame report now writes the same raw stderr line as thread exit and marks intents reported only after that write succeeds. The report also runs before `BEGIN IMMEDIATE` / `BEGIN EXCLUSIVE`, so the debug-build stale-frame assertion can no longer leave a connection inside an open write transaction.
