**The curator no longer overwrites a metadata edit made while it was tagging or checking a memory (#4287).**
`persist_auto_tags` and `persist_contradiction` cloned the metadata the curator
sweep had read before its LLM call, added their own key, and wrote the whole
object back without a version check. A metadata edit committed while the model
ran (another agent, the HTTP or MCP API, or the CLI on another connection) was
silently replaced, and the bumped row version hid the loss. Both writes are now
pinned to the version the metadata was read at; on a version conflict the
curator re-reads the row and re-applies only its own key (`auto_tags` and
`curated_at`, or `confirmed_contradictions`), up to three attempts, after which
it skips the row for this cycle and reports it. Refs #6055.
