A failed subscriber lookup at dispatch no longer drops the lifecycle event of a committed row (#7366). Both dispatch funnels (SQLite and Postgres) now write a durable record to `subscription_dlq` before the retry ladder runs and take the ladder off the request path (#7498, #7499, #7500); a retry that recovers deletes the record, and a spent ladder settles it with the event, memory id, namespace, writer and details needed to re-dispatch. `memory_subscription_dlq_list` shows these rows to their writer and to a trusted admin on MCP, CLI and the HTTP route (#7501, #7542). The table is bounded per namespace, per writer and in total (#7503); the per-writer bucket is keyed on the claimed writer id, so the per-namespace and total caps carry the bound (#7712). The failed-lookup sentinel is per namespace so one namespace cannot starve the others (#7409), the SQLite lookup retry no longer sleeps while the caller holds the connection lock (#7410), and the total cap holds across namespaces (#7430). The double-failure and worker-open ERROR lines name the event and path and never the payload (#7504, #7505), the recorder opens the database through the migrating funnel (#7507), and the new tests satisfy the structural gates for record stop and tracing capture (#7708, #7709). A replay surface for these rows is tracked in #7502.
