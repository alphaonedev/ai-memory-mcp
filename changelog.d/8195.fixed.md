**Python SDK TLS configuration hardened (#8195).**
- `verify=False` and weakened `ssl.SSLContext` objects are refused. That covers `CERT_NONE`, hostname checking turned off, TLS below 1.2, auth-null/PSK/SRP suites, relaxed verify flags and overridden handshake methods.
- The SDK builds one validated TLS context. It re-checks the context on every request and checks the session the handshake actually used on the direct, tunnel and proxy legs.
- `SSL_CERT_FILE` and `SSL_CERT_DIR` trust is loaded once, under the same rules. A missing or wrong-kind path is refused instead of falling back silently.
- The CA path is walked one component at a time with these rules:
  - a cap on symlink hops;
  - sticky-bit, owner and mode checks;
  - macOS extended ACLs refused;
  - `fstat` on the opened file;
  - the opened inode checked again.

  A failed check raises a typed `ValueError`.
- The owner-only credential reader never reads by path after its check. On a platform without `O_NOFOLLOW`, the `fstat` of the opened file must match the checked device, inode, owner and mode.
- Malformed delegation bundles raise a `WakeError` that does not include the bundle content.
