**Python SDK TLS configuration hardened (#8195).**
- `verify=False` and weakened `ssl.SSLContext` objects are refused. That covers `CERT_NONE`, hostname checking turned off, a TLS range below 1.2, anonymous, NULL-encryption and low-strength suites, relaxed verify flags and overridden handshake methods.
- The SDK builds one validated TLS context with a TLS 1.2 minimum, and refuses a session that negotiated an older protocol. That holds for every `verify` value: `None` and `True` use a certifi context built the same way, and a caller context is held to the same floor.
- A base URL whose scheme is not `https` is refused at construction in the sync and async clients; the API key is never sent in plaintext. The base URL is parsed with `httpx.URL`, the parser the client sends with, so a whitespace-prefixed, control-character, hostless, userinfo, or non-`str` form (bytes, `httpx.URL`, a path, `None`), and a non-ASCII host that does not IDNA-encode, is refused with the same typed `ValueError`, which echoes no part of the URL; a `str` subclass is checked and sent as one plain copy, and a context whose TLS bounds, `verify_mode`, `check_hostname` or `verify_flags` disagree with the C-level value, read through descriptors resolved from the real `ssl.SSLContext` MRO, is refused. ASCII label shape is not validated by the SDK; the check and the send agree. The default trust (`verify=None`) is the context the SDK builds with the TLS 1.2 floor, not httpx's own default.
- A plain `ssl.create_default_context()` is accepted on every OpenSSL build; PSK and SRP suites in a distro default are not refused.
- The SDK builds one validated TLS context. It re-checks the context on every request and checks the session the handshake actually used on the direct, tunnel and proxy legs.
- `SSL_CERT_FILE` and `SSL_CERT_DIR` trust is loaded once, under the same rules. A missing or wrong-kind path is refused instead of falling back silently.
- The CA path is walked one component at a time with these rules:
  - a cap on symlink hops;
  - sticky-bit, owner and mode checks;
  - macOS extended ACLs refused;
  - `fstat` on the opened file;
  - the opened inode checked again.

  A failed check raises a typed `ValueError`.
- The owner-only credential reader never reads by path after its check. On a platform without `O_NOFOLLOW`, the `fstat` of the opened file must match the checked device, inode, owner and mode.
- Malformed delegation bundles raise a `WakeError` that does not include the bundle content.
