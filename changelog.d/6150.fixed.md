**`latch_for_test` no longer lets the 4400 latch test flake on a slow runner (#6150, same root cause as #5011).**
The test-only helper stamped the latch time as "now", so the fail-closed gate
retried its probe once `PROBE_INTERVAL_MS` (1000 ms) of wall clock had passed.
The isolated child installs no audit sink, so the retry succeeded, the latch
cleared and `a_latched_audit_trail_refuses_sync_push_on_both_backends_4400`
saw `200` instead of `503` whenever the child's setup exceeded one second under
load. The helper now stores `u64::MAX` (retry never due); tests that need an
immediate retry still call `reset_probe_clock_for_test`. Production code is
unchanged. Regression:
`audit::fail_closed::tests::latch_for_test_stays_refusing_past_the_probe_interval_6150`.
