**`doctor` is actually read-only (#3434).** A missing `--db` is a
Critical Storage finding and is never created (shared
`open_existing_read_only` with #3411). Identity reports the resolved
caller id and whether a signing key for THAT id is enrolled
(`signing: ready (ai:foo)` vs `UNSIGNED — no key for ai:foo`, with a
`keygen` note) instead of only the `daemon.pub`/`daemon.priv`
inventory (`#3354` doctor half). Daemon-file inventory remains as
`daemon_signing`. The Index FTS5 `'integrity-check'` is a SQLite
writer, so a `query_only` doctor reports
`fts_index_integrity: not_observed (read-only; …)` at Info rather
than a false Warning. Regression:
`doctor_missing_file_in_existing_dir_is_not_created_3434`,
`caller_without_key_is_unsigned_not_first_boot_3434`,
`caller_priv_present_reports_ready_3434`,
`local_run_index_skips_writer_fts_check_on_read_only_3434`.
