**#3806 W1b — the `[decision]` boot chokepoint: the second inference endpoint is covered by the egress posture.** `EgressClass::InferenceDecision` joins the #1963 taxonomy, and `build_decision_provider` (`src/decision_boot.rs`) is the single construction site for a decision provider — mirroring `build_llm_client` one endpoint over.

**Egress.** Under `AI_MEMORY_INFERENCE_EGRESS=deny`, and under `loopback-only` against a non-loopback target, **no decision provider is constructed** and a signed refusal row (`egress.inference_refused`, class `inference_decision`) is appended to the audit chain in the operator-resolved `--db`. Under `loopback-only` a loopback `base_url` **is** constructed. `provider = "local-nli"` opens no socket — its `base_url` is empty by construction — so the gate is *skipped* for it, never waived: an air-gapped deployment keeps its decider under `deny`. The enforcement is the ABSENCE of the provider, decided once at boot, not a per-request check somebody can forget; and because a `DecisionProviderHandle` has private fields and no public constructor, W1c's clients attach to an already-gated handle rather than minting their own — a client that wanted to skip the gate would have to add a constructor to that file, which is a reviewable act instead of an oversight. This is the same defect class #3808 found in `[llm.auto_tag]`: a second endpoint that, had it been wired as documented, would have bypassed `build_llm_client`'s gate.

**Per call.** `DecisionEgressGuard::check_outbound` re-resolves the live posture before every outbound request and returns a `Result` the compiler will not let a client ignore. A refusal is an **abstain** (`AbstainReason::EgressRefused`), never a `false` — so tightening the knob on a running daemon degrades the seam instead of corrupting its verdict.

**Reporting.** `GET /api/v1/capabilities` and MCP `memory_capabilities` (v2 and v3; v1 stays frozen) now carry `decision_provider`, whose `state` comes from a CLOSED four-token vocabulary — `absent` | `configured` | `refused_by_egress` | `constructed` — so a fleet orchestrator can assert "this node's decider really is off" rather than parsing prose, and an unexpected token fails to deserialize instead of being silently ignored. The snapshot carries the provider alias, the model, the posture and whether the provider is local; it deliberately carries **no endpoint URL and no credential**, because `/capabilities` is a broadly-readable surface while the audit chain already records the refused target for the operator who can read it.

**`[decision]` unset stays byte-identical v1.0.0.** The chokepoint returns before it resolves anything, opens no database, records no snapshot — so the capability key is omitted from the wire exactly as before — and the W1a golden pin is unchanged. A reload that REMOVES the section clears the snapshot rather than leaving a stale `constructed` claim standing.
