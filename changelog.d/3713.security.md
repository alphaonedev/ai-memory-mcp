**MCP tool errors are rendered from a closed vocabulary; a driver's, `std::io`'s or a codec's text never reaches the MCP caller (#3713).**
`crate::mcp::error_text::mcp_error_text` is now the ONE place a tool error
becomes the `isError: true` text an MCP client sees. It renders from the
typed `MemoryError` VARIANT: our own refusals (not-found, validation,
conflict, governance, quota, the LLM client's #3648-bounded diagnostics) pass
through unchanged, while the foreign classes (`DatabaseError`, the new
`Filesystem` and `Codec`) render a constant — `internal storage error`,
`filesystem operation failed`, `encoding operation failed`. The detail is not
lost: the conversion (`log_foreign` / `mcp_foreign_err`) owns the operator
log line (`tracing` target `mcp.tool.error`, with the site's context), so a
site cannot route an error through the funnel and forget to log it. Before
this, 237 sites across 58 tool files built the caller's string from
`e.to_string()` / `format!("…: {e}")` — rusqlite text with table and column
names, io errors, the operator's resolved skills import/export root — and
`/api/v1/…` #1111 parity routes forwarded the same strings. Gate 7's
`pending:#3713` ledger goes from 237 to 0 with the gate green; two of the
gate's own defects found on the way are fixed with R-203 controls: a
`let`/`if let Err(e) = …` PATTERN was read as an `Err(e)` re-raise
expression, and only the LAST `mapper=` allowlist line took effect.
