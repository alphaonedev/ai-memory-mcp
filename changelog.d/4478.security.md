**A federation peer can no longer open the first namespace standard under a locally governed ancestor (#4478, #4495, CWE-863).** The `/sync/push` `namespace_meta[]` apply skipped the #4356 ancestor-owner bind gate on both backends: sqlite bound the row directly and postgres applied it through the federation admin context, whose bypass skipped the gate. Its only check was the #2479 / #2536 peer-scope gate. That gate asks whether the peer may touch the row's namespace; it never asks whether a governed ancestor above that namespace is owned locally. A peer scoped to `P/x/**` could therefore bind a permissive first standard at `P/x` and opt that subtree out of `P`'s write, promote, delete and approval gates for every local caller. The origin node's own bind check does not cover this, because it judged the origin's chain and owners, not the receiver's. Both receive loops now run the shared #4356 verdict on each inbound first bind (or severed-binding repair), after the peer-scope check and inside the bind's own write transaction: `BEGIN IMMEDIATE` on sqlite, the bind advisory lock on postgres. The admin apply context no longer bypasses it. The federated caller is the agent the pushing peer is authenticated to act for under the lane's existing authorship contract (#238 sender attestation, #1464 `allowed_sender_agent_ids`): the bound standard's stored owner when the peer is that agent or is allowlisted for it, otherwise the attested sender. When no identity can be established (no `X-Peer-Id`, or `AI_MEMORY_FED_TRUST_BODY_AGENT_ID=1`), a first bind under an owned governing ancestor is refused. A refused entry is a per-entry skip counted in `namespace_meta_refused` and `skipped`, with one fixed, value-free WARN line; nothing is written and the rest of the batch applies. The same lane now also gates rebinds and re-parents (#4495): a rebind of an existing standard needs the federated actor to own the standard currently bound (#3758 parity), and after the write a re-parent may not have detached the namespace from a governing ancestor the actor does not own (checked in the same transaction, rolled back otherwise). A missing standard memory is a plain not-found skip on both backends (the existence check runs before the gate). In the zero-config posture (no peer-attestation allowlist configured) any peer acts for whoever owns the memory it binds, and an unsigned `X-Peer-Id` naming an owner is that owner. This is the existing faith model of that posture: #1464 treats row ownership the same way, and the lane is refused there unless the push-scope requirement is explicitly turned off. Governed deployments should configure `AI_MEMORY_FED_PEER_ATTESTATION` with per-peer `allowed_sender_agent_ids` and scopes, plus peer attestation, so that a peer acts only for the agents it is allowlisted for. Unchanged: an ungoverned target and an unowned ancestor are unaffected, and `namespace_meta_clears[]` keeps its #2479 gate. The postgres SET body moved into `store/postgres/ns_standard_bind.rs` (behaviour-neutral for the SAL trait method).
