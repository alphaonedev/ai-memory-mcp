**Schema v103: agent signature places and the agent cutover marker (#10108).** One additive
migration on both backends. `transcript_line_dedup` gains two NULL-able columns, `host_signature`
(64 bytes) and `host_pubkey` (32 bytes), which are both set or both NULL. A new
`atomisation_receipts` table holds one receipt per atomised source. In the same transaction as
the v103 stamp, the migration appends one unsigned `signed_events.agent_cutover` row at the chain
head. That row binds its sequence, the hash of the row below it and the count of agent-labelled
rows below it. Both audit walks recompute the marker. A tampered marker or a second marker fails
with `agent_cutover_marker_invalid`. The append path refuses the marker event type, and an import
refuses a different marker. Hard delete and forget purge the receipts of the erased source on both
backends. No existing row is rewritten. There is no down migration: a downgrade is a restore of
the pre-v103 backup.
