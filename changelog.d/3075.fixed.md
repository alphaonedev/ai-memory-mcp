### Fixed

- **[data-integrity][federation] Federated governance/checkpoint lanes no
  longer stop at a postgres receiver** ([#3075](https://github.com/alphaonedev/ai-memory-mcp/issues/3075)).
  On a PostgreSQL-backed `/sync/push` receiver, seven subcollections were
  bucketed `unsupported_on_postgres` — an honest, sender-visible non-ack, but
  a real coverage gap: federated commit-checkpoint RESOLUTIONS
  ([#125](https://github.com/alphaonedev/ai-memory-mcp/issues/125), the
  separation-of-duties `EpochAdvance` freeze), federated governance-pending
  execution ([#2478](https://github.com/alphaonedev/ai-memory-mcp/issues/2478))
  and federated namespace-standard rebinding
  ([#2479](https://github.com/alphaonedev/ai-memory-mcp/issues/2479)) simply
  did not replicate to a pg peer, so two nodes in one federation answered
  `get_standard` — and resolved a freeze anchor — with divergent state.
  Lane L-PGP migrates these families to the SAL trait one at a time; each is
  gated by the SAME `receive_auth` verdict the sqlite receiver runs, so a lane
  that cannot be applied faithfully stays an honest non-ack rather than
  becoming a silent drop or a partial apply.
  - **Governance-STANDARD lanes (`namespace_meta[]` +
    `namespace_meta_clears[]`) now APPLY on postgres.** Both loops route
    through `receive_auth::inbound_namespace_meta_authorized`, which is
    backend-BLIND (no connection, no probe — `namespace_meta`'s PRIMARY KEY is
    the namespace itself, so the #2447 stored-vs-claimed relocate bypass has no
    subject here) and is therefore called VERBATIM by the pg funnel: the #2479
    Amendment E UNCONDITIONAL refusal on the global `*` standard for any peer
    that did not declare `**`, the own-namespace + declared-parent union, and
    the #2536 deep-descendant probe all hold identically on both backends.
    There is no second implementation for the two to drift apart on — the
    #2488 lesson, applied before the lane opened rather than after.
  - The federated apply runs on a dedicated `federation_apply_ctx`
    (`for_admin`, C8-allowlisted with the rationale). This is PARITY, not
    convenience: the sqlite twin applies these lanes through raw `db::*`
    functions that consult no caller identity at all, so the peer-scope gate is
    the federation authorization — routing the apply through a tenant-scoped
    context would make the pg receiver refuse rows the sqlite receiver applies,
    a silent cross-backend divergence. The local #1777/#2545 owner gate still
    governs the TENANT surfaces (`hook_subscribers`, the MCP namespace tools).
  - Response counters are honest per lane: `namespace_meta_applied` /
    `namespace_meta_cleared` / the additive `namespace_meta_refused` join the
    postgres envelope, and the migrated lanes no longer inflate
    `unsupported_on_postgres`.
  - Regression coverage on BOTH backends asserts the refused AND the applied
    half of every cell (`tests/federation_ns_meta_scope_2479.rs`,
    `tests/federation_ns_meta_scope_2479_pg.rs`) — asserting only the refusal
    would also pass on the pre-#3075 funnel that applied nothing at all, and
    asserting only the apply would pass on an ungated funnel.
  - **Archive / restore lanes (`archives[]` + `restores[]`) now APPLY on
    postgres.** Three new SAL methods with BOTH adapters —
    `apply_remote_archive`, `apply_remote_restore` and the
    `archived_namespace_by_id` scope probe. The sqlite adapter delegates
    verbatim to the `db::*` functions the inline receive loop has always
    called (so the sqlite wire behaviour is byte-for-byte unchanged); the
    postgres adapter composes the ALREADY-gated `archive_by_ids` /
    `archive_restore` funnels, so the link snapshot (#1771/#3161), the
    namespace-meta sever (#3272), the governance pre-write hook, the cid
    re-mint (#1825), the AGE unprojection and the record-stop gate all still
    run and there is no duplicated archive/restore SQL to drift from them.
  - The #2447 by-id confinement runs on BOTH lanes against the row's STORED
    namespace, resolved through a SCALAR projection (`namespace_by_id` for
    archives, the new `archived_namespace_by_id` for restores — the row lives
    in the archive table at that point, which is the whole point of the lane).
    An unresolvable probe fails CLOSED with the `namespace_probe_unresolvable`
    cause token; a missing row stays the lane's no-op.
  - The #1848 / G30 forget-tombstone gate lives on `apply_remote_restore` on
    BOTH adapters, NOT on `archive_restore` — which is the OPERATOR un-forget
    path and must keep round-tripping per #1771. The postgres `archive_restore`
    comment that justified its missing gate with "federation restores[] are
    sqlite-only" is corrected in place: that premise is retired, and the gate
    moved rather than vanished.
  - `archived` / `restored` join the postgres response envelope with the
    sqlite-twin names; both lanes leave `unsupported_on_postgres`.
  - Coverage: `tests/fed_archive_restore_lane_3075.rs` (sqlite — in-scope
    archive+restore apply, out-of-scope archive refused, tombstoned restore
    refused, plus a direct SAL cell because the sqlite receive loop keeps its
    inline path and would otherwise leave the new sqlite trait methods
    untested) and `tests/fed_archive_restore_lane_3075_pg.rs` (the pg twin,
    row state read with raw SQL against a live PostgreSQL 18 + AGE + pgvector
    receiver).
  - **Checkpoint-RESOLUTION lane (`checkpoints[]`) now APPLIES on postgres —
    the #125 headline.** New `apply_remote_checkpoint_resolution` on BOTH
    adapters. It is deliberately NOT `checkpoint_resolve`: that verb SIGNS, and
    a receiver stamping its own attestation onto another node's verdict is
    exactly what a separation-of-duties freeze anchor must never allow. The
    sender's `signature` / `resolver_pubkey` are persisted VERBATIM by both the
    pending->resolved CAS and the first-landing INSERT (asserted byte-for-byte
    on pg).
  - The whole FED-RQ-01 chain is SHARED with the sqlite funnel, not re-derived:
    the resolved-only filter, the #2708 claimed-AND-stored namespace
    confinement (fail-closed on an unresolvable by-id probe), the #125
    `authorize_remote_checkpoint_resolution` verification against the
    resolver's locally-ENROLLED key (never the wire `resolver_pubkey`), the
    #3049 secret screen AFTER that verification, the L5
    substrate-reserved-anchor refusal on both the claimed and the stored kind,
    and first-resolution-wins — for which `checkpoints::classify_against_local`
    becomes `pub(crate)` so the pg twin renders the identical disposition
    rather than growing a second definition of "idempotent replay".
  - `checkpoints_applied` / `checkpoints_conflicted` join the pg envelope.
  - The two stale K3 parity notes that recorded "postgres never reaches an
    inbound-checkpoint apply, so there is no twin to poison"
    (`tests/federation_reserved_anchor_l5.rs`,
    `tests/federation_checkpoint_ns_scope_2708.rs`) are corrected in place and
    now name the live postgres cells.
  - Coverage: `tests/fed_checkpoint_lane_3075_pg.rs` — 6 cells against a live
    PostgreSQL 18 + AGE + pgvector receiver: enrolled+signed applies verbatim;
    forged signature refused EVEN under the `=0` rollout hatch; unenrolled
    resolver refused under the fail-closed default AND accepted under the hatch
    (so #125 is proven load-bearing on pg, not merely present); L5 reserved
    anchor kind refused; #2708 out-of-scope namespace refused with the in-scope
    half applied; first-resolution-wins keeping the local verdict while a
    byte-identical replay stays a no-op.
