**Namespace-only subscriptions record their events instead of filling the DLQ (#4280).**
`POST /api/v1/subscriptions` with `{agent_id, namespace}` and no `url` stores a
subscription whose url is the synthetic `https://localhost/_ns/<agent>/<namespace>`.
The dispatcher treated it as a webhook: every matching event wrote its audit row
and then attempted a delivery that the dispatch-time SSRF guard refuses by
default, so each event also left a permanent `subscription_dlq` row no operator
could act on, drowning real delivery failures; with `allow_loopback_webhooks`
the daemon instead sent a request to whatever listened on localhost:443. Such an
event now writes its audit row with the new terminal `delivery_status` value
`recorded` (read by `memory_subscription_replay`) and nothing is sent: no DLQ
row, no dispatch counters. The marker is the synthetic URL itself, identical on
the sqlite and postgres backends and on rows registered before this change; its
`https://localhost/_ns/` prefix is now reserved, so a caller-supplied webhook URL
that starts with it (in any letter case) is refused at registration on every
surface. Design by 5-agent vote (4-1).
