**`memory_calibrate_confidence` is now a CALLER-SCOPED aggregate on both
backends (#3507, Master lane L-AUTHZ).** The Form-5 calibration sweep had NO
caller gate on SQLite (a pre-existing posture) and therefore none on the
#3064 Postgres port either. Its `baselines` array NAMES every namespace that
produced a shadow observation and reports per-namespace confidence
statistics, so any caller that reached the MCP tool, the HTTP route or the
SAL method received a cross-namespace aggregate over rows it may not read —
the #3171/#3348 residual disclosure class, in aggregate form.

The sweep is now computed ONLY over rows the caller can read, using the
store's OWN visibility machinery rather than a second predicate that could
drift (#951): `crate::storage::visibility_clause` (the #1921 subtree scopes +
the #1720 owner-keyed private arm), `crate::visibility::substrate_exclusion_sql`
(#3348) and `crate::models::lifecycle_visible_clause`. The SQLite and
Postgres statements are rendered from the SAME generator — `visibility_clause`
gained a `crate::visibility::SqlParamStyle` knob that selects ONLY how a bound
parameter is spelled (`?n` vs `$n::text`), because the predicate body reads
generated columns (`scope_idx` / `agent_id_idx` / `target_agent_id_idx`) that
both schemas declare with identical projections.

- **Who sees what.** `CalibrationAudience` is the gate, and its `Caller`
  discriminant is private so it can only be built through the fail-closed
  `for_caller` constructor. An ADMIN caller — admitted on HTTP by the
  existing `handlers::admin_role::is_admin_caller_trusted` (allow-list AND
  request authn AND the #2093 per-agent-key attestation), or at the SAL
  boundary by `CallerContext::bypass_visibility` — keeps the GLOBAL
  aggregate, byte-identical to the pre-#3507 report. Everyone else is scoped.
  Both adapters derive the audience through the one shared
  `CallerContext::calibration_audience`, so the gate cannot be closed on one
  backend and left open on the other.
- **Fail-closed, three ways.** An UNRESOLVABLE caller is REFUSED, never
  widened to "everything": HTTP answers `403` when `X-Agent-Id` is absent
  (without it the shared resolver would synthesise a per-request
  `anonymous:req-…` that owns nothing), and the SAL method refuses an empty /
  shape-invalid / synthetic-`anonymous:` principal with `InvalidInput`. An
  ORPHAN observation (source memory CASCADE-deleted) has no row whose
  visibility can be evaluated, so a scoped sweep DROPS it — the audit-honest
  orphan tolerance the module documents survives only for the admin sweep.
  Substrate namespaces (#3348) are excluded because the sweep takes no
  `namespace` argument and is therefore always an AMBIENT read.
- **A scoped sweep is strictly READ-ONLY.** The `recall_outcome` ledger
  backfill is the one write the sweep performs; it now runs for the ADMIN
  audience only, so a non-admin can never drive a corpus-wide UPDATE over
  rows it cannot read. The optional `consumption_utility` /
  `consume_access_divergence` evidence then degrades to `null` for
  un-backfilled rows — the honest "no evidence yet" the fields already
  document, never a wrong number.
- **MCP and CLI keep working for a single operator.** Neither surface has an
  authenticated admin gate, so neither has an admin arm. Both bind to a
  principal using the #1557/#3356 `memory_inbox` ladder: the enforced
  `AI_MEMORY_AGENT_ID` caller when configured (a present-but-unusable value
  refuses), otherwise the SAME process-derived identity the write path
  stamps (`ai:<client>@<host>` / `host:<host>`, pid-free and durable since
  #1720 B1). `[mcp] single_tenant_trust_all` is deliberately NOT honoured
  here — it is an inbox-specific legacy opt-in, and admitting it would
  restore the global sweep this closes.

No new MCP tool, HTTP route, CLI verb, schema rung, tool description or input
schema — the wire shape of the report is unchanged; only WHICH rows it
aggregates changes. Regression coverage: `tests/calibrate_confidence_caller_gate_3507.rs`
(SQLite: scoped vs foreign vs admin group sets and counts, orphan exclusion,
substrate exclusion, read-only proof, the fail-closed constructor, the MCP
envelope) and `tests/calibrate_confidence_caller_gate_3507_pg.rs` (Postgres:
the SAL method and the live HTTP route on a postgres-backed daemon).
