**Self-hosted runners no longer accumulate test executables; one debuginfo level per fleet `target/` (#6118).**
One full `cargo test` build linked ~1000 test executables (~170 MB each at
`line-tables-only`) into each self-hosted runner's persistent `target/debug/deps`
and no step removed them: two linux-fed runners each held 164 GB and took the
f2 root filesystem from 224 GB to 78 GB free in two hours. Every self-hosted
cargo job (`ci.yml` `check`, `cert-postgres-age.yml`, `postgres-ignored.yml`,
`session-boot-lifetime.yml`) now ends with `Prune runner target dir (#6118)`
under `if: always()`, running the new `scripts/ci/prune-runner-target.py`
(Python 3.9+, stdlib): it deletes the test/example executables, their `.d` /
`.dSYM` companions and `incremental/`, keeps the rlib / rmeta / proc-macro,
`build/` and `.fingerprint/` warm cache, fails closed on anything that is not a
cargo target dir, never follows a symlink, and prints `freed_bytes=<n>`
(`--dry-run`, `--scope all` for the disk-emergency wipe). The same four jobs
declare `CARGO_PROFILE_DEV_DEBUG` and `CARGO_PROFILE_TEST_DEBUG` = `"0"`: the
level is part of cargo's artifact hash, so the linux-fed runners kept two
complete artifact trees (`check` at `line-tables-only`, the two Postgres jobs at
`"0"`), and `line-tables-only` was already in force when the 164 GB was
written. The macos-fed leg of `session-boot-lifetime.yml` took its level from
the runner's `.env` (`line-tables-only`); the workflow `env:` now overrides
any runner-side value. Measured on Linux x86_64 (packed debuginfo): an
integration test binary is 484 MB at cargo's default, 130 MB at
`line-tables-only` and 11.6 MB at `0` (11x). On macOS (unpacked debuginfo) the
binaries shrink only 1.11x, but `debug/deps` falls from 3.7 GB to 2.0 GB
because ~1.1 GiB of loose `.o` debuginfo is no longer written. Pinned by
`scripts/test/test_ci_runner_target_hygiene_6118.py` (Section G of
`scripts/test/test-ci-workflow-invariants.sh`); runbook §3.3 of
`docs/DEV-CI-ENVIRONMENT.md`.

Round 2 (review fold-in). The workflow guard reads every `runs-on` form a job
here can use (inline label, flow list, block sequence, `matrix.<key>` and
`fromJSON(matrix.<key>)` resolved against every matrix value) and fails on any
other form. It censuses every job that can land on a self-hosted runner,
whether or not it calls cargo directly. It flags any step `env:`, `run:`
assignment, `$GITHUB_ENV` write or rustc `debuginfo=` flag that sets a level
other than `0`. The prune step runs only after a successful checkout
(`steps.checkout.outcome == 'success'`). The prune script validates
`--profile` first. It treats a missing target dir as nothing to prune (exit 0)
and refuses a symlinked target or profile dir, a dir outside
`GITHUB_WORKSPACE` that is not `CARGO_TARGET_DIR`, and a `CACHEDIR.TAG` without
the cachedir signature. It deletes through `O_NOFOLLOW` directory fds held from
scan to delete. It skips entries that vanish, and turns any other removal
error into a `::warning::` and exit 1 after the totals. It counts a hard-linked
file's bytes only when all of its links are removed.

Round 3 (review fold-in). The guard also flags a debuginfo level set through
`cargo --config profile.<p>.debug=...` or a rustc `-g` in any `RUSTFLAGS`
spelling, and treats `ubuntu-slim` as GitHub-hosted. A scan-phase read error
(an unreadable dir, an entry whose `lstat` fails) is now a `::warning::` with
the run continuing, the totals printed and exit 1, not a traceback; an entry
that vanishes is skipped. Every name printed in a workflow-command or listing
line is escaped (`%`, CR, LF), so a file name cannot inject a workflow command.
An empty `--target-dir` is refused (exit 2). `CACHEDIR.TAG` is opened
non-blocking and must be a regular file by `fstat`, so a FIFO cannot stall the
step. Examples are pruned: cargo hard-links `examples/<name>-<hash>` as
`examples/<name>`, which the hard-link rule used to keep, so the pair is now
deleted together and counted once (the `deps` <-> `debug/<bin>` uplift is
still kept). A target dir outside `GITHUB_WORKSPACE` needs the explicit
`--allow-outside-workspace` flag, which no workflow passes. The run ends with a
`::notice::prune-runner-target freed_bytes=<n> deleted=<k> mode=<...>` line.
The runbook adds: never symlink a runner's `target`, and the one-time
`--scope all` prune per fleet runner.

Round 4 (review fold-in). The prune script now also escapes `#` (`%23`) in
every printed name, because the runner parses the legacy `##[command]` form
anywhere in a line, and writes a non-UTF-8 byte as `\xNN`, with stdout and
stderr set to `backslashreplace`, so a name can no longer forge a command or
crash the run before its totals. A scandir failure inside a removal is a
warning, and a tree nested more than 100 levels is warned about and left in
place. The bin's uplift source `deps/<bin>-<hash>` is now identified by name
and size against `<profile>/<bin>`, not by link count: on macOS cargo copies
(an APFS clone, nlink 1), so the old rule pruned it on every job and forced a
relink of the bin (`cargo build -v` printed "Dirty"; it now prints "Fresh").
`freed_bytes` is exact on Linux and an upper bound on macOS, where each clone
counts at full size. A dashed example (`my-demo` and `my_demo-<hash>`) is now
paired. Each `kept` line names its real reason. The R-DEBUG guard also flags an
inline `profile.<p>={debug=..}` table, a `rustflags` value in any case or
written to a config file or a `$GITHUB_ENV` heredoc, YAML-escaped separators,
`cargo --config <file>` and a custom `cargo --profile`, and no longer flags
`git log -g`, prose that mentions `-g`, or `debug=false` / `"none"`.

Round 5 (review fold-in). The prune script escapes every control character
other than CR and LF, DEL and the C1 range as `\xNN` (#6254), so an ESC or BEL
in a file name cannot reach the log raw. The summary's category rows count only
successful deletions and failures get `failed <category>` rows (#6258). On
macOS the `.dSYM` symlink that cargo writes next to an example is pruned with
it instead of dangling (#6257). A same-size file in `deps/` is named as the
bin's uplift source only when its bytes match too. The R-DEBUG guard decodes
bash `$'..'` strings (`\x1f`, `\037`, `\n`) before matching (#6256) and reads
cargo TOML by section in `Cargo.toml`, `.cargo/config.toml` and any config a
step writes: a `[profile.dev|test.package.<spec>]` or `build-override` `debug`
above 0 beats the env pin, and a multi-line `rustflags` array is joined (#6255).

Round 6 (review fold-in). A completed prune now exits 0 even when it could not
read or remove an entry: each is a `::warning::` line, the totals and a summary
follow, and the `::notice::` line carries `warnings=<n>` (#6300, decided by
5-agent vote 4d3ea1c5: the step runs under `if: always()` and must not turn a
finished prune into a red job; refusals keep exit 2). This supersedes the exit 1
of rounds 2 and 3. Printed names escape a backslash first so the escaping is
injective, and escape U+2028 / U+2029, bidi, zero-width, private-use and
unassigned code points as `\u{hex}` (#6299, #6313). A same-size file whose
bytes cannot be read is kept and reported as "content unreadable, not
verified", never as a content match (#6301, #6314); this narrows the round-4
and round-5 statements that the uplift source is identified "by name, size and
content": it is by name and size, confirmed by content where readable. The
R-DEBUG guard now reads a run body as shell (quote concatenation, `$".."`,
`+=`, line continuation, command substitution, `printf -v`, `read`,
`NAME<<DELIM` blocks and here-document bodies), flags `CARGO_HOME`, `RUSTC*`
and `build.rustc*` overrides, reads multi-line TOML strings, `\u` key escapes,
inline-table profile overrides, nested `.cargo/config` files, step `with:`
inputs and `working-directory`, and fails on any `uses:` outside an allowlist
(#6295 #6296 #6297 #6298 #6311 #6312). It no longer flags the inert `[env]`
RUSTFLAGS table or commented-out lines (#6316). The round-5 claim that the
guard covers every spelling of #6255 is narrowed accordingly: the guard is a
text-level regression test, not a proof of cargo's effective configuration.
