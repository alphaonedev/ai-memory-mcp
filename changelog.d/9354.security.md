### Security

- **[auth] A blank configured shared API key never authenticates**
  ([#9354](https://github.com/alphaonedev/ai-memory-mcp/issues/9354)). An `ApiKeyState` built without the boot
  normalizer (library `build_router`, `build_router_with_timeout`, `daemon_runtime::build_router`, the
  `serve_http_with_shutdown*` harnesses, the middleware used directly) with an empty or whitespace `key` used to admit
  any request whose `X-API-Key` was empty or the same whitespace, and the monitoring `/status` access gate compared the
  raw key the same way. The configured key is now read through a `ConfiguredKey` type with a private field and a
  fallible constructor that refuses a key that is blank after `trim`; both compare sites use it. A blank configured key
  is refused closed in every identity mode with the existing 401 `missing or invalid API key` (it is not treated as
  "no key configured"); enrolled per-agent keys still authenticate. The boot path keeps its #1903 behaviour (a blank
  key is no key; a non-loopback bind without a key refuses to start) and now says so at boot with one WARN naming the
  remedy (set a non-blank top-level `api_key`, or remove the blank value); health and monitoring probes answer as on a
  daemon with no key. `ApiKeyState.key` stays `Option<String>`.
