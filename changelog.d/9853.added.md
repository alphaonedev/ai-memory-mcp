**CI: a reviewed installer for a system-domain launchd daemon of the macOS PostgreSQL test tier (#9853).**
The macOS native tier was supervised by a launchd agent of the GUI login domain and stopped with the login session,
so every macOS enterprise-fed leg failed or hung until it was restarted by hand. `scripts/ci/tier_daemon_installer.py`
prepares the lasting fix, a daemon in the system domain that runs `postgres` as a named non-root account. It does a dry
run by default, which changes nothing: it prints the plist, the account, the install commands, the hand-over order and
the removal commands. `--install` and `--remove` refuse unless the effective uid is 0 and print the `sudo` command to
run; the tool never calls sudo and never signals a process. `--install` refuses a plist target with different bytes,
is a no-op when identical bytes are loaded, refuses while a postmaster holds the data directory unless `--handover` is
given, writes the plist without clobbering, then bootstraps and probes the port. `--remove` is its inverse and refuses a
plist it would not have written. Installing it is the operator's decision (`docs/DEV-CI-ENVIRONMENT.md`, "macOS tier
supervision"). Tests: `scripts/ci/tests/test_tier_daemon_installer_9853.py`.
