**The doc symbol-anchor gate now sees bare `src/<path>.rs:<line>` anchors.** `scripts/check-doc-symbol-anchors.sh` only matched line anchors with a leading backtick, so a bare anchor in prose, a markdown link label or HTML text was never checked and a stale one passed (three were live until #4550). A new `BARE_LN` rule makes every bare line anchor in a scanned doc a failing finding, except the label of a commit-pinned `https://github.com/<owner>/<repo>/blob/<40-hex sha>/` permalink whose path and `#L` line (or range) equal the label's, which is immutable (the 76 such labels in `docs/ROADMAP-v1.1.0-ADDENDUM.md` pass). The `--self-test` plants plain-prose, link-label, HTML, `./`- and `../`-prefixed, `_`-emphasised, branch-pinned, abbreviated-sha, hex-named-branch and mismatched-label anchors (all must fail) and a pinned-permalink control (must pass). No scanned doc needed re-anchoring after #4550 (#4651).
