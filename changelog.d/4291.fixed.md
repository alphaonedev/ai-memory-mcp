**The batman-active compose init now rewrites only the top-level `api_key` (#4291).** The #3838/#4213 rotation step took the first `api_key =` line anywhere in `config.toml` as the stored key, and removed every such line on each `up`. That deleted an `api_key` inside a TOML table (`[llm]`, `[embeddings]` or any other). For `[llm]`/`[embeddings]` this silently turned the boot refusal an inline key causes into a boot. It also edited lines inside multi-line strings, and printed "API key rotated" when the only key was table-scoped. The rewrite now lives in `scripts/docker/set-api-key.sh` (shell builtins only; the key comes from the environment, never argv). It touches only the TOP-LEVEL key: lines before the first real table header, outside multi-line strings and multi-line array values. It refuses (exit 64, file untouched) when that scope cannot be established, because a guess could leave two top-level keys (a boot refusal) or drop an operator line. It reports a rotation only when a top-level key existed and its VALUE changed: the same key in another valid spelling (other quotes, spacing, a trailing comment) is left untouched and not reported. The script also enforces the key rules itself (charset `[A-Za-z0-9._~+/=-]`, at least 32 characters; exit 64, file untouched), so it cannot write a key that breaks out of the TOML string. It also refuses (64) two or more top-level `api_key` lines (ambiguous), treats `"api_key"`/`'api_key'` as the top-level key (on a changed value the old line and any trailing comment on it are removed and the bare `api_key = "..."` is written as line 1, never duplicated; quoting is kept only when the value is unchanged), tracks `{`/`}` depth so an `api_key` inside a multi-line inline table is left alone, and exits 64 on an empty or whitespace key (#4307). Found by the SECPROG L8 retest of #3838.
