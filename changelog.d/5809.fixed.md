The CURRENT_SCHEMA_VERSION docs gate now bounds each schema-claim-history ledger entry to exactly one hit (#5809): one number on one line, however many views of the line see it. An entry that shields the same span on two lines, or twice on one line, fails and names every file:line; a hit that two entries shield fails and names both entry lines; an entry that shields nothing still fails as stale. The two byte-identical history spans in ROADMAP.md and docs/v1.0.0/release-notes.md are reworded once each and given their own ledger entries.

A ledger needle must also read as written (#5809): every character is printable ASCII or a non-ASCII letter, punctuation mark or symbol, so an entry whose needle carries a zero-width space, a no-break space, a combining mark, a byte-order mark or a control character is refused as malformed, naming the first such code point and its category, and the hits it would have shielded are reported as claims. Every ledger refusal spells such characters as a backslash-u code instead of echoing them. The ledger exempts hits of the CURRENT_SCHEMA_VERSION sweep only; the separate bold-form schema rule does not read it.
