### Fixed

- **[test-hygiene] `postgres_subscription_dispatch` no longer depends on
  a 30 s wall-clock sink window**
  ([#3589](https://github.com/alphaonedev/ai-memory-mcp/issues/3589)).
  Test-only wait. Production fire-and-forget dispatch is unchanged;
  `drain_dispatches` (the #3403 shared shutdown drain) still honours
  its timeout as a hang detector, now via the idle `Notify` rather
  than a 10 ms poll.

  The positive-path HMAC pin polled wiremock for 30 s after
  `dispatch_event_postgres` returned. Delivery is admitted on a
  `spawn_blocking` worker (`Handle::spawn` → reqwest blocking send +
  first-call TLS prewarm), so under full-suite load the POST landed
  after the window and the test panicked as a false "dispatch dropped"
  regression. `DispatchInFlightGuard` now notifies when the last
  admitted worker drops; the test awaits that idle signal
  (`wait_dispatch_idle`) and then asserts the HMAC header. A dropped
  dispatch never increments in-flight, so the wait returns immediately
  and the sink assertion still fails closed. The namespace-filter pin
  drops its 300 ms sleep for the same idle wait.
