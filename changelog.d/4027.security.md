Federation `/sync/push` on a PostgreSQL-backed receiver now refuses a signal carrying a present-but-invalid (forged) signature on its original wire bytes, before the receive-side secret screen runs. Previously the screen cleared the stale attestation when it redacted a signed field and the later store-side check only rejected a non-empty signature, so with `AI_MEMORY_FED_REQUIRE_SIGNAL_SIG=0` a forged signal could be stored as an accepted unsigned one. Both receive funnels now share one forged-signature predicate, so the "forged signatures are rejected unconditionally" guarantee holds on SQLite and PostgreSQL alike (#4027).
