### Security

- **[federation] Outbound namespace scope per peer, deny by default**
  ([#9996](https://github.com/alphaonedev/ai-memory-mcp/issues/9996)). The sender now admits each
  namespace per peer before any byte leaves it. `AI_MEMORY_FED_PEER_OUTBOUND_SCOPE` maps a peer URL
  to `{"allowed_namespaces": [...]}`, the same shape and the same glob matcher as the inbound peer
  scope; `**` is the explicit all-namespaces scope and is reported by a doctor posture row. A peer
  with no entry receives nothing: boot logs one WARN per unscoped peer and doctor shows a failing
  row per such peer. Every outbound path (store, store with embedding, delete, delete batch,
  archive, restore, link, consolidate, pending, pending decision, action transition, checkpoint
  resolution, signal, namespace standard set and clear, bulk catch-up, DLQ replay and `/sync/since`)
  filters by that scope; an id whose namespace cannot be resolved is not sent. The quorum counts
  only admitted peers and a shortfall fails with the typed reason `OutboundScope`. A scope refusal
  is permanent and queues nothing; a queued row outside the current scope is never sent and never
  deleted: it is quarantined with a typed reason and returned to the replay window at boot, so a
  widened scope delivers the writes made under deny. A 2xx reply whose body is not JSON is no
  longer counted as an ack; it is retried and bounded by `MAX_REPLAY_ATTEMPTS`. A per-peer,
  per-namespace filtered counter is visible in stats and doctor.
