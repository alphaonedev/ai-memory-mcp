**HTTP debug logs no longer record the request URL (#3649).**

With HTTP debug logging turned on (for example `RUST_LOG=tower_http=debug`), the daemon used to write the full request URL on every request, including the query string. A `GET /api/v1/recall?query=…` therefore copied the recall text into the log, and a credential passed in a query string would have been copied too. The per-request `request` span now records the method, the HTTP version and the matched route template (`/api/v1/memories/{id}`) instead. The URL, the query string, path values such as memory ids, and headers are never recorded. A request that matches no route is labelled `<unmatched>`.

**What changes for you:** a log pipeline that parsed the `uri` field of the `request` span will no longer find it; use the new `route` field. The filter directives that enabled the span before (`tower_http=debug`, `tower_http::trace=debug`, `tower_http::trace::make_span=debug`) still enable it. Normal INFO-level logging is unchanged.
