**MCP `initialize` negotiates `protocolVersion` (#6157).** The handshake used
to answer a hard-coded `2024-11-05` and never read the client's requested
revision. `src/mcp/jsonrpc.rs` now carries `SUPPORTED_PROTOCOL_REVISIONS`
(newest first, currently `["2024-11-05"]`) and `negotiate_protocol_revision`:
a supported `params.protocolVersion` is echoed back; an unsupported, missing
or non-string value is answered with the newest supported revision (the
spec's downgrade) and a stderr `MCP initialize downgrade` diagnostic. The
list stays truthful: `2025-03-26` is not listed because it makes JSON-RPC
batch receipt a MUST and the stdio loop answers a batch array with `-32700`.
`tests/mcp_protocol_revision_ssot_6157.rs` pins every `protocolVersion` use
in `tests/`, `src/`, `docs/` and `scripts/` to the supported list. No wire
shape change: the field already existed.
