TypeScript SDK: `DelegationBundle.load`'s Windows leg (no `O_NOFOLLOW` / `O_NONBLOCK` in `node:fs`) no longer checks the credential's mode and owner on the path and then reads the path again (CodeQL js/file-system-race, alert 355). It now opens once, `fstat`s that descriptor and reads from it, exactly as the POSIX leg does; the symlink refusal stays as a best-effort `lstat` pre-check, so the only residual on Windows is a link swapped in between that pre-check and the open, never a check-then-read on the path (#3812). The delegation-bundle loader is a POSIX surface: on Windows `node:fs` reports a regular file's mode as `0o100666` or `0o100444`, so the `mode & 0o077` check refuses every bundle (TypeScript), and Python's owner check calls `os.geteuid()`, which Windows does not have. Both fail closed; neither SDK loads a credential on Windows today (#6318).
