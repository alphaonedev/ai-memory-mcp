**Read-only and diagnostic commands no longer write the default config file at start (#9620).** `src/main.rs` called `AppConfig::write_default_if_missing()` for every subcommand, so `wake-hub --posture` (whose contract is "binds nothing and must change nothing"), `doctor`, `config check` and the `verify-*` verbs created `<config dir>/ai-memory/config.toml` on a host that had none, and the function checked `exists()` then `fs::write` (a truncating check-then-write race) and dropped both `io::Result`s. Now one allow-list classifier, `writes_default_config`, names the writing commands (`serve`, `mcp`, `sync-daemon`, `boot`, `install`, `wrap`, `store`, `capture-turn`, `import`, `restore`, `mine`); every other verb leaves the config file alone, including a verb added later. This covers the config file only; the other start-up writes are tracked as #9574 (key pair), #9663 (audit and forensic log directory) and #9776 (database file). The write has two outcomes: the complete default file exists at the path as a regular file, or the path is left exactly as it was and one error is reported. A regular file already there is kept byte for byte; a symbolic link (dangling or not), directory, FIFO, socket or device at the path is refused with `config path exists and is a <kind>, not a regular file; it was left unchanged` and is never followed or opened; a missing path is filled through a synced temp file in the same directory and published with a hard link that refuses an existing path, so a failed or concurrent write never leaves a partial config file, and the temp file is removed on every outcome. A refused or failed write prints `ai-memory: WARN could not write the default config <path>: <error>` while the command still runs. `ai-memory config check` with no `--file` on a host with no config file exits 0 with `OK: no config file at <path>; the daemon starts on compiled defaults (nothing to check)` (decision: exit 0 over exit 2 because #9620 asks only that read-only verbs write nothing, the base exited 0 there, and the daemon boots on compiled defaults when the file is missing); a missing `--file` path still exits 2. A mutating verb that is not listed (for example `update`, `delete`) no longer seeds a default config as a side effect; run any listed verb, or `ai-memory install`, to seed one.
