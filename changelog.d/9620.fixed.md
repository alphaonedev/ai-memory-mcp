**Read-only and diagnostic commands no longer write the default config at start (#9620).** `src/main.rs` called `AppConfig::write_default_if_missing()` for every subcommand, so `wake-hub --posture` (whose contract is "binds nothing and must change nothing"), `doctor`, `config check` and the `verify-*` verbs created `<config dir>/ai-memory/config.toml` on a host that had none, and the function checked `exists()` then `fs::write` (a truncating check-then-write race) and dropped both `io::Result`s. Now one allow-list classifier, `writes_default_config`, names the writing commands (`serve`, `mcp`, `sync-daemon`, `boot`, `install`, `wrap`, `store`, `capture-turn`, `import`, `restore`, `mine`); every other verb writes nothing, including a verb added later. `write_default_if_missing` returns `io::Result<()>` and creates the file with `create_new`, so an existing config is never truncated, and a refused write prints `ai-memory: WARN could not write the default config <path>: <error>` while the command still runs. A mutating verb that is not listed (for example `update`, `delete`) no longer seeds a default config as a side effect; run any listed verb, or `ai-memory install`, to seed one.
