### Fixed

- **[recall] malformed `since`/`until` and `subscription_replay.since`
  now refuse instead of silently mis-filtering, and valid bounds are
  canonicalized to the fixed-width UTC form before TEXT bind**
  ([#3366](https://github.com/alphaonedev/ai-memory-mcp/issues/3366)).
  `memory_recall` and CLI/HTTP search `since`/`until`, and `memory_subscription_replay`
  `since` were bound as TEXT against `created_at` / `delivered_at`
  without RFC3339 parsing, so `since:"garbage"` returned 0 rows,
  `until:"not-a-date"` returned all rows, and a unix-epoch digit string
  became an arbitrary cutoff (`valid_at` was already validated). All
  three surfaces (MCP, HTTP, CLI) now parse-or-refuse with the same
  RFC3339 error `valid_at` uses, then bind
  `canonicalize_valid_time` (micros + `Z`) so an offset such as
  `+05:00` selects the same rows as `+00:00` of the same instant.
  Tests: malformed → refused; ALLOWED-path recall with rows
  `2026-01-01Z` / `2026-05-05Z` returns only the newer for both
  `since=2026-03-01T00:00:00+00:00` and the same instant as `+05:00`.
  Direct subscription replay callers also reject malformed bounds before SQL.
  Stored caller-signed `created_at` values remain unchanged.
