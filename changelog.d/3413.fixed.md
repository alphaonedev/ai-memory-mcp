### Fixed

- **[cli] `list --since`/`--until` and `recover-previous-session --host`/`--transcript` now refuse bad input instead of succeeding with a silent empty result**
  ([#3413](https://github.com/alphaonedev/ai-memory-mcp/issues/3413)).
  `list` passed malformed RFC3339 bounds through to SQL (`strftime` matched
  nothing → empty list, exit 0) while `--valid-at` already refused; it now
  uses the same #3366 parse-or-refuse + canonicalize path `search` already
  had. `recover-previous-session` swallowed an unknown `--host` into `auto`
  and treated an unreadable explicit `--transcript` as a successful empty
  report (exit 0); both now error before recovery runs. The SessionStart
  miss (no `--transcript`, none located) still exits 0. Denied + allowed
  pins on sqlite; postgres `run_store` shares `build_opts`.
