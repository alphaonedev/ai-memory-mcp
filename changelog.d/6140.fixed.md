**Cert-expiry gate gains a trusted base-copy companion job (#6140).**
The required cert-expiry gate in `c8-precheck.yml` runs on `pull_request`, so it
executes the pull request's own copy of `scripts/check_cert_expiry.py` and of its
workflow job: a change that edits the federation wire and also edits the gate
could report green. A new `pull_request_target` workflow,
`.github/workflows/cert-expiry-trusted.yml`, checks out only the BASE commit
(`persist-credentials: false`, `contents: read`, no secrets), fetches the pull
request head and merge commit as git objects, and runs the base copy of the gate
with `python3 -I scripts/check_cert_expiry.py --trusted`. Trusted mode reads git
objects only (no checkout of the head), takes its range only from its arguments
(the process environment is not consulted), fails closed on a missing object,
wrong merge parentage or a symlinked cert doc, and prints `GUARD CHANGED` and
fails when the gate script, the trusted workflow, its canonical-form pin
(`scripts/check-claude-md-size.py`) or the `cert-expiry-gate` job block of
`c8-precheck.yml` changes without a `Rule-Change-Approved-By:` trailer (the
`claude-md-rule-compare` mechanism); a trailer never waives the section 7 verdict.
`scripts/check-claude-md-size.py` pins the new workflow's canonical form. The
cert doc is now read through a tree-entry check in every mode: a symlink or other
non-regular entry at its path is refused instead of being read as text. The
existing required job and its context name are unchanged; making the trusted job
a required context is a branch-protection change deferred until a scratch pull
request records a passing `pull_request_target` run. Round-2 hardening: the
trusted checkout is `github.sha` (the commit the workflow file itself comes
from) instead of the payload base sha, which can be older for an unsynced pull
request; an approved guard change is also raised as a `::warning` annotation;
any workflow file at the merge commit that can produce the required check name
outside the guarded `cert-expiry-gate` job fails closed as `GUARD SHADOW` and is
not waivable by a trailer (the duplicate-producer rule for
`check-required-contexts` is #6177); and self-test cells now pin the guarded
header keys of `c8-precheck.yml`, fail-closed git read errors and the blob size
cap. Refs #6137, #6138, #6177.
