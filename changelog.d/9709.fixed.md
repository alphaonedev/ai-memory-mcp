**A red CI test job names its cause in the step summary and as annotations (#9709).** The new step `Red cause summary (#9709)` (`scripts/ci/red_cause_summary.py`) runs after the test steps of the `check`, `sal-feature` and `vectorlite-feature` jobs of `ci.yml` and the `per-module-thresholds` job of `coverage.yml` when the job fails or is cancelled. It lists the failing test binaries, the failing tests (`failing tests: N` counts every name distinct in its binary and its first `NAME_KEY_BYTES` UTF-8 bytes) and the `test result: FAILED` lines. A binary section opens only on cargo's exact `Running` or `Doc-tests` line, and a test is named as failing only from its own section's `failures:` list or `FAILED` lines, committed by that section's `test result: FAILED` line, so captured test output cannot add, drop or double a name. When no test failed it names the last `error[`/`error:` line of the failing step as `last error line (a candidate cause)`, or prints `cause not identified` plus the failing step's name. Every shown value is cut on a character boundary with any token the cut went through dropped whole and counted (`shown values cut: N`), then passes the redaction of `scripts/cert_gate_evidence.py` unless it has the plain Rust path shape and no token shape; a test name dropped whole by that cut is shown as `<redacted>` and still counted. Markdown cells neutralise HTML, links, GFM autolinks and @mentions. Every input bound (line, file tail, files, directory walk, total bytes, summary bytes, annotations, redaction calls) is a named constant with an exact count line, and a log tail without a complete line is reported as not parsed. The step has `continue-on-error: true` and `timeout-minutes: 5`, reads no secret, makes no network call, and on `check` it skips fork pull requests like the other shared-target steps. The steps that feed it pipe their cargo output through `tee` under `shell: bash` and take the step status from cargo alone (`PIPESTATUS[0]`), with the log directory made best effort, so the capture can neither mask a red cargo command nor turn a green one red. No required-check name, test selection or product code changes.
