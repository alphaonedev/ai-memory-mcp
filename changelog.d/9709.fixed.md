**A red CI test job names its cause in the step summary and as annotations (#9709).** The new step `Red cause summary (#9709)` (`scripts/ci/red_cause_summary.py`) runs after the test steps of the `check`, `sal-feature` and `vectorlite-feature` jobs of `ci.yml` and the `per-module-thresholds` job of `coverage.yml` when the job fails or is cancelled. It lists the failing test binaries, the failing tests (`failing tests: N` counts every distinct name) and the `test result: FAILED` lines. When no test failed it names the first `error[`/`error:` line of the failing step (a Clippy or build error), or prints `cause not identified` plus the failing step's name. Every shown value passes the redaction of `scripts/cert_gate_evidence.py` unless it has the plain Rust path shape and no token shape. Markdown cells neutralise HTML, links, GFM autolinks and @mentions. Every input bound (line, file tail, files, directory walk, total bytes, summary bytes, annotations) is a named constant with an exact count line. The step has `continue-on-error: true` and `timeout-minutes: 5`, reads no secret, makes no network call, and on `check` it skips fork pull requests like the other shared-target steps. The steps that feed it pipe their cargo output through `tee` under `shell: bash` (errexit + pipefail), so the tee cannot mask a red cargo command. Residual: when the runner's temp disk is full, `tee` fails with ENOSPC and the step fails red with that write error instead of the cargo result; the job is still red and the error names the disk. No required-check name, test selection or product code changes.
