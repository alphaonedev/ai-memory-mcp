**A red CI test job names its cause in the step summary and as annotations (#9709).** The new step `Red cause summary (#9709)` (`scripts/ci/red_cause_summary.py`) runs after the test steps of the `check`, `sal-feature` and `vectorlite-feature` jobs of `ci.yml` and the `per-module-thresholds` job of `coverage.yml` when the job fails or is cancelled. It lists the failing test binaries, the failing tests (`failing tests: N` counts every distinct progress line of a failing section) and the `test result: FAILED` lines. A binary section opens only on cargo's exact `Running` or `Doc-tests` line. Each section is read in two states (#9831): before its first column-0 `failures:` line, failing names come only from the runner's `test <name> ... FAILED` progress lines; from that line to the end of the input nothing is read but `test result:` lines, a `FAILED` one kept over a later passing one, so captured test output cannot add a binary, a name, a section or a count. A section whose result is FAILED with no progress name, or whose kept result line is a passing one read after its `failures:` line, is one `failed, names not available` row (never green). When no test failed it names the last `error[`/`error:` line of the failing step as `last error line (a candidate cause)`, or prints `cause not identified` plus the failing step's name. Every shown value goes through one funnel (#9830), the only maker of the `Redacted` type that the cut and every writer require: a raw value over 400 bytes is the fixed marker `<line not shown: N bytes>`; any other value is redacted whole by `scripts/cert_gate_evidence.py`, then cut to 300 bytes on a character boundary with `...` and counted (`shown values cut: N`), so a cut never runs on unredacted text. A failed or spent redaction is a fixed marker, never the raw text. The shared redactor masks names of 32 or more characters (#9856), so such a name shows as `<redacted>` and is still counted. Markdown cells neutralise HTML, links, GFM autolinks and @mentions. Every input bound (line, file tail, files, directory walk, total bytes, summary bytes, annotations, redaction calls) is a named constant with an exact count line, and a log tail without a complete line is reported as not parsed. The step has `continue-on-error: true` and `timeout-minutes: 5`, reads no secret, makes no network call, and on `check` it skips fork pull requests like the other shared-target steps. The steps that feed it pipe their cargo output through `tee` under `shell: bash` and take the step status from cargo alone (`PIPESTATUS[0]`), with the log directory made best effort, so the capture can neither mask a red cargo command nor turn a green one red. No required-check name, test selection or product code changes.
