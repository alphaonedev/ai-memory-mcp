### Fixed

- **[data-integrity][fail-open] The mandated ≥2-non-Rust-reader conformance
  proof could silently never run** ([#2452](https://github.com/alphaonedev/ai-memory-mcp/issues/2452)).
  `tests/conformance_readers.rs` SKIPped-and-PASSed when `python3` / `node`
  were absent — libtest scores an early `return` as `ok`, and it *captures*
  the "loud" SKIP note, so the pass was also invisible. No workflow
  referenced the suite at all, so no environment anywhere was known to carry
  both interpreters. The ROADMAP Gate-1 freeze-critical item "≥2 independent
  non-Rust reference readers (§11.6, **not relaxed**)", marked DISCHARGED,
  therefore rested on two tests that could both no-op to green. Measured on
  the pre-fix harness with an interpreter-free `PATH`:
  `test result: ok. 2 passed`.
  - The harness is now **fail-CLOSED**: an absent or unusable interpreter is
    a test FAILURE carrying a stable `conformance proof UNPROVABLE (#2452)`
    token. A local developer without the non-Rust toolchains may set
    `AI_MEMORY_CONFORMANCE_ALLOW_SKIP=1`; the run is then reported
    **UNPROVEN** on the real process stderr (bypassing libtest capture),
    never as passed. That variable is HARD-BLOCKED from `.github/`.
  - A third test asserts the **count** (`≥2` readers actually verified).
    Previously, with `python3` present and `node` absent, the mandated two
    silently became one and CI stayed green.
  - New `scripts/check-conformance-readers.sh` is the authoritative CI proof
    (no cargo build required): it resolves an interpreter for every declared
    reader (**absent is a violation, never a skip**), runs both over the
    corpus, and asserts exit status, the absence of `FAIL` lines, an
    `N/N items passed` summary at or above a pinned floor cross-checked
    against the record files on disk, and a PASS verdict for each
    load-bearing vector **by name**. `--self-test` plants ten failures and
    proves each is rejected *for the stated reason* — including the
    MUST-REJECT tampered vector re-labelled VALID, which only a reader that
    genuinely checks Ed25519 can catch. `--r203 <ref>` reproduces the silent
    pass on any historical revision.
  - Wired into `.github/workflows/c8-precheck.yml` as
    **Non-Rust conformance-reader proof gate (#2452)**, with `python3` and
    `node` explicitly provisioned; `ci.yml`'s `Check` matrix provisions them
    too, so the fail-closed harness can never red for an image accident.
  - Honest scope, now measured rather than assumed: **two** readers
    structurally verify (restricted-CBOR decode, re-encode-and-compare,
    domain-tag/element pins, corpus-digest anchor), but only **one** (`node`,
    via WebCrypto) checks the Ed25519 signatures — the Python reader is
    stdlib-only by policy and labels its signature verdicts `PASS (partial)`.
    The gate pins that count so the shortfall against §11.6 cannot silently
    worsen.
