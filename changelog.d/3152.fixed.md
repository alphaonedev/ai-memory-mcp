**One commit per logical update (#3152).** An update that carries a content
patch AND a lifecycle transition now lands all-or-nothing on both backends.
Before this fix the patch committed first and the transition ran as a second,
separately committed statement. A crash, an illegal edge or any error between
the two persisted the patch, dropped the transition and returned an error.
The row was left in a silent mixed state.

- **SQLite.** New `storage::in_write_txn` runs a multi-statement write as one
  `BEGIN IMMEDIATE` transaction and joins a caller's open transaction instead
  of nesting. The SAL `update`, the MCP `memory_update` tool and the legacy
  HTTP `PUT /api/v1/memories/{id}` path now apply the patch and the transition
  inside it. `set_lifecycle_state` runs its read and write in the same
  transaction, so two racing transitions can no longer both validate from the
  same prior state. `update_with_expected_version` now uses the same
  combinator instead of a hand-rolled copy.
- **PostgreSQL.** The trait `update` and the If-Match
  `update_with_expected_version` apply the transition on their own update
  transaction, before its single COMMIT, through the new
  `apply_lifecycle_patch_in_tx`. It reads the state with `SELECT … FOR UPDATE`.
  The pool-based `apply_lifecycle_patch`, which ran after the commit, is gone.
  The If-Match path now returns the version the row actually carries, counting
  the transition's bump.
- **Behaviour change.** An illegal lifecycle edge now leaves the row fully
  unchanged: title, content, version and the `in_place_edit` snapshot all roll
  back. The HTTP response is still 409 and the MCP error text is unchanged.
  The storage-growth charge for the patch is refunded, because the bytes never
  landed. A legal edge is unchanged: the row still ends one version bump for
  the patch plus one for the transition.

Proof on both backends, in `src/store/update_atomicity_3152_tests.rs` and
`src/mcp/tools/update_3152_tests.rs`, plus an HTTP case in
`src/handlers/tests.rs`:

- **Refusal.** The patch rolls back, with no snapshot left and no version bump.
- **Visibility (sqlite).** At the test-only fault point between the patch and
  the transition, a second connection still reads the original row.
- **Crash.** The test binary is re-executed as a child that `abort()`s at that
  point (the #3550 pattern). The parent then reads the row directly from the
  store and finds it unchanged. This runs for the sqlite SAL, the pg trait
  `update` and the pg If-Match update.
