**wake-hub ops surface — metrics, health probe, bounded SIGTERM drain, supervisor units, `doctor` posture check** ([#3471](https://github.com/alphaonedev/ai-memory-mcp/issues/3471), EPIC [#3466](https://github.com/alphaonedev/ai-memory-mcp/issues/3466)).

- **Metrics.** `crate::wake_hub::metrics` now answers the four questions an
  operator actually pages on: connected agents and live recipients; per-recipient
  queue depth in BOTH bounds (bytes AND frames — different faults, different
  remedies); WHY a delivery was dropped (`recipient_queue_full` /
  `global_egress_full` / `channel_full` / `write_failed` / `offline_unknown`,
  replacing one undifferentiated `overflow` total); the slow-consumer signal that
  fires BEFORE the drop it predicts; and fan-out + mint-to-delivery latency as
  fixed-bucket, allocation-free histograms (`crate::wake_hub::histogram`) with
  p50/p99. Nothing here can grow: the queue census is COMPUTED from the routing
  table rather than retained, so a churn of agent ids cannot grow an
  observability structure. A bucketed quantile reports the containing bucket's
  UPPER bound (a conservative over-estimate — the hub can look slower than it is,
  never faster) and a quantile with no observations behind it is `null`, never
  `0`. `MetricsSnapshot::to_json` is the one stable wire shape every ops surface
  reads.
- **`ai-memory wake-hub --health [--json]`.** Probes the configured socket as an
  ORDINARY client — connect, read the hub's opening challenge, close — and exits
  `0` reachable / `2` unreachable, suitable for a systemd `ExecStartPost` or a
  launchd health check. Deliberately not a privileged side channel, not a bypass
  of the peer-credential gate, and not an authenticated session: it presents no
  identity and sends no frame, so it needs no credential and can enumerate
  nothing. Every inconclusive outcome is `unreachable` with a named cause and
  remedy; the whole probe is bounded by a 2 s budget so it cannot hang the
  supervisor it reports to. `--posture --json` gains the fd budget in force, the
  drain deadline, the slow-consumer watermark and the at-rest `metrics_schema`.
- **Bounded SIGTERM/SIGINT drain.** The hub stops accepting FIRST, asks every
  session to flush what it already holds (emitting nothing content-bearing — it
  holds no durable truth, so it owes a peer nothing at shutdown), waits at most
  `wake_hub::limits::DRAIN_DEADLINE_MS` (5 s, under both supervisors' default
  stop timeouts) and exits `0` regardless. It unlinks the socket only when the
  path still carries the `(device, inode)` this process created, so a slow
  predecessor can never delete a REPLACEMENT hub's socket and blackhole every
  agent on the host.
- **Supervisor units.** `packaging/systemd/ai-memory-wake-hub.service` (full
  hardening set, `RestrictAddressFamilies=AF_UNIX`, `ExecStartPost` running
  `--health`) and `scripts/templates/dev.alphaone.ai-memory.wake-hub.plist`. Both
  pin the file-descriptor budget to `wake_hub::limits::DESIRED_NOFILE` (4096) —
  macOS's default soft limit of 256 lands `EMFILE` at exactly the 256-agent
  design target. Start-up now separates the two ways a ceiling can be too small
  (fd budget vs configured `--max-connections`) so an operator is sent to fix the
  right thing, reports the desired-vs-granted limit, and still refuses to bind
  when the budget cannot cover `MIN_CONNECTION_CEILING + FD_HEADROOM`.
- **`ai-memory doctor` gains a `Wake hub (#3471)` section** (`src/cli/doctor_wake_hub.rs`):
  socket + directory mode and ownership (Critical when a LIVE socket is not
  owner-only), the fd budget (Warning below the desired value, Critical below the
  binding floor), and the installed supervisor unit (informational — an absent
  unit is a deployment choice, never a finding). Filesystem and `getrlimit` only;
  it never binds, connects or opens a store.
- **Socket-directory creation window closed** (from the #3467 review): the leaf
  directory is now created with `std::fs::DirBuilder::mode(0o700)`, so it never
  exists at umask mode between `mkdir` and a follow-up `chmod` — a window in
  which anything that could `open` the directory won a handle whose rights the
  later `chmod` could not take away. The mode is re-verified after creation, on a
  directory the process just made as much as on one it found.
