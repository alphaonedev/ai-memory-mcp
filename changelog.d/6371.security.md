**Webhook SSRF guards and the HTTP client now read the same host (#6371).**
Both webhook guards carved the host out of the raw URL by hand while the
dispatcher handed the string to reqwest, whose WHATWG parser ends the
authority at a backslash and normalizes legacy IPv4 spellings. A URL such as
`https://127.0.0.1\@8.8.8.8/hook` read as public to the guard and as
loopback to the client, so a tenant could reach loopback and link-local
metadata targets with the loopback opt-in off. Host, port and the DNS pin
now come from one `reqwest::Url` parse, and the dispatcher posts that parsed
URL, so what the guard clears is what the client connects to; a string the
client cannot parse is refused. This is the webhook-lane half of #4018.
