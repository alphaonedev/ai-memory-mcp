**Durable replaces sync their directory (#10214).** Every durable replace and
publish in `src/storage/snapshot_file.rs` (`write_replacing`, `publish_at`,
`vacuum_into_private`, `write_new_private_unique`) now runs stage, fsync the file,
rename, fsync the parent directory, so a crash after the rename can no longer
bring back the old file or none (for the row-attestation seal, a rolled-back
high-water mark). The keypair writers, the hub-cache snapshot and the audit
sequence high-water mark go through the same funnel. A failed directory fsync is
returned as a typed error naming the directory and the file; the complete new
file stays in place and is never removed.
