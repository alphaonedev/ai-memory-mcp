### Fixed

- **[security][fail-open] `memory_action_transition`'s lease binding was
  opt-in — omitting `claimed_by` bypassed the holder check and NULLed the
  recorded owner**
  ([#3360](https://github.com/alphaonedev/ai-memory-mcp/issues/3360)).
  The #3009/#3226 holder bind was correct but only ran inside an
  `if let Some(cb)` on every transition funnel. A second agent that simply did
  not send `claimed_by` therefore skipped the check entirely: it could drive
  another agent's *leased* action through any legal edge to `done`, and
  because `transition`'s statement is `SET claimed_by = ?`, the omitted field
  was written back as SQL `NULL` — erasing the live holder from the row while
  its lease was still valid.
  - `actions::authorize_claimed_by` now takes `Option<&str>` instead of
    `&str`. That is the control, not a patch: there is no longer a shape in
    which a funnel *can* skip the question, so a future funnel cannot
    reintroduce the gap. `None` + a live lease is REFUSED naming the blocking
    holder; `None` + no (or an expired) lease is the unchanged lease-free
    flow; `Some(cb)` keeps the existing shape-validate + holder-match.
  - All three funnels now read the lease unconditionally and defer to it: the
    MCP `memory_action_transition` handler, and both HTTP local-write lanes —
    sqlite (`local_transition_via_db`) and postgres
    (`local_transition_via_store`, SAL `lease_get`) — so the two backends
    cannot drift on ownership.
  - A dead holder still cannot wedge an action: the guard keys on a
    *non-expired* lease, and the background lease sweep reclaims an expired
    lease and requeues its action through its own internal path.
  - Regression pins for BOTH directions at the control, the MCP funnel and
    HTTP (sqlite + a live-postgres twin): DENIED — an unbound transition on a
    leased action is refused, the state and `claimed_by` survive untouched, a
    non-holder `claimed_by` is still refused; ALLOWED — the holder transitions
    its own action, and once the lease is released the unbound flow is
    byte-identical to before.
