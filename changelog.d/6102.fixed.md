**`config show --effective` no longer prints a credential held in a scheme-less `db` value (#6102, CWE-532).** A `db` setting now always renders through `url_display::db_path_display`: a value holding `://` through the store-URL allowlist, a value holding `@` or `=` (the single-slash `postgres:/svc:<pw>@host/db` typo, a libpq `host=db password=<pw>` DSN) as `<unparseable-store-url>`, and any other path as itself; previously a value with no `://` was printed exactly as written. Regression: `tests/config_show_scheme_less_db_6102.rs`.
