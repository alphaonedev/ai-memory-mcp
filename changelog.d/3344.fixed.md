Boot and the live embedding-backfill worker no longer re-scan and re-WARN the same permanently unembeddable rows (undecryptable envelopes, oversize content) on every pass. Those rows are remembered in an `embed_skip` table keyed by memory id and the agent's current encryption-key fingerprint; a restored or rotated key invalidates the skip so the row is retried (healing path). One INFO at boot names the remembered count. Stale-marker invalidation is amortised per store instance (not process-global): at most one full-table walk per 60 s, so a key rotation is honoured within that interval; two stores in one process do not share a timer. The rusqlite MCP backfill tick (`get_unembedded_ids_batch_after`) uses a caller-owned twin (`…_amortised`) so that lane is O(1) per tick as well; one-shot CLI callers keep the throwaway-amort free function.
