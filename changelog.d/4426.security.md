**Governance `network_request` rules reach NAT64 and IPv4-translated spellings of an IPv4 host (#4426).** The #4415 host canonicaliser unified only the IPv4-mapped form (`::ffff:a.b.c.d`), so an IPv4 `refuse` / `escalate` rule was skipped for the NAT64 well-known-prefix spelling `64:ff9b::a.b.c.d` (RFC 6052) and the IPv4-translated `::ffff:0:a.b.c.d` (RFC 2765) of the same destination. Both now canonicalise to the embedded IPv4 address on the rule and the request side. Forms whose embedded IPv4 is not the destination (6to4 `2002::/16`), whose layout is operator-chosen (local-use NAT64 `64:ff9b:1::/48`), or which collide with `::` / `::1` (the deprecated IPv4-compatible `::a.b.c.d`) are documented as distinct IPv6 hosts.
