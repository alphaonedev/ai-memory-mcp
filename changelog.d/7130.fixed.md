The Certified postgres+AGE cells no longer fail with XX000 `failed to re-find shared lock object` on the shared native tier (#7130). Root cause: Apache AGE 1.8.0 (apache/age#2580) runs its parse hook on the ROLLBACK of an aborted transaction and, after a shared-invalidation reset, reads `pg_extension` there; the ROLLBACK fails with `ResourceOwnerEnlarge called after release started` and leaks fast-path locks into the backend's PGPROC, so every later connection on that slot fails until the server restarts. The tier now runs AGE 1.8.0 with the upstream fix (apache/age 06ce678) and a new cert cell, `tests/age_rollback_lock_leak_7130.rs`, reproduces the race on every run and fails if the certified server's AGE build lacks the fix. Deployments on stock AGE 1.8.0 are exposed to the same leak; the install-path requirement is tracked separately.
