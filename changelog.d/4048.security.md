**Ollama model pulls go through the admitted inference client (#4048, #3822
residual).** Both model pulls (`ensure_model_async` for the chat model and
`ensure_embed_model_async` for the Nomic embedding model) built a FRESH
`reqwest::Client` for `POST /api/pull`, so the pull carried none of the
admission policy the client's other requests carry: under `internal-only` it
re-resolved the host itself and could connect to an address that was never
admitted (the DNS pin applied to `/api/tags` but not to the pull); under
`loopback-only` / `deny` it honoured a process-wide `HTTP_PROXY` and followed
a 307 off the admitted endpoint (the #4193 class). Both pulls now send
through `self.client` — the one pinned, posture-aware client — with a
per-request `PULL_TIMEOUT`, so there is one client and no second copy of the
policy to drift. Pinned by `tests/model_pull_egress_pin_4048.rs` (RED on the
pre-fix tree: a pull built outside the pin never reached the admitted
listener, an environment proxy received the pull under `loopback-only`, and a
307 was followed; each leg has an `allow` control) plus a structural leg that
refuses any bare `reqwest::Client::builder()` in the production half of
`src/llm.rs` outside the `#[cfg(test)]`-only constructor.
