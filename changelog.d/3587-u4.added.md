**`capture-turn` CLI twin + Claude Code `Stop` capture hook (#3587 U4).**
`ai-memory capture-turn` closes the last leg of the `memory_capture_turn`
three-surface gap: the MCP tool and the `POST /api/v1/capture_turn` HTTP
route already existed, and the CLI now drives the SAME
`handle_capture_turn` funnel, so the `--json` envelope is structurally
identical across surfaces. It accepts either a `memory_capture_turn` body
or a Claude Code `Stop` payload (`last_assistant_message` + `session_id`)
on stdin, and when no turn index is supplied it derives `MAX+1` for the
session INSIDE the existing `BEGIN IMMEDIATE` transaction
(`capture_turn_idempotent_auto`), so two concurrent `Stop` hooks on one
session cannot swallow each other. The second guard is a content check
against the session's LATEST captured turn only, compared both raw and in
the storage form the write funnel persists (`redact_memory_for_storage`
under `AI_MEMORY_SECRET_SCREEN_MODE=redact`), so a redacted turn still
dedups on host re-delivery while a legitimate `A,B,A` sequence stays three
memories. Stdin is hard-capped at 16 MiB (`INVALID_INPUT` over cap, before
the JSON parse). `--quiet` makes the verb exit 0 on
every path — the hook can never block the operator's turn.

`ai-memory install claude-code --hook capture --apply` writes one managed
`hooks.Stop` entry (`type:command`, `async:true`, no `matcher`, managed keys
`["hooks"]`) whose command is
`<binary> capture-turn --host-kind claude-code --quiet --agent-id <resolved>`.
Re-running is idempotent; the uninstall removes only the managed entry and
leaves operator-authored `Stop` hooks intact. Non-`claude-code` targets keep
the pinned refusal — Codex cannot install a turn-capture hook (its user
hooks are trust-gated), so the refusal names the documented transcript
source (`ai-memory watch --host codex`).
