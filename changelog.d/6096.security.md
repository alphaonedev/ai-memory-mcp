### Security

- **[logging] `store_url_display` redacts an ambiguous store-URL authority instead of rendering credential bytes as host / port / path**
  ([#6096](https://github.com/alphaonedev/ai-memory-mcp/issues/6096), umbrella
  [#6052](https://github.com/alphaonedev/ai-memory-mcp/issues/6052), CWE-532).
  A store DSN whose userinfo carried an unencoded `/`, `?` or `#` made the
  WHATWG parser end the authority inside the credential, so the remainder was
  read as host, port or path and the allowlist renderer printed it on the boot
  `info!` line, `doctor`, `schema-init` / `migrate` output and refusals. Such a
  URL now renders `scheme://<redacted-authority>` (no host, port or database);
  detection is first-party (an `@` past the parsed authority end) and errs on
  the side of redaction. Well-formed shapes, including percent-encoded
  userinfo, render exactly as before. Regression tests:
  `url_display::tests::store_url_redacts_an_ambiguous_authority_6096` and
  `tests/store_url_ambiguous_userinfo_6096.rs`.
