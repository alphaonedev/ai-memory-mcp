### Security

- **[logging] An ambiguous store-URL authority is redacted and refused instead of being reinterpreted as host / port / path**
  ([#6096](https://github.com/alphaonedev/ai-memory-mcp/issues/6096), umbrella
  [#6052](https://github.com/alphaonedev/ai-memory-mcp/issues/6052), CWE-532).
  A store DSN whose userinfo carried an unencoded `/`, `?` or `#` (or `\` on
  `http` / `https`) made the WHATWG parser end the authority inside the
  credential, so the remainder was read as host, port or path and
  `store_url_display` printed it on the boot `info!` line, `doctor`,
  `schema-init` / `migrate` output and refusals. One shared predicate,
  `url_display::store_url_is_ambiguous`, decides from the PARSED URL (an `@`
  in the parsed path, query or fragment), so inputs the parser normalises
  (tab / LF / CR inside the separator, a single slash, a missing `//`, a
  case-variant scheme) are covered. It is deliberately conservative: a literal
  `@` in a query value also redacts. `store_url_display` renders such a URL as
  `scheme://<redacted-authority>`, and the transit floor (`dsn_transport`)
  refuses it as `Unparseable` before any connection or DNS lookup, the same
  fail-closed precedent as its existing unparseable-DSN refusal
  (#3866 / #4434). Well-formed shapes, including percent-encoded userinfo,
  render exactly as before.
  Also in this change: `unparseable()` echoes a scheme token only when it is a
  valid RFC 3986 scheme of bounded length, otherwise `<unparseable-store-url>`
  ([#6100](https://github.com/alphaonedev/ai-memory-mcp/issues/6100), a libpq
  key/value DSN could print its password as the "scheme"); and
  `config show --effective` compares the store scheme case-insensitively so
  `POSTGRES://` reaches `store_url_display`
  ([#6102](https://github.com/alphaonedev/ai-memory-mcp/issues/6102)).
  Not covered here: `url_origin` / `url_origin_and_path`
  ([#6101](https://github.com/alphaonedev/ai-memory-mcp/issues/6101)) and the
  scheme-less `db` value of #6102. Regression tests:
  `url_display::tests::*_6096`, `*_6100`, and
  `tests/store_url_ambiguous_userinfo_6096.rs`. The `migrate --from`
  unrecognised-scheme refusal now renders through the same allowlist
  (r2 security N1).
