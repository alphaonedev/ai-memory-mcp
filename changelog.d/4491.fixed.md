**A write of the process-global `PermissionsMode` without a live `lock_permissions_mode_for_test` guard is now a CI failure (#4491, #4763-#4767).** The discipline was convention only and recurred three times (#1465, #2165, #4468: the `store::postgres::tests::live_governance_*` cells flaked on every `--test-threads=4` governance run). `scripts/check_permissions_mode_lock.py` scans `src/**` function by function: every call of `set_active_permissions_mode`, `override_active_permissions_mode_for_test` or `clear_permissions_mode_override_for_test` is refused unless it is `main` in `src/main.rs` (the boot setter) or the `config.rs` alias, or the enclosing fn holds a LIVE guard at that call: bound by `let <ident>` in a block that encloses the write, not mentioned again before it (a rebind, drop, move or reassignment ends its cover); a write inside a `spawn`/`spawn_blocking`/`spawn_local` argument is covered only by a guard acquired or moved into that closure. The slot static `ACTIVE_PERMISSIONS_MODE` is modelled too (#4763) and the allowlist is the exact repo-relative top-level `fn main` of `src/main.rs` plus the `config.rs` setter bodies (#4764); `#[cfg_attr(.., test)]` counts as a test attribute. A delegate (`rules_scope`, `pin_governance_enforce_for_test`, ...) counts only when its tail and every `return` yield the guard (or a type owning it); a `Drop` reset is accepted only for a type a delegate returns. A `#[test]` fn on a line the #3623 boundary mis-classes as production, a `cfg(any(test, ..))` item, and a test module in an out-of-line file are all checked (the boundary is a secondary `--parity` check plus a visible note, `src/bench.rs` being #4755). Writer aliasing (`use .. as`, fn pointers) is refused; an unreadable or non-UTF-8 file exits 2. It has a 92-case `--self-test` and a `--mutation-sweep` proving each of its 27 checks is load-bearing, runs as the `permissions-mode-lock-gate` job in `c8-precheck.yml`, and is red on the four `live_governance_*` cells with the #4468 fix reverted. `tests/` is tracked separately as #4754.
