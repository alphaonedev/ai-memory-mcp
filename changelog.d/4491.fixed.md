**A write of the process-global `PermissionsMode` without holding its lock no longer compiles (#4491).** The discipline was convention only and recurred three times (#1465, #2165, #4468: the `store::postgres::tests::live_governance_*` cells flaked on every `--test-threads=4` governance run). Per the 5-agent vote (4d3ea1c5, option B), every writer (`set_active_permissions_mode`, `override_active_permissions_mode_for_test`, `clear_permissions_mode_override_for_test`) now takes a `&PermissionsModeGuard`. The guard's only field is private and its only constructor is `lock_permissions_mode_for_test`, so a write without the guard (E0061), a forged guard built from another mutex (E0451), a write after the guard is dropped (E0505) and a guard moved into another thread (E0277) are compile errors, each pinned by a `compile_fail` doctest. A second lock call on a thread that already holds the guard panics with a clear message instead of deadlocking. Production boot installs the resolved mode through `install_boot_permissions_mode`, which takes the lock itself and is called only from `src/main.rs`. Every call site in `src/` and `tests/` was migrated; integration tests that wrote the mode without the lock now take it, which serialises them without changing what they assert. `scripts/check_permissions_mode_lock.py` (2079 lines down to about 780) now pins only what the compiler cannot see: the slot is written only in `src/config.rs`, there is one lock, the boot entry is called only from `src/main.rs`, the guard stays private (no forging literal, no impl other than `Drop`, no alias), no `unsafe` names the guard or appears inside a writer's arguments, there is no token pasting, and the `compile_fail` doctests stay present. It keeps the compiled-set scan and the exit-2 fail-closed paths, and has a 37-case `--self-test` and a `--mutation-sweep` proving each of its 17 checks is load-bearing. The lexical lock-holding analysis and its `--parity` mode are retired; the defect classes they chased (#4754, #4764-#4767, #4775-#4777, #4811) are closed by construction. Forging the guard with `unsafe` through type inference remains a residual, tracked separately.
