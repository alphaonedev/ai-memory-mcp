**A store DSN given as the database path is refused on every channel instead of becoming a SQLite file named after the credential (#6699, CWE-312).** #3142 refused a `://` value on `--db` and `AI_MEMORY_DB` only, so a config `db` URL, and a libpq key/value DSN (`host=db password=<pw> dbname=mem`) on any channel, created and ran on a SQLite file named after it. One predicate (`url_display::db_value_is_dsn_shaped`) now refuses a URL or a key/value DSN on `--db`, `AI_MEMORY_DB` and config `db` before any store is opened; a bare `@` or `=` in a real path (`/home/user@corp/ai-memory.db`, `/data/run=3/x.db`) is still accepted. The refusal names only the redacted value; when a file already exists under the DSN-shaped name it says so and how to rename it, and deletes nothing. `ai-memory config` (which never opens the store) still runs so a config `db` can be repaired.
