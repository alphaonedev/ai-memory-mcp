**CI: self-heal the AGE extension on the macos-fed runner (#6161).** A Homebrew
upgrade relinks the `postgresql@18` trees and drops the hand-built Apache AGE
files, failing `Configure enterprise-fed tier` with `extension "age" is not
available`. New `scripts/ci/ensure-age-extension.py` runs before `CREATE EXTENSION`
(macos-fed only). It treats AGE as present only when `pg_available_extensions`
lists it AND the five AGE files (`age.dylib`, `age.control`, three SQL scripts)
are installed with their pinned sha256. Otherwise it restores exactly those five
files from a node-local, brew-independent directory after rejecting symlinks,
foreign-owned or group/world-writable sources and hash mismatches. Writes are
atomic per process (safe for concurrent runners, lib before share; a failed run
leaves only complete, pinned files), the tier password reaches psql through `PGPASSWORD` rather than
argv (a URL with a TAB, line break or NUL, a `#`, more than one `@` in the host
part or an `@` after it, a query segment without exactly one `=`, an empty host part,
or any query key outside a case-sensitive allowlist of non-secret libpq
parameters, such as `sslpassword`, is refused without printing the value; only known libpq keywords are named, and the query is percent-decoded only, so `+` stays literal and kept segments are passed on as written, #6221), and every failure is one `ensure-age-extension:` stderr line with a
non-zero exit. Pinned by `scripts/test/test_ensure_age_extension_6161.py`.
