`tools/list` compacted descriptions keep the verb-noun gist, and closed
MCP params advertise their legal values as inline JSON-Schema `enum`
lists (#3378).

Unit 1: `compact_description` still prefers a 32-byte first-sentence /
word-boundary cut, but a cut that would end on a dangling `+`,
preposition, article, or conjunction is extended up to 80 bytes (first
sentence when it fits) so labels such as `Report per-agent +` and
`Skill body +` no longer ship. Budget-by-tool: only the dangling tools
spend the extra bytes; a clean first sentence (e.g. `Calibrate
confidence baselines`) is unchanged.

Unit 2: a word-walk can still stop on list punctuation — `memory_forget`
shipped `"Bulk delete memories matching a pattern,"`. Trailing `,` / `:`
are now stripped from the final compact. Closed fields
`to` / `edge_type` / `signal_type` / `condition_type` / `state` carry
inline `enum` arrays from the domain SSOT (`ActionState::ALL`,
`EdgeType::ALL`, `SignalType::ALL`, `ConditionType::{CALLER_MINTABLE,ALL}`,
`CheckpointState::{RESOLUTION,ALL}`, `RoutineState::ALL`). Request
structs stay `String` (handler `from_str` unchanged).
`memory_swarm_rewind.to` stays a free string (it is a SHA).
`memory_checkpoint_create.condition_type` advertises the caller-mintable
subset only (reserved substrate anchors omitted). Pinned by
`tests/mcp_compact_description_3378.rs` and `tests/mcp_enum_lists_3378.rs`.
Per-description capabilities pointers are a later unit of the same issue.
