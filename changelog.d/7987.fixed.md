**The corpus ratchet baseline can no longer be moved, hidden or skipped (#7987).** The base manifest was
looked up at the path of the tree under review, any `git show` error counted as "no manifest", and the
CI discover job (fetch-depth 2) never had a base ref, so the ratchet silently fell back to the in-tree
comparison that one identical edit to both files defeats. The base manifest is now read at a canonical
path constant from the merge-base tree; a git error, or a base that holds the harness but not the
manifest, fails closed with a message naming the path; with no base ref the ratchet is refused unless
`CERT_MANIFEST_ALLOW_INTREE=1` is set, and then prints a loud WEAKER note. `ci.yml` fetches the base
branch before the discover step. Proof: `test_base_anchor_refuses_both_file_edits` runs the relocated
manifest case and both-file flip and delete edits in a repo with a base ref and a repo without one.
