**`export --full`, `import` and `migrate` carry every durable state class and never replace another owner's row (#8908, #8911, #8888, #8932, #8968).** `export --full` now carries checkpoints, routines, routine runs, entity aliases, offloaded blobs and expired rows that GC has not swept yet, as additive arrays under `spec_version` `"2"` (3-agent vote (71472661)). Every class is screened like the existing ones, and a withheld row is recorded in the withhold ledger. A new `class_counts` map always names the rows each array class carries. Import refuses the whole bundle, with zero rows applied, when a count disagrees with its array, when the map names an unknown class, or when the map is absent while a new array is present. An unknown top-level field is refused by name as a bundle from a newer build. Bundles without the new arrays still import. An offloaded blob is checked against its size bound, content hash and ref id before it is written. `migrate` copies expired-but-unswept rows and the `archived_memories` table, and reports the new archive phase as `archived_read` and `archived_written`. A row whose id or `(title, namespace)` slot is held by another owner's row is kept, counted in `cross_owner_kept` and logged with a WARN, never merged. This applies on `migrate`, HTTP `POST /api/v1/import`, CLI `import --on-conflict merge` and the v2 envelope import. `docs/spec/PORTABILITY-V2.md` (V2-2.7, V2-4, V2-7), the conformance corpus and both non-Rust readers carry the `class_counts` rule.
