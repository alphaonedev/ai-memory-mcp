Check `memory_archive_purge`'s `as_admin` escalation against the operator's
admin allowlist. `as_admin: true` switches an owner-scoped purge into an
every-owner wipe of the archive — the one operation in the substrate with no
recovery path — and on the MCP surface it was honoured on the caller's say-so,
because MCP stdio has no `AppState` to read `[admin].agent_ids` from. A
non-admin could pass the flag and get `owner_scope: "admin"` back with every
tenant's archived rows destroyed. The allowlist is now resolved once at MCP
boot from the same `[admin].agent_ids` / `AI_MEMORY_ADMIN_AGENT_IDS` ladder the
HTTP daemon uses, and the escalation requires the resolved caller (never a
wire-asserted `agent_id`) to appear in it, matching verbatim exactly as the
HTTP twin does. Default-closed: with no allowlist configured no caller is an
admin, so a deployment that never opted anyone in cannot be cross-tenant wiped.
The refusal is chained into the forensic trail against the resolved caller.

`memory_gc` had the mirror-image gap: it sweeps every namespace and every
owner, and with `archive_on_gc` off that sweep is a permanent hard delete plus
crypto-erase, yet it carried no owner dimension at all while its purge sibling
was owner-scoped. Under the multi-tenant posture (`AI_MEMORY_AGENT_ID` set) a
real sweep now requires the same admin allowlist. It REFUSES rather than
narrowing the sweep to the caller's own rows, and that is the deliberate
choice: the eviction chokepoint archives and deletes through several
statements that must address one identical id set, so an ownership predicate
that drifted between the archive insert and the delete would archive one set
and destroy another. Refusing a convenience verb degrades function; a drifted
predicate corrupts data — degrade, never corrupt. A non-admin keeps every
owner-scoped collection verb (`memory_forget`, `memory_archive_purge`) and the
ungated `dry_run` preview, and automatic TTL collection is unaffected — the
daemon's gc loop calls the substrate directly. The single-operator default
(`AI_MEMORY_AGENT_ID` unset) is unchanged on both verbs.
