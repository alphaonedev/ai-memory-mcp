### Security

- **[skills] Skills are verified on every read through one funnel**
  ([#8834](https://github.com/alphaonedev/ai-memory-mcp/issues/8834)). The read paths
  (`memory_skill_get`, `memory_skill_list`, `memory_skill_resource`, `memory_skill_export`,
  `memory_skill_compositional_context`, the CLI twins and the HTTP routes) now load a skill through
  one verified reader that re-derives every resource digest and the skill digest and checks the
  stored signature. A row that names a signer without a signature is refused, a signer is stored
  only when the register call signs, and `signing_agent` is returned only for a signature that
  verified. `memory_skill_list` omits a row that fails verification (with a warning) and refuses the
  call when the store fails instead of answering an empty list; it filters in SQL and returns at most
  `SKILL_LIST_PAGE_LIMIT` (1000) rows with `truncated: true`. The four HTTP read routes (get,
  resource, export, compose) render one closed vocabulary: `404`, `400` with the skill-level text
  (never a stored resource path) and the sanitized `500`. Binding the signed state into the digest,
  so an unsigned row cannot be presented as never signed, is tracked in
  [#9197](https://github.com/alphaonedev/ai-memory-mcp/issues/9197).
