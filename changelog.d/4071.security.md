`GET /api/v1/inbox/stream` frames no longer carry the process-wide wake sequence. Every inbox wake draws its `seq` from one counter shared by all recipients, so the gap between two of a subscriber's own frames equalled the number of wakes published for OTHER agents in between: a cross-tenant notify-rate side channel the stream's own `lagged` handling already refused to leak. The SSE frame is now a tenant-safe projection built by exhaustive destructuring (`handlers::inbox_stream::InboxWakeWire`), so a field added to the bus event later cannot reach the wire unreviewed; the only counter on it is the recipient's own `recipient_seq` (#4125), which moves only for that recipient's wakes. The host-wide `seq` stays on the in-process bus for internal consumers only (#4071).
