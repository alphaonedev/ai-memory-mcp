### Security

- **[http] inbox SSE frames no longer carry the process-wide wake sequence**
  ([#4071](https://github.com/alphaonedev/ai-memory-mcp/issues/4071)).
  `GET /api/v1/inbox/stream` filtered wakes to the subscriber's own inbox but serialised
  each allowed event unchanged, including a `seq` drawn from one counter shared by every
  recipient — so the gap between two of a subscriber's own frames measured other tenants'
  notify volume, the signal the stream already refuses to leak via skipped-frame ticks or
  lag counts. Frames are now a tenant-safe projection (`event`, `recipient_agent_id`,
  `correlation_id`, `inbox_row_id`, `namespace`, `sender_agent_id`, `content_digest`,
  `notified_at`) built by exhaustive destructuring, so a field added to the event later
  cannot reach the wire without a decision. The global sequence stays internal. Pinned on
  sqlite- and postgres-published wakes by `tests/inbox_stream_seq_isolation_4071.rs`.
