**End-to-end scope envelope, slice E1 (#8278).** A namespace can be sealed under a per-namespace scope key (envelope `0x05`, a per-record DEK wrapped under the scope key, AAD bound to role, format version, key id, epoch, `memory_id` and `namespace`), with a hash-chained, append-only scope-key ledger per namespace. Crypto erase covers every version in `CRYPTO_ERASABLE_ENVELOPE_VERSIONS` (`0x03` and `0x05`) on SQLite and Postgres, and every doc comment that describes erase scope names that constant as the authority (a pin test fails if one lists `0x03` alone). The namespace end-to-end marker fails closed: a dangling key-dir link, a lock failure, a key-dir listing failure and a garbled ledger each answer "end-to-end" and are each pinned by a test, and the marker's fail-closed fallback now logs a warning naming the operation and the error (never key material).
