The enterprise-fed CI suite now compiles once and runs as one serial Postgres/federation shard plus two parallel shards balanced by measured seconds (scripts/ci/partition_test_binaries.py), cutting the estimated wall time from about 13,900-14,100 s (contended, serial) to about 3,900 s (#6344). Each target is classified on the union of the sources it compiles (`mod`, `#[path]` and `include!` followed recursively; an unresolved `mod` goes to the serial shard; shared `tests/common` helpers count through the items a binary references), so a Postgres test pulled in through `#[path]` can no longer run in a parallel shard. The lib Postgres-coverage gate checks every code site that names the test URL, including through a const or static, against the exact libtest test path. Each shard is bounded by a 5400 s watchdog and the job by 120 minutes, derived from the longest-shard estimate of 3,913 s; the per-shard logs and the partition manifest are uploaded on every outcome; the partition and the shard wiring are pinned by unit tests that CI runs.
