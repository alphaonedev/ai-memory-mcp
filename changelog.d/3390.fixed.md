**`memory_reflect` refuses a wrong-typed or out-of-range optional instead of
silently defaulting it (#3390).** `tier`, `namespace`, `priority`,
`confidence` and `tags` were read with `unwrap_or(default)`, so a present
value of the wrong type — `tier: 123`, `priority: "high"`,
`tags: "notarray"`, `confidence: "hi"` — or a `priority` outside its
documented `1..=10` domain (including one too large for the column) fell to
the default and the reflection was written as if the caller had asked for
it. Each such value is now refused with a message naming the field; an
absent optional still takes its default. Callers that relied on a
malformed optional being ignored will now get a refusal.
