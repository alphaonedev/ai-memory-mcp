**Webhook and inference DNS pins resolve an implicit-port `https://` target
on 443, not 80 (#4075).** The DNS-resolved SSRF guard appended `:80` to
every authority that omits a port and installed the resolved `SocketAddr`s
as reqwest per-host overrides. The locked connector keeps an override's port
unless the URI port is explicit or the override port is 0, so for the most
common webhook shape — a public HTTPS hostname on the default port — the TLS
connection was opened to TCP 80, every delivery failed, retried through the
ladder and landed in the DLQ. The `internal-only` inference pin shared the
same helper and had the same defect. The default port now follows the scheme
(`subscriptions::dns_guard::host_port_with_default_port`: 443 for `https`,
80 otherwise); explicit ports and literal-IP targets are unchanged, and the
all-address SSRF validation is untouched. Pinned by
`src/subscriptions/dns_guard_4075_tests.rs` (webhook lane) and
`tests/inference_egress_pin_port_4075.rs` (inference lane), both RED on the
pre-fix tree with every address pinned on 80.
