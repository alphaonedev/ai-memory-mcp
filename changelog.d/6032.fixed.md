The append-only scratch janitor (`scripts/clear-append-only-scratch.py`) now excludes a second run from its pending-restore journal (#6032). Each run takes an exclusive lock, without waiting for it, on the journal before it reads it and on the path that creates it, and checks after locking that the name still leads to the locked file. A run that finds the journal held, or replaced while it was opened, neither reads nor writes it and refuses every widen it would record, the same fail-closed refusal an untrusted journal already gets.
