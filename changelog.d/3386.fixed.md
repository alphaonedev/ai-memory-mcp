Make `memory_kg_query`'s `namespace` and `as_agent` parameters take effect on
the main `source_id` traversal path, not only inside the `by_source_uri` branch:
`namespace` (also the `ai-memory kg-query --namespace` flag) was silently
ignored, and `as_agent` — documented as mirroring `memory_search.as_agent` —
did nothing, so a query naming another agent still returned that agent's
`scope=private` node in full. Both paths now share one gate built on the
canonical visibility predicate, with the team/unit/org subtree arms keyed on
`as_agent` and the private arm keyed on the identified caller (fail-closed when
there is none), matching what the SQL visibility clause already enforced for
search. Negative `max_depth` / `limit` are refused instead of being silently
coerced to the server default, and the `by_source_uri` response envelope now
carries the same structural keys as the main one.
