**A push to a Promotion carrier (`chain/**`) now runs the required-set workflows (#6117).**
Since #6105 the carrier gated PRs opened *into* it, but a signed merge *onto*
it (a lane PR landing, a release sync, a bootstrap merge) ran no workflow at
all, so carrier-only defects (#6115, #6116) stayed invisible until the next PR
opened against the carrier. `ci.yml`, `c8-precheck.yml`, `coverage.yml`,
`release-shape.yml`, `cert-postgres-age.yml` and `postgres-ignored.yml` list
`chain/**` under `push.branches`. The carrier is also the head of its promotion
PR (#6160), so the three workflows whose cancel group was not yet keyed per
event (`ci`, `coverage`, `c8-precheck`) fold `github.event_name` into it: the
push run and the PR run complete side by side instead of one cancelling the
other (the #2508 class). A carrier push runs the full pipeline and the
range-scoped gates judge the whole carrier against `release/v1.0.0`, so the
push verdict is never narrower than the promotion-PR verdict beside it.
