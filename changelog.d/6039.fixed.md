The test suite for the append-only scratch janitor now pins the ORDER in which the journal's lock is taken, not only that it is taken (#6039). The torn-tail test's tail was disjunctive, so a green run took the `refused` branch and its data-loss assertion never executed; an ordering that locked the journal after reading the length it later truncates to therefore left every test green while reproducing the #6034 data loss. The torn-tail test now asserts the surviving line unconditionally, and a new test probes the journal's lock from an independent descriptor at every seam that reads, cuts or appends to it, so an ordering that reads before it owns the journal fails.
