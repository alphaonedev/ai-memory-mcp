**`ai-memory wake-hub` starts in every mode for a hub user whose home cannot be written (#9562).**
The #3354 unsigned-ledger refusal treats an unlisted verb as a ledger writer, and
`wake-hub` was unlisted, so serve, `--posture` and `--health` all refused to start
without a creatable signing-key place, although none of them writes a
`signed_events` row; under a writable home they created a signing key they
never use. The boot now skips the key setup for every `wake-hub` mode: no key
is loaded, ensured or generated, and the forensic sink starts without a key,
creating only its directory and no forensic file. Under the packaged unit (user
`ai-memory-hub`) the hub never started, and the `--posture --require-admits`
gate reported the key refusal as exit `3` ("admits nobody"). `wake-hub` is now
classified per mode by one exhaustive match (`WakeHubMode::writes_ledger`,
no wildcard arm) that the dispatch also uses; every mode and modifier is
read-only, with its exit codes unchanged. A forensic sink that cannot start
prints the one degraded-boot warning and, for these modes, records no outage
row. Writer verbs still refuse with the exact #3354 text. Tests:
`tests/wake_hub_readonly_modes_9562.rs` (each mode under two unwritable-home
shapes and under a writable home with no key or forensic file afterwards, the
unit's three command lines parsed from the unit file, the sink warning in the
reporting modes and in serve, and a pin that wake-hub-reachable code and the
boot path gain no ledger or ungated key call).
