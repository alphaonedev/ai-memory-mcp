The append-only scratch janitor (`scripts/clear-append-only-scratch.py`) no longer lets released journal lines pile up behind one line no run can resolve (#6031). A run that cannot empty its pending-restore journal rewrites it without the `+`/`-` pairs it can prove released, keeping every other line byte for byte and in order. The rewrite goes to a sibling name opened without following a symlink and held to the journal's own checks (a planted link is refused, not written through), is emptied first, fsynced, renamed over the journal, and the directory is fsynced after, so a kill leaves the old journal or the new one.
