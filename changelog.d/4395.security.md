**The curator reflection pass is governed like an external reflect (#4395).** The pass wrote reflections through `store.reflect` under the admin context, skipping the #3638 write admission and the `require_approval_above_depth` approval gate every external funnel must pass, so a namespace owner's depth threshold did not hold against curator output. Each curator reflection now runs the same governed decision before the write, as the curator principal and on both backends through the trait: a `Pending` admission or a proposed depth above the threshold parks the reflection as the same `reflect` pending action the MCP gate queues (replayed on `memory_pending_approve`); a denied admission skips it with the reason in the report; nothing is written ungoverned. The report gains `reflections_parked`.
