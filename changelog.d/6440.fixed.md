**Carrier-ruleset verifier ruleset-id and issue-number checks are type-strict (#6440, carrier gate #6143, #6231 follow-up).** `scripts/check_carrier_ruleset_live.py` compared the per-ruleset detail `id` and the tracking-issue `number` with `==`, so `true` equalled listing id 1 and `6182.0` equalled 6182. Both now require a real integer (`is_int_id`, which rejects bool and float) before the comparison. The self-test pins the listing-id guard with a route that returns a valid detail, so deleting the bool clause is caught (mutant S2).
