**A failed LLM hook is now a recorded degraded outcome, never a silent clean verdict (#9213).** `memory_store` adds the response-only key `autonomy_hook_degraded`, an array of `{hook, candidate_id?, reason}` entries, when the post-store `auto_tag` call or the legacy per-pair contradiction classifier fails; `memory_session_start` adds the response-only key `summary_degraded` with the reason code when the LLM summary fails. Both keys are absent when every hook ran clean, carry the same shape on the MCP and HTTP paths, and use only the closed reason codes of `src/llm/reply_integrity.rs` (`reply_truncated`, `reply_filtered`, `reply_not_done`, `reply_no_stop_reason`, `reply_unrecognised_stop`, `reply_tool_stop`, `reply_empty`, `reply_no_content`, `verdict_unclassifiable`, `llm_error`); provider text is never echoed. `candidate_id` appears only when the caller can read that candidate. Nothing is written to row metadata, following the response-only precedent of `autonomy_hook_skipped` (`src/mcp/tools/store/mod.rs`), which is unchanged and still reports eligibility skips only. Each failure also emits one structured WARN (`llm hook degraded`, with memory id, hook and reason code). Files: `src/mcp/tools/store/legacy_classifier.rs`, `src/mcp/tools/session_start.rs`, `src/background/auto_tag_worker.rs`. A durable row-addressable record is tracked in #9224.
