**The pre-migration snapshot restores through the verified path, and `restore --skip-verify` no longer waives the cross-backend refusal (#2565).**
Before a schema upgrade, the binary snapshots the SQLite database to
`<db>.pre-migration-vN-to-vM-<token>.bak`. That file had no manifest, so the
documented rollback worked only with `restore --skip-verify`, which skipped
the sha256 check and the cross-backend refusal along with it. The snapshot
now gets an unsigned sibling manifest (`<stem>.manifest.json`: sha256, size,
backend, schema version), so `ai-memory restore --from <snapshot>
--allow-unsigned-manifest` checks the bytes. `--skip-verify` still waives
only the sha256: a manifest next to the snapshot is read for its backend, a
cross-backend snapshot is refused, and an unreadable manifest is refused.
The `asi-hard` posture still accepts only signed manifests.
