### Security

- **[identity] Bootstrap public-key bind requires a verified principal, not the admin header**
  ([#8494](https://github.com/alphaonedev/ai-memory-mcp/issues/8494), umbrella
  [#8493](https://github.com/alphaonedev/ai-memory-mcp/issues/8493)). Under the
  default `advisory` posture a request carrying the shared transport key and a
  CLAIMED allowlisted admin `X-Agent-Id` was admitted by `require_admin` with a
  WARN, and could take a bind challenge for and bind a keypair it controls to
  any registered agent, then mint `agent_attested` writes in that agent's
  name. `POST /api/v1/agents/{id}/pubkey/challenge` and
  `PUT /api/v1/agents/{id}/pubkey` now refuse (403) unless the admin is
  key-authenticated (the presented `X-API-Key` is the enrolled per-agent key of
  that admin id) or the operator explicitly set `AI_MEMORY_ADMIN_HEADER_TRUST=1`.
  Every refusal lands on the forensic audit chain (`bind_agent_pubkey`, reason
  `claimed_admin_not_key_authenticated`) and binds nothing, on SQLite and
  Postgres. The CLI (`ai-memory agents bind-key`) and MCP stdio paths are
  local-operator funnels and are unchanged. A boot WARN now names
  `AI_MEMORY_ADMIN_HEADER_TRUST` when it is set with admin ids configured,
  because it also re-opens this route to header claims. Operators who bound
  keys over HTTP with a shared key and an admin header must enrol the admin's
  per-agent key first (`ai-memory agents bind-api-key`).
