### Security

- **[docs][revocation] The per-agent key-refresh interval is no longer called
  an upper bound on a revoked key's lifetime**
  ([#4001](https://github.com/alphaonedev/ai-memory-mcp/issues/4001)). The
  NSA-CSI mapping (Markdown and HTML), `ADMIN_GUIDE.md`, the `CLAUDE.md` knob
  row, the `agents bind-api-key` / `revoke-api-key` `--help` and output lines,
  and the `serve` boot line all said a revocation takes effect "within" the
  `AI_MEMORY_AGENT_KEY_REFRESH_SECS` window and that the window bounds how long
  a leaked key stays live. It does not: a failed refresh keeps the previous key
  map (`apply_agent_key_refresh` -> `KeptLastKnown`) and nothing expires it, so
  while store reads fail a revoked key keeps authenticating. The text now says
  revocation lands at the next SUCCESSFUL refresh and that the interval is a
  cadence, not a bound. Behaviour is unchanged; a maximum-staleness deadline
  would need a ruling (it trades availability of every key-bound caller for the
  bound). Pinned by `tests/agent_key_hot_enroll_3418.rs::a_revoked_key_outlives_the_interval_while_refreshes_fail_4001`
  and `tests/fit_docs_b_false_claims_4000_4009.rs`.
