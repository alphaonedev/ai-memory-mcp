Federation `/sync/push` now re-authorizes the pushing peer's namespace scope against the stored row a same-ID memory merge actually overwrites, inside the merge's own transaction (the row is read `FOR UPDATE` on PostgreSQL and under `BEGIN IMMEDIATE` on SQLite). Previously the scope check ran on an earlier read, and because the merge takes `namespace` by last-writer-wins, a row moved out of the peer's scope by a broader writer between that read and the merge could be relocated and overwritten by the narrow peer. Such a merge is now refused and writes nothing, as the same typed `PermissionDenied` refusal on both backends; the unchecked `merge_inbound` is `#[doc(hidden)]` and a ceiling test pins that no production caller reaches it (#4023).
