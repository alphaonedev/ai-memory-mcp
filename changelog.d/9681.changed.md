CI speed (#9681): a pull request into a `chain/**` branch now restores a warm Rust dependency cache. GitHub lets a pull-request run read the cache of its base branch, but no workflow ever saved one on `chain/**`, so the hosted `Check (ubuntu-latest,sqlite)` and `Per-Module Coverage` jobs compiled every dependency from scratch on each chain PR. A new push-only, GitHub-hosted workflow, `.github/workflows/rust-cache-warm.yml`, runs on each `chain/**` push and writes the same `shared-key` (`ci-check-hosted-sqlite`, `coverage-per-module`) under the same toolchain, key environment and compile commands as those two jobs; it runs no tests, holds `contents: read` only, starts no self-hosted leg, and skips every build on a full key match. Every `Swatinem/rust-cache` step in every workflow now saves only on a `push` (`save-if: ${{ github.event_name == 'push' }}`), so a pull-request or merge-group run restores but never writes a cache, and the HuggingFace model cache in `coverage.yml` is split into a restore step and a push-only save step. `scripts/ci/tests/test_rust_cache_save_scope_9681.py` pins the pairing, the push-only save on every cache step of every job, and the unchanged test and gate steps of every job in the touched workflows.
