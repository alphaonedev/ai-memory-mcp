**A config-file `db =` value no longer reaches `doctor` or `serve` output raw (#6106, CWE-532).** The `doctor` report `source:` field, its cannot-open notes (text and `--json`) and `--posture` warning, and the `serve` boot `database:` line, `--db`/`--store-url` conflict message and open-failure warnings render the database path through `url_display::db_path_display`, so a store DSN or a key/value DSN written into `db =` (or a scheme-less `--db` value) prints as its allowlisted form or `<unparseable-store-url>` instead of its credential. The deferred-audit journal and spool paths (derived from the database path) render through the same allowlist in every log line and error context, so a refused spool ancestor or a failed journal open at `serve` boot no longer echoes the value either. Regression: `tests/config_db_value_sinks_6106.rs`.
