**[release][supply-chain] The payload check reads packages with the same strictness as dpkg and rpm (#7019, umbrella #6062).**
`--verify-payload` read deb data archives with Python's `tarfile`, which applies
pax extension headers and stops silently at a corrupt header, and read rpm
packages from the cpio payload only, never from the header rpm installs from.
A package could therefore show one file to the check and another to the
package manager. Now one strict reader handles each format: tar members must be
plain GNU/ustar regular files or directories with verified header checksums,
root ownership and nothing but zeros after the end-of-archive blocks (no pax,
GNU long-name or link entries); ar members must end exactly at the archive end;
cpio names must be single NUL-terminated UTF-8 with zeros after the trailer; and
the rpm main header's file list, payload digest and compressor must agree with
the cpio entries. Regression: the `6907b` packer self-test cases.
