**`ai_memory_store_total` now counts HTTP creates, and the store and recall HELP text states its scope (#3653).**
The store counter was registered with the HELP "Total memory_store calls" but
no production code path ever incremented it, so a dashboard read a flat zero
while the daemon was writing or failing to write. Every `POST /api/v1/memories`
request now records its final outcome on both backends: `result="ok"` for a
2xx, `result="err"` for any other status (validation, governance, quota,
conflict, backend failure), labeled by the requested tier. The HELP text for
`ai_memory_store_total`, `ai_memory_recall_total` and
`ai_memory_recall_latency_seconds` now says what each counts: HTTP creates, and
successful HTTP recalls only; MCP-stdio, CLI and bulk writes, and failed
recalls, are not counted. The observability reference, the enterprise
deployment table (which named two series that do not exist) and the
DigitalOcean runbook SLO say the same. A write-latency histogram and failure
classes for recall remain out of scope for this fix.
