`POST /api/v1/import` no longer lands a forged attestation. The handler
re-owns every imported row to the importing admin (`metadata.agent_id`) but
carried the request body's `metadata.attest_level` and
`metadata.write_signature` through verbatim, so an unauthenticated body minted
durable `agent_attested` rows whose retained signature was computed over a
*different* `agent_id` / `namespace` / `title` — an attestation no principal
ever signed, which every downstream trust surface (`row_is_agent_attested`,
federation relay, the attestation census) then believed. Both backends now
re-derive the attestation from what the destination can verify, through the
one shared funnel `identity::attest::reconcile_imported_attestation` that the
CLI/portability import route already used: the wire `agent_pubkey` claim is
stripped, a re-owned row lands `claimed` with the stale signature dropped, an
author with no destination-enrolled key lands `claimed`, a presented-but-forged
signature skips the row entirely (never downgraded into storage), and only a
signature this node verifies against the enrolled author key keeps
`agent_attested`. A row that asserted nothing is imported byte-for-byte as
before.
