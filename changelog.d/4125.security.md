The wake-hub `seq_high_watermark` is now PER RECIPIENT. It carried the producer's host-wide wake sequence, so the gap between two of one recipient's watermarks counted every other recipient's notifies: a cross-tenant activity-volume side channel, the same one #4071 removes from the inbox SSE stream. Each `agent_notified` wake now carries a `recipient_seq` assigned at PUBLISH time (a per-recipient counter next to the host-wide one, taken under the same short lock as the broadcast send, bounded in BYTES (`wake_hub::limits::RECIPIENT_SEQ_BUDGET_BYTES`, 8 MiB; at the budget the least-recently-woken recipient is evicted per entry)), and the wake sink forwards it verbatim, never renumbering it. The self-heal contract is unchanged: a gap in the recipient's own sequence, including one caused by a lagging broadcast receiver, still means one catch-up inbox read, and the <=60 s backstop poll is untouched. Counters start from a wall-clock base, so a producer restart or an eviction from the counter table moves a recipient's number forward (at worst one wake is labelled `gap`, which costs no extra read; only an evicted recipient ever sees such a jump, a documented residual: a bounded count oracle costing ~26k+ notifies per probe, mitigated by the per-agent daily quota, carrying no identity and no content) and never backwards across a real gap. The wire format is unchanged (same `u64` field) (#4125).
