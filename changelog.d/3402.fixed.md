`ai-memory store` now honours the namespace standard's `auto_atomise` policy
instead of only its access-control half. The CLI routes through the same
`hooks::pre_store::run_auto_atomise` funnel the `memory_store` MCP tool uses,
so an over-threshold body stored from either surface produces the same atoms
and the same `atomise_mode` / `atomise_outcome` report. A one-shot CLI has no
daemon to defer to, so a `deferred` namespace runs the same bounded worker
in-process and joins it before the command exits.
