### Security

- **Curator reflections keep the visibility of their sources**
  ([#8850](https://github.com/alphaonedev/ai-memory-mcp/issues/8850)). The reflection pass
  read its source observations with an admin context, so it could cluster rows the curator
  identity was not allowed to see, and it stamped every derived reflection `collective`, which
  republished private or team rows to every reader. Reads now use the curator's own agent
  context; a reflection's `scope` metadata carries the most restrictive scope of its sources
  (`visibility::narrowest_scope`), recomputed from a fresh read just before the write. A source
  that is missing, not readable or moved to another namespace at persist time refuses the write
  with an exact error, and the substrate re-verifies every source inside the write transaction
  (readable by the curator, same namespace, stamped scope equal to the narrowest source scope)
  on SQLite and Postgres (fail closed). Test: `tests/curator_reflection_visibility_8850.rs`.
  - **Declared narrowing.** Rows written with the default scope are owner-private, so the
    curator (which reads as itself) produces no cross-owner reflection over them. The pass logs
    the skipped count per namespace (`skipped`, `visible`, `curator` fields). decision:
    narrow-and-declare over owner-private reflection in this release because it never widens a
    row (`3-agent vote (71472661) Q2 A 3-0`, conditions Y-7..Y-11). Do not stamp rows
    `collective` only to make the curator reflect them: that publishes them to every reader.
    Owner-private reflection is tracked separately (Refs #9222).
