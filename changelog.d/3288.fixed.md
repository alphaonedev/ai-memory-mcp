**Breaking for large corpora:** `GET /api/v1/export` is now bounded. It used
to read the whole corpus and the whole link table into memory and send them
as one JSON body, so exporting a large postgres tenant (for postgres this
route is the only backup path) could run the daemon out of memory and kill
it.

- **Paged mode.** Pass `?limit=N`, then `?limit=N&cursor=<next_cursor>`
  until `next_cursor` is `null`. `N` can be up to the page ceiling
  (`AI_MEMORY_MAX_PAGE_SIZE`, default 1000). Each page holds at most `N`
  memories and the links that page owns. Importing the pages in order
  never references a memory before it is imported.
- **Unpaged request.** A request with no parameters still returns the old
  single body while the corpus fits the page ceiling. Past the ceiling it is
  now refused with `413 EXPORT_PAGING_REQUIRED` instead of being sent whole.
  **If a backup script calls `GET /api/v1/export` on a corpus over 1000
  memories, switch it to paging** (the Python SDK has a new
  `export_pages()` for this), or raise `AI_MEMORY_MAX_PAGE_SIZE`.
- **Rows left out are reported in the body.** On postgres, a row the export
  cannot decrypt used to be dropped with only a log line, so a partial backup
  looked complete. Every body now carries a `withheld` object with counts of
  forbidden-class drops, quarantined, undecryptable, tombstoned, expired and
  redacted rows and withheld links, plus a `partial` flag. On sqlite an
  undecryptable row still fails the export, as before.
