### Security

- **[skills] A signing node serves only signed skills**
  ([#9174](https://github.com/alphaonedev/ai-memory-mcp/pull/9174)). On a node that holds a private
  signing key, every skill read surface (`memory_skill_get`, `memory_skill_list`,
  `memory_skill_resource`, `memory_skill_export`, `memory_skill_compositional_context`, the CLI
  twins and the HTTP routes) refuses an unsigned skill row with
  `skill integrity check failed: signature required on a signing node for skill <id>` (HTTP `400`).
  A presented signature that does not verify is refused on every node. The refusal is per row:
  `memory_skill_list` leaves the row out and logs one warning per call with the count of rows it
  left out, and get, resource, export and compose refuse that skill only.

  What an operator with unsigned skills sees after enabling a signing key: those skills stop
  being served on that node (list leaves them out, get names the reason above). Re-register each
  skill on the signing node (`ai-memory skill register` or `memory_skill_register`); the new
  version is signed and is served with `signature_verified: true`. Register and delete never
  read the old row through the verified reader, so both work on a refused row. A node without a
  private key keeps serving unsigned rows as unsigned (`signature_verified: false`).
