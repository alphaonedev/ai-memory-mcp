**Secret screen prefix boundary (#8452).** The prefix detectors (`sk-`, `xai-`,
`ghp_`, `github_pat_`, `Bearer `, `AKIA`) no longer match a prefix glued to a plain
word (`task-`, `disk-`, `kiosk-`, `whisk-`), so a hyphenated slug such as
`task-ownership-scoping-r3` is stored instead of refused or rewritten. The rule
fails closed: a prefix is skipped only when the byte before it is alphanumeric and
the whole whitespace-delimited run before it is alphanumeric, hyphen or
underscore. Every other lead is still detected: whitespace, punctuation, a slash,
a backslash escape, a percent code, an HTML entity, a quoted-printable code or a
terminal colour code, and a hyphen- or underscore-joined key such as `tag-sk-...`
or `my_ghp_...` stays masked (the #1844 title, tag and metadata contract). A key
glued directly to a plain word (`xsk-...`, `v2ghp_...`) is stored: that is the
designed trade-off. The tests use representative fixtures, not an exhaustive list
of spellings. The JWT and PEM detectors are unchanged.

**Preimage change.** `screen()` output feeds the content-id genesis and the v2
write-attestation preimage, so for text that carries a word-glued prefix the
screened bytes differ from earlier builds. Stored `cid_genesis` values are
unaffected (verification uses the stored blob), but a v2 signer or federation
peer on an older build redacts that text where this build keeps it: upgrade
signers and peers together. The golden test
`screened_output_golden_per_boundary_class_8452` pins the screened output for one
fixture of each lead class.
