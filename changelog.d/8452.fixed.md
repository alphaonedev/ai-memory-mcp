**Secret screen prefix boundary (#8452).** The prefix detectors (`sk-`, `xai-`,
`ghp_`, `github_pat_`, `Bearer `, `AKIA`) no longer match a prefix inside a word
(`task-`, `disk-`, `kiosk-`), so a branch name such as
`fix/task-ownership-scoping-r3` is stored instead of refused or rewritten. Real
keys after a separator, an escaped delimiter (a backslash with `n t r b f v 0 a e`,
an octal escape, `\xXX`, `\uXXXX`, `\UXXXXXXXX`), a percent-encoded one (`%3D`, `%253D`,
`%u0022`), a quoted-printable one (`=3D`) or a terminal colour code are still
refused. A real key glued directly to a word (`xsk-...`, `build_ghp_...`) is
stored: that is the designed trade-off. The JWT and PEM
detectors are unchanged.

**Preimage change.** `screen()` output feeds the content-id genesis and the v2
write-attestation preimage, so for text that carries a mid-word prefix the
screened bytes differ from earlier builds. Stored `cid_genesis` values are
unaffected (verification uses the stored blob), but a v2 signer or federation
peer on an older build redacts that text where this build keeps it: upgrade
signers and peers together. The golden test
`screened_output_golden_per_boundary_class_8452` pins the screened output for one
fixture of each boundary class, including `\x22`, a non-ASCII lead, `\f`, octal,
`\U00000022`, `%253D`, `=3D` and a colour code.
