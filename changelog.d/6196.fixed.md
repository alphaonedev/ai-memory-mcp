**Only a canonical, always-rendered erratum line clears a stale script name (#6196).**
`scripts/check_compliance_script_names.py` counted any line containing "erratum", the stale
name and an existing successor, including text a rendered document never shows. An erratum is
now only a line that starts `Erratum (#<issue>): ` at column 0 and begins a paragraph (the
first line, or after a blank line or a closing fence), outside any fenced block or `$$` block
(an unclosed one runs to the end of the file), raw HTML block (where backticks protect
nothing), HTML comment, processing instruction, CDATA section, declaration or tag (each runs to
its closer, across blank lines and fences), and whose text has no `[` or `]` outside code
spans. A backtick escaped by a backslash opens no code span. Any other shape is rejected, which
fails closed; stale names are still found in all text. The two #6141 errata in
`docs/compliance/BALLOT-PROCEDURE.md` and `docs/compliance/MISSION-CRITICAL-CERTIFICATION-STANDARD-v1.md`
sat in the header comment and are moved, unchanged, to a visible canonical line directly after
it; the adopted text below is untouched.
