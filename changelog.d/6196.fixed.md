**An erratum inside an HTML comment no longer clears a stale script name (#6196).**
`scripts/check_compliance_script_names.py` counted any line containing "erratum", the stale
name and an existing successor, including a line inside `<!-- ... -->` that a rendered
document never shows. Erratum lines are now read from the reader-visible text only (HTML
comment text removed, comments spanning lines tracked); stale names are still found inside
comments. The two #6141 errata in `docs/compliance/BALLOT-PROCEDURE.md` and
`docs/compliance/MISSION-CRITICAL-CERTIFICATION-STANDARD-v1.md` sat in the header comment and
are moved, unchanged, to a visible line directly after it; the adopted text below is
untouched.
The body of a diagram fence (`mermaid`, including its `%%` comments, `math`, `geojson`,
`topojson`, `stl`), which GitHub renders as a figure rather than text, is now also
reader-invisible and cannot carry an erratum.
Raw HTML that GitHub renders as nothing is also reader-invisible now: a processing
instruction (`<? ... ?>`), a CDATA section, a declaration (`<!DOCTYPE ...>`) and the markup of
a tag, its attribute values included (`<span title="...">`), each also across lines. An
erratum in any of these forms no longer clears a stale script name; an unclosed tag ends at a
blank line or a fence, where GitHub shows it as text.
