**#3806 W1c — the `[decision]` provider CLIENTS: the structured chat-completions call, the direct decision-route adapter, the generative fallback, the calibration-row adapter, and the factory the boot chokepoint calls.** Still unreachable at runtime — nothing constructs a provider until the boot chokepoint lands — so `[decision]` unset remains byte-identical v1.0.0.

`src/decision_clients/chat.rs` sends a STRUCTURED chat-completions request: `response_format = {"type": "json_schema", …, "strict": true}` whose single property is an `enum` over the closed vocabulary (or a `number` with `minimum`/`maximum` for a score), plus `logprobs`, `temperature = 0` and a fixed `seed`. Today's generative bodies carry none of those four, which is why a decision could only ever be read back out of prose. An off-vocabulary answer is now refused by the ENDPOINT before our parser refuses it again, and two calls with the same prompt get the same answer, so a calibration figure measured once still describes the system later. This covers the reference decision model on OpenRouter, every `[llm]` vendor alias, a self-hosted `vllm` / `lmstudio` / `llama.cpp` server, Ollama's OpenAI-compatible surface, and any customer endpoint (`provider = "openai-compatible"` plus an explicit `base_url`).

**Confidence is attributed, never assumed.** A confidence is emitted only when exactly one contiguous run of returned `logprobs` tokens concatenates to the decided label EXACTLY; the value is then `exp(Σ logprob)` over that run. No logprobs block, an ambiguous attribution (the label also appears in the schema key), a token that straddles the label, a positive or non-finite logprob, or a response whose logprobs we did not ask for — each reports NO confidence. A `score` never carries one at all: a continuous answer has no closed vocabulary to attribute tokens to. An endpoint that rejects `logprobs` with a client error makes the client latch the parameter OFF, retry that one call without it, and answer with no confidence from then on — a degradation, never a fabricated `1.0`, and one-way so it cannot oscillate under load.

`src/decision_clients/systemone.rs` adds the direct decision-route adapter (`POST /v1/systemone`). The design fixes the route and nothing else, so the body is not guessed silently: it lives behind a two-function `SystemOneWire` trait, the shipped `DefaultSystemOneWire` documents this build's ASSUMPTION in its module header, a golden test pins the exact bytes, and `SystemOneDecider::with_wire` swaps in a published or customer shape in one line without touching the decider, the factory, the egress hook or any seam. The response's `probability` field is optional and its absence — or a value outside `0.0..=1.0` — is an ABSENT confidence, never a repaired one.

`src/decision_clients/fallback.rs` adds `GenerativeFallbackDecider` over the existing `[llm]` client (no second endpoint, no second credential, the same circuit breaker and redaction discipline). It prompts for one token from the closed vocabulary and parses strictly: `"Yes, because the two records disagree about the port."` does not parse, it ABSTAINS. That sentence is the defect — `detect_contradiction`'s `starts_with("yes")` reads a refusal, a preamble and a hedge alike as a verdict. The generative leg is held to `[decision].timeout_secs` rather than the 30-second generative budget, and every answer it returns carries `DecisionSource::GenerativeFallback` and NO confidence.

`decision_clients::construct()` is the single factory the boot chokepoint calls. It takes an outbound-check hook that is invoked with the fully-resolved request URL before EVERY request — including the `logprobs` retry and the generative fallback leg — so a per-call egress posture applies to the second endpoint the way it already applies to the first. **An egress refusal is the one abstain that never falls back**: re-asking a refused destination's question of a different endpoint would turn the posture into a suggestion. `provider = "local-nli"` is REFUSED by name rather than quietly turned into a network client, `fallback = "generative"` with no generative backend is a refusal rather than a half-configured provider, and a `base_url` that is not an `http`/`https` URL fails at construction rather than at the first call. Credentials live in a `SecretKey` whose `Debug` is the redaction placeholder and whose `Drop` zeroizes; every log line renders the endpoint through the URL redaction funnel, so neither the key nor a token-in-query reaches a `{:?}` or a log.

`src/decision_clients/calibration.rs` renders any decision into the preregistered calibration input shape `{item_id, seam, source, predicted|null, label}`, so the seams can emit calibration rows without touching the harness. `predicted` is the probability assigned to the preregistered label being TRUE — so a judgement of `false` at confidence `0.9` records `0.1`, not `0.9` — and `null` is always an explicit key, never an omitted one, because an abstain and an absent confidence are both "no probability exists" rather than "no opinion was recorded".
