**`ai-memory audit verify` now fails on a missing audit event (#4021).**
Every event is numbered before it is written, so an event lost to a failed
write (#3975) leaves a gap in `sequence` while the hash chain stays intact.
Before this, verify rejected only a sequence that failed to INCREASE, and a
trail missing events verified clean. An interior gap now fails with exit 2
and `"kind":"SequenceGap"`, a distinct class ("events missing") that never
reuses the tamper wording. The JSON output gains additive `gaps` and
`gap_count` fields; existing fields and failure kinds are unchanged. Known
losses are passed with `--acknowledge-gaps FROM-TO[,...]`, which must name
each gap EXACTLY: a broad range is not a blanket pass, a later gap fails
again, and a pass reads `"status":"ok_acknowledged_gaps"`, never `"ok"`.
The acknowledgement is not a signed record and covers operational loss only.
Events lost at the tail just before a restart are reported too: a persisted
sequence high-water keeps their numbers from being reused (#4086).
Decided by a 5-agent vote (5/5).
**Upgrade note:** a trail that already has a historical gap (from a past
write failure) fails its first verify after upgrade. Run `ai-memory audit
verify`, confirm the printed ranges match known incidents, and add
`--acknowledge-gaps <ranges>` to the scheduled check.
