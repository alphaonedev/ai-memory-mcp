**The SQLite dequarantine-on-attest primitive joins a caller-held transaction (#6162, port of #4314).**
`dequarantine_if_verified_unit` now runs its check-and-release through the join-aware `connection::in_write_txn` (#3152): standalone it still opens `BEGIN IMMEDIATE` (same one-lock guarantee); inside a transaction the caller already holds it joins, and the caller's `COMMIT`/`ROLLBACK` decides. Before, a caller inside an open transaction got a nested-BEGIN error and an attested row that should have been released stayed quarantined with only a WARN. Regressions: `tests/dequarantine_verified_4208.rs` `*_4314`.
