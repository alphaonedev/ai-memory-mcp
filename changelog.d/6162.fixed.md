**Federation dequarantine-on-attest releases a quarantined row only when the signed content won the merge (#6162, port of #4208 onto the SSH-signed carrier).**
The route-OUT dequarantine-on-attest (#1948) now releases a quarantined row only when the row actually stored carries the signed content this node verified, on both backends. "Signed content" is content, title, namespace, memory kind and author; `created_at` and the signature key are deliberately excluded (the merge keeps the local genesis instant and may keep either side's signature metadata). Before, a validly signed but OLDER push for the row's own id lost the newer-wins merge, left the local never-attested content on the row, and still released it from quarantine. The release primitives require the incoming row to be `agent_attested` themselves rather than trusting the caller, and the check and the release run under one write lock (SQLite `BEGIN IMMEDIATE`, Postgres `FOR UPDATE`); a push whose content did not win leaves the row quarantined for an operator release. New `MemoryStore::dequarantine_verified` (fail-closed `Ok(false)` default). Regressions: `tests/federation_dequarantine_crossid_3901.rs` `*_stale_same_id_attested_push_keeps_row_quarantined_4208`, `tests/dequarantine_verified_4208.rs`, `models::crdt_merge::tests::verified_unit_*_4208`.

**The SQLite dequarantine-on-attest primitive joins a caller-held transaction (#6162, port of #4314).**
`dequarantine_if_verified_unit` now runs its check-and-release through the join-aware `connection::in_write_txn` (#3152): standalone it still opens `BEGIN IMMEDIATE` (same one-lock guarantee); inside a transaction the caller already holds it joins, and the caller's `COMMIT`/`ROLLBACK` decides. Before, a caller inside an open transaction got a nested-BEGIN error and an attested row that should have been released stayed quarantined with only a WARN. Regressions: `tests/dequarantine_verified_4208.rs` `*_4314`.
