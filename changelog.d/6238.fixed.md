**A stale-script-name violation now names the near-miss erratum line (#6238).**
`scripts/check_compliance_script_names.py` rejected an erratum that was not in the one accepted
form (a link reference definition, a footnote, a list item, an indented or mid-paragraph line)
with the same message as a document with no erratum at all, so an author could not tell which
line to fix. When a line names the stale name and an existing successor with the word
"erratum" but is not an erratum, the violation now ends with
`; line N is not an erratum (an erratum line starts `Erratum (#<issue>): ` at column 0, ...)`.
The verdict is unchanged: the near-miss line still clears nothing.
