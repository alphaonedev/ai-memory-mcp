**A world-writable `[audit].path` now refuses boot (#3974).** With
`[audit].enabled = true` and a configured audit directory that is
world-writable, `audit::init_from_config` used the non-strict resolver,
which silently moved the trail to the platform default. Compliance and
forensic queries against the configured path then found nothing.
`docs/security/audit-trail.md` promised a refusal, and boot now gives
one: exit 78, naming the world-writable directory and the
`[audit].enabled = false` escape hatch.

The two places that still fall back now say so on stderr, naming the
refusal and the path they used. They are the best-effort forensic JSONL
init, and `ai-memory audit verify` / `tail` / `path` on the read side.
Upgrade note: a deployment whose audit directory is world-writable stops
booting. `chmod o-w <dir>`, or point `[audit].path` elsewhere.
