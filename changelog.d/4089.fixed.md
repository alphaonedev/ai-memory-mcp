- **HTTP handlers no longer run CPU-bound embed/rerank inline on tokio
  workers** ([#4089](https://github.com/alphaonedev/ai-memory-mcp/issues/4089)).
  Every HTTP handler that ran the embedder or the cross-encoder reranker
  inline on an async worker now runs it on the blocking pool through one
  module, `handlers::embed_offload` (rust-1.98 CONCURRENCY-22), the
  request-path twin of the #3988 boot-backfill fix. Sites: bulk create
  (`embed_batch` per chunk), single create (both backends), update
  embedding regeneration, `check_duplicate` (both backends), the recall
  query embedding and the hybrid rerank (both backends), the
  `memory_smart_load` family pick (both backends; the sqlite branch now
  picks BEFORE taking the DB lock), and the sqlite `memory_reflect`
  embedding (precomputed BEFORE the DB and vector-index locks).
  - **Effect.** A forward pass held its worker for 10–200 ms per row
    (bulk: whole 100-row chunks; smart_load: the intent plus every family
    descriptor). Since tokio 1.52.2 reverted LIFO-slot stealing, work
    parked behind that worker (`/health`, the postgres pool acquire,
    shutdown) stayed stranded until it returned.
  - **Integrity.** The update regeneration runs AFTER the new text is
    committed, so the embed, `set_embedding` and the vector-index refresh
    run as ONE blocking task that owns the DB guard: a dropped request
    (client disconnect) can no longer leave the row with its old vector
    for its new text.
  - **Failure posture.** A blocking task that does not complete (a panic,
    or runtime shutdown) degrades exactly like an embed failure
    (vectorless write, keyword recall, pre-rerank ordering, keyword family
    routing) or fails closed (`check_duplicate` 503). It is never silent:
    one `embed.task.failed` WARN plus the new
    `ai_memory_embed_task_failed_total{surface}` counter.
  - **Tests.** `tests/http_embed_off_worker_4089.rs` drives every site
    through the real router on a one-worker runtime with a stand-in
    forward pass (`embeddings::test_hold_hook`, test builds only) and
    asserts a concurrently spawned task is still polled promptly; on the
    unfixed tree each probe waits the full 2 s hold.
