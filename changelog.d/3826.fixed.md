Replace the `[decision]` structural ratchet with one that asserts the property
instead of the calendar. `no_seam_consults_the_decider_yet` asserted a fact with
an expiry date — it had to be deleted by the first unit that wired a seam — and
on the stacked `[decision]` integration base it was already red for a reason
that was not a defect in any cut: the allowlist was tightened on one branch and
five provider-client modules were added on a branch cut before the tightening,
so the stack inherited a list that had never seen them. Those five modules
IMPLEMENT a decision provider and are constructed BY the boot chokepoint; none
of them obtains a decider from a production path, and the allowlist now says so
in the file.
The successor, `every_decider_comes_from_the_boot_chokepoint_3806`, pins what
does not expire: a `DecisionProviderHandle` is obtainable only from
`decision_boot::build_decision_provider`, so an ungated second decision endpoint
cannot appear without someone editing a reviewed list. It asserts the chokepoint
monopoly in BOTH directions (no unlisted file may reach it, and every listed
file must), that the handle type is named by exactly one file, that its fields
are all private, and that the whole crate holds exactly ONE construction site
for it. Every absence assertion is paired with a presence control — the walk
must see the tree, the token scan must register hits where the tokens really
are, and the allowlist may not rot into a permission nobody exercises — so an
empty offender list can never silently mean the walk is broken.
