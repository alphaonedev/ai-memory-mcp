Governance policy resolution on SQLite now fails closed on a read fault. A `namespace_meta` query error, a parent-link read error, or a failure to load the bound namespace standard (for example a fail-closed decrypt of an encrypted standard) previously collapsed into "no policy configured", so an Owner/Approve policy that could not be read was treated as absent and an Enforce-mode write fell through to the ungoverned allow decision. `resolve_governance_policy`, the governance chain walk, the namespace-owner lookup and the approval / skill-promotion depth thresholds now return the error; the Enforce gate, approve/reject approver resolution, reflection and link depth caps, bulk forget, gc sweep, skill promotion and federation receive (both backends; the PostgreSQL receive path also stopped mapping a policy read error to the default depth cap) refuse on it. Advisory mode still logs and allows by contract, and optional policy-driven features (auto-classify, auto-atomise, auto-export) stay off when the policy is unreadable (#4043).
