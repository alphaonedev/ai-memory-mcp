The wake plane now has a client. `ai-memory wake-listen` replaces the fleet's
three-minute `ai-memory inbox` cron — one process boot per poll, three minutes
of worst-case latency, a database read whether or not anything happened — with
ONE long-lived session that reads the inbox when there is something to read.

It loads the scoped `a2a-hub/join/v1` delegation bundle
`ai-memory identity delegate --scope a2a-hub` writes into the key directory
(`<key-dir>/<agent-id>.a2a-hub.json`, mode 0600), which holds a DELEGATED
private key and never the enrolled one — there is no second identity root and
no second enrolment ceremony. It connects to the hub's Unix domain socket after
checking it the way the hub hardened it (an owner-only `0700` directory holding
an owner-only `0600` socket, both owned by the caller), performs the hello
handshake with the same codec and frame ceiling every other peer uses, and
verifies the welcome rather than assuming it.

From there it performs **exactly one** catch-up inbox read per event, through
the same `memory_inbox` funnel `ai-memory inbox` uses — never a read per queued
hint: one on the welcome, one on each wake, one when the welcome reports
`lagged`, and one when a wake's `seq_high_watermark` skips (wakes happened that
this listener did not see). On each wake it prints one JSON line (`--json`) or
runs an exec hook (`--exec`) whose wake metadata rides in environment variables
— `AI_MEMORY_WAKE_REASON`, `_INBOX_ROW_ID`, `_NAMESPACE`, `_SENDER`, `_DIGEST`
(lowercase hex SHA-256 **of the body**), `_SEQ`, `_MISSED`, `_PENDING`,
`_INBOX_COUNT` — and never the body, which the plane structurally never
carried. The hook is bounded at 30 s and killed past it, so a hung notifier
cannot become a listener that stops reading its inbox.

`ai-memory inbox --wait [--timeout <secs>]` is the one-shot form: block on the
wake plane (the hub when one is configured, otherwise the bounded backstop
poll), then perform and print the read exactly as a plain `ai-memory inbox`
does. Waiting changes WHEN the read happens, never WHAT it returns; on timeout
the read still happens, because "nothing arrived in that window" is never a
reason to skip the durable truth.

The bounded `<= 60 s` poll (`wake_sink::BACKSTOP_POLL_MAX`) is ALWAYS armed,
hub or no hub, and its clock is reset by every catch-up read rather than firing
on a fixed schedule. A hub that is down, refusing, or was never deployed
therefore costs wake LATENCY and nothing else; `--poll-secs` is REFUSED above
60 rather than clamped, because a listener that silently polled less often than
the plane's contract would be reporting a guarantee it does not provide.
Reconnects use jittered exponential backoff capped at that same bound, with the
ladder resetting only after a session that actually lasted, so a hub that
accepts and instantly drops cannot become a hot loop and a fleet restart cannot
produce a synchronised reconnect blast.

Identity fails closed with no flag that opens it: a bundle that is not mode
0600, not owned by the caller, reached through a symlink, a version this build
does not understand, minted for another hub, minted for a different agent than
the one being watched, holding a private key that is not the one its certificate
authorises, carrying a certificate that does not verify under the agent's
ENROLLED public key in the same key directory, or outside its validity window,
is refused BEFORE the socket is dialled — the expiry case with the re-mint
command in the message, rather than as an opaque `401` after a reconnect ladder.

Minimal SDK clients ship alongside: `ai_memory.wake` (Python) and
`@alphaone/ai-memory/wake` (TypeScript). Both load the same on-disk bundle from
the key directory — no embedded second identity root — speak the same frames,
run the same state machine, and honour the same bounded reconnect.

Proven on both backends: `tests/wake_client_3470.rs` drives a real
`memory_notify` on a real sqlite store through the real `agent_notified` bus,
the real #3469 sink, a real hub across a real Unix domain socket, past the
SHIPPED `ScopedDelegationVerifier` (no permissive test verifier), into a real
listener that reads the durable row back; `tests/wake_client_postgres_3470.rs`
proves the same chain for a committed `PostgresStore::notify` against a live
cluster.
