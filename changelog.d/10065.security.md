### Security

- **[federation] The shared-source binding compares and digests exactly what the daemon acts on**
  ([#10065](https://github.com/alphaonedev/ai-memory-mcp/issues/10065),
  [#10067](https://github.com/alphaonedev/ai-memory-mcp/issues/10067),
  [#10076](https://github.com/alphaonedev/ai-memory-mcp/issues/10076),
  [#10077](https://github.com/alphaonedev/ai-memory-mcp/issues/10077),
  [#10079](https://github.com/alphaonedev/ai-memory-mcp/issues/10079)). Under the
  enterprise-federation posture the flag-to-source comparison and the boot / check #23 digest now
  take one canonical binding key: per peer, the push URL the daemon dials (scheme and host
  lowercased, default port dropped, path and userinfo case kept), the outbound patterns as a sorted
  set without repeats, and the pull-side `peer_ids`. Before, a flag that differed only in path or
  userinfo case bound as matching although the daemon dialled other URLs, a `peer_ids` change left
  the digest unchanged, and a reordered pattern list changed it. The digest domain is now `v2`, so a
  digest printed by an earlier build differs. A divergence refusal from `sync-daemon` now names
  `--peers` (the flag it was given), not `--quorum-peers`.
