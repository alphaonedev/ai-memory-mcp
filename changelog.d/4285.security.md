A namespace governance standard whose `metadata.governance` does not deserialize is now handled as a SEVERED standard (#2503) at every level of the chain on both backends, reversing the #1384 behaviour of skipping it as if no policy were set (which silently fell through to allow-on-silence). The walk continues and write/promote/delete resolve to at least the Owner floor, so a corrupt stricter child or a corrupt `*` standard no longer opens the namespace to non-owners and no longer locks out the owner. PostgreSQL gains the same typed-parse WARN the SQLite read already emitted (it previously swallowed the error silently). `ai-memory doctor` reports every corrupt standard as Critical on both backends and the daemon, MCP server and postgres connect log a boot WARN listing each one. Documented limit: a corrupt policy that meant stricter than Owner (approve/consensus) degrades to the Owner floor until repaired with `memory_namespace_set_standard`; federation receive is unaffected by the Owner floor (peer attestation and namespace scope authorize it) (#4285).
