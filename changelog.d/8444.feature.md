The daemon now speaks the Google Agent2Agent (A2A 1.0) standard on the server side (#8444, shape S1, posture P1, decided by 3-agent vote 6def5ab6). Two routes are added: `GET /.well-known/agent-card.json` and one JSON-RPC 2.0 endpoint `POST /api/v1/a2a` serving `SendMessage` (blocking), `GetTask`, `ListTasks` and `CancelTask`. Streaming, subscribe and the extended card answer `-32004`, the push-notification-config methods answer `-32003`, and the Agent Card declares exactly that. Both routes sit behind the existing `api_key_auth` (an unauthenticated card request is `401`, no exemption was added) and every method needs a credential-derived agent identity; inbound messages are stored in the caller's inbox stamped with `content_principal` (the authenticated agent id) and an untrusted `a2a_role` label, and another caller's task answers `-32001` with HTTP 404, while a terminal task of the caller answers `-32004` with HTTP 400 naming the state. A task's history is content-free (message ids, role and the inbox memory id); GetTask renders the text from the inbox memory, so erasing, deleting or garbage-collecting that memory removes it from every task view, and export carries the content-free `a2a_tasks` rows. The Agent Card URL comes from `AI_MEMORY_PUBLIC_URL` or the daemon's own scheme and bind address, never from request headers. Tasks persist on SQLite (migration 0085) and Postgres (migration 0058) with atomic compare-and-set state changes. The schema version is now 101, the production route count 105 and unique paths 91. Wire types from the official a2a-lf 0.4.2 crate (operator-approved Option B) are adopted for the A2A wire types and error codes only; the server, authentication, dispatch and storage are first-party.
