Fix the documented seed-rule ceremony (`rules sign-seed` →
`governance install-defaults --yes`), which produced four silently INERT rules.
`install-defaults` issued a raw `UPDATE governance_rules SET enabled = 1` that
did not touch the signature column, while `sign-seed` commits `enabled` into the
canonical payload — so every seed signature stopped verifying, the #1042 L1-6
load gate dropped all four rows, and `rules check` answered `allow` while the CLI
reported them activated/enabled/operator_signed. Enabling a signed rule now goes
through the audited `set_enabled_signed` transaction (flip + re-sign of the
post-state + signed audit row + policy-version advance), refuses before any write
when the operator key cannot be loaded, and self-heals rows an earlier ceremony
left inert. `rules_store::set_enabled` now refuses to flip `enabled` on an
`operator_signed` row without re-signing. Every status surface —
`install-defaults` output, `ai-memory rules list`, MCP `memory_rule_list` and the
`ai-memory doctor` Governance section — reports the REAL enforcement state
(`enforced` / `enforcement_state`) derived from signature validity, never from the
raw `enabled` column.
