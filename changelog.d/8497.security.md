### Security

- **[identity] `entity_register` owner is the verified subject on MCP, HTTP and both backends**
  ([#8497](https://github.com/alphaonedev/ai-memory-mcp/issues/8497), umbrella
  [#8493](https://github.com/alphaonedev/ai-memory-mcp/issues/8493)). Before
  this change the MCP tool let a wire `agent_id` beat the process principal,
  `POST /api/v1/entities` preferred the body `agent_id` over `X-Agent-Id`, and
  the postgres funnel kept an inline `metadata.agent_id` over the resolved
  owner (`or_insert`), so a caller could register an entity as anyone.
  - **One rule** (`identity::entity_owner`): the owner is the verified
    governance subject. A differing body `agent_id` or inline
    `metadata.agent_id` is refused (HTTP 403 `AGENT_ID_MISMATCH`, MCP mismatch
    error, SAL `PermissionDenied`) and written to the audit trail with outcome
    `deny`; no entity row is written.
  - **Backend parity**: `SqliteStore` and `PostgresStore` `entity_register`
    both stamp the resolved owner with `insert` (the #3171 behaviour).
  - **Behaviour change**: an inline `metadata.agent_id` that differs from the
    caller used to be silently overwritten; it is now refused.
