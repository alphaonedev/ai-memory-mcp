### Security

- **[sdk-python] TLS verification is enforced at use time on an SDK-owned context**
  ([#6249](https://github.com/alphaonedev/ai-memory-mcp/issues/6249),
  [#6267](https://github.com/alphaonedev/ai-memory-mcp/issues/6267),
  [#6306](https://github.com/alphaonedev/ai-memory-mcp/issues/6306)). `AiMemoryClient` and
  `AsyncAiMemoryClient` no longer hand the caller's `verify=` object to `httpx`. Every client builds
  its own private, frozen TLS context, loads `cert=` into it, and re-checks `CERT_REQUIRED` plus
  hostname checking before every handshake and again after the SSL object is created. A caller
  context weakened after construction, a truststore context with verification off, or a concurrent
  `verify_mode` flip can no longer reach a handshake.
- **The owned context never verifies more weakly than a caller's `ssl.SSLContext`.** Each stricter
  caller setting is carried and read back, or the construction is refused by name: CA certificates,
  `verify_flags` (for example `VERIFY_X509_STRICT`), `options` (for example `OP_NO_TLSv1_2`), a
  higher minimum or lower maximum TLS version, a higher security level, a narrowed cipher list and
  `hostname_checks_common_name` off are carried; the SDK floor (default-context flags and options,
  TLS 1.2 minimum) is never lowered. Refused with `ValueError`: `verify=False`, verification or
  hostname checking off, CRL checking, no copyable CA certificate, an empty version range, unknown
  flag or option bits, a cipher list that cannot be carried (including TLS 1.3 suites narrowed
  with `set_ciphersuites()` on Python 3.15+), a non-default `sni_callback`, a
  setting whose getter is missing or raises, an unclassified `SSLContext` attribute that differs
  from a default context, CA paths that are missing, unreadable, larger than 16 MiB or neither a
  file nor a directory, and any unclassifiable `verify=` or `cert=` value. Never carried:
  `set_client_sigalgs` (Python 3.15+; the client's own signing algorithms, not server
  verification). Named residuals with no getter: the ECDH curve, the key-exchange groups
  (`set_groups`, Python 3.15+), the signature algorithms accepted for the server's handshake
  signature (`set_server_sigalgs`, Python 3.15+; bears on server verification, the owned context
  keeps OpenSSL's default list bounded by the carried security level) and the NPN list (httpcore
  sets ALPN).
- **truststore without the 0.10.5 shape is refused at construction** (a re-entrant `_ctx_lock`
  and the verifying socket and SSL-object classes); truststore 0.10.4 and older are refused by
  name instead of risking a deadlock or an unverified handshake.
- **CI tripwire.** The `sdk-python-tls-tripwire` job in `clients-ci.yml` runs on Python 3.10,
  3.11, 3.12, 3.13 and the newest 3.x, and fails, naming the attribute and the table, when a
  Python adds an `SSLContext` setting the SDK does not classify.
