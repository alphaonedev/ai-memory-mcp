- **[data-integrity] An unset archive retention bound no longer purges the
  whole archive** ([#9945](https://github.com/alphaonedev/ai-memory-mcp/issues/9945),
  GA standard 1). The PostgreSQL maintenance loop called the archive purge
  with no bound whenever `archive_max_days` was unset, which deleted every
  archived row on every tick. The bound is now a validated type
  (`RetentionDays`, 1..=36500): an unset, zero, negative or over-cap value
  has no constructor and the maintenance pass deletes nothing on both
  backends. The SAL `archive_purge` takes `RetentionDays` (the `Option` form
  is gone) and the explicit operator purge-all is the separate
  `archive_purge_all`. The serve loops now read the documented
  `[storage].archive_max_days` (it wins over the deprecated flat key; before
  this fix the `[storage]` key was ignored). HTTP `DELETE /api/v1/archive`,
  MCP `memory_archive_purge` and CLI `archive purge` refuse a zero, negative
  or over-cap `older_than_days` with the exact reason instead of purging every
  row; MCP also refuses a malformed value instead of failing open to
  purge-all. Coverage: `tests/archive_purge_unset_bound_9945.rs` (sqlite and
  postgres cells) and `tests/l07_3_chunk_d_http_surface.rs`.
