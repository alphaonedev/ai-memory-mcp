### Security

- **[http][identity] `POST /api/v1/session/start` no longer takes its visibility caller from an unproven body `agent_id`**
  ([#8947](https://github.com/alphaonedev/ai-memory-mcp/issues/8947)). Under `enforce`, a shared-transport-key caller
  that sent no `X-Agent-Id` header and named an agent in the body `agent_id` got that agent's private rows. The body
  principal is now held to the same proof as the header principal. Changed answer, the only one: under `enforce` a
  shared-key caller that sends an agent id in the session-start body now gets `403` `attested_identity_required`
  (it was `200`, including for the caller's own claimed id) and must use a per-agent key or a mapped certificate, the
  same answer the header form already gave. Every other mode, key kind, header and body combination answers as before,
  pinned by `m8947_*_default_mode_matrix_is_unchanged` and `m8947_*_enforce_own_id_matrix`.
