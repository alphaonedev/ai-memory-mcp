### Security

- **[http][identity] `POST /api/v1/session/start` no longer takes its visibility caller from an unproven body `agent_id`**
  ([#8947](https://github.com/alphaonedev/ai-memory-mcp/issues/8947)). Under `enforce`, a shared-transport-key caller
  that sent no `X-Agent-Id` header and named an agent in the body `agent_id` got that agent's private rows. The body
  principal is now held to the same proof as the header principal. Changed answer: under `enforce` a shared-key caller
  that sends an agent id in the session-start body now gets `403` `attested_identity_required` (it was `200`,
  including for the caller's own claimed id) and must use a per-agent key, the same answer the header form already
  gave. A certificate-bound caller on the shared key is refused the same way today
  ([#8590](https://github.com/alphaonedev/ai-memory-mcp/issues/8590)). Pinned by
  `m8947_*_default_mode_matrix_is_unchanged` and `m8947_*_enforce_own_id_matrix`.
- **[http][identity] session start acts as the principal its identity gate judged.** An empty `X-Agent-Id` header
  is resolved to the anonymous principal by the gate, and that principal (not the empty string) is now the
  visibility caller, so an empty header sees the shared rows and no private row of any owner. Pinned by
  `e8947_*_blank_header_*`.
- **[http][identity] the namespace-standard read (`GET /api/v1/namespaces/{ns}/standard` and
  `GET /api/v1/namespaces?namespace=...`, with or without `inherit=true`) now runs the per-agent identity gate** ([#9355](https://github.com/alphaonedev/ai-memory-mcp/issues/9355)) before it resolves
  its visibility caller, as the set and clear forms already did. Changed answer: under `enforce` a shared-key caller
  naming another agent in `X-Agent-Id` gets `403` `attested_identity_required` instead of that agent's
  `scope=private` standard. The default mode and zero-enrolled-key deployments answer as before.
- **[visibility] a blank caller never matches a `scope=private` row**
  ([#9356](https://github.com/alphaonedev/ai-memory-mcp/issues/9356)). The visibility SSOT compared an absent owner,
  target or legacy-inbox recipient (read as `""`) to the caller with `==`, so an empty or whitespace caller matched
  every such row on SQLite. It now denies a blank caller first; PostgreSQL already refused these rows in SQL.
