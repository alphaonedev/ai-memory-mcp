Federation `/sync/push` now re-authorizes the pushing peer's namespace scope inside the write transaction for the `deletions[]`, `archives[]`, `restores[]` and `links[]` lanes on both SQLite and PostgreSQL, the sibling of the #4023 merge fix. Previously each lane authorized the target row's stored namespace on a read that preceded the write, then wrote by id, so a broader-scoped writer that moved the row out of the peer's scope in between had the narrow peer's delete, archive, restore or edge land on a row it was never authorized for (data loss on the deletion lane). The row's stored namespace (the archived row's for restores, both endpoints' for links) is now re-read under the write lock (`FOR UPDATE` on PostgreSQL, the write transaction on SQLite) and the same shared by-id verdict is re-evaluated; a refusal rolls back, writes nothing and is the typed `PermissionDenied` on both backends. The unchecked writers remain for tests and operator tooling and are pinned by a production-caller ceiling.
