**`logs tail --follow` no longer goes quiet when a recreated log file cannot be opened yet.** On a same-name rename-and-recreate the new file is opened before the follower leaves the old handle; on failure one `logs: cannot open <path>` note is written to stderr, the renamed file keeps draining, and the open is retried every poll until it succeeds, then the new file prints from its start (#8062, duplicate report #8063).
