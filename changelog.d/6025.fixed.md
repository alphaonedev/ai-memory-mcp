The append-only scratch janitor (`scripts/clear-append-only-scratch.py`) no longer puts back a mode recorded in its pending-restore journal on an inode that has more than one link (#6025). Finishing a recorded widen is a mode change like the widen itself, and an inode with a second name may live outside the scratch tree, so the replay now applies the same shared-inode refusal the widen step applies (#5936): the inode is left exactly as it is, the entry is reported, the run exits non-zero and the journal line is kept for a run that meets the inode with one link again. Before this, a journal line could reach a shared inode the normal path refuses, which was a fail-open regression introduced with the journal itself.
