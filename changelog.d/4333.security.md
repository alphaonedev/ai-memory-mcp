**`ai-memory doctor`'s postgres probes now refuse a store URL below the transit-encryption floor.** The Postgres extensions, Unstamped owners and Identity key-registry sections (and the `keys` and `schema-init` enumeration reads) built their own connection from the store URL and dialled the driver default, so a URL the daemon refuses (no `sslmode`, `prefer`, `disable`, `require`, a later weaker `sslmode`, a Unix socket) was still connected to without a verified TLS channel. Every production postgres connection now takes its options from one function that applies the same `sslmode=verify-full` floor as the store funnel before any socket opens; a refusal is reported as the section's own fact and the URL is never echoed (#4333).
