The count-assertion gate (`scripts/check-count-assertion-declared.sh`) compares the assertion set of every eligible `src/` and `tests/` `.rs` file between a commit and its parent (rename and copy sources included) and flags every assertion `assert(_eq)!(<expr>.len()|.count(), <rhs>)` whose count moved, appeared or disappeared (#5499, #5517, #5518). A brand-new assertion is skipped only when its file is added in that commit and the same expression does not exist anywhere in the PARENT tree; the same expression added in two new files of one commit is skipped in both. The right-hand side is read in full (decimal, `0x`, `0o`, `0b`, underscores and type suffixes are normalised; any other right-hand side is an undecidable `?<spelling>` value that a declaration must repeat), and a named const is resolved over the whole tree, so a const bumped in another file moves every assertion spelled through it; an unresolvable or ambiguous name is flagged, never read as unchanged (#5577, #5578). A move is accepted only when the commit's own `Count: <what> <old> -> <new> (<why>)` trailer, or a later `Count-Declared: <40-char sha> <what> <old> -> <new> (<why>)` trailer of the same range, names it: `<what>` is the whole expression or a whole-token word of at least 3 characters (a one- or two-character word names nothing), and items are consumed one-to-one, one item per changed assertion (#5575, #5576). The workflow chooses the range only through `scripts/ci-commit-range.py` (#5579), which refuses what it cannot decide and has no fallback range: `pull_request` runs merge-base(base, head)..head; `merge_group` runs `merge_group.base_sha..head_sha`; `push` runs `before..sha` only when `before` is a full, non-zero, 40-char lowercase sha that resolves to a commit in the checkout; any other event, or a missing, zero, malformed or unreachable sha, is a red job (exit 1), never a one-commit check. Limits: the creation push or force-push of a protected branch is red and a re-run cannot turn it green (its commits were checked under `pull_request`); and the `merge_group.base_sha` field is taken from the GitHub event payload and has not yet been observed in a real merge-queue run. Carrier-history offenders outside the range are not checked. Merge commits are exempt by design.
