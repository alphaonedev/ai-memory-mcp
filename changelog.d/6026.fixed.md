The janitor's pending-restore journal can no longer wedge every later run (#6026). A journal that ends in an incomplete line has that line cut off and the walk proceeds: every line is fsynced before the chmod it describes, so a line that never became whole describes a chmod that was never made, and the run that cuts it off reports it once and exits non-zero. An append that fails part-way takes back the bytes it wrote, so it leaves no incomplete line behind; if it cannot, the journal stays refused as before. A journal over the 1 MiB read limit is still not read, and the report now says how to resolve it.
