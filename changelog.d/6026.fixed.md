The janitor's pending-restore journal can no longer wedge every later run (#6026). A journal that ends in an incomplete line has that line cut off and the walk proceeds. The cut is safe only because one run at a time owns the journal: the run holds an exclusive lock on it from before its first read until it lets it go (#6032, #6034), every line is fsynced before the chmod it describes, so under that lock an incomplete line describes a chmod that was never made, and the run that cuts it off reports it once and exits non-zero. A run that cannot take the lock does not read, cut or write the journal. An append that fails part-way takes back the bytes it wrote, so it leaves no incomplete line behind; if it cannot, the journal stays refused as before. A journal over the 1 MiB read limit is still not read, and the report now says how to resolve it.
