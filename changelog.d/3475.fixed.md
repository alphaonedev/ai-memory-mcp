Lib tests no longer install a process-global `AI_MEMORY_AGENT_ID`, which had
made `mcp::tests::handle_get_*` fail nondeterministically on the
`Check (macos-fed,sqlite)` leg. `AI_MEMORY_AGENT_ID` is read by
`identity::resolve_read_visibility_caller()` on every MCP read dispatch, and
`visibility::is_visible_by_fields` treats a row with no `metadata.scope` as
`private` and therefore owner-keyed — so while one lib test held a shape-valid
value there, every concurrently-running test in the same process stopped seeing
rows carrying no `metadata.agent_id`: `memory_get` masked them as not-found and
`memory_get_links` filtered their neighbours away. The crate-wide
`identity::agent_id_env_test_lock()` could not close this, because it
serializes the mutators while the victims are the hundreds of unlocked readers.
#3356's boot-refusal test therefore moves, with identical assertions, into its
own test binary — `tests/mcp_agent_id_env_isolation_3475.rs`, which is its own
process — the two `memory_inbox` envelope tests now assert against the default
fail-closed posture's own derived owner instead of installing `test-bot`, and
the lib-test-only `agent_id_env_set_guard` fixture is deleted so the affordance
no longer exists. `scripts/check-test-env-lock.sh` gains arm
(d): a per-file census ratchet
(`scripts/qc-allowlists/test-env-mutation-baseline.txt`) that refuses any new `src/**` env
mutation, and any increase in `AI_MEMORY_AGENT_ID` installs, going forward. No
production behaviour changes; #3356's caller-isolation and fail-closed boot
gate are untouched.
