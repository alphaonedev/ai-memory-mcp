**#4218 — a federation peer can no longer pin `memories.version` at `i64::MAX`.**
The merge only ever takes the larger version, so one enrolled peer pushing
`i64::MAX` pinned the row on every node and overflowed the next local
`version + 1` (on sqlite the column turned into a REAL). The shared receive
validation now refuses an inbound version outside `0..=2^40` (per item, the rest
of the batch is applied), every merge funnel clamps the peer's version to
`local + 2^32`, and every sqlite `version + 1` saturates at `i64::MAX` instead
of overflowing (postgres fails the statement cleanly on the bigint edge).
