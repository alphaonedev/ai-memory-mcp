**Cross-build database safety (#8677).** An older ai-memory binary that opens a
database written by a newer build is refused with a typed `SchemaAheadOfBinary`
error whose text now says what happened and how to recover: the database was
written by a newer ai-memory build (schema vN), this binary supports schema vM,
upgrade ai-memory to the build that wrote it, or open a backup copy with
`--db <copy>`. The file is left byte-identical (sqlite sha256, postgres table
digest). The derived-state trigger repair that runs at an unchanged schema
version (#4078) now takes the same pre-migration safety snapshot as a schema
move. `docs/integrations/claude-code.md` gains "Running more than one ai-memory
build". New suites: `cross_build_db_compat_8677` (sqlite) and
`postgres_cross_build_db_compat_8677` (postgres).
