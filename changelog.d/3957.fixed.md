**SQLite ownership gate is atomic across processes (#3957, the sqlite sibling of #3953).** The SAL `update` and `delete` funnels now run the caller-owns check and the write it authorises in ONE `BEGIN IMMEDIATE`. The in-process mutex only serialised one process, and MCP stdio, `curator`, `serve` and every CLI invocation can share one database file, so another process could commit an ownership change between the check and the write and the write landed on a row someone else owned by then. `archive_memory` and `set_lifecycle_state` now join a caller-owned transaction instead of failing on a nested `BEGIN`. On the sqlite trait `update`, a content patch plus an illegal lifecycle transition now rolls back as a unit rather than committing the content and then returning 409. Pinned by `src/store/sqlite/owner_gate_txn_3957.rs`, which fires a second connection on the same file between the gate and the write.
