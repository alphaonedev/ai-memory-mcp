**A read never mints an at-rest key (#3718, GA data-loss amplifier).** A read
of a sealed row whose per-agent `.x25519.priv` was missing minted and
persisted a brand-new key before failing to decrypt, masking the loss as
"wrong key" and forking the key generation so no single restore could heal
the corpus. The accessor is split: `encryption::load_keypair` (cache +
disk, NEVER mints) serves both decrypt arms of `open_content`;
`get_or_create_keypair` stays the SEAL path only. A missing key is the
typed `encryption::KeyAbsent { agent_id, expected_path }`, distinct from an
AEAD failure — the caller gets the class (`key_absent`) and the agent, the
operator log (`security.encryption.keys`) gets the expected path and the
remedy; the row is untouched. Sibling: a write for an agent whose key
directory holds archived material of a prior generation and no live key is
refused (`key_generation_gap`) instead of minting generation N+1.
`encryption::evict_cached_keypair` lets a restored key be picked up without
a restart. `tests/encryption_at_rest.rs::commit_b_missing_key_fails_closed_on_read`
tested a WRONG key, not an absent one, and is renamed
`commit_b_wrong_key_fails_closed_on_read` (the pg parity twin likewise);
the absent-key case is pinned by `tests/encryption_key_absent_3718.rs`
(+ `_pg`, `_head`).
