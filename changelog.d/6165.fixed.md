**Dead `Write(...)` deny rules in `.claude/settings.json` (#6165).** The three
`permissions.deny` entries that enforce the "no agent-created files under /tmp,
/var/tmp, /private/tmp" project rule were written as `Write(path)`, a form Claude
Code never matches against file-editing tools (every launch printed "Permission
deny rule ... is not matched by file permission checks - only Edit(path) rules
are"), so the rule was a no-op. They are now `Edit(//tmp/**)`, `Edit(//var/tmp/**)`
and `Edit(//private/tmp/**)`. The double leading slash is required: in a Claude Code
permission rule a single leading slash is project-root relative, so `Edit(/tmp/**)`
would only deny `<repo>/tmp/**`. `Edit` covers Write, Edit and NotebookEdit. The new
gate `scripts/check-settings-deny-rules.py` (with `--self-test`, wired into the
`c8-precheck.yml` docs gate job beside the CLAUDE.md size guard) requires the three
`//` entries, rejects the single-slash absolute forms, and rejects `Write(`,
`NotebookEdit(` and `MultiEdit(` entries in `deny`, `ask` and `allow`.
