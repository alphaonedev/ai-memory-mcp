**Vector-index insert rejections are classified: malformed caller data is a WARN and a counter, index loss stays an ERROR (#3665, audit #3645 F19).**

Strict-dimension and empty-vector rejections (`hnsw` and `vectorlite` backends) emitted `tracing::error!` per item at the same severity as an index that cannot load or has degraded, so a caller or mis-configured embedder sending bad vectors paged like an infrastructure incident and could bury the one ERROR that meant the index was actually lost. New `vector_index_rejections` module: every refused insert is counted on `ai_memory_vector_index_insert_rejected_total{cause}` (`invalid_dim` | `empty_embedding` | `capacity`, closed set, pre-touched) and logged at the class's severity — invalid input at WARN with `cause` and the dimensions, capacity (hard-fail-at-cap) at ERROR as before. Sustained invalid input (10 rejections inside one 60 s window) emits exactly ONE ERROR per window naming the embedder dimension-drift shape, then re-arms. Backend failures (extension load, hard-failure degrade) keep their ERROR lines and gain `ai_memory_vector_index_failure_total{kind}`. Index behaviour is unchanged (rejected vectors never enter the graph). Tests cover invalid input vs capacity vs backend failure, the once-per-window escalation with an injected clock, and the counters through the real `hnsw` insert path.
