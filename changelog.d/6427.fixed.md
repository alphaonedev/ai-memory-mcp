**The cert-expiry gate compares identifier occurrences per defining line, so an offsetting mention can no longer hide a removed `AI_MEMORY_FED_*` definition (#6427).** The #6370 fix compared one occurrence count per identifier name, so a change that removed the live definition and added a mention elsewhere (another file, a comment in its place, a longer token containing the name, a block comment opened and closed on the defining line, text copying the drift annotation) kept the count and the certificate stayed LIVE. `extract_fed_id_counts` now keys matches on (identifier, trimmed line text) and the pattern has a left word boundary; `fed_id_delta` reports a name as removed when any of its lines is gone from the head, and a line moved between files or re-indented is not drift. The `(mask-xfile)`, `(mask-incomment)`, `(mask-longer)`, `(mask-blockcomment)` and `(mask-annot)` cells pin the five bypasses; `(mask-confusable)`, `(mask-confusable-note)`, `(mask-zwsp)`, `(mask-crsplit)`, `(mask-note-removed)` and `(mask-moved)` pin the neighbours. An edit to the identifier-bearing line itself (a value on that line, a rewrap, a trailing comment) is drift; a value on another line is not. The check is a text scan: a change that leaves every identifier-bearing line byte-identical (a comment opened on a neighbouring line, a compile-out attribute on the line above, a raw-string wrap, a move into a file that is not compiled) is not seen; that lexical bound is stated in the `check_cert_expiry.py` docstring and tracked in #6560. The `(value-same-line)`, `(value-next-line)` and `(doc-bound)` cells pin the split and the wording.
