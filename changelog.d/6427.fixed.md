**The cert-expiry gate compares identifier occurrences per defining line, so an offsetting mention can no longer hide a removed `AI_MEMORY_FED_*` definition (#6427).** The #6370 fix compared one occurrence count per identifier name, so a change that removed the live definition and added a mention elsewhere (another file, a comment in its place, a longer token containing the name, a block comment opened and closed on the defining line, text copying the drift annotation) kept the count and the certificate stayed LIVE. `extract_fed_id_counts` now keys matches on (identifier, trimmed line text) and the pattern has a left word boundary; `fed_id_delta` reports a name as removed when any of its lines is gone from the head, and a line moved between files or re-indented is not drift. The `(mask-xfile)`, `(mask-incomment)`, `(mask-longer)`, `(mask-blockcomment)` and `(mask-annot)` cells pin the five bypasses; `(mask-confusable)`, `(mask-confusable-note)`, `(mask-zwsp)`, `(mask-crsplit)`, `(mask-note-removed)` and `(mask-moved)` pin the neighbours. An edit to the identifier-bearing line itself (a value on that line, a rewrap, a trailing comment) is drift unless the old line text still occurs elsewhere under src/: the line texts are compared as a multiset over all of `src/` without the path, so a copy kept in any file, comment, string or compiled-out code offsets the edit (`(value-copy-bound)`, #6652); a value on another line is not drift. The check is a text scan: a change that leaves every identifier-bearing line byte-identical (a comment opened on a neighbouring line, a compile-out attribute on the line above, a raw-string wrap, a move into a file that is not compiled) is not seen; that lexical bound is stated in the `check_cert_expiry.py` docstring and tracked in #6560. The `(value-edit-5-to-6)`, `(value-next-line)`, `(trailing-comment-added)` and `(doc-bound)` cells pin the split and the wording. The #6564 cells `(mask-u2028)` (a U+2028 line split) and `(mask-trailing)` (a trailing comment removed) pin the two removal shapes, the #6565 cells `(mask-lost2)`, `(mask-trailing-ws)`, `(mask-dup-add)` and `(mask-longer-digit)` pin the lost-count, trailing-blank, identical-line and digit-prefixed-longer-token behaviour, and the #6566 cells `(mask-xfile-gate)`, `(mask-incomment-gate)`, `(mask-longer-gate)`, `(mask-blockcomment-gate)`, `(mask-annot-gate)`, `(mask-u2028-gate)` and `(mask-trailing-gate)` run the seven offset removals through the `pull_request` gate.
