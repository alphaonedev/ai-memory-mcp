### Security

- **[cli][tls][docs] `serve --help`, `docs/SECURITY.md` and
  `docs/CLI_REFERENCE.md` state the real authentication and transport
  default** ([#9017](https://github.com/alphaonedev/ai-memory-mcp/issues/9017)).
  `docs/SECURITY.md` said the HTTP daemon "trusts no one by default. API key +
  mTLS gate inbound" and that peer sync trusts the mTLS allowlist; the transit
  table said a bind without `--tls-cert`/`--tls-key` is refused on every host.
  At the head `serve` binds loopback, demands an API key only when `api_key` is
  set, serves a keyless loopback bind with two boot WARN lines, refuses a
  keyless non-loopback bind (exit 75), serves local-CA TLS on a singleton with
  no flags (`resolve_tls_material`), gates sync by peer enrollment (#1789) and
  requests client certificates only with `--mtls-allowlist`. The documents now
  say that, including what an unauthenticated local client can reach; the
  default-on API key is #2046. The `--mtls-allowlist` help names the TLS
  handshake (not TCP accept) as the gate, and the mTLS-off boot WARN no longer
  says the sync endpoints accept any client. Log and help text only; nothing
  the daemon accepts, refuses or binds changes. The cargo-skip classifier now
  treats `SECURITY.md` and `docs/SECURITY.md` as test-read files. Pinned by
  `tests/cli_serve_help_text.rs` (exact help paragraphs, a plaintext-claim
  scan, a row per bind-guard outcome) and
  `tests/fit_docs_b_false_claims_4000_4009.rs`.
