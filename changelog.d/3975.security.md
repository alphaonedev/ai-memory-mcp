**A flat audit trail that stops recording after boot is no longer silent
(#3975).** `audit::emit` reported a failed write only through `tracing`,
which is a no-op unless the logging pipeline is enabled, and it discarded a
failed flush outright (`.ok()`). A disk filled after start therefore turned
auditing off with no signal, while the daemon kept serving. Every lost event
is now counted in `ai_memory_audit_write_failures_total`, next to
`ai_memory_audit_records_written_total`, `ai_memory_audit_last_write_seconds`
(absent until the first write) and `ai_memory_audit_trail_active`. It is
also reported on stderr at most once a minute, naming that metric. `ai-memory
doctor` gains an "Audit trail (#3975)" section, which is Critical on any lost
event or when `[audit].enabled = true` but no trail is recording. See
docs/security/audit-trail.md §"Detecting a trail that stopped recording".
