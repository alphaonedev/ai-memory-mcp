### Security

- **Curator-derived rows and forensic manifests are signed by the one daemon identity**
  ([#8863](https://github.com/alphaonedev/ai-memory-mcp/issues/8863)). The curator and the
  forensic bundle picked the first key in sort order from the key directory, so whichever label
  sorted first (any agent's key) signed derived rows and manifests. First-sorted-key signing is
  gone: both now use only the daemon key (`DAEMON_KEYPAIR_LABEL`, `daemon.pub` / `daemon.priv` in
  the key directory) through the helper the daemon uses
  (`identity::keypair::ensure_and_load_label_keypair_in`).
  - **The CLI may create the daemon key file.** `curator --once` / `--reflect` and forensic
    export mint the daemon key on first use when it is absent (atomic create, owner-only
    permissions on the private half). The mint logs a WARN naming the key id and the key path;
    back that key up, it is now the attestation identity. With it, curator reflections are owned
    and signed as `daemon`.
  - **Unsigned bundles warn.** Every unsigned outcome (no usable key directory, public half only,
    unreadable private half, key generation disabled) logs a WARN with the reason and the action
    that provisions the key. Under the `asi-hard` profile each of those outcomes refuses the
    export instead, and an unprovisioned daemon key is refused before any mint attempt, so no
    key file is written.
  - **What a first-use key proves.** A key minted on first use proves only continuity (later
    bundles are signed by the same key) and tamper evidence after export; it does not prove who
    ran the export. `forensic verify` still accepts an absent or unknown signer until signer
    pinning lands (Refs #9219).
  - Decision record: `3-agent vote (71472661) Q1 A 2-1` (mint-then-sign, conditions Y-1..Y-6).
