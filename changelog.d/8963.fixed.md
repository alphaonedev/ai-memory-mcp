**LLM-derived results now fail closed on truncated, empty, malformed or unclassifiable replies (#8945, #8963, #9018).** Every chat call on both providers now reads the stop reason (Ollama `done` / `done_reason`, OpenAI-compatible `choices[0].finish_reason`) and accepts a reply only when it finished normally; a truncated (`length`), filtered, tool-call, unrecognised or missing stop reason, and an empty reply, is an explicit `ERR_REPLY_*` error that never echoes the provider's text. A contradiction verdict other than a clear yes or no is now an error instead of being read as "no contradiction" (#8945), and a blank auto-tag reply is refused instead of reported as a clean success. Consolidation with no LLM and no caller summary is refused with `400 CONSOLIDATE_SUMMARY_REQUIRED` instead of storing a placeholder (#9018); an LLM summary failure is `502`/`504 CONSOLIDATE_LLM_SUMMARY_FAILED`; and the legacy disposition now archives every source (`archive_reason` `consolidate`) before deleting it, on SQLite and PostgreSQL, so no path hard-deletes sources without an archive row. `src/llm/reply_integrity_tests.rs` and `tests/consolidate_archive_first_9018.rs` pin the tables.
