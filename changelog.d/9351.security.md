### Security

- **[secret-screen] A password assignment is accepted as a non-credential shape only when the whole value matches
  that shape** ([#9351](https://github.com/alphaonedev/ai-memory-mcp/issues/9351)). The detector accepted an
  unquoted value when only its start looked like an environment lookup (`os.environ["X"]…`, `process.env.X…`), a
  type annotation (`Option<X>…`, `&str…`) or a placeholder (`<…>…`, `${…}`), so bytes after the closer or the type
  were stored verbatim. Each shape is now one grammar matched over the whole value: bytes after a lookup's closer, a
  balanced type or a reference's type name, an unclosed or mismatched bracket, a default inside a lookup
  (`ENV.fetch("X","d")`, `${X:-d}`) and a fallback after a lookup (`or`, `||`, `??`, `?:`, `//`) are now findings
  (reason `password_assignment`). An unclosed lookup and a fallback are masked to the end of the line. Every scan
  stays a single forward pass. Well-formed lookups, annotations (`Option<Vec<u8>>`, `&'static str`, `&mut String`)
  and placeholders stay accepted. Behavior change: a write holding one of the newly refused forms is now refused.
