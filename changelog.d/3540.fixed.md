**Wake-plane authority: the shipped ceremony was refused, and the daemon
producer was evicted every refresh (#3540, EPIC #3466).** Both defects were
found by the #3473 acceptance run against a release build of the wake plane,
and both are authority-plane bugs: a legitimate ceremony refused, and a
legitimate producer evicted.

- **A delegation minted in the same second as its key binding was denied.**
  `AllowlistCache::check_delegate` compared the delegation's `not_before` —
  WHOLE SECONDS by the format's own contract (#3511) — against the allowlist
  entry's `bound_at`, which carries sub-second precision, so the shipped
  ceremony (`generate` -> `register` -> `bind-key` -> `delegate`, back to back
  in one script) minted a bundle the hub always refused with
  `delegation_invalid`. The comparison now runs at the precision the delegation
  carries, through one definition —
  `identity::hub_delegation::check_binding_order` — that lives beside the
  timestamp-precision contract it enforces. The property the check exists for
  is unchanged: a delegation minted in an EARLIER second than the binding is
  still refused, and an unparseable stamp on either side still fails closed.
  Only the equal-second case moves from refused to admitted.

- **The reserved `wake-hub-producer` row was re-stamped on every republish.**
  `identity hub-cache --daemon-producer` wrote `bound_at` = the PUBLISH
  instant, so each 30 s refresher tick moved the binding forward past the
  `not_before` of the delegation the daemon's live session was established
  under; the hub's once-per-second re-validation then refused that session
  (`session authority expired or revoked`) and the wake sink reconnected —
  a permanent, periodic wake-loss window on the shipped refresher cadence.
  `bound_at` is a property of the BINDING, not of the snapshot, so it is now
  read from the binding's own durable record: the modification time of this
  host's `daemon.pub`, which `ensure_keypair` does not rewrite on a restart.
  Two successive publishes of an unchanged key now produce a byte-identical
  row — which also stops the `identity.hub_allow` event the audit spine
  recorded on every single refresh for a grant that never changed. The stamp
  is clamped to the publish instant if the key file is dated in the future, so
  one odd timestamp degrades that host to the old per-publish behaviour instead
  of making the hub refuse the whole snapshot fleet-wide.

No wire or stamp format changed: `not_before` is still whole seconds,
`bound_at` is still RFC3339 with whatever precision its source carries, and the
allowlist file version is unchanged.
