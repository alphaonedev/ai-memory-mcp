**`ai-memory mcp` now drains its forensic writer when stopped by a signal (#4347).** After #4319 `mcp` queued forensic rows on the background writer and drained them at exit, but it installed no signal handler, so SIGTERM (supervisor stop, `kill`), SIGINT (Ctrl-C) and SIGHUP (terminal hang-up) ended it by the default action, `atexit` never ran, and every row still queued was lost. `mcp` now handles all three (Ctrl-C only on a non-unix build): it stops accepting requests, lets a request already in flight finish (bounded by 10 s; an acknowledged write is already durable, a cut-off one was never acknowledged), runs the bounded 5 s forensic drain exactly once (shared with the `atexit` path, so a signal racing a normal exit is one drain), and exits with the conventional code 128 plus the signal number (143, 130, 129). SIGHUP is a stop, not a config reload: the stdio child reloads `[llm]` by config mtime (#2166). `serve` SIGTERM remains #4072. If a stop listener cannot be installed, `mcp` refuses to start (non-zero exit, message on stderr) rather than run with a signal that would lose rows. A request still running when its 10 s budget expires is never acknowledged. A SIGHUP or SIGINT that the parent left ignored (`nohup`, a background job) stays ignored (#4473); SIGTERM always stops it. A second signal during the drain does not abort it. A late row queued behind the first drain is written by a follow-up barrier at exit.
