**`ai-memory mcp` now drains its forensic writer when stopped by a signal (#4347).** After #4319 `mcp` queued forensic rows on the background writer and drained them at exit, but it installed no signal handler, so SIGTERM (supervisor stop, `kill`), SIGINT (Ctrl-C) and SIGHUP (terminal hang-up) ended it by the default action, `atexit` never ran, and every row still queued was lost. `mcp` now handles all three (Ctrl-C only on a non-unix build): it stops accepting requests, lets a request already in flight finish (bounded by 10 s; an acknowledged write is already durable, a cut-off one was never acknowledged), runs the bounded 5 s forensic drain exactly once (shared with the `atexit` path, so a signal racing a normal exit is one drain), and exits with the conventional code 128 plus the signal number (143, 130, 129). SIGHUP is a stop, not a config reload: the stdio child reloads `[llm]` by config mtime (#2166). `serve` SIGTERM remains #4072. This supersedes the "mcp drains only on a normal exit" limit stated in the #4319 entry.
