**Receiver lifecycle state is a federation merge barrier; the nonce replay guard is store-scoped.**
Closes #9147, #9149, #9150 and #9140 (umbrella #8741), on SQLite and PostgreSQL.

- A row the receiver holds at a hidden state (archived without a live copy,
  quarantined, contaminated, federated-deleted) is no longer made live again,
  and the bytes behind a hold no longer change, through any inbound funnel
  (`apply_remote_memory`, `merge_inbound`, `restores[]`, the archive-restore
  verb). A barrier hit is an idempotent no-op inside the funnel's write
  transaction. `dequarantine` lifts a hold only when the stored
  `attest_level` is `agent_attested` (#9150).
- The federation nonce replay guard is now decided by the store every daemon
  shares, so a signed push accepted by one daemon is refused as a replay by a
  sibling daemon of the same store (#9140). PostgreSQL daemons claim each
  nonce in the new `federation_nonce_cache` table (bootstrap DDL, `INSERT ...
  ON CONFLICT DO NOTHING`, bounded per peer); SQLite daemons claim it in the
  existing table of the shared file. New trait method
  `MemoryStore::federation_nonce_claim`; its default refuses.
- Fail closed: a nonce claim that cannot be made (store or disk error) is a
  replay, never fresh, and the daemon no longer falls back at boot to an
  in-memory-only nonce cache when rehydration fails.

**What it costs you.** A sibling replay that used to return 200 now returns
401 with `error: "x_memory_nonce_replay"`. While the store cannot record a nonce
claim, signed federation pushes are refused until it recovers.
