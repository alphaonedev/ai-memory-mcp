**The lax-permissions escape hatches now share one documented grammar (#3620).**
`AI_MEMORY_PASSPHRASE_FILE_ALLOW_LAX_PERMS` opens the strict-permission check
on two secret files, the database passphrase file (`--db-passphrase-file`) and
the `[llm]` / `[embeddings]` `api_key_file`, and the two readers parsed it
differently: the passphrase reader took only `1` or `true` (widened by #3200,
which shipped without a changelog entry), and the `api_key_file` reader kept
its own copy of the wider grammar. Both now read it
through the house truthy grammar (`1`, `true`, `yes` or `on`, trimmed and
case-insensitive), the same grammar as the store-url, capability-file and
api-key token-file hatches; `=yes` and `=on` therefore now open the
passphrase-file hatch too. The environment-variable reference documents that
grammar for all four hatches and names both files the passphrase hatch covers;
it previously documented `1`/`true` only and named the passphrase file alone.
