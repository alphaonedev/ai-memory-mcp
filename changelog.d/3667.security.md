**Credentialed URLs at the remaining sinks render from the allowlist — #3667 re-implemented in the #3711 idiom (reconciliation ruling on #3330).**
#3667 had wrapped ~50 sites in the userinfo maskers (`logging::redact_url_password` /
`redact_urls_in_message`, widened to query keys). The ruling: a masker is a denylist
and can only hide the shapes its author enumerated; #3711's allowlist renderer
(`url_display`) shows scheme / host / port (/ database) and nothing else. Every site
#3667 protected now renders through `url_origin`, `url_origin_and_path` or
`store_url_display`; NO production file gains a masker call, so the `src/llm.rs` and
`src/tls.rs` collisions between #3667 and #3705/#3711 disappear.

- LLM: the construction `debug!` lines and the Ollama reachability refusal render the
  base URL's origin; the four Ollama list/pull transport errors are classified at the
  origin (`ProviderFailure`, #3648/#3710) instead of `.context` over a `reqwest`
  Display that appends the request URL.
- Doctor: the `base_url` (LLM and embeddings) and `probe_url` facts and the
  unexpected-status note render origin (+ path for the probe) — a fact is a sink in
  text, `--json` and every pasted report.
- Federation: the duplicate-peer and peer-id-collision refusals, the registered-peer
  boot line, the quorum "did not ack" warning and the sync-daemon boot line render
  each peer as its origin + path (its #3675 identity).
- Config display (`config_redact`): a URL-valued setting renders through
  `store_url_display` (store schemes) or `url_origin` (everything else) before the
  secret screen; the query string is never shown.
- `--store-url` argv warning (#1927): the trigger now also fires on libpq's
  credential query keys (`password`, `sslpassword`, matched percent-decoded and
  case-insensitively). This is a documented ENUMERATION that decides whether a
  WARNING fires; it never decides what is rendered.
- `benches/age_vs_cte.rs`: its hand-rolled `***` masker is replaced by
  `store_url_display`.
- Pins: `tests/url_allowlist_render_3667.rs` (doctor LLM facts text + JSON; URL-shaped
  `--db` refusal) and unit pins beside `federation::peer`, `config_redact`,
  `store_url` — each asserts the PRESENCE of the endpoint origin as well as the
  absence of the canaries.
- Not changed: `handlers::postgres_gate::sanitize_store_err_message` (already a
  whole-URL eraser, not a userinfo masker; #3667's extra pre-mask is not added);
  `federation_receive` vector-clock keys (already `url_origin_and_path` after the
  #3675 rekey); `src/egress.rs` and `tests/credential_to_sink_3711.rs` (items two and
  three of the ruling, authored by the rehearsal lane on this branch).
