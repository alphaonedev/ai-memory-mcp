### Security

- **[identity] Agent api-key mint and revoke require a verified principal, not the admin header**
  ([#8535](https://github.com/alphaonedev/ai-memory-mcp/issues/8535), umbrella
  [#8493](https://github.com/alphaonedev/ai-memory-mcp/issues/8493); closes the
  end-to-end property of [#8494](https://github.com/alphaonedev/ai-memory-mcp/issues/8494)).
  `POST /api/v1/agents/{id}/api-key` and `.../api-key/revoke` admitted through
  `require_admin` alone, so under `advisory` (and under `enforce` while the
  enrolled registry is empty) a caller holding the shared transport key and a
  CLAIMED admin `X-Agent-Id` could mint a per-agent key for any registered agent,
  the admin ids included; that self-minted key resolves key-authenticated and
  defeated the #8494 pubkey-bind gate. Both routes now share one gate with the
  bind routes: the admin must present its own enrolled per-agent key, or the
  operator must have set `AI_MEMORY_ADMIN_HEADER_TRUST=1`. A refusal is a typed
  `403`, writes a durable `agent_api_key_mint` / `agent_api_key_revoke` deny row
  (reason `claimed_admin_not_key_authenticated`) and changes nothing, on SQLite
  and Postgres. Bootstrap the first admin key with
  `ai-memory agents bind-api-key --token-file <0600 file>` on the data-tier host
  (a token on argv is refused since #3781), or with the env opt-in.
  Also fixes [#8536](https://github.com/alphaonedev/ai-memory-mcp/issues/8536):
  the path `{id}` is validated before the refusal audit row is written, so an
  unvalidated segment can no longer reach the signed chain from the pubkey bind
  routes.
