#4045 — Curator and autonomy consolidation now pass the summarized source versions through to the storage transaction and refuse a stale summary before replacing any source. SQLite checks under its immediate write transaction; PostgreSQL locks sources in stable ID order and checks their versions before mutation. The write-ahead originals correspond to the versions admitted by the transaction. Per the 5-agent vote (4d3ea1c5, memory 656eb5ff): a stale source now refuses as `StoreError::Conflict` on SQLite as on PostgreSQL (it used to surface as an opaque backend error), and a structured WARN logs the expected and stored versions. The version-less curator persist is test-only, so production consolidation always passes the versions it summarized.
