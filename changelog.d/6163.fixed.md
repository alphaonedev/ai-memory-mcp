**CodeQL alerts on the Promotion 6 carrier fixed (#6163).** Thirteen code-scanning
alerts introduced by `chain/promo6-ssh` are resolved in the scripts and the
workflow they point at:

- `scripts/claude-md-rule-compare.py` (py/clear-text-logging-sensitive-data,
  py/clear-text-storage-sensitive-data): the values CodeQL traced were
  repository paths carried by identifiers named `trusted_*`, which its
  sensitive-name heuristic reads as credentials. The carriers are renamed
  (`GUARD_PATHS`, `guard_path_changes`, `pinned_guard_paths`,
  `guard_file_write`), and the
  self-test refuses any identifier of the script that falls in the
  heuristic's secret, password and private-data name classes (written out in
  the self-test, plus `trusted`, the name CodeQL traced). Names on the
  heuristic's not-sensitive list, names ending in a path/file/url word and
  imported module names are exempt; the id and certificate classes, which the
  Python clear-text queries ignore, are not checked. The comparison summary
  masks credential-shaped head text where it enters the report: a
  credential-named `name=value` / `name: value` (quoted, multi-word and
  JSON-quoted forms, past an escaped or doubled quote and to the end of the
  line when a quote is never closed, and past a quote inside an unquoted
  word), URL userinfo (the password up to the last `@`, an empty user name
  included, and a user-only userinfo of 20 or more characters), an
  Authorization Bearer/Basic value, a GitHub, AWS access key id, Slack or
  `sk-` provider token, and a PEM or PGP private key block. A count of at most
  9 digits or a switch word stays visible, and an UPPER_SNAKE value only as an
  environment variable name (under an `_env`/`_var`/`_name` name or ending in
  a credential word, with no run of 4 digits), unless the name is a password
  or passphrase. A diff line inside a private key block is masked by its
  index on its own side of the diff, so a key line stays masked when its
  BEGIN line falls outside the hunk. Masking runs per diff block and per
  inline span, so an unterminated BEGIN line masks only its own block; the
  lines the script writes (`GUARD CHANGED`, the approval list, `RESULT`) are
  never masked. The report says
  when it masked something, and the verdict is still computed on the
  unmasked text. The unused `census_heading` local is removed.
- `.github/workflows/claude-md-rule-compare.yml` (actions/untrusted-checkout):
  no workflow step fetches the pull request head any more. The base
  comparison script fetches `refs/pull/<N>/head` as git objects itself
  (`--pr-number`, a validated decimal), so the head stays data that is never
  checked out or executed. The trigger stays `pull_request_target`, because a
  `pull_request` run would execute the head's own copy of this workflow. The
  guard's pinned form of the workflow and its danger list refuse a `git
  fetch`, `git pull` or `pr checkout` step.
- `scripts/check-claude-md-size.py` (py/overly-permissive-file): self-test
  fixtures whose mode is restored after an unreadable-file case are restored
  to `0o600`, and the self-test asserts it.
- `scripts/check_cert_expiry.py` (py/empty-except,
  py/implicit-string-concatenation-in-list): a refused UTF-8 reconfigure of an
  output stream is reported on stderr instead of being swallowed, and the
  two-part message line is parenthesised.

Guard files changed (rule-change approval recorded):
`scripts/check-claude-md-size.py`, `scripts/claude-md-rule-compare.py`,
