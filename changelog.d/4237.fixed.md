`docs/CONFIG_SCHEMA.md` no longer states universally that a legacy flat field is a lowest-precedence fallback "not inert" while listing `max_memory_mb` among those fields: the claim is now bounded to *most* legacy fields and `max_memory_mb` is called out as the exception — both its flat and `[storage]` forms are parsed and carried for compatibility but enforce no memory or storage limit and emit a one-shot warning, with `[limits].max_storage_bytes` named as the real per-agent storage quota (and not a process RAM limit). The `max_memory_mb = 4096` example in the `[storage]` block carries the same no-enforcement status instead of appearing as a working cap (#4237).
