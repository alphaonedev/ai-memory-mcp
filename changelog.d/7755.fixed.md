**A transaction that appends several signed events under a persistent genesis read fault records one skip per due window, not one per row (#7755).** The committed retry backoff is claimed only after the commit (#7746), so it is invisible to the later appends of the same transaction; `GENESIS_SKIP_TENTATIVE_SEQ` marks the in-transaction skip, `watermark_emission_due` suppresses the heads above it within one interval (never the head that recorded it, so the re-append of a rolled-back sequence still re-reads the genesis), and the inflated genesis re-reads, WARNs and `ai_memory_audit_watermark_genesis_read_skips_total` counts in bulk transactions (hub allowlist audit, crypto-erase loops) fall back to the once-per-window contract of #7236.
