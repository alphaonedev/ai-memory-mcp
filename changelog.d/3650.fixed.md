**Default logging no longer drops events outside `ai_memory` (#3650).**

The console filter was `RUST_LOG` plus an appended `ai_memory=info`.
Many subsystems log under their own target instead: `store::postgres`,
`federation::…`, `signed_events`, `schema_guard`, `security.posture`,
`http::auth`, `hnsw.eviction`, `encryption.undecryptable_row_skipped`
and others. With `RUST_LOG` unset those events were discarded below
ERROR, and the shipped systemd units' `RUST_LOG=ai_memory=info` hid
them completely — including boot posture reports, replay and signature
warnings, schema guards and degraded-mode warnings. The appended
default also reset an operator's `RUST_LOG=ai_memory=debug` back to
`info`.

What changes for operators:

- **Default output now includes every target at `info`.** Expect log
  lines that were missing before (postgres adapter, federation,
  security-posture events). Nothing new is written at `debug`.
- **`RUST_LOG` layers last and wins for the target it names**, so
  `RUST_LOG=ai_memory=debug` now works as written. A bare level such
  as `RUST_LOG=warn` sets the level for everything it does not name.
- **The shipped systemd units now export `RUST_LOG=info`** (pinned
  against the `logging::DEFAULT_LOG_DIRECTIVE` SSOT by test).
- **A misspelled `[logging].sink` / `AI_MEMORY_LOG_SINK` value is now
  reported in the log it falls back to.** The warning used to fire
  before any subscriber existed, so it was never shown.
- **Noise cost:** third-party crates are admitted at INFO/WARN/ERROR
  too. Narrow per target via `RUST_LOG` as before.
