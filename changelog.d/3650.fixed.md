**Default logging no longer drops events outside `ai_memory` (#3650).**

The console log filter was `RUST_LOG` plus an appended `ai_memory=info`. Many subsystems log under their own target instead: `store::postgres`, `federation::…`, `signed_events`, `schema_guard`, `security.posture`, `http::auth`, `hnsw.eviction`, `encryption.undecryptable_row_skipped` and others. With `RUST_LOG` unset those events only showed at ERROR, and the shipped systemd units set `RUST_LOG=ai_memory=info`, which hid them completely. That covered boot posture reports, replay and signature warnings, schema guards and degraded-mode warnings. The appended default also reset `RUST_LOG=ai_memory=debug` back to `info`.

What changes for operators:

- **Default output now includes every target at `info`.** You will see log lines that were missing before, including postgres adapter, federation and security-posture events. Nothing new is written at `debug`.
- **`RUST_LOG` is applied on top of the default, last.** A directive always wins for the target it names, so `RUST_LOG=ai_memory=debug` now works. A bare level such as `RUST_LOG=warn` sets the level for everything it does not name. A deployment that still exports `RUST_LOG=ai_memory=info` keeps every other target at `info`, so existing units work unchanged.
- **To get the old, narrower output back,** set `RUST_LOG=warn` or name the targets you want to quiet (for example `RUST_LOG=store::postgres=warn`).
- **The `[logging]` file / stdout / syslog sinks now honour `RUST_LOG` as well.** They start from `[logging].level` and apply `RUST_LOG` on top, like the console. If a unit exports `RUST_LOG`, those directives now also apply to the sink.
- **The shipped systemd units, the Plan C entrypoint, the DigitalOcean cloud-init template and the wake-hub launchd template no longer set `RUST_LOG`.**
- **A misspelled `[logging].sink` / `AI_MEMORY_LOG_SINK` value is now reported in the log it falls back to.** The warning used to be emitted before any logger existed, so it was never shown.
