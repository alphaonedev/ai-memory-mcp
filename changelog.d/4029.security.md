### Security

- **Federation admission can no longer resurrect an id a concurrent erasure tombstoned**
  ([#4029](https://github.com/alphaonedev/ai-memory-mcp/issues/4029)). The G30 forget-tombstone
  guard read `forget_tombstones` outside the transaction that then wrote the inbound row, so a
  forget / hard delete / eviction committing on another connection in between left a live row
  beside its tombstone (erased content back). SQLite: the probe now runs after `BEGIN IMMEDIATE`
  in `insert_if_newer`, inside `merge_inbound`'s write lock, and inside the federated restore's
  transaction (`restore_archived_unless_tombstoned`). Postgres: a transaction-scoped advisory-lock
  protocol (`tombstone_serial_4029`) — admissions (`apply_remote_memory`, `merge_inbound`, the
  federated `restores[]` apply) take shared locks before probing inside their write transaction;
  every tombstone-writing erasure (delete / `apply_remote_deletion`, `forget`, TTL/byte-cap
  eviction) takes the exclusive locks before its tombstones commit. A genuine same-id race
  resolves as a `40P01` abort of one whole side, never a half-applied resurrection.
