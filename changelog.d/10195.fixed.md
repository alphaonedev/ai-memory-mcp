**A signed agent cut-over marker is reported unchecked, not invalid, when the process has no verifier (#10195).**
`verify_chain` on SQLite and the PostgreSQL chain check now report a correctly signed cut-over marker as
`Skipped(NoVerifier)` when the process holds neither a pinned audit key nor an in-process daemon key, like
every other daemon-signed row. Before, the marker was judged `CutoverMarkerInvalid` and every agent row above
it `AgentEraUnresolvable`, so a fresh database read as tampered. With a verifier present nothing changes: an
edited marker, a bad signature and a duplicate marker stay invalid and a removed marker stays missing. A
marker with no verifier must still match its structure (sequence, previous-row link and legacy count) or it
is invalid. The unchecked state is carried in the type (`MarkerSignature::Unchecked`), so no caller can
collapse it into verified.
