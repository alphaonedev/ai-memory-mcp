The governance glob matcher (`permissions::glob_matches`, used to select `[permissions]` rules and agent-action rule namespaces, paths and hosts) now matches patterns that mix `**` and `*` exactly. The previous single-checkpoint backtracker dropped the earlier `**` alternative once it reached a later `*`, so a pattern such as `**/secret/*` did not match `a/secret/b/secret/c` and a configured Enforce Deny silently did not apply to a namespace it covered. The matcher is now a bounded dynamic program over (pattern token, value offset): O(|pattern| x |value|) time, O(|value|) space, no recursion (#4042).

Upgrade note: the new matcher only widens what a pattern matches; every rule that matched before still matches, and a Deny is still evaluated before an Allow. Existing `[permissions]` Allow rules whose patterns mix `**` and `*` now cover namespaces they previously missed, so they now match what they say. Where an operation on such a namespace previously needed approval under Enforce (an Ask that resolves to Deny), it is now satisfied by the Allow, and the approvals event stream now grants the events those Allow rules name. Operators should review their mixed `**`/`*` Allow rules after upgrading.
