**A script loads its sibling modules from one exact file, never through the import search path (#9399, refs #9365, #8216).**
Thirteen scripts under `scripts/ci`, `scripts/bench` and `scripts/evidence` put their own folder on `sys.path` and
imported a sibling by name, so a same-named module on `PYTHONPATH` or in the working directory could take its place
(and `python -I` dropped the folder altogether). They now load the sibling by file from
`Path(__file__).resolve()` through one loader, kept as `scripts/ci/sibling_load.py` and embedded byte for byte in each
script (a materialised base copy holds only the files a workflow lists, so a shared import is not available there;
`scripts/ci/tests/test_sibling_load_9399.py` pins every copy and finds any script that still loads by name). A sibling
that is absent, unreadable, not a regular file or a symlink leaving the script's folder ends the script with one stderr
line naming the path and the script's own exit code (3, and 5 for `sccache_env.py`); it never falls back to another
module of that name. `sys.path` is unchanged after the load and the module is registered under one stated name. The
shell capture `scripts/bench/host-facts.sh` became `scripts/bench/host-facts.py` (same JSON, same `--check`) so the
benchmark facts use the same loader.
