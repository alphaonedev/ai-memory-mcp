**A script loads its sibling modules from one exact file, never through the import search path (#9399, refs #9365, #8216).**
Thirteen scripts under `scripts/ci`, `scripts/bench` and `scripts/evidence` loaded their siblings by name through
`sys.path` (an insert, or the script folder at `sys.path[0]`), so a same-named module on `PYTHONPATH` or in the working
directory could take a sibling's place. They now load each sibling by file from the script's own resolved folder
through one loader, kept as `scripts/ci/sibling_load.py` and embedded byte for byte in each script (a materialised base
copy holds only the files a workflow lists, so a shared import is not available there). The loader opens the file by
descriptor, one folder at a time from the script folder without following a symlink, checks that descriptor is a
regular file and compiles the bytes read from it, so the object checked is the object run. A sibling that is absent,
unreadable, empty, not a regular file (a folder, a FIFO, a device) or a symlink leaving the script's folder ends the
script within a bounded time with one stderr line naming the path and the script's own exit code (3, and 5 for
`sccache_env.py`); it never falls back to another module of that name. `sys.path` is unchanged after the load and the
module is registered under one stated name. `scripts/ci/tests/test_sibling_load_9399.py` pins every copy, and its
census reads every `.py` file under `scripts/` outside the test folders: a file that changes `sys.path` or imports a
same-tree name by name is a finding. The whole-tree allowlist census comes in a separate change (refs #8213), and the
older loaders that load a file by path are left to #9857. The shell capture
`scripts/bench/host-facts.sh` became `scripts/bench/host-facts.py` (same JSON, same `--check`) so the benchmark facts
use the same loader.
