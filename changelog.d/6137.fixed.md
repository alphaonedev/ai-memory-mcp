**Cert-expiry gate judges the pull_request merge commit; ported to Python (#6137).**
`scripts/check-cert-expiry.sh` evaluated rule (C) at the PR head and took the
range base from the event payload, so a branch cut before the #6121 banner fix
failed although the merged tree records `EXPIRED`, and a stale payload base sha
skewed the range. The gate is now `scripts/check_cert_expiry.py` (Python 3.9+,
stdlib only, per the Python-not-shell rule; the bash gate is removed). On
`pull_request` it judges (B) and (C) at the checked-out merge commit
(`GITHUB_SHA`, falling back to `HEAD`), computes the merge-base against the live
base ref (`origin/$GITHUB_BASE_REF`, fetched explicitly if absent) and measures
(A) drift and the (B) banner flip from the merge commit's first parent (verified
to be the live base tip) to the merge commit, so base-side changes since the fork
point are not re-counted against a stale branch; it fails closed when the base
ref, the head or the merge commit cannot be resolved, the merge commit does not
descend from the PR head, or its first parent is not the live base tip. Every earlier rule, message and self-test cell is preserved;
the self-test adds the stale-branch, banner-flip, stale-payload-base and
fail-closed cells. Refs #6121, #3556.
