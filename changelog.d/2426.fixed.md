**`doctor --hooks` and the boot log name every configured hook that cannot fire (#2426).**
`hooks.toml` accepts every hook event, but 12 of the 22 have no production
dispatch site (`post_store`, `post_recall`, `post_search`, `post_delete`,
`post_promote`, `post_link`, `post_consolidate`, `post_governance_decision`,
`post_reflect`, `on_index_eviction`, `on_compaction_rollback` and
`pre_recall_expand`), and eight deny-capable `pre_*` events are consulted only
through the PE-1 enforcement gate, which is installed only when
`[hooks].enforce_mode` is not `off` and `required_events` is non-empty. Such a
hook loaded cleanly and was listed like a live one, so an operator could believe
a gate or notifier was in place when nothing ran. The new registry
`crate::hooks::dispatch_status` records which events dispatch, and a
source-scan test fails if a verdict drifts from the tree. `ai-memory doctor
--hooks` prints a WARN per inert subscription (and `--json` carries
`inert_subscriptions`), and `serve` / `mcp` log the same WARN at boot.
`docs/hook-pipeline.md` now states the per-event status, correcting its claims
that every `pre_*` hook fires and that `pre_recall_expand` is wired.
