**Docs: PgBouncer `session` mode is the supported pool mode; `transaction` mode is unsupported until #4679 (#5355).**

The enterprise guide (§5.6.3, §5.6.6, §10.4, the §14.8 checklist) no
longer asserts that `transaction` pooling is required or made safe by
`max_prepared_statements`. The adapter installs session-scoped state at
connect (`search_path` via `set_config(..., false)`, `statement_timeout`,
`lock_timeout`, a session advisory lock) that the #4667 probe measured
leaking between clients on a shared backend; prepared-statement tracking
does not address it. The `infra/pgbouncer/pgbouncer.ini` comment on
`max_prepared_statements` states the same limit.
