Close a cross-tenant read-and-destroy primitive in `memory_consolidate` and
`POST /api/v1/consolidate`. Sources were resolved with no caller on either
surface and no ownership check on either backend, so a non-owner could name
another agent's `scope=private` ids, receive their content back as the LLM
summary, and have their rows consumed — on rows the same caller is told "not
found" about by `memory_get`. Every source is now resolved once, before any model call and
before any write, through the single canonical mutation predicate
`memory_update` and `memory_delete` gate on, and the rows the gate admitted
are exactly the rows the model sees and the merge consumes. Consumability
rather than readability is the question that matters here and is the stronger
one: a row owned by another agent is refused even when it is readable
(collective scope, an inbox row), which is what closes the summary leak, while
the predicate keeps the legacy carve-out so an unowned row stays
consolidatable exactly as it stays updatable and deletable. A source the
caller may not consume refuses with the same message an absent id produces,
so neither surface is a presence oracle. On HTTP the gate runs unconditionally: previously the sources
were only ever read when the caller omitted `summary`, so a caller who supplied
one consumed the victim's rows having performed no source read at all. A source
that exists but is not visible refuses with the identical message an absent id
produces.

The request-shape half of the consolidate validator (id count, duplicate ids,
title, namespace) now runs BEFORE the summary is materialised, so a malformed
request such as `{"ids": []}` no longer costs a paid LLM round-trip. Note the
deliberate error-precedence change: a request that is invalid in both its id
count and its summary now surfaces the id-count error first.

The `memory_consolidate` tool documentation claimed unconditionally that
provenance is metadata-only with no KG-traversable link rows. That holds under
the delete disposition, but when the tombstone disposition retains the sources
the merge writes navigable `derived_from` edges that survive; the text now says
which contract belongs to which disposition. The single-operator default
(`AI_MEMORY_AGENT_ID` unset) is unchanged.
