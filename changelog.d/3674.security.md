**Postgres store-URL secrets never reach the log sinks (#3674, with #3685 folded in).** sqlx logs every store-URL query parameter it does not recognise, value included, at WARN; since #3650 made the default filter a bare `info`, that was a default-on credential leak on every postgres node (for example `?sslpassword=` or `?PASSWORD=`). Every production sqlx connection now takes its options from one funnel, `store::postgres::dsn::connect_options`, which removes the parameters sqlx would log (it ignores them anyway, so no working connection changes) and reports only their count and positions, never a name or value. A source walk pins that inventory, so a new raw `.connect(url)` fails CI. #3685: sqlx also logs a whole malformed `~/.pgpass` line, password included, when the URL carries no password; every filter the logging module builds now caps `sqlx_postgres::options::pgpass` (and, as defence in depth, `sqlx_postgres::options::parse`) at `error`, applied after `RUST_LOG` so no operator directive re-opens them.
