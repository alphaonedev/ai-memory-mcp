**`ai-memory recall` no longer hangs when the MiniLM download fails (#4284).** `recall` holds the process-wide stderr lock for its whole run and builds its embedder on a worker thread. Two embedder loader messages used `eprintln!`: the Hugging Face Hub download failure on a cold cache and the Ollama embed-model pull failure. A write to stderr from the worker therefore blocked forever, so `recall --tier semantic` on a host with no staged weights and no Hub reachability hung with no output instead of degrading to keyword recall. Both messages now go through `tracing::warn!`. `tests/recall_stderr_lock_deadlock_4284.rs` runs the real binary on an empty cache with the Hub endpoint at a closed loopback port and requires it to exit 0 (it hung past 90 s before the fix). It also forbids `eprintln!`/`eprint!` in `src/embeddings.rs`.
