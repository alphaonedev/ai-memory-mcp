**A forensic lock that is never released no longer costs every audited write a full second (#4353).** Since #4304 an append waits up to 1 s for `forensic.lock` and then goes ahead without it. A holder that never let go made every row pay that second: each row of a CLI command, and each queued row of `serve` or `mcp`, whose 5 s exit drain then ran out after five rows. After a wait times out, appends for the next 30 s wait only 50 ms (long enough for a normal holder, which keeps the lock for milliseconds), each further timeout extends that window, and the first successful lock ends it. Every row still lands, chained from the re-read tail, and every unlocked append is still counted in `ai_memory_forensic_lock_unavailable_total`. The 50 ms is a trade: inside the window, a legitimate holder that keeps the lock longer than 50 ms makes that append go ahead unlocked (counted), and two unlocked appenders can interleave. The window belongs to one process, so each separate CLI command still pays the full second once under a holder that never lets go.
