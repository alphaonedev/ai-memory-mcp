**[docs][tooling] `CLAUDE.md` shrunk from 448 KB to under 80 KB so agent sessions stop loading 200k+ tokens on turn one** ([#4507](https://github.com/alphaonedev/ai-memory-mcp/issues/4507)).
The `## Architecture` and `## Code Style` bodies moved verbatim to `docs/reference/ARCHITECTURE_REFERENCE.md` and `docs/reference/CODE_STYLE.md` (the Architecture body is verbatim except the `signed_events.rs` module row and the `AI_MEMORY_REQUIRE_ENTERPRISE_FEDERATION_POSTURE` row, corrected by #4529); `CLAUDE.md` keeps every rule section plus pointers. `check-docs-vs-ssot.sh` (env-var census, narrative counts, pinned-knob count) and `check-doc-symbol-anchors.sh` read the moved content at its new location, and `scripts/check-claude-md-size.py` fails CI if `CLAUDE.md` exceeds its byte ceiling.
The guard also pins a minimum body size for each of the 15 rule sections, requires `docs/reference/` and both reference files to be real (not symlinks) with their `##`/`###` subsection headings intact, indexes the agent-directed prohibitions that now live only in the reference files as verbatim, line-cited quotes in `CLAUDE.md` (each quote must equal its cited lines, the quote set and the exact index lines are pinned by sha256, and each file:range may be cited once), and treats tilde fences and HTML comments as non-heading regions. `check-docs-vs-ssot.sh` and `check-doc-symbol-anchors.sh` now fail closed when either reference file is missing. About 65 live citations of the moved content (a mechanical scan found 66 at the base; the later review sweep found two more, in `src/handlers/auth_backoff.rs` and `scripts/check-docs-vs-ssot.sh`, now retargeted) in docs, source comments, test messages and html pages were retargeted to the reference files.
Each `CLAUDE.md` rule section is also pinned by a sha256 manifest (`scripts/qc-allowlists/claude-md-rule-sections.sha256`, rewritten only by `scripts/check-claude-md-size.py --update`), and a `pull_request_target` job (`.github/workflows/claude-md-rule-compare.yml`) runs the BASE guard and BASE manifest over the pull request head, which it reads from git objects and never executes. The comparison runs under `python3 -I` (isolated mode; it refuses to run without it, and that refusal is the first statement after `import sys`, before any other import, so a file next to the script named like a standard module never runs) and compiles the base guard from its source file, never from a cached `.pyc` ([#5163](https://github.com/alphaonedev/ai-memory-mcp/issues/5163)). It prints every changed, added or removed rule section with its diff (`RULE TEXT CHANGED`; `COUNT CHANGED` only when every changed line is a number in the generated census inside the Prime directive section, since a digit edited anywhere else in a rule section is a rule change; `GUARD CHANGED` for any edit to a trusted file: the guard, the compare script, the two workflows and CODEOWNERS) and fails a rule change or a trusted-file change unless a commit in the range carries a `Rule-Change-Approved-By: <who>` trailer. This is tamper-evidence, not authority: an agent can also write the trailer, so the two reviews and the sole merger enforce. The job runs only once the workflow is on the base branch, so the introducing pull request is judged by review.
