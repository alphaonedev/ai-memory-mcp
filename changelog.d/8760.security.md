### Security

- **[authz] A K9 Deny rule now covers every agent-id form**
  ([#8760](https://github.com/alphaonedev/ai-memory-mcp/issues/8760), refs
  [#8741](https://github.com/alphaonedev/ai-memory-mcp/issues/8741)). The
  rule's `agent_pattern` was matched with the namespace glob, whose `*` stops
  at `/`, so a Deny written as `*` (the default) or `ai:*` let a caller whose
  id contains `/` (team-scoped and SPIFFE ids) through, and a Deny on an exact
  id let a different case spelling of it through. One matcher
  (`governance::agent_match`) now decides every agent pattern, for rule
  selection on MCP, HTTP and CLI on both backends and for SSE approval
  visibility:
  - `*` in an agent pattern matches any run of characters, `/` included, as
    the `PermissionRule` documentation always stated.
  - Deny and Ask rules compare ASCII letters case-insensitively; Allow rules
    compare exactly.
  - Fail closed: an unclassifiable pattern (empty, over 1024 bytes, or a
    character outside the agent-id alphabet plus `*`) or caller id matches
    every Deny / Ask rule and no Allow rule, with a log line; installing such a
    pattern logs a warning per rule.
  - Upgrade note: an Allow `ai:team/*` now also covers `ai:team/a/b`. Review
    Allow rules whose pattern ends in `*` after a `/`.
