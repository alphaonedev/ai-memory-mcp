An `escalate` agent-action rule now queues a signed-approval pending on every SQLite write funnel that evaluates the governance pre-write hook while holding a write transaction (restore, caller-scoped restore, consolidate, merge_inbound, and any funnel called inside a caller-owned write transaction such as the store-level update). The hook consults on its own connection, so its pending INSERT used to wait out `busy_timeout` behind the caller's writer lock and fail `SQLITE_BUSY`: the escalated write was refused without being queued for approval, and the lock was held for the whole timeout. The hook now defers the queue write to the caller's open write transaction, which writes it on its own connection the moment the transaction ends; governance evaluation still happens inside the lock (#4116).
