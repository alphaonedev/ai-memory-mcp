**`GET /api/v1/kg/timeline` no longer builds a privacy-bypass context for a
tenant (#3982).** On postgres, the #1804 per-target visibility filter read
every event's target with `CallerContext::for_admin(caller)` for every
caller, then filtered. It now reads under the caller's own context
(`for_admin_checked(caller, caller == daemon)`). The pg `get` already folds
a target the caller cannot read into NotFound, so a tenant's timeline is
unchanged. The explicit filter stays as a second, independent barrier: a
later edit that forgot the filter would no longer disclose another tenant's
private row. The C8 allowlist entry for the site is removed, so reintroducing
the bypass is a gate HARD-BLOCK.
