**A content-changing write no longer leaves the old document's vector on the row (#8907, #8948; refs #9062).** Every write that changes a memory's title or content now clears its stored embedding in the same SQL statement as the text change. This covers the in-place update, the upsert on (title, namespace), federation and import overwrites, undo-edit, and the MCP autonomous synthesis merge, on both SQLite and Postgres. Each surface then re-embeds through one decision, `embed_document_with_status`. When that works, the row carries the new document's vector. When it fails, or the surface has no embedder (the CLI, or MCP `--tier keyword`), the row stays vectorless and the receipt says why with `embed_status` / `embed_status_reason` (`failed` / `embedding_failed`, or `skipped` / `no embedder configured`). The Postgres `PUT /api/v1/memories/{id}` now re-embeds; before, it never did, so semantic recall ranked the row by its old text. The Postgres create reports a degraded embed the way SQLite already did. A re-embed that races a newer text change clears the vector again rather than store a stale one. The synthesis merge now also drops the merged row's old entry from the in-memory vector index after COMMIT when the re-embed fails. `tests/embedding_follows_content_8907.rs` and `synthesis_merge_vector_follows_content_8907` pin every surface on both backends, including semantic rank after an update.
