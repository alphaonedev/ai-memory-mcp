**`verify-reflection-chain`: a root content-id that mismatches or cannot be read now fails the verification with exit 2 (#9505, #9507).**
Behaviour change: a root whose stored content-id genesis is read and does NOT
match its cid used to exit `0` with a `cid_verified: false` line after a passing
report; it now gives `ok: false` and exit `2`. An unreadable genesis used to
print a complete-looking report and then leave through the generic error path
with exit `1`, the same code as "root not found"; it is now `ok: false`, exit
`2`, with the error class named (`decode_error`, `schema_fault` or
`storage_error`) and never the stored bytes. The root is checked before
anything is printed, in text and in JSON mode; the text summary line ends
`ok=<bool>`, and the JSON report gains an optional `root_cid` field
(`verified`, `mismatch` or `unreadable`), omitted when the root carries no
genesis or no cid and never set in a forensic bundle's `verification.json`.
`docs/forensic-export.md` now lists the exit codes `0`, `1` (not found) and
`2` (verification failed) (#9507). Decided by 3-agent vote (71472661). Tests:
`tests/verify_chain_genesis_exit_code_9505.rs`.

Behaviour change, `--cid` (#9634, #9635): the fleet-wide content-id sweep now
runs before anything is printed and is part of the one verdict. A swept row
whose content-id mismatches used to leave the exit code at `0`; a row whose
genesis could not be decoded used to stop the sweep with exit `1` after a
passing summary. Both now give `ok: false` and exit `2`, the row is named with
its error class (`decode_error`, `schema_fault` or `storage_error`), and the
text sweep line gains an `unreadable=` count. `--cid --format json` used to
print two JSON documents; it now prints ONE, with the sweep as the optional
`cid_sweep` field (omitted without `--cid`, never set in `verification.json`).

Behaviour change, unreadable inputs (#9505, 3-agent vote (71472661)): a
database that cannot be opened, a root row or chain that cannot be read, or a
`--cid` sweep query that cannot be prepared or stepped used to leave through
the generic error path with exit `1` and nothing on stdout, the same code as
"root not found". It is now the state unreadable: `ok: false`, exit `2`, and
ONE document naming the stage (`open`, `root`, `chain`, `cid_sweep_prepare`,
`cid_sweep_step`) and the error class; the storage error's text and the path
are never printed. Exit `1` keeps its old meaning. A `reflection_depth` that
does not decode and a `signed_events` read that fails are now errors, no longer
read as depth 0 and as no events. The forensic export (`export-forensic-bundle`)
now FAILS when the `signed_events` read of its embedded chain report fails: it
used to write a bundle whose `verification.json` listed no events; it now writes
no bundle, prints no `forensic bundle written` line and exits `1`, as it already
did when its own `signed_events` slice could not be read.

Behaviour change, output (#9636): every stored value the text report prints,
on stdout and stderr, is escaped (control, bidi and zero-width characters as
`\u{…}`) and cut at 512 characters with a `...(+N chars)` marker, so a stored
value can no longer forge a second summary line or drive the terminal. JSON
output escapes the same characters as `\uXXXX`; the parsed value is unchanged.
