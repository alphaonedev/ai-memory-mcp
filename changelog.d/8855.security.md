### Security

- **[secret-screen] Common credential forms are now screened on every write and receive path, fail closed by
  construction** ([#8855](https://github.com/alphaonedev/ai-memory-mcp/issues/8855)). Content carrying a URL
  userinfo password for any RFC 3986 scheme (`postgresql+psycopg2://`, `mongodb+srv://`, `svn+ssh://`, any case), a
  value under any key whose normalised name (case folded, `_` `.` `-` dropped) contains `password`, `passwd` or
  `pwd` (`DB_PASSWORD_PROD`, `password2`, `passwordConfirm`; operators `:`, `=`, `:=`, `=>`, comparisons, JSON,
  escaped-JSON, XML, CLI-flag and subscript keys), a Slack `xox[abeprs]-` / `xapp-` token or incoming-webhook path,
  or a Stripe `sk_` / `rk_` live or test key or a `whsec_` secret was stored verbatim; it is now refused on
  caller-origin writes (reasons `url_userinfo_password`, `password_assignment`, `slack_token`, `stripe_live_key`) and
  masked on federation receive. A credential-named value is a finding unless the WHOLE value is a pure reference
  (`$UPPER_SNAKE`, `${UPPER_SNAKE}`, `***`, one whole environment lookup, a null literal or an ellipsis); a default
  or fallback (`or`, `||`, `??`, `:-`), a literal beside a reference, a value on the next line, a YAML block scalar
  and a continuation line are findings, and the mask covers the whole logical value. A value hidden behind JSON or
  backslash escapes, `%XX` escapes, invisible characters, fullwidth or homoglyph letters is screened again in its
  decoded views (at most 4 unescape levels, texts up to 1 MiB; past either bound the write is a finding). The
  `Bearer` detector now takes the RFC 6750 `token68` charset, so a `~` inside a Bearer token no longer ends the mask
  early. Each detector is a single forward pass (linear in the input). Type annotations (`password: String`), a
  comparison against a bare variable name (`password == expected`) and empty values stay accepted; an angle-bracket
  or brace value (`<your-password>`, `{msg}`) after a credential-named key is now a finding.
- **Behavior change (upgrade note).** After redaction the redacted copy is screened again; if anything still screens
  as a hit, the write is refused on both backends and on federation receive with the reason `content rejected:
  credential material remains after redaction (<kinds>); the write is refused and no row is stored`. A write that was
  stored redacted before this release may now be refused with that reason, and a write that holds one of the forms
  above and was accepted before is now refused.
