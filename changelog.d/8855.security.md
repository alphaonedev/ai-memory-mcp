### Security

- **[secret-screen] Four common credential forms are now screened on every write and receive path**
  ([#8855](https://github.com/alphaonedev/ai-memory-mcp/issues/8855)). Content carrying a database or broker URL
  userinfo password (`postgres`, `postgresql`, `mysql`, `redis`, `rediss`, `amqp`, `amqps`, `mongodb`,
  `mongodb+srv`; scheme case-insensitive), a `password` / `passwd` / `pwd` assignment (`:`, `=`, `:=`, `=>`, JSON
  and subscript keys), a Slack `xox[abprs]-` token or a Stripe `sk_live_` / `rk_live_` key was stored verbatim; it is
  now refused on caller-origin writes (reasons `url_userinfo_password`, `password_assignment`, `slack_token`,
  `stripe_live_key`) and masked on federation receive. Each detector is a single forward pass (linear in the
  input). Documentation placeholders (`user:password@host`, `<password>`, `${VAR}`, `$VAR`, `***`, `{name}`, `...`),
  type annotations (`password: String`), environment lookups (`os.environ[...]`, `env::var(...)`), null values,
  empty values and comparisons (`==`, `!=`) stay accepted. Behavior change: a write that holds one of these forms
  and was accepted before is now refused.
