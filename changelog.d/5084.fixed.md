**SQLite write transactions now open `BEGIN IMMEDIATE` (#5084, the #2250 class).** Thirteen production functions (14 transaction sites; `mine` has two) opened a DEFERRED write transaction: 8 read first and then wrote, and 5 wrote first. For the read-then-write eight, a concurrent writer that commits inside the read-then-write window makes the lock upgrade fail at once (`SQLITE_BUSY_SNAPSHOT`, error code 517), which `busy_timeout` does not retry, so a write that should have waited for the lock instead failed. All thirteen now use `WriteTxn::begin` (BEGIN IMMEDIATE with rollback on drop). Read-then-write: `create_guarded`, `materialize_template_for_caller`, `mine` (both transactions), `generate_in_scope`, `stamp_contaminated_descendants_as`, `set_embeddings_batch`, `rekey_peer`, `reclassify_memory_kind`. Write-first: `set_embeddings_batch_reembed` (its plan read precedes the transaction), `sweep_expired_leases_reclaim`, checkpoint `resolve`, `run_repair_schema_version`, `sweep_pending_action_timeouts`. `WriteTxn::begin_deferred` and `SQL_BEGIN_DEFERRED` are removed so the helper can no longer open a deferred write transaction. The two read-only snapshots (`policy_version::with_read_snapshot` and the `keys prune` preview) stay DEFERRED and are allowlisted with a reason. The #3163 decision that `mine` should stay DEFERRED because the importer owns a process-private connection is superseded: the daemon is a second writer on the same file, so each chunk now takes the write lock at `BEGIN`, where contention is retried, at the cost of holding that lock for the chunk (#5462). New gate `scripts/check-sqlite-write-txn-immediate.py` (with `--self-test`) refuses the transaction-open forms it scans for in `src/` outside that allowlist. It runs in `tests/sqlite_write_txn_immediate_gate_5084.rs`, in `scripts/qc-codegraph-precheck.sh` and in the `c8-precheck` workflow. It is a static check, not a complete closed-world proof: a write reached through a helper or a closure inside a read-only snapshot is not seen (#5235). Every one of the thirteen conversions has a regression test (`*_is_immediate_5084`) that fires a second writer inside the function window and asserts that the hook fired; the tests fail on the old DEFERRED code: read-then-write functions with error code 517 (or a wrapped `database is locked`), write-first functions because the second writer commits inside the window.
