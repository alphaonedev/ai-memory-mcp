### Fixed

- **[data-integrity] HTTP consolidate fails closed instead of replacing sources with a placeholder**
  ([#4091](https://github.com/alphaonedev/ai-memory-mcp/issues/4091)).
  `POST /api/v1/consolidate` with no caller `summary` asked the LLM and, when none was wired,
  the call timed out, or it errored / returned an empty completion, fabricated a titles-only or
  fixed-string "summary" and consolidated anyway — tombstoning the sources by default and
  HARD-DELETING them under `AI_MEMORY_CONSOLIDATE_TOMBSTONE_SOURCES=0`, so a transient model
  failure replaced the memories' meaning. It now answers `503` with
  `{"code": "summary_unavailable", "reason": "llm_unavailable|llm_timeout|llm_error|llm_empty"}`
  BEFORE any write: nothing is consolidated, tombstoned or deleted, and the caller can supply a
  `summary` or retry. One resolver serves both backends. MCP `memory_consolidate` already
  refused these cases (no LLM → `summary is required`, model error → error, empty → content
  validation) and the CLI requires an explicit summary; the autonomy/curator empty-summary path
  is #4046. Pinned on sqlite and postgres by `tests/consolidate_summary_fail_closed_4091.rs`
  (absent, timeout, error and empty-completion cases leave both sources live and unchanged with
  no consolidated row; a real model summary still consolidates). Tests that pinned the old
  placeholder now pin the refusal.
