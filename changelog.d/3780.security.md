### Security

- **[sdk] the wake delegation bundle is now checked and read through ONE
  descriptor in both SDKs**
  ([#3780](https://github.com/alphaonedev/ai-memory-mcp/issues/3780)).
  `DelegationBundle.load` resolved the bundle path TWICE — `lstatSync(path)` /
  `p.lstat()` to refuse a symlink, a non-regular file, mode `0077` and a
  foreign owner, then `readFileSync(path)` / `p.read_text()` to fetch the
  bytes — so the bytes that were read were never the bytes that were checked
  (CodeQL `js/file-system-race` #262 on the TypeScript half; the Python twin
  went unflagged). A local user able to write in the agent's key directory
  could swap a symlink in between the two and make the SDK read a credential
  it had just refused (confused-deputy read), or swap a FIFO in and PARK the
  listener with no credential of their own (availability). Both SDKs now open
  the bundle ONCE with `O_NOFOLLOW | O_NONBLOCK` (plus `O_CLOEXEC` in Python),
  `fstat` THAT descriptor, apply every existing check — same refusal wording —
  to the descriptor's stat, and read from the descriptor: the pattern the Rust
  tree already ships in `src/wake_client/bundle.rs` (`open_owner_only`,
  modelled on `AllowlistCache::open_checked`, #3504). A symlink is refused at
  the open (`ELOOP`/`EMLINK`) and still reported as a symlink rather than a
  bare errno. **Platform caveat:** Windows has neither flag, so that leg keeps
  the historical path-based check-then-read, unchanged and still racy, and
  says so in the code.
