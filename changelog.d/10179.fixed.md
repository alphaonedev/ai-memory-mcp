**A ledger-writing command over a partial daemon key refuses at boot whatever the agent id (#10179).**
When only one half of the `daemon` key is in the key directory, `serve` (and every other ledger-writing
command) now stops before it creates or bumps the database, under any resolved agent id, with the typed
`DaemonKeyMissing` cause reachable through the error chain and a context line that names the id. Before,
only the `daemon` id was refused; any other id minted its own key, opened the store with it and served
with link, persona and witness signing off. A whole key, or none at all, is not refused. The curator's
store open keeps the same typed cause on both SQLite arms (`--db` and `sqlite://`).
