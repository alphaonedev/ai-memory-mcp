### Security

- **[http][mcp] Recall-observation rows are scoped to their owner or an admin**
  ([#9366](https://github.com/alphaonedev/ai-memory-mcp/issues/9366)).
  `POST /api/v1/memory_recall_observations` and the `memory_recall_observations`
  MCP tool listed the whole recall-consumption ledger to any caller, so an
  anonymous shared-key caller could read another agent's id, namespace and
  private memory ids. Both surfaces now return a row only to the agent it
  belongs to or to an admin caller; the anonymous principal reads none, and
  rows without an `agent_id` are visible to an admin only. The scope is a
  required parameter of the single ledger query on both backends, so no
  surface can list the ledger unscoped by omission. The CLI
  `recall-observations` (local operator on its own database) is unchanged.
