### Security

- **Outbound federation push responses are byte-capped**
  ([#4033](https://github.com/alphaonedev/ai-memory-mcp/issues/4033)). The per-row fanout, the
  push-DLQ replay and the bulk catch-up lane buffered a peer's response body with no size bound
  (`resp.json()` / `resp.bytes()`), and the `sync-daemon` pull did the same. Every peer response
  body now goes through one capped reader (`federation::capped_body`, early `Content-Length`
  rejection + per-chunk accounting; 1 MiB for push reports, the existing 64 MiB for
  `/sync/since` pages). An oversize 2xx is a typed non-ack — it no longer falls through the
  legacy "unparseable 2xx = ack" arm, so it cannot meet quorum or retire a DLQ row — and an
  error-body drain stops at the cap.
