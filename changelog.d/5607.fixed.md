**The doc symbol-anchor gate decodes every character reference with the full HTML5 table and refuses a reference whose reading is undecidable (#5607).** Only `&nbsp;`, `&ensp;`, `&emsp;`, `&thinsp;` and numeric references were read as whitespace, so `<&Tab;b`, `<&hairsp;b`, `<&NonBreakingSpace;b` and the other whitespace names opened a phantom group that absorbed a real over-closer after the anchor. A qualified anchor's line is now decoded once, before analysis, with `html.entities.html5`; a decoded format character (a zero-width space) is dropped, a decoded backtick never opens a code span and `&amp;lt;` stays the text `&lt;`. A Markdown line is read both as CommonMark (a `;` is required, at most 7 decimal or 6 hex digits) and as HTML (a legacy name or a number with no `;`, any padding); when the two readings judge an anchor differently every anchor on the line is refused as `UNDECIDABLE_REF`, cited as written. An `.html` doc has the HTML reading only. Not modelled: a reference inside a Markdown code span is read decoded, as HTML would, although CommonMark shows it literally. Base: accepted; tip before this fix: accepted; now reported or refused. Real tree: 0 lines change. The `--self-test` gains 16 cases (#5607).
