**The do-hive cloud-init memory template now connects the daemon straight to Postgres over verified TLS, and checks the tarball it installs (#4654, #4635, #4637, #4638, #4642).** `infra/do-hive/cloud-init-memory.yaml.tpl` no longer installs PgBouncer; the store URL is `postgres://aimemory:<percent-encoded password>@localhost/aimemory?sslmode=verify-full&sslrootcert=/etc/ai-memory/tls/pg-ca.crt` on the default port, so the connect funnel's sslmode floor (src/store/postgres/dsn.rs:213-255 evaluate, :283-285 floored_connect_options) is met. Postgres runs with `ssl = on` and a CA-signed server certificate minted on the node, and `pg_hba` starts with `hostnossl all all all reject`, so no role can log in to any database over TCP without TLS (the packaged `host all all` lines are reachable only over TLS; unix-socket `local` lines are unchanged; proven on a scratch PG 18 cluster: non-TLS refused for the aimemory and postgres roles on 127.0.0.1 and ::1 across three databases, verify-full admitted, #4676). The role password is read back from the store-URL file, percent-decoded and SQL-quoted on the node and sent to psql on stdin, so it is no longer interpolated into a SQL literal; provision.sh no longer runs under `set -x` and writes a root-only log. The tarball is downloaded into a root-only directory, checked against the new `ai_memory_image_sha256` variable before extraction, extracted without ownership and version-probed as the service user; a mismatch stops provisioning. `scripts/check-cloud-init-serve-flags.py` loses its do-hive exemption and now also fails on a store URL on port 6432 or carrying channel_binding, a local Postgres without the all-roles hostnossl reject line, a root-run script under a service-user-owned directory, a block scalar line indented less than its block (every cloud-init template), a local Postgres without `ssl = on` or a `hostssl` line, a tarball without a digest check before extraction (or ignored with `|| true` or `|| :`), and a terraform value written into a SQL password literal; these are semantic rules that fire even when the line is allowlisted (#4676, #4677, #4702, #4704, #4705). `channel_binding` is not put in the daemon URL and the daemon does not channel-bind: the connect funnel removes keys the driver does not honour (the recognised-key list is src/store/postgres/dsn.rs:60-79), so only psql/libpq clients bind (#4677). The root-run scripts moved to /usr/local/sbin (root:root 0755) and the service user's home to /var/lib/ai-memory, so nothing root runs sits under a directory the service user owns (#4674); the provision log is appended, not truncated, each run (#4709); the loadgen template parses as YAML (#4707); the leg-3 daemon step can now pass and fail (#4708). Measurement results taken before this change ran through a transaction-pooling PgBouncer and are not like-for-like with results after it (infra/do-hive/README-measurement.md). Phase 2 (#4712, #4673, #4675, #4678, #4702, #4704, #4705): the daemon binary now lives in /usr/local/lib/ai-memory/bin (root:root 0755), so the unit ExecStart, the root-run bootstrap and the identity step execute nothing the service user can write (#4712); the tarball is extracted in a staging directory and only a regular file is installed (#4673); the Postgres TLS CA private key is minted in RAM under /run and wiped on exit, and only the CA certificate persists (#4675); the node mints the role password with openssl and the `db_password` Terraform variable is removed, so no password passes through Terraform state or user-data (the do-hive half of #4610; the gate's SQL password literal rule, #4705); `ai_memory_image_url` has no default, refuses non-https, `%` and releases/latest URLs, and spawn.sh refuses a URL without its sha256 pin (#4678). The cloud-init gate now has do-hive probes for each of these and its pending file is empty.
