**The do-hive cloud-init memory template now connects the daemon straight to Postgres over verified TLS, and checks the tarball it installs (#4654, #4635, #4637, #4638, #4642).** `infra/do-hive/cloud-init-memory.yaml.tpl` no longer installs PgBouncer; the store URL is `postgres://aimemory:<percent-encoded password>@localhost/aimemory?sslmode=verify-full&sslrootcert=/etc/ai-memory/tls/pg-ca.crt` on the default port, so the connect funnel's sslmode floor (src/store/postgres/dsn.rs:213-283) is met. Postgres runs with `ssl = on` and a CA-signed server certificate minted on the node, and `pg_hba` admits the `aimemory` role only over `hostssl` (a non-TLS TCP attempt is rejected). The role password is read back from the store-URL file, percent-decoded and SQL-quoted on the node and sent to psql on stdin, so it is no longer interpolated into a SQL literal; provision.sh no longer runs under `set -x` and writes a root-only log. The tarball is downloaded into a root-only directory, checked against the new `ai_memory_image_sha256` variable before extraction, extracted without ownership and version-probed as the service user; a mismatch stops provisioning. `scripts/check-cloud-init-serve-flags.py` loses its do-hive exemption and now also fails on a store URL on port 6432, a local Postgres without `ssl = on` or a `hostssl` line, a tarball without a digest check before extraction (or ignored with `|| true`), and a terraform value written into a SQL password literal. `channel_binding=require` is not put in the daemon URL: the connect funnel removes keys the driver does not honour (src/store/postgres/dsn.rs:53-75). Measurement results taken before this change ran through a transaction-pooling PgBouncer and are not like-for-like with results after it (infra/do-hive/README-measurement.md).
