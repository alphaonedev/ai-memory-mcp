### Security

- Round 12 of `scripts/check-docs-no-argv-secrets.py`, per the 5-agent vote (4d3ea1c5): a waivable hit (`unknown-head-operand`, `array-element-operand`) now names the value kind of its flagged operand (`value=literal`, `placeholder`, `expansion` or `none`) and never prints the value; a quoted value (`pw='x'`, `pw="x"`) is masked like an unquoted one. A literal value, meaning any character left after removing expansions, quotes and backslashes (so `pw=abc$X` counts), can never be allowlisted: `scripts/regen-argv-secrets-allow.py` prints it as `REFUSED-LITERAL` with file, class, hash and masked preview, never writes it and exits 1 in every mode, and the gate refuses an allowlist line whose kind is `literal`. The allowlist format gains a value-kind field and the 16 entries were regenerated (none literal). (#5835)
- The operand allowlist must be byte-identical to what `scripts/regen-argv-secrets-allow.py` renders for the tree: the header now lives in the gate (`ALLOW_HEADER`, rendered by `allow_render`), and a changed header, an extra comment or blank line, CRLF or a missing final newline is a form fault (exit 2). Neither script can tell who typed a line, so the headers and the CI step (now `Operand allowlist matches the regen output`) say the approval is the reviewed diff, not the writer. (#5836)
- The `argv-credential-shape` rule reads more credential words and headers. At the end of any name: password, passwd, passphrase, secret, token, apikey, credentials. As a whole name part only: pass, pwd, pw, creds and the api, access, secret, auth, account, master and sas key spellings (`--api-key`, `--pwd=`, `db_pw=`; never `bypass=`). Headers: Authorization, Proxy-Authorization, (X-)Api-Key, auth, access, vault, private, api, session, csrf and xsrf tokens, `*-Secret` headers and (Set-)Cookie. The tree lines this newly finds are listed as PENDING under their issues (#5848, #4872, #4878, #4866). STATED LIMITS, each pinned as missed by a self-test row: a plain key, auth or cred flag, the client, private and tls key spellings (which name a key file in most programs) and a whole-name `PASS=` test counter (#5847). (#5837)
- An indexed array element assignment (`ARGS[1]=--password=VALUE`, `ARGS[2]+=db_token=VALUE`, `local ARGS[1]=...`) and a `[k]=v` element of an array body (`args=([1]=pw=VALUE)`) are read by their VALUE as an array element: by the array operand rule and by the shape rule. Before, both passed the gate. (#5838)
- The shape rule reads a quoted word that holds an expansion without its quotes, so `curl -H "Authorization: Bearer $TOKEN"`, `-H "X-API-Key: $KEY"` and `"--token=$T"` are flagged like their unquoted spellings; `eval` is read as the command line it runs. The 18 tree lines this finds are listed PENDING under #4877, #4878, #4866, #4874, #4875 and #5876. (#5875)
