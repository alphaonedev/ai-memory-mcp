**Breaking signature compatibility:** action-state transition signatures and
routine freeze attestations now include domain-separation tags. Signatures
created by binaries without #3616 no longer verify on upgraded binaries;
there is no fallback to the old untagged encoding.

Upgrade all federated peers in lockstep **before exchanging newly signed
transitions**. Old and upgraded peers use incompatible signing bytes. The
HTTP `/api/v1/sync/push` federation receiver verifies transitions on both SQLite
and PostgreSQL paths; transitions with legacy signatures cannot pass the
signature check and must be reissued by upgraded peers under the normal
state and replay checks.

Before running a persisted routine frozen by an older binary, review its
template and parameters, then **re-freeze it using `memory_routine_freeze`
with an active signing key on the upgraded binary**. Re-freezing an already
frozen routine replaces its attestation while preserving its freeze timestamp.
A present but unverifiable attestation refuses materialization, with an error
pointing to this remedy; it is never treated as an unsigned routine. MCP
`memory_routine_run` records a failed run with that error (also available via
`memory_routine_status`) and creates no actions. The same check protects
SQLite and PostgreSQL storage materialization callers. Deliberately unsigned
routines retain their existing behavior.

Frozen epoch manifest and succession formats are unchanged here. Explicitly
versioned v2 formats, with retained v1 verification, are tracked in #3644.
