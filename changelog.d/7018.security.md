**[release][supply-chain] Package metadata and the whole `dist/` directory pass the payload check before publication (#7018, umbrella #6062).**
The #6907 payload check compared only the one packaged file. The deb control
archive, the rpm header (maintainer scripts, scriptlets, triggers, dependencies,
file modes and owners) and any other file in `dist/`, which the upload, attest
and release steps publish through `dist/ai-memory*`, shipped without being
checked. Now `--verify-payload` refuses a deb whose control archive holds
anything but `control` (only the fields nfpm writes, package `ai-memory`), the
`md5sums` of the payload and an empty `conffiles`, and an rpm whose main header
carries a tag nfpm does not write for `nfpm.yaml` or a file list, mode, owner,
size or digest that does not describe the one checked file. After the checksum
sweep, the bound `--verify-dist` requires `dist/` to hold exactly the checked
tarball, at most one deb and one rpm, and one `.sha256` sidecar each, whose
digest is that of the bytes checked. Regression: the eighteen `6907a`/`6907b`
packer self-test cases, the `7018 ...` guard cases, and the "unchecked file
planted in dist" package runtime form.
