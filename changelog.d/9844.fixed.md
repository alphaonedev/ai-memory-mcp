**CI: the fail-closed `host_semaphore` token scan is back, and a workflow call of the host-slot wrapper is now checked as a canonical form, not parsed as shell (#9844, #9851).** `scripts/ci/host_slots_check.py` reads every file under `.github` again and accounts for every `host_semaphore` token, searched with every character outside the canonical set deleted, so a name split by a quote or a backslash still counts. Outside the listed `HOST_SEMAPHORE_` names the token may appear only on a content line of a `run: |` literal block of a .yml or .yaml file; a token in a folded, plain, quoted or flow value, under another key, in a comment or in a file that is not YAML is a finding. A call line may hold only letters, digits, space and `_ . / = : , -`: any other character (a quote, `$`, a backtick, `;`, `&`, `|`, `(`, `)`, `#`, `*`, a backslash, a control or a non-ASCII character) is named by its code point, so no expansion, substitution, ANSI-C quoting or operator can make bash read a call the checker did not. The parsed YAML `run` values must hold the same call lines as the raw text, and a file the YAML subset parser cannot read (including one over its 8 MiB cap) is a finding. A 100K-call line and a 100K-line block are each scanned in linear time. Known limit: a script path the shell computes at run time is not text, so review is the defence there.
