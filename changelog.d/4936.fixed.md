**Release guard pins the `on:`, `concurrency:` and `name:` values of `release.yml` and `release-shape.yml` (#4936, umbrella #6062).**
`scripts/check_release_features.py` pinned the key set of `release.yml` but
not the values of `on:` and `concurrency:`, so a `workflow_call`, `push: tags`
or `workflow_run` trigger, a `dry_run` input defaulting to `false`, or
`cancel-in-progress: true` (a second dispatch cancelling a release between its
publish steps) all passed the guard. `RELEASE_WORKFLOW_NAME`, `RELEASE_ON` and
`RELEASE_CONCURRENCY` now pin those values whole (single-quoted scalars are a
new `Single` pin style), and `SHAPE_WORKFLOW_NAME` / `SHAPE_CONCURRENCY` do the
same for `release-shape.yml`, whose check name becomes load-bearing once the
context is required (#4720). Regression: the ten `4936 ...` guard self-test
cases.
