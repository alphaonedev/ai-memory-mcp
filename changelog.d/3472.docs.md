The wake plane is now written down where a reader betting on ai-memory looks
for what is guaranteed: the enterprise-federation certification, the glossary,
the developer architecture map — and a harness row that proves the hub is
removable.

The certification's §6 NOT COVERED section now names `ai-memory wake-hub`
(EPIC #3466) as **transport-only** and outside the certified trust boundary.
The entry NARROWS what a reader may bet on rather than widening it, which is
why it does not re-mint anything: the hub federates nothing, is reachable only
over a mode-0600 Unix-domain socket on one host, and no `/sync/push` verdict,
`receive_auth` control, envelope gate or signature gate the certification
cites consults it. It records three properties as LIMITS. The plane is
CONTENT-FREE — a wake frame is exactly
`{inbox_row_id, namespace, sender, digest, seq_high_watermark}`, with no body
and no title on the bus frame or on the wire, so a hub process observes no
memory content and the plaintext-to-peer exposure already disclosed is
unchanged by it. Losing it degrades LATENCY ONLY — the inbox row is committed
before any hint is minted and stays the durable truth, and the normative
`<= 60 s` backstop poll is armed hub or no hub. And it is covered for nothing
else: no wake-latency SLO, no delivery / ordering / at-least-once guarantee
for a hint, no MEASURED hub scale envelope, and no authority derived from a
hint — what a woken recipient may read is decided by the ordinary inbox read
it then performs.

The load-bearing half is that the hub is PROVABLY removable, not merely
described as removable. `scripts/check-cert-removal-proof.sh` gains the row
`wake_backstop_always_armed_3472`, which runs in the opposite direction to
every other row in that harness: the others prove a control the certification
COVERS is load-bearing, this one proves the subsystem it does NOT cover is the
disposable half. It mutates the one thing that carries the claim — the
UNCONDITIONAL spawn of the backstop loop in `wake_client::WakeStream::start`,
which happens before and independently of the `if let Some(hub)` arm — and
asserts that
`tests/wake_client_3470.rs::inbox_wait_returns_on_the_bounded_backstop_with_no_hub_3470`,
which drives `ai-memory inbox --wait` on a host with no hub at all, turns RED
and then GREEN again on restore. Disarming that spawn is exactly the world in
which the hub is the sole delivery mechanism, so a green row is the executable
form of the sentence the page has always opened with: the POLL is the
guarantee, the wake is a prompt. The row takes the `subst` shape because the
control is one call site rather than a guard function, it is sqlite/UDS-local
(no live Postgres), and it gates no authorization — the mutation costs wake
latency in the working tree for the length of the run and can lose no durable
row.

Alongside it: `docs/wake-hub.md` gains a certification section stating the
three properties and walking the removal proof; `docs/GLOSSARY.md` gains
`Backstop poll`, `Subscribe acknowledgement`, `Wake frame`, `Wake hub` and
`Wake sink`, which it had none of; `docs/DEVELOPER_GUIDE.md` gains the wake
plane in both the architecture tree and the per-subsystem Code Structure list,
where all four modules were missing; and the `docs/README.md` index entry now
covers the client, the topic scoping, the subscribe acknowledgement and the
certification stance rather than only the bus and the switch.

No production code changed. The route, unique-path, CLI-subcommand and MCP
tool-count pins were re-derived against the merged wake-hub surface and are
already correct — `GET /api/v1/inbox/stream` is inside the production route
and unique-path counts, `wake-hub` and `wake-listen` are inside both CLI
subcommand counts, `inbox --wait` is a flag on an existing subcommand and
moves no count, and the wake plane registers no MCP tool, so the derived tool
count is untouched. They pass on the truth; none was edited to pass.
