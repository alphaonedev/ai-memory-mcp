The at-rest content decode now fails closed on a corrupt `encrypted_envelope` cell: a non-NULL value that is not a BLOB (TEXT / INTEGER / REAL, from corruption or tampering) is no longer read as "no envelope" (which returned the plaintext `content` column as if the row were unencrypted). It takes the same disposition as an undecryptable envelope: an error on targeted reads (`memory_get`), omission with a WARN and the corrupt-provenance metric on scan reads (recall, list, composition). The in-place-edit undo snapshot reader and the PostgreSQL decoder twin (any decode error other than an absent column) follow the same rule (#4133).
