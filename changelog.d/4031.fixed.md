### Fixed

- **CRDT merge is order-independent for retained metadata keys and optional fields**
  ([#4031](https://github.com/alphaonedev/ai-memory-mcp/issues/4031)). A value kept from an
  operand the other side lacked inherited the merged row's newer clock, so replicas that saw the
  same versions in different orders diverged. Metadata (at any depth) and the optional provenance
  fields are now an LWW-element map with per-path versions: a retained value's true version is
  recorded in the reserved `metadata.crdt_field_clocks` key (bound to the row clock it was minted
  at, so any later local write re-versions the whole row and an edited-away-and-back value can
  never resurrect an old version; fingerprint-validated; capped at the row clock, so a forged
  entry can only lose), and object/scalar type flips record a floor that prunes the superseded
  subtree. The visibility keys (`scope`, `target_agent_id`, `recipient_agent_id`) resolve by their
  own version with ABSENCE versioned too, so neither delivery order nor a stale peer row can re-widen
  a row its owner narrowed (made private by dropping `scope`, or un-shared by dropping
  `target_agent_id`). A peer-supplied clock map is untrusted: floors inconsistent with the sender's
  own values are dropped, so a forged floor cannot erase nested metadata. Merged values converge;
  the clock-map bytes themselves may differ between replicas.
  Round 2 (f2r): the visibility register compares VERSION only (not the merged row's attestation
  rank, which made a fail-OPEN grouping possible at an equal-microsecond write), and an absence
  wins at an equal version. Operator-visible availability effect: a missing visibility key is dated
  at its row's clock, so a peer row newer than a share revokes it even when that peer never
  received the share; re-share to recover (a fresh write outranks every older absence).
