### Fixed

- **CRDT merge is order-independent for retained metadata keys and optional fields**
  ([#4031](https://github.com/alphaonedev/ai-memory-mcp/issues/4031)). A value kept from an
  operand the other side lacked inherited the merged row's newer clock, so replicas that saw the
  same versions in different orders diverged. Metadata (at any depth) and the optional provenance
  fields are now an LWW-element map with per-path versions: a retained value's true version is
  recorded in the reserved `metadata.crdt_field_clocks` key (bound to the row clock it was minted
  at, so any later local write re-versions the whole row and an edited-away-and-back value can
  never resurrect an old version; fingerprint-validated; capped at the row clock, so a forged
  entry can only lose), and object/scalar type flips record a floor that prunes the superseded
  subtree. `metadata.scope` resolves by its own version, so delivery order can no longer let a
  retained `collective` override a newer `private`.
