**Every notify funnel now refuses an invalid `target_agent_id` identically on both backends (#4338).** `PostgresStore::notify` (and so `POST /api/v1/notify` on a postgres daemon) never validated the recipient, so an empty, oversized or out-of-charset id was persisted as an inbox row and namespace no agent could read, was published on the in-process wake bus, and an oversized one surfaced as a 5xx backend error instead of a validation error. One shared validator, `validate::validate_notify_target`, now runs in `memory_notify`, `POST /api/v1/notify` (above the backend branch), and both `MemoryStore::notify` adapters, before any quota charge, write or wake. A refused recipient returns the same typed `InvalidInput` / HTTP 400 with a fixed message that never echoes the supplied value, on sqlite and postgres.
