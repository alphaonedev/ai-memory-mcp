The append-only scratch janitor (`scripts/clear-append-only-scratch.py`) now records every mode widen it makes in a pending-restore journal (`.clear-append-only-pending` in the scratch root) instead of one durable record slot, so a run killed by an uncatchable `SIGKILL` with more than one widen outstanding has each of them put back by the next run (#6006, #6020). Each widen appends its own line - an entry id, the inode, the mode the walk found and the mode it widened to - and fsyncs it before the chmod it covers; the release of one widen appends a release of that line only, so an inner lookup's release can no longer discharge a directory's outer widen (#6013). The next run finishes a line only on the inode its own walk reaches inside the scratch tree, and only when that inode carries exactly the widened mode (put back) or exactly the found mode (already back); a mode changed since the kill is left as it is and reported (#6014), a name that now holds a different inode is reported by every run until it is resolved rather than forgotten after one (#6015), and a name that is not valid UTF-8 is journalled and put back like any other (#6016). A journal line that names a path outside the scratch tree, or describes a change that is not a widen this script makes, is refused and kept, never acted on (#6018: an integrity and fail-open defect, not a privilege escalation), and a journal that is not a regular file with one link, owned by the running user and writable by nobody else, is neither read nor written, and the widens it would record are refused (#6019). The journal is emptied only by a run that settled every line in it.
