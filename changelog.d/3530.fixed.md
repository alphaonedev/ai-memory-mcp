An unvalidated `{id}` path segment can no longer reach the signed audit chain
from the admin api-key mint route.

`POST /api/v1/agents/{id}/api-key` refuses a mint over a transport the daemon
has not promised is confidential, and audited that refusal BEFORE
`validate_agent_id` ran — so the row carried the raw, never-validated path
segment. It was JSON-encoded and therefore structurally safe, but the forensic
chain is signed and append-only and unbounded caller-controlled bytes do not
belong on it. Validation now runs first. The `400` for a malformed id depends
on the SHAPE of the id alone — never on whether the target exists, never on the
transport posture — so refusing earlier discloses nothing the route did not
already disclose, and `require_admin` still runs before either check, so an
unauthenticated caller learns nothing at all. The transport refusal itself is
unchanged: a well-formed id over a non-confidential transport is still
`403 credential_transport_not_confidential` with its audit row.
