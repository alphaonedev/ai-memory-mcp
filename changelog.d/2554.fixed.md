**A failed schema upgrade no longer leaves newer tables behind an older schema stamp (#2554).**
On SQLite the bootstrap DDL ran before the migration ladder and outside its
transaction, so a ladder that died (crash, full disk, a refusing migration)
left the newer tables, indexes and triggers committed while the stamp still
named the old version. An older binary then saw a matching stamp, passed the
schema-ahead guard and wrote into a database it did not understand. When an
upgrade is pending, the bootstrap now runs inside the ladder's exclusive
transaction, so it commits or rolls back together with the stamp. The
pre-migration snapshot now captures the file exactly as it was before the
open. Postgres is unaffected: each migration rung stamps in its own
transaction.
