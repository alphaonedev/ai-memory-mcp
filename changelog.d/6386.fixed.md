Enterprise-fed CI can run the class (a) Postgres test binaries side by side behind an OPT-IN lane. The lane runs only when `AI_MEMORY_TEST_PG_ISOLATE=1`, which `ci.yml` sets on no leg (default-on waits for two green sharded carrier runs and a 5-agent vote); `CI_PG_ISOLATE_OFF=1` is a hard kill switch. With it on, `scripts/test/pg_isolated_binary.py` clones one database per binary from a locked age+vector template and runs up to eight at a time, with in-binary `--test-threads=1` unchanged. Supporting behaviour: a live connection budget (`max_connections` minus reserved slots minus open sessions) that fails closed; clone names scoped to a run id, so teardown never touches another run's clones; no FORCE drops, plus a keepalive hold on each clone; an admin-only `sweep --older-than`; connection details passed through libpq environment variables, never argv; SIGTERM handling that stops dispatch and reclaims the clones; one log file per binary, uploaded with `if: always()`; and a residual-serial list, run on the shared database, for binaries that share a loopback port or path (#6386, umbrella #6383).
