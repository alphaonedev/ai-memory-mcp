**security: one owner gate for skill, routine, agent, entity-alias and action-edge mutations (#8771, #8772, #8774, #8775, #8790, #8557).**
`memory_skill_retire`, `memory_skill_delete`, a superseding `memory_skill_register`,
`memory_routine_freeze`, `memory_agent_register` over an existing roster entry,
`memory_entity_register` merging aliases into an existing entity, and
`memory_action_add_edge` now succeed only when the resolved caller is the recorded
owner (or holds a shipped governance grant). The caller is the authenticated
principal, never an `agent_id` argument. Any other caller gets the single error
`caller does not own this object` (HTTP 403 `NOT_OWNER`), identical on MCP, HTTP and
CLI and on SQLite and PostgreSQL, and the stored rows are left unchanged. The check
lives in one helper, `ai_memory::identity::object_owner`. No tool, route, CLI
subcommand, wire field or migration was added.
