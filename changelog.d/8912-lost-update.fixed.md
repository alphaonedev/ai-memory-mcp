**Writes no longer lose a newer row or revive a forgotten one (#8912, #8890, #4287, #4034).** `ai-memory sync` (pull, push and merge) wrote every source row through the plain insert funnel, so an older source row replaced a newer destination row with the same id or title slot and a forgotten (tombstoned) id came back; it now decides newer-wins and tombstone-wins inside the same write transaction as the write, keeps the destination when the source row is older, skips a tombstoned id as `skipped_by_covenant`, counts a row the destination rejects as `refused` (named on stderr) and exits `3` (`EXIT_EXPORT_INCOMPLETE`, as `import` does) when any row was refused. The vertical promote clone (#8890), the `If-Match` update and the archive-on-supersede write (#4034) now read the row and write it inside one SQLite write transaction, so a failed link write leaves no orphan clone and a concurrent commit between the read and the write can no longer be overwritten from a stale snapshot. The curator auto-tag and contradiction write-backs (#4287) re-read the row's metadata inside the write transaction, merge into the current value instead of the curator's earlier snapshot, and refuse a row that vanished instead of reporting it written. They also refuse (#9300), and write nothing, when the title or content a verdict was computed from changed after the sweep read the row, or when the contradicting row's content changed; the cycle report lists the row under `errors` with the reason `the row changed after the sweep read it (stale snapshot); nothing written` and does not count it as tagged or as a contradiction. The PostgreSQL update pre-reads take a `FOR UPDATE` row lock, so the read and the write see the same row on the visibility-bypass path too.
