### Security

- **[federation] A local lease-read error refuses an inbound action transition instead of reading as "no lease"**
  ([#3986](https://github.com/alphaonedev/ai-memory-mcp/issues/3986)). Both `/sync/push`
  transition funnels (sqlite `federation_receive`, postgres `federation_signing_check`) read the
  local lease with `lease_get(..).ok().flatten()`, so a storage error became "no lease holder" and
  `authorize_remote_transition` skipped its lease-holder conflict check — fail OPEN: a validly
  signed transition by one agent applied over a live lease another agent holds whenever the node
  could not read that lease (and, under a permissive transition-signature posture, an unsigned
  one did too). A read error now refuses the item: it is counted in the push envelope's `skipped`
  and logged with the distinguishable cause token `lease_unresolvable`
  (`receive_auth::CAUSE_LEASE_UNRESOLVABLE`). These were the only two lease reads of that shape;
  the local transition funnels (HTTP, MCP) already propagated the error.
  Pinned by `tests/federation_transition_lease_read_error_3986.rs` (sqlite: a corrupted lease row;
  postgres: the `leases` table taken offline), each with a lease-free control that still applies.
