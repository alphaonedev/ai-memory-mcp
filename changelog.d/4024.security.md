**A federated action transition's replay identity is recorded atomically with the transition it authorizes (#4024; #1805 replay protection kept, now durable).**
Both `/sync/push` receive funnels (sqlite `federation_receive`, postgres
`sync_push_via_store`) used to record a signed transition's `nonce` in the
in-memory replay cache BEFORE the compare-and-swap, and counted a CAS miss as
a `noop`. A transition that arrived ahead of its causal predecessor was
therefore acknowledged as done while it was not applied, and its nonce was
consumed, so the sender's retry was refused as a replay: the transition was
lost. A transient CAS error lost it the same way. Schema **v101** adds the
`action_transition_nonces` table (both adapters; additive, NoLoss). The
identity `(action_id, nonce)` is written in the SAME transaction as the CAS,
through `actions::transition_cas_once` and
`MemoryStore::action_transition_cas_once` (whose default fails closed). A row
therefore exists exactly when the transition applied. A state mismatch, an
illegal edge or a substrate error writes nothing and is reported as `skipped`,
which the sender treats as a non-ack and retries; it is no longer a `noop`.
**A re-delivery of an APPLIED transition (a lost ack retried by the sender, a
relay via another peer, a cyclic-edge replay) is acknowledged as a `noop` and
re-applies nothing** (#4204, 5-agent vote 4d3ea1c5, decision f41cf98b): the
identity probe runs before the CAS, so #1805 "never re-apply" holds, and the
op is never reported `skipped`, so it never lands in the push-DLQ and is never
retried to quarantine. The refusal no longer depends on the bounded, per-peer,
best-effort-persisted cache: it survives cache eviction and restarts, and it
holds when the same signed op is relayed by a different peer. The identity
table's foreign key to `actions` is `ON DELETE RESTRICT` (a future
delete/purge path must handle recorded identities rather than silently
reopening #1805 replay). The table is never pruned below the replay window, so
its row count is reported as `action_transition_nonces` in `stats` (both
backends, sqlite + postgres HTTP envelope + MCP `memory_stats`) and in
`ai-memory doctor` (Storage fact; a postgres-only "Action transition
identities (#4024)" section). Unsigned transitions admitted under the rollout
hatch `AI_MEMORY_FED_REQUIRE_TRANSITION_SIG=0` carry no nonce and record no
identity: replay protection covers signed ops only (the hatch's contract; the
strict default refuses unsigned ops).
