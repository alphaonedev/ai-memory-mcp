**Release feature guard hardened and ported to Python (#4719).** `scripts/check-release-features.sh` is ported to `scripts/check_release_features.py` (stdlib only, Python 3.9+) and rebuilt as an allowlist instead of a list of bad shell forms. The release.yml build step, the strict-assert step, the SBOM step, the release-shape build step and the Dockerfile builder `RUN` must each equal their one expected statement list, compared after joining `\` continuations, collapsing whitespace and dropping whole-line comments only; a trailing `#` is not trusted. Anything else is refused: an extra, reordered or reassigned statement (`FEATURES=`, `REQUIRE_FLAGS=`, `bin=`), a function, alias, heredoc, `hash`, `exec`, `PATH` or `cd` change, `set +e`, `|| true`, a conditional or backgrounded assert, `--no-default-features`, `--all-features` or a literal feature list, a missing `--locked`, a second `cargo build` of the matrix target or in the Dockerfile, and a declaration rewritten inside the unit. Those steps may carry only `name`, `shell: bash` (not the SBOM) and `run: |`; `env:`, `working-directory:`, `if:`, `continue-on-error`, a folded or quoted `run`, a duplicate key and flow-style lines are refused. The assert must be in the same `release:` job as the matrix build, after it, and that job may carry only `name`, `needs`, `runs-on`, `permissions`, `strategy` and `steps`, so no job-level `if:`, `env:` or `defaults:`; the workflow top level is limited to `name`, `on`, `permissions`, `concurrency` and `jobs`. `BASH_ENV` is refused anywhere in release.yml and the Dockerfile, as is a Dockerfile `SHELL` instruction and any control character (CR, form feed, NUL). A missing input file fails the guard (exit 1); an unreadable one (non-UTF-8, a directory, a symlink loop) exits 2. The units are also pinned by POSITION, not only by text: the workflows are read with a strict, fail-closed YAML subset parser (one indentation per mapping; tabs, over-indented or stray lines, quoted or complex keys, duplicate keys, anchors, aliases, tags, flow mappings and multi-line quoted scalars are refused, and a block scalar is allowed only as a step `run:` or `with:` value), and the build and strict assert are located under top-level `jobs:` -> `release:` -> `steps:`, the SBOM under `jobs:` -> `sbom:` (a second `cargo ... cyclonedx` anywhere is refused) and the proof build under `jobs:` -> `release-shape:`. The release job skeleton is pinned: `runs-on` is exactly `${{ matrix.os }}`, the strategy is `fail-fast: false` with `matrix: include:` entries whose `target`/`os`/`artifact`/`nfpm_arch` values are unquoted literals matching a strict pattern (they are substituted into the pinned build and assert text before bash runs), and the target set is pinned in `RELEASE_TARGETS` (a legitimate matrix change updates it in the same commit); a pinned step name may not carry `${{`. No other release-job step may run `cargo`, `rustc`, `cross` or `cargo-zigbuild` (any case or option order), and the docker job may not pass `target:` or `file:` to the image build. In the Dockerfile only the line-1 `# syntax=docker/dockerfile:1` directive is allowed (no `escape` or second directive), heredocs, `ONBUILD` and unknown instructions are refused, and the stage chain is verified: the final stage copies the binary exactly once from a named earlier stage and takes nothing else `--from` elsewhere, and that builder stage copies `Cargo.lock`, takes no `--from` and ends with the declaration COPY followed by the canonical RUN; `cargo` anywhere else in the Dockerfile is refused. NBSP and every other non-ASCII space, zero-width character, BOM and line separator are refused like control characters, never folded. Refusal messages name the step (`step N \`name\``) and the first differing statement, also for the Dockerfile RUN. The self-test has 223 guard cases and 9 entry-point cases (every refusal has one), fails if an input file is missing, and `--mutation-sweep` reproduces the proof that disabling any of the 55 refusal sites turns the self-test red (55 mutants, 0 survivors). The SBOM step no longer counts as the matrix build.
