**Release feature guard hardened and ported to Python (#4719).** `scripts/check-release-features.sh` is ported to `scripts/check_release_features.py` (stdlib only, Python 3.9+) and rebuilt as whole-unit allowlists that refuse anything the guard cannot model, instead of a list of bad shell forms.
- **Units.** The release.yml build, strict-assert and SBOM steps and the release-shape build step must each equal their one expected statement list.
  - Only whitespace runs are normalised and only whole-line comments are dropped. A trailing `#` is not trusted.
  - Anything else is refused: an extra, reordered or reassigned statement, a function, alias, heredoc, `PATH` or `cd` change, `set +e`, `|| true`, a conditional or backgrounded assert, a feature-flag change, a missing `--locked`, and a declaration rewritten inside the unit.
  - Those steps may carry only `name`, `shell: bash` (not the SBOM) and `run: |`.
- **Line continuations are not modelled.** A run line ending in `\` is refused in release.yml and release-shape.yml.
  - In the Dockerfile, every line ending in `\` is refused except those of the canonical builder `RUN`, which must equal its pinned physical lines one by one (no comment or blank line inside, no re-indent).
- **Strict YAML subset parser.** The workflows are read with a strict, fail-closed YAML subset parser, and the units are located by position (`jobs:` -> `release:`/`sbom:`/`release-shape:` -> `steps:`).
  - The parser refuses tabs, over-indented or stray lines, quoted or complex keys, duplicate keys, anchors, aliases, tags, flow mappings, multi-line quoted scalars and a backslash inside a double-quoted scalar.
  - A block scalar is allowed only as a step `run:` or `with:` value.
- **The release job skeleton is pinned:** its keys, `runs-on: ${{ matrix.os }}`, the strategy, matrix values that are unquoted literals matching a strict pattern, and the target set (`RELEASE_TARGETS`).
  - No other release-job step may run `cargo`, `rustc`, `cross` or `cargo-zigbuild` (read with quote and backslash characters removed).
  - At most one line in release.yml builds the matrix target.
- **The `docker:` job is pinned whole:** its keys and values, and its six ordered steps.
  - The steps are checkout, Buildx setup, registry login, version, image build and provenance attestation.
  - Each step's keys, `uses` SHA, `with:` inputs and run text are pinned, so any added, removed, reordered or changed step, and any job `env:` or `container:`, is refused.
- **Permissions, secrets and the registry.**
  - The top-level `permissions:` is exactly `contents: write`, and every job's `permissions:` is pinned. `packages: write` exists in the docker job only.
  - The job set is pinned and no job may call a reusable workflow.
  - `secrets` references are limited to the pinned names.
  - The registry host appears only in the docker job.
- **release-shape.yml is pinned as a skeleton:** top-level keys, `on:` triggers, `permissions:`, `env:`, and exactly one job with pinned keys and values (no `needs:`, `if:`, `env:`, `defaults:` or `container:`).
  - The Postgres proof is exactly one run step equal to the pinned invocation, after the build, with no step `if:` or `continue-on-error`.
  - Job-level `continue-on-error: true` is required while `SHAPE_ADVISORY` is True (#4480). #4720 flips the constant to False with the workflow, after which the key is refused.
- **Dockerfile.**
  - Only the line-1 `# syntax=docker/dockerfile:1` directive is allowed. Heredocs, `SHELL`, `ONBUILD`, unknown instructions, `--mount` and a `FROM` image containing `$` are refused.
  - The stage chain is verified: the final stage copies the binary once from the named builder stage, which copies `Cargo.lock`, takes no `--from` and ends with the declaration COPY and the canonical RUN.
  - A build tool anywhere else in the Dockerfile is refused, read with quote and backslash characters removed.
- **Refused anywhere:** `BASH_ENV` (release.yml, release-shape.yml, Dockerfile), control characters, non-ASCII spaces, zero-width characters and line separators.
- **Pin maintenance.** Every pin-mismatch message names the constant to update in `scripts/check_release_features.py`.
  - A Dependabot SHA bump of a docker-job action fails with one message naming its `*_USES` constant. Update that constant to the new SHA in the same commit.
- **Self-test and mutation sweep.**
  - The self-test has 370 guard cases, 6 advisory-state cases, 11 message cases, 16 BuildKit parity cases, 7 scalar cases and 9 entry-point cases.
  - `--mutation-sweep` proves that disabling any of the 81 refusal sites, or changing any of 57 guard conditions or regexes, turns the self-test red (138 mutants, 0 survivors).
- **Exit codes.** A missing input file exits 1; an unreadable one exits 2.
- **Tracked separately.**
  - #4752: the shipped file differing from the asserted one. Spellings built by shell expansion are outside the best-effort spelling view.
  - #4768: another step or Dockerfile instruction tampering with the inputs the allowed units read. Examples are a builder-stage `ENV`, `ARG` or `ADD`, a different base image, `os: self-hosted`, or a release-shape step between the build and the proof.
- **Intel macOS build.** The cross-built `x86_64-apple-darwin` artifact was only arch-checked. It now builds on the Intel `macos-15-intel` runner and runs the same strict `ai-memory features` assert (narrows #4480; runner end of life tracked in #4770).
