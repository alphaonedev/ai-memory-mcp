**Release feature guard hardened and ported to Python (#4719).** `scripts/check-release-features.sh` is ported to `scripts/check_release_features.py` (stdlib only, Python 3.9+) and rebuilt as an allowlist instead of a list of bad shell forms. The release.yml build step, the strict-assert step, the SBOM step, the release-shape build step and the Dockerfile builder `RUN` must each equal their one expected statement list, compared after joining `\` continuations, collapsing whitespace and dropping whole-line comments only; a trailing `#` is not trusted. Anything else is refused: an extra, reordered or reassigned statement (`FEATURES=`, `REQUIRE_FLAGS=`, `bin=`), a function, alias, heredoc, `hash`, `exec`, `PATH` or `cd` change, `set +e`, `|| true`, a conditional or backgrounded assert, `--no-default-features`, `--all-features` or a literal feature list, a missing `--locked`, a second `cargo build` of the matrix target or in the Dockerfile, and a declaration rewritten inside the unit. Those steps may carry only `name`, `shell: bash` (not the SBOM) and `run: |`; `env:`, `working-directory:`, `if:`, `continue-on-error`, a folded or quoted `run`, a duplicate key and flow-style lines are refused. The assert must be in the same `release:` job as the matrix build, after it, and that job may carry only `name`, `needs`, `runs-on`, `permissions`, `strategy` and `steps`, so no job-level `if:`, `env:` or `defaults:`; the workflow top level is limited to `name`, `on`, `permissions`, `concurrency` and `jobs`. `BASH_ENV` is refused anywhere in release.yml and the Dockerfile, as is a Dockerfile `SHELL` instruction and any control character (CR, form feed, NUL). A missing input file fails the guard (exit 1); an unreadable one (non-UTF-8, a directory, a symlink loop) exits 2. The self-test has 157 guard cases and 9 entry-point cases (every refusal has one), fails if an input file is missing, and `--mutation-sweep` reproduces the proof that disabling any of the 23 refusal sites turns the self-test red (23 mutants, 0 survivors). The SBOM step no longer counts as the matrix build. Still tracked separately: the shipped file differing from the asserted one (#4752) and another step tampering with the assert's inputs (#4768). The cross-built `x86_64-apple-darwin` artifact was only arch-checked; it now builds on the Intel `macos-15-intel` runner and runs the same strict exact-set `ai-memory features` assert as the other three targets (narrows #4480; runner end of life tracked in #4770).
