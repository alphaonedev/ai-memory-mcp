**Release feature guard hardened and ported to Python (#4719).** `scripts/check-release-features.sh` is ported to `scripts/check_release_features.py` (stdlib only). It refuses a `FEATURES=` / `REQUIRE_FLAGS=` reassignment (including `read`, `eval` and env-prefixed forms) between the declaration and the release.yml build, SBOM or assert step and inside the Dockerfile `RUN`, a `--locked` that exists only in a comment, `--no-default-features` / `--all-features` / a literal feature list on a build (including `cargo +toolchain build`), and a strict assert that can be skipped: a step `if:`, `continue-on-error`, `|| true`, `&&`, `set +e`, or a shell or Dockerfile conditional. The assert must target exactly `"$bin"` (workflow) or `target/release/ai-memory` (Dockerfile), and `bin` is assigned once. Refusals run on a view where only whole-line comments are dropped, so no comment form can hide code. The SBOM step no longer counts as the matrix build, and non-UTF-8 input exits 2. The self-test has about 80 cases and every refusal is mutation-tested (44 mutants, none survive). The cross-built `x86_64-apple-darwin` artifact was only arch-checked; it now builds on the Intel `macos-15-intel` runner and runs the same strict exact-set `ai-memory features` assert as the other three targets (narrows #4480).
