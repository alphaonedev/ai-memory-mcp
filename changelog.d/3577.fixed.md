**Test isolation: process-global LINEAGE_DAG seeders restore on drop; readers hold a funnel; cycle pre-seeds are newer→older (#3577).**

`LINEAGE_DAG` is a process-global `AtomicBool` (compiled production default ON, unseeded atomic default OFF). `handlers::consolidate_federation` tests flipped it to `true` under a module-private `FLAG_LOCK` that **only the seeders took**, then set `false` on the success path only. Every lib test that writes a lineage relation (`reflects_on` / `derived_from` / `derives_from`) was a reader that took no lock, so an older→newer pre-seed failed Pass 0 of `validate_link_pre_create` whenever a seeder's window was open — and `http_create_link_refuses_cycle` failed that way in both lib slices once #3539 shifted boot-test scheduling.

The funnel is `crate::test_support::LineageDagIsolation` (lock + snapshot + restore on drop, OWNERSHIP-24/25). Seeders call its methods. The production boot seed in `daemon_runtime::run` stays `#[cfg(not(test))]`; lib `bootstrap_serve` tests never hit that seed and are not re-seeded here (QUAL-10: `daemon_runtime.rs` is at its ceiling). `simulate_production_lineage_seed()` lives on the funnel for tests that must opt into the production-ON posture and restores on drop. Readers hold `no_lineage_dag_guard()` which asserts the flag is OFF (loud, not flaky). Tokio tests take the tokio DB lock first, then the lineage std mutex. Two sites hold the std guard across `.await`: seeder `store_finalize_and_disposition_matches_sqlite_twin` must keep the funnel live across its awaited finalize, and reader `live_link_reflects_on_cycle_refused_1568` holds it across `store.store().await`. That is a documented CONCURRENCY-20 exception, safe because the test-only mutex is never contended by any task on either runtime. Cycle tests pin `created_at` so the pre-seed is strictly newer→older (`LINEAGE_FIXTURE_OLDER_AT` / `LINEAGE_FIXTURE_NEWER_AT`) and the closing write is refused by Pass 0 or Pass 1 under either flag value. `scripts/check-test-env-lock.sh` arm (g) greps `src/**` for a qualified `config::set_lineage_dag(` / `config::set_consolidate_tombstone_sources(` outside the funnel (`test_support.rs`) and the production boot seed (`daemon_runtime.rs`). Integration tests under `tests/` keep their own process.

The restore-on-drop pin asserts under the same `LineageDagIsolation` hold (`restore_flags`, which `Drop` calls). An unlocked before/after snapshot races sibling seeders (`before=(true,true)` from a live seeder, `after=(false,false)` from this guard's captured prev) — std `Mutex` is not reentrant (CONCURRENCY-04), so a second Isolation cannot wrap the first.

Control: ERRORS-09 (illegal state unrepresentable — no `cfg(test)` seeder without the guard), OWNERSHIP-24 (restore on drop), OWNERSHIP-25 (infallible Drop), CONCURRENCY-04 (no nested std Mutex), CONCURRENCY-18 (poison recovery), CONCURRENCY-20 (documented exception: two tokio tests hold the test-only mutex across `.await`; never contended by any task on either runtime).
