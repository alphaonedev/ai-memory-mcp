**CI tier credential handling (#8187).** The enterprise-fed tier steps in `ci.yml` now load the tier URL only through `scripts/ci/tier_credential.py`: the connection reaches `psql` and the Postgres isolation wrapper through libpq environment variables, so no credential is on argv or in a shell variable (#6172). The helper and `scripts/ci/check-tier-password.py` refuse a URL file that is group- or world-accessible (#6180), and the checker is pinned: the 8-character contained-component boundary, every host of a multi-host URL, the `user`, `dbname` and `hostaddr` query keys, read errors that print only the exception class, and an unremovable, unskippable call in the step (#6640, #6645, #6671, #6672, #6872, #6899, #7971).
