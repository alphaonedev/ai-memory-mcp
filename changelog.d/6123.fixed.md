Every lib-test write to an environment variable or to the working directory now runs under the crate's single process-env lock (`crate::config::test_env_lock`, or the identity lock for the agent-id surface), and eight test fixtures build their scratch root from `CARGO_MANIFEST_DIR` instead of the working directory, so `recover::tests::limit_caps_atomised_lines` no longer fails when run in parallel with a `migrate` test that changes into a tempdir and deletes it (7 of 10 parallel runs before, 0 of 10 after); the new gate `scripts/check-env-mutation-lock.py` fails on any unguarded `set_var` / `remove_var` / `set_current_dir` in lib test code. Test code and gate only; no runtime code changes.
