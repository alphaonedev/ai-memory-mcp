**#3806 W1a — the `[decision]` provider seam: a structured-decision model class beside the generative `[llm]` backend.** Trait + config + resolver only; nothing is wired yet (the boot chokepoint, the clients and the seams land next).

`src/decision.rs` declares `DecisionProvider` with `choose(prompt, options) -> Choice`, `score(prompt, range) -> Scored` and `judge(prompt) -> Judgement`. Three invariants are made *unrepresentable* rather than documented: the decision itself is `Option<T>` — **abstain is a first-class value carrying an `AbstainReason` (`no_provider` / `timeout` / `egress_refused` / `unusable` / `unsupported`), never a default `false`**; `confidence` is `Option<f64>`, absent whenever no logprobs or calibration evidence back it, range-validated so a `NaN` or out-of-`0.0..=1.0` probability DEGRADES to absent instead of being stored (a `NaN` confidence would otherwise sail through every `conf < threshold` guard); and every answer carries a `DecisionSource` (`DecisionModel` / `GenerativeFallback` / `Deterministic`) so a surface can never report a generative guess as a decision-model verdict. Fields are private with constructors as the only way in, so `value.is_some()` iff `abstain_reason.is_none()` and a confidence can never be attached to an abstain. `NullDecider` (plus `decider_or_null`) is the absent-provider path: it always abstains, which is what a seam consults when `[decision]` is unset. The trait is `async` and object-safe, so an OpenAI-compatible client, a SystemOne adapter, a local NLI cross-encoder on candle and a generative fallback can each implement it unchanged.

`src/decision_config.rs` adds the `[decision]` section (`provider`, `model`, `base_url`, `api_key_env` | `api_key_file`, `timeout_secs`, `fallback`), `ResolvedDecision` and `resolve_decision()`. **Unset `[decision]` is byte-identical v1.0.0**: the resolver returns `None` before it even looks at the parent `[llm]` view, and a golden over the config resolution plus a structural pin (no production call site consults the decider) hold that. One predicate — `plan()` — decides what is acceptable, so the parse-time refusal and the resolver *cannot disagree*: a section that refuses at load can never resolve to a live endpoint through some other entry point, and anything the resolver cannot honour exactly as written becomes NO provider rather than a half-configured one. Refused by name: an unrecognised `provider` (accepted at GA: every `[llm]` alias plus `systemone`, `openai-compatible`, `ollama`, `local-nli`); a `model` that would otherwise be guessed; a `base_url` for `openai-compatible` / `systemone`, which have no compiled default and are never guessed; `base_url` or any `api_key_*` on `local-nli`, which opens no socket; `timeout_secs = 0`. `timeout_secs` defaults to **2** (approximately 3.4x the measured P99) and a timeout is an abstain; `fallback` defaults to **`abstain`**, the only safe posture on a destructive seam.

Secret handling mirrors `[llm]`: inline `api_key` is REJECTED at parse time, `api_key_env` / `api_key_file` are mutually exclusive, the resolved key is private, redacted in `Debug` and zeroized on `Drop`. **The parent `[llm]` credential is inherited only when the decision endpoint is literally the same endpoint** (same provider AND same resolved base URL) — a deliberate tightening of the `[llm.auto_tag]` resolver's backend-name-only match — and there is deliberately no generic `AI_MEMORY_DECISION_API_KEY`: a catch-all env var would ship the chat credential to a different vendor's host. The shared key ladder therefore takes an *optional* primary env var; `[llm]` and `[embeddings]` keep theirs.

**BREAKING (#3808, absorbed here): `[llm.auto_tag].backend` / `.base_url` / `.api_key_env` / `.api_key_file` are now REFUSED at parse time.** They were documented as a second inference endpoint, but `resolve_llm_auto_tag` had **zero callers** — production threads the legacy flat `auto_tag_model` — so an operator who pointed `[llm.auto_tag]` at a second endpoint had it dropped without a warning, and had it been wired as written that endpoint would also have bypassed the `build_llm_client` egress gate. A config that is accepted and then ignored is a config that lies, so the key is refused by name rather than warned about. The dead resolver is deleted in the same change. **Repair: delete the line** (behaviour is unchanged — it never did anything), or express the second endpoint under `[decision]`, which is resolved and will be gated. `[llm.auto_tag].model` still parses, because `ai-memory config migrate` writes exactly that key when it lifts a legacy `auto_tag_model` — refusing it would make the repair tool emit a config the loader rejects. The shipped `[llm.auto_tag]` examples in `CONFIG_SCHEMA.md`, `ADMIN_GUIDE.md` and `integrations/llm-backends.md` are corrected in the same change; `ai-memory config check --file <path>` reports a config that would refuse, before an upgrade.
