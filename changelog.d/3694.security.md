**`ai-memory reown` defaults to its narrowest action and names what it moves (#3694).**
The bare command (no selection flag) used to rewrite EVERY row that already had an
owner — rows taken from other agents — while `--claim-unowned`, the safest-sounding
flag, selected every row in scope, owned included. On a multi-tenant node one
invocation with `--all-namespaces` reassigned every tenant, fully audited and
completely done.

- The default is now `--only-unowned`: rows with no ownership stamp are adopted; a
  row that has an owner is never touched by the bare command. Both backends.
- `--take-owned` is the explicit seizing selection (every row in scope that has an
  owner). Without `--dry-run` it requires `--yes`; without `--yes` it plans, refuses,
  names the row count and the owners it would take, and writes nothing.
- `--claim-unowned` is a hard error naming the two replacements. It is not renamed,
  so an old script fails loudly instead of quietly doing what it always did.
- The report names the SET, not only the count: `owners` (prior owner -> rows taken
  from it), `changes` (the first 200 rows with the owner each came from) and
  `changes_omitted`, in the JSON and the human output, on dry runs too.
- Pinned: the bare default leaves an owned row untouched and adopts the unstamped
  one, on SQLite and on Postgres.
