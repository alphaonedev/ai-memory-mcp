**The PostgreSQL agent cut-over marker is signed and verified like the SQLite one (#10108, #10194).**
The PostgreSQL v103 step now builds its marker with the same signed constructor as SQLite, with the same
bytes, and inserts it with its daemon signature: at sequence 1 on an empty chain (the genesis marker of a
fresh database) or directly above the chain head. The daemon key is provisioned before the migration
ladder starts, so a missing key refuses with the database untouched. The PostgreSQL walk judges the
marker under the same verifier as the rows, so an unsigned, tampered or second marker fails it, and a
v103 database without its marker fails every walk. The unsigned marker builder and resolver are removed
from the tree, the marker writers take a `SignedMarker` that only the signed constructor makes, and the
marker-writer ratchet allowlist is exact again (#10194).
