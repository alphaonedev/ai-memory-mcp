**Embedding backfill no longer fails a whole batch on ONE non-BLOB `encrypted_envelope` cell (#4214, WP-FAULT #6051).**
`embeddable_row_mapper` — the row mapper behind every unembedded / reembed
scan — read the envelope with a typed `Option<Vec<u8>>` get, so a TEXT /
INTEGER / REAL cell (the #4133 corrupt-or-tampered input) failed the whole
`query_map` with `Invalid column type` and the backfill never got past that
row. The mapper now reads the cell through the #4133 `read_envelope_column`
decoder and a malformed cell takes the scan-read disposition an undecryptable
envelope already takes: WARN, `corrupt_provenance_rows_total{column=
"encrypted_envelope"}` bumped, counted as a decrypt-skip, remembered as
unembeddable, and the raw cursor advances past it so every later row is still
embedded. The plaintext column is never handed to the embedder.
