**Storage: a failed or unparsable provenance read in front of a decision is an error, never "absent" (#9435, #9496, #9484).**
The content-id genesis read (`read_cid_genesis`), the lineage cid mirror read
(`read_memory_cid`) and the lineage guard's `created_at` read used to fold a
query or decode failure into "no value", so `verify-reflection-chain` skipped
its verdict line, a link stored a NULL cid mirror, and the wall-clock guard
answered "not forward" and admitted the edge. Each read now returns present,
absent or an error, and the error stops the verb or the write. An unparsable
`created_at` on either endpoint refuses the link with a named error (#9484); an
absent endpoint row is still left to the existence check. A missing content-id
column is named by what the store's own stamp says (#9496): below v74 the
error keeps the `ai-memory --db <path> stats` remedy; at v74 or later it says
the stamp and the table shape disagree and does not advise a migration; an
unreadable or impossible stamp, or a missing `memories` table, each gets its
own error that names no cause. A failed import backfill cid read names the
link (source id, target id, relation) and the endpoint. Tests:
`tests/provenance_read_error_surfaces_9435.rs`.
