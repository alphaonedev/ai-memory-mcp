**`ai-memory logs tail --follow` re-reads a file that was truncated and regrown past the old read position within one poll (#7965).** The truncation check compared only the file length with the cursor, so a same-inode truncate followed by enough writes to pass the old offset before the next poll looked like plain growth: output resumed mid-file and the new head was lost. The cursor now remembers the (up to 64) bytes before it and treats a mismatch as truncation, re-reading from the start with the usual note on stderr; inode replacement remains detected on unix only, and the docs now say so.
