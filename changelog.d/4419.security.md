**Approved pending replay re-checks the requester's current write admission (#4419).** `execute_pending_action` replayed an approved store / delete / promote / reflect without re-applying the requester's current admission, so a namespace standard tightened after the request was queued (for example `write: any` to `write: owner`) still landed the write on approve while a fresh request by the same principal was refused. Execution now re-decides the requester's admission for the action's namespace (deciding only, never queueing a second pending) and refuses with a typed governance refusal plus an audit row when it no longer admits the write; the sqlite reflect arm replays under the requester's source visibility, as the postgres twin already did.
