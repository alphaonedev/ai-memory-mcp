### Fixed

- **The wake-hub refresher unit grants the database's DIRECTORY, so SQLite's
  WAL side files are writable under `ProtectSystem=strict`**
  ([#3522](https://github.com/alphaonedev/ai-memory-mcp/issues/3522)).
  `packaging/systemd/ai-memory-wake-hub-refresh.service` named
  `ReadWritePaths=/var/lib/ai-memory/ai-memory.db` — the FILE only. SQLite runs
  the store in WAL mode, which creates and locks `ai-memory.db-wal` and
  `ai-memory.db-shm` beside the database (a reader opens them too, and
  `identity hub-cache` is not a pure reader: it audits its allow/revoke
  decisions onto the `signed_events` spine), so on a stock install the parent
  directory stayed read-only, every refresh failed, nothing was published, the
  previous snapshot aged past the hub's 60 s ceiling and
  `ai-memory wake-hub` refused every hello. Fail-closed, but a Linux
  deployment that admitted nobody. The unit now grants
  `ReadWritePaths=/var/lib/ai-memory`, the same directory grant
  `ai-memory.service` has always used, with the WAL side files named in the
  unit comment and in `docs/wake-hub.md`. The companion `.timer` carries no
  `[Service]` section and the launchd template carries no path allowlist, so
  neither needed a change.
- **The delegation bundle is read from the descriptor its permissions were
  proven on**
  ([#3522](https://github.com/alphaonedev/ai-memory-mcp/issues/3522)).
  `src/wake_client/bundle.rs` checked the credential with a path-based
  `symlink_metadata` and then read it with a path-based `std::fs::read`, so the
  inode that was checked and the inode that was parsed were established
  separately. It now opens ONCE with `O_NOFOLLOW` (a symlink is refused at the
  open, reported as its own refusal rather than a bare `ELOOP`) plus
  `O_NONBLOCK` (a FIFO planted at the path cannot park the process; the
  regular-file check then refuses it), re-proves regular-file, mode 0600 and
  caller ownership through `fstat` on that descriptor, and reads the bytes from
  the same descriptor — the pattern the hub's allowlist reloader already uses
  (`AllowlistCache::open_checked`, #3504). The key directory is caller-owned so
  the window was only ever reachable by the caller itself; the refusal table
  and every message are unchanged.
