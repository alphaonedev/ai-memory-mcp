**CI: a workflow call of the host-slot wrapper may give only its five call flags (#9847, #9851).** `scripts/ci/host_slots_check.py` splits a canonical call line on spaces and admits `[exec] python3 [no-argument flags] scripts/ci/host_semaphore.py`, then only `--name`, `--max-wait-secs`, `--slots`, `--label` and `--poll-secs`, `--name`, `--max-wait-secs` and `--slots` required, each given once with one word as its value (a next word that starts with `-` is never a value), then ` -- ` and the command. Every other word before the `--` is a finding: an unknown flag or abbreviation (`--config` and `--root` steer the wrapper off the checked configuration and lock root), a flag without its value, a repeated flag, a missing `--slots` or one other than the gate's configured slot count, a `--poll-secs` that is not a plain decimal integer, and a stray word that the wrapper would run as the command. The linux-fed step now copies itself to `.local-runs/semaphore-step` and gives every value as a literal. The checker judges what the runner executes, not the source text: it also reads the parsed YAML (escapes such as `\x5f` and `\u005f` of the underscore decoded, folded and literal block scalars, quoting) with every backslash-newline continuation joined, so a call spelled across a continuation, by an escape or under a key is a finding with a named reason (a line joined by a backslash-newline continuation, or a decoded token where no raw line holds one). The `HOST_SEMAPHORE_MAX_WAIT_SECS` run-text check reads the same joined and decoded text, and the interpreter word must be exactly `python3`. Every spelling of the wrapper path that the runner or the shell resolves first is a finding (#9879): a run line that names `ci/host` holds only canonical characters once quotes are removed, a gated job's run text holds no `${{` expression (the check job now passes `matrix.leg`, the load-gate label and the sweep size cap through env), and a line that names `host_sem` or `semaphore.py` with `${{`, a glob or a dollar-quote is a finding. Known limits: a path taken wholly from a variable (#9882) and environment keys written through `$GITHUB_ENV` or `$GITHUB_PATH` by earlier steps (#9885), both closed at run time.
