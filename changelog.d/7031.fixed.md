**Per-binary Postgres isolation setup now refuses a shared or poisoned base and owns only what it creates (#7031).**
`scripts/test/pg_isolated_binary.py setup` builds its template only beside an ephemeral CI base
(`ai_memory_test_ci_<run>_<attempt>_<leg>`); the URL default, `ai_memory_test` and every other name are refused with
exit 2 unless `--allow-shared-base "<reason>"` is passed, and setup never creates a base. A base whose
`lineage_integrity_watermark` high-water mark is above `count(*)` of `agent_lineage` is refused with the #6983
REGRESSED diagnostic, and an unreadable watermark row is a refusal (#7157). Setup and teardown run under one ownership
guard: only databases this run created are dropped, with a plain DROP (never FORCE), on every exception and on
SIGTERM, SIGINT and SIGHUP; a name left behind is exit 5 and named on an `unreleased:` line, distinct from the usage
exit 2 (#7114, #7152, #7179, #7200, #7212). Teardown refuses a `--db` that disagrees with the emitted template
(#7180), `--emit-env` writes only the template and run-id variables (#7153), the age sweep keeps an active run's
clones (#7156), and a failed teardown names the cause (#7159).
