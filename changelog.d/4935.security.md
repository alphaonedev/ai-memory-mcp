**[supply-chain] GHCR publication authority is bounded across every workflow (#4935, umbrella #6062).**
A repository `GITHUB_TOKEN` with `packages: write` can write any GHCR package
linked to the repository, the released `ghcr.io/<owner>/ai-memory` image and
its `:latest` tag included, and the release guard read only `release.yml`.
`publish-ci-image.yml` held that scope at its top level. The grant now sits on
its single push job (top level `contents: read`), and
`scripts/check_release_features.py` sweeps every `.github/workflows/*.yml`:
`packages: write` (plain, quoted or in a flow mapping) and
`permissions: write-all` are refused everywhere except `release.yml`'s pinned
`docker` job and the pinned `publish-ci-image` job (`CI_IMAGE_TOP_PERMISSIONS`
/ `CI_IMAGE_JOB_PERMISSIONS`, exactly one job), and the release image name
`ghcr.io/<owner>/ai-memory` (any case; `ai-memory-ci` is not it) may appear in
no workflow but `release.yml`. The text match cannot see a name built from an
expression; the permission bound is the load-bearing control. Consumers verify
a pulled image with
`gh attestation verify oci://ghcr.io/alphaonedev/ai-memory:<ver> --repo alphaonedev/ai-memory-mcp --signer-workflow alphaonedev/ai-memory-mcp/.github/workflows/release.yml`.
