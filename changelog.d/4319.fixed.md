**A short-lived command no longer loses its forensic audit row at exit (#4319).** Forensic rows were handed to a background writer thread (#1472) and nothing drained it before a process exited, so a CLI command or per-call hook verb could exit with its row still queued: the chain did not fork, but signed decision evidence went silently missing (41 contended runs left 38 rows). Every process now writes its forensic rows before recording returns, except the long-running request servers (`serve`, `mcp`), which keep the background writer so per-request file I/O stays off the request path; they drain it at exit, bounded by 5 s, and a drain that times out is counted in `ai_memory_forensic_sink_unavailable_total` and reported on stderr.
