**[release] `supply-chain` and `crates-io` run with `contents: read` instead of the inherited `contents: write` (#4937, umbrella #6062).**
`release.yml` grants `contents: write` at the top level for the jobs that
attach release assets. The `supply-chain` job (audit / deny gates) and the
`crates-io` job (`cargo publish` with `CARGO_REGISTRY_TOKEN`) declared no
`permissions:` block and so inherited that write scope without using it. Both
now declare `permissions: { contents: read }`. The release guard
(`scripts/check_release_features.py`) no longer models an inheriting job:
`RELEASE_JOB_PERMISSIONS` pins a block for every job and a missing or widened
block is refused. Regression: guard self-test cases
`4937 supply-chain job inherits the top-level contents: write`,
`4937 crates-io job inherits the top-level contents: write`,
`4937 supply-chain widened to contents: write` and
`4937 crates-io widened to packages: write`.
