**The `(title, namespace)` slot belongs to LIVE rows; one lifecycle admission predicate on every create funnel (#3690, #3695, #3691, #3693, #3626, #3699 — Consolidation Unit 1).**
Schema **v100** makes the `(title, namespace)` unique index PARTIAL (`WHERE
lifecycle_state <> 'tombstoned'`, both adapters; index-only, no stored row is
touched). A consolidation tombstone therefore gives its slot up: a later store
of the same title lands as a fresh, VISIBLE row beside it instead of being
merged into the hidden one (#3690 — the CLI printed an id and `get`/`list`/
`recall` never showed the text). A `quarantined` / `contaminated` occupant
keeps its slot, and every create arm (merge, no-overwrite, same-id restore,
batch, reflect, capture/recover turn, consolidate) now refuses to write into
it with a typed conflict that names NO row (#3695) — the local author's text is
never written into a peer-attributed hidden row. The admission is derived once
(`LifecycleState::title_slot_admission`) and re-asserted atomically inside each
statement (`title_slot_merge_backstop`), so a quarantine that races the probe
still updates nothing. Every `ON CONFLICT (title, namespace)` target spells the
ONE predicate (`TITLE_SLOT_CONFLICT_TARGET`), structurally pinned. The same-id
restore of a tombstone (#2887 rollback) still merges in place and stays
tombstoned.
Also: the consolidation tombstone UPDATE is guarded by the visible allow-list
and aborts the cluster when a source went hidden mid-consolidation (#3691); the
contradiction / synthesis / proactive-conflict / persona read lanes apply the
fail-closed lifecycle allow-list (#3693); a dedup / upsert / synthesis merge
onto an UNSTAMPED row (no `metadata.agent_id`) leaves it unstamped instead of
silently claiming it for the caller (#3626 — claiming stays `ai-memory reown`);
and each `/sync/push` body is applied in CAUSAL order (`updated_at`, `id`) so a
consolidation tombstone lands before the new memory that reuses its title
(#3699, 5-agent vote 4d3ea1c5), with every cross-id title merge counted
(`ai_memory_fed_cross_id_title_merge_total`) and WARNed. The cross-PUSH
reorder residual is #3747. The
admission predicate answers BOTH visibility axes: an occupant the caller
cannot READ (another agent's `scope=private` row) is refused unnamed like a
hidden one (#3696), and the near-duplicate refusal on store neither fires on
nor names such a row (#3712); the same-id restore of a tombstone still merges
in place and stays tombstoned (behaviour preserved across the index change —
#2894 is NOT fixed by this: the restored original stays hidden).
