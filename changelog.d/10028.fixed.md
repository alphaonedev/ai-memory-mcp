**Export no longer writes a sealed row as plaintext (#10028, #10032, #10033).** A
memory sealed at rest (`encrypted_envelope` set) has no field in the convenience
export, the `export --full` v2 envelope or the `GET /api/v1/export` body, so every
export path now classifies each row from that column before any decrypt and
REFUSES when one is sealed: `SEALED_EXPORT_REFUSED` naming the table, the count and
the least sealed id, never content. The CLI exits non-zero and writes nothing; the
HTTP export answers `409` on SQLite and PostgreSQL alike (PostgreSQL used to skip
the row and exit 0), and a paged walk refuses on its first page. Archived rows are
covered by the same guard. Move an encrypted store with `backup` / `restore`.
