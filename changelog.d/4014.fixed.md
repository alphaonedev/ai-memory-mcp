**`ai-memory boot --cwd <dir>` no longer changes the process working
directory (#4014).** To infer a namespace from `<dir>`, `boot` called
`set_current_dir(<dir>)` on the whole process and ignored a failure, so a
bad `--cwd` silently fell back to the caller's directory. Every later
relative path in that process also resolved against a directory the
operator did not choose. The new `cli::helpers::auto_namespace_in(dir)` runs
`git` with `dir` as its working directory and reads `dir`'s basename, and
the process cwd is left untouched. For a `--cwd` that exists the inferred
namespace is unchanged: the directory is canonicalized, as the old
`current_dir()` read was, so `.` and symlinks still name the real directory.
For a `--cwd` that does NOT exist, the namespace is now that path's basename.
Before, the failed `chdir` was ignored and the caller's own directory named
the namespace.
Related test-isolation fixes: #4015 (fixture roots anchored on
CARGO_MANIFEST_DIR) and #4016 (one shared test cwd lock).
