- `mcp` and `serve` no longer acknowledge a request before its forensic audit
  row is durable (#9864). The background audit writer now syncs each batch
  and settles a sequence ledger; a reply to a request that can mutate waits
  for it, at most `ACK_BARRIER_DEADLINE` (5 s). At the deadline, or when the
  row could not be written, the request is answered with the named error
  instead of success: JSON-RPC code `-32010` in `mcp`, HTTP `503` in
  `serve`, both with a message starting `audit row not durable` that says
  the mutation may have been applied (a retry of `memory_store` or
  `memory_link` creates nothing twice) and counted in
  `ai_memory_forensic_sink_unavailable_total`. A timed-out row stays queued
  and is written once the writer recovers. Read-only requests never wait.
  The 5 s exit drain now covers only rows of requests that were never
  acknowledged. Known limit: on a barrier timeout the mutation may already
  be committed, so the guarantee is "acknowledged implies row", not
  "mutated implies row".
