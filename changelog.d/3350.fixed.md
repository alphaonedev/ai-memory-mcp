`memory_check_duplicate` (MCP), `POST /api/v1/check-duplicate` and
`ai-memory check-duplicate` no longer report a confident "not a duplicate" for
a candidate they could not evaluate. A check that compared nothing — no query
embedding, or a scope whose rows carry no comparable vector — now answers
`status: "degraded"` with `is_duplicate: null` and a `reason`, instead of the
fail-open `is_duplicate: false`; `candidates_available` joins
`candidates_scanned` so the difference is visible. An exact
`(title, namespace)` collision is also reported as a duplicate without needing
any embedding, since the store enforces that pair as unique and the write
would have collided. Both backends behave identically.
