**`memory_check_duplicate` no longer answers a confident `is_duplicate: false` when no candidate could be compared (#3350, WP-FAULT #6051).**
When live memories exist in scope but none carries an embedding in the
active embedding space (unembedded, foreign-space or malformed rows), or on
a postgres-backed daemon no query embedding could be produced, the phase-2
cosine scan compared nothing and the tool, HTTP route and CLI still reported
`candidates_scanned: 0, is_duplicate: false` — a fail-open pre-write gate.
The check now fails closed: `is_duplicate` is `null` (unknown) and the
additive `status: "degraded"` + `reason` keys name the fault (healthy
responses are byte-identical; an empty scope stays a confident `false`).
The CLI summary prints `DEGRADED  no verdict` instead of "no duplicate".
Decided by 5-agent vote (4d3ea1c5), option A, 4-1.
