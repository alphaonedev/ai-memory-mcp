**HTTP and MCP consolidate refuse to consume a source edited while the LLM summary was generated (#4286).**
When a consolidate request omitted `summary`, `POST /api/v1/consolidate` and the
`memory_consolidate` MCP tool read the sources, waited on the model, and then
consumed the sources by id only. A source edited in that window (another agent,
the CLI, or a second daemon on the same database) was tombstoned or hard-deleted
with its newer text in neither the summary nor any live row. Both surfaces now
pin each source's `version` from the gate read and consolidate through the
version-checked primitive on both backends: on a mismatch nothing is consumed,
HTTP answers `409` and MCP returns the `{"status":"conflict", ...}` envelope
`memory_update` already uses, and the caller can retry. A caller-supplied summary
is unchanged. Refs #6055, #4045.
