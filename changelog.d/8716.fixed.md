**The private export directory refusal text and docs now state the contract the check enforces (#8716).** The check compares only the nine permission bits, so an existing export root or namespace directory with a setgid, sticky or setuid bit on top of 0700 was always accepted while the refusal text and three docs pages said "mode 0700". The refusal now reads "permission bits 0700 (owner only)", `PERMISSION_MASK` documents why the special bits are ignored (a setgid bit inherited from the parent grants nothing on an owner-only directory), and `docs/CLI_REFERENCE.md`, `docs/RECURSIVE_LEARNING.md` and `docs/persona.md` say the same. The accepted and refused modes are unchanged; `tests/export_directories_8593.rs` pins the table (0700, 01700, 02700, 04700 accepted; 0750, 0701, 0770, 0600, 0777 refused) and the exact text.
