**A non-hex `hmac_secret` with a multi-byte character now refuses boot with `EX_CONFIG` instead of panicking (#4074).**
The `[hooks.subscription] hmac_secret` boot validator decoded the value by
slicing the string two bytes at a time after checking only that its byte
length was even. A value such as a single emoji, `a€` or `éé` cut inside a
UTF-8 code point and panicked, so the daemon exited 101 without the #1048
`boot refused` diagnostic, and a `+f+f` value was accepted as hex. The decoder
now works over bytes and accepts only hex digits; the same fix applies to the
`epoch-apply` manifest-signature decoder. A valid hex secret is unchanged and
an invalid one is still refused, never turned into an accepted key.
