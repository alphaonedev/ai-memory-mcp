**Signed row attestations for SQLite (#10040, GA standard 3).** Schema v103 adds the
additive `row_attestations` side table. When a session signer is configured, every
write to an attested table appends an Ed25519-signed attestation in the same
transaction as the row change. Each attestation records the row digest, its place in
the row's chain and the signed table head. The migration alters no existing row. The
first armed open signs one cutover watermark per attested table and a baseline for
each pre-existing row. Reverting the version leaves the table in place.

The verifier takes its public keys only from the trust anchor outside the database
(the configured key directory), never from a database row. With no anchor configured
the result is `unanchored`, which is never reported as clean. A key rotation keeps
earlier attestations verifiable. Verification detects a removed cutover signature, a
rolled-back sequence counter, a replayed attestation and a duplicate JSON key. A
connection that does not attest cannot write an attested table of an armed store,
because the write is refused with an exact reason. A row that drifted fails only its
own memory, while a store-wide defect fails every row.

New verb: `ai-memory audit verify-rows [--json]`. It exits 0 when clean, 2 when
defective, 3 when unanchored, and 1 for a PostgreSQL or indeterminate store.
`doctor --posture enterprise-federation` gains check 23, "row attestation trust
anchor".
