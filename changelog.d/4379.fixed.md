**A failed deferred escalation queue write no longer forwards the storage error chain to the caller (#4379).** When a funnel-owned write transaction settles a deferred escalation and the `pending_actions` INSERT fails, the rewritten refusal used to splice the full rendered storage error (constraint names, lock / I/O states) into the `GovernanceRefusal` reason, which reaches HTTP 403 bodies and MCP error data. The caller text is now the fixed phrase `escalation NOT queued (storage error; see server log)` followed by the rule reason; the chain is logged at ERROR on the server, matching the immediate (non-deferred) path. The write stays refused.
