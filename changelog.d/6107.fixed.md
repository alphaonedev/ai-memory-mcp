**A `sqlite://` store URL carrying userinfo no longer prints its credential (#6107, CWE-532).** `store_url_display` matches the `sqlite://` scheme case-insensitively and renders `sqlite://<redacted-authority>` for any value holding an `@` (otherwise the path without its query or fragment), so `sqlite://` and `SQLITE://` render identically; the missing-database refusal (`migrate --from`, `boot`, `doctor`) and the SQLite open error (`serve`) render the path through the new `url_display::db_path_display` instead of echoing it raw. Regression: `tests/store_url_sqlite_userinfo_6107.rs`.
