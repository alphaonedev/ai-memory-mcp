### Security

- **[http-identity] An unusable `X-Agent-Id` header is one named `400` on every route and both backends**
  ([#9616](https://github.com/alphaonedev/ai-memory-mcp/issues/9616)). Before this fix an
  `X-Agent-Id` header that was not one well-formed identity could become a principal: an invalid
  header fell back to a sentinel at 26 handler sites, and on the postgres
  `DELETE /api/v1/memories/{id}` arm to the named principal `ai:http`; a header whose bytes were not
  UTF-8 was read as absent and served as a fresh anonymous caller; and a request with two
  `X-Agent-Id` headers was served as whichever came first, so a destructive request could act
  as one principal while another layer judged a different one. Shared resolvers on the
  postgres path (`http_caller_ctx` and its ten callers) and three family-load and consolidation
  routes folded the same errors into `anonymous:invalid` or an empty principal. Every read of the
  header under `src/handlers` now goes through one reader, `handlers::caller_identity`: a header
  that is malformed, reserved, oversized, not UTF-8 or repeated is refused with `400` and an
  `error` of `invalid agent_id: <reason>` on every route and on sqlite and postgres alike, at the
  authority layer, the per-agent-key binding layer and in each handler, and no fallback becomes a
  principal. `POST /api/v1/links/verify` now resolves its caller before it consults the store, so
  an unusable header is that `400`, never a `404` for an unknown link. A request with no
  `X-Agent-Id` header keeps its documented anonymous default (`anonymous:req-<uuid8>`,
  `docs/API_REFERENCE.md`). When a client-certificate binding is active, the certificate layer
  still reads the first header value before this reader runs; that read is tracked in
  [#9666](https://github.com/alphaonedev/ai-memory-mcp/issues/9666). The test
  `tests/agent_id_refusal_9616.rs` holds a census over 27 routes, five invalid forms each: through
  the full router and through each handler with the authority layer removed, on both backends (a
  refused destructive request must leave its fixture in place), each cell asserting the exact
  status and body. Its source ratchet is an allowlist over every tracked `.rs` file of
  the crate: a file whose count of header-name reads, raw-resolver calls, `anonymous:invalid`
  sentinels or funnel refusals folded into a value differs from what its row grants (no row
  means zero) fails it.
