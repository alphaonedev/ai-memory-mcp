### Security

- **[http] A private row answers exactly like an absent one on id-addressed write and walk routes**
  ([#8994](https://github.com/alphaonedev/ai-memory-mcp/issues/8994),
  [#9043](https://github.com/alphaonedev/ai-memory-mcp/issues/9043)).
  Several routes answered differently for an id naming another agent's
  private row and an id naming no row, so a caller could confirm that a
  private row exists. Each route now uses one not-found answer per resource
  (`handlers::parity::not_visible_refusal`) for both cases, on SQLite and
  PostgreSQL, and writes nothing. A row the caller can read but does not own
  keeps `403 NOT_OWNER`.

  Before cells read "private row / absent id"; "after" is the same for both.

  | Route | SQLite before | PostgreSQL before | Both backends after |
  |---|---|---|---|
  | `PUT` / `DELETE /api/v1/memories/{id}` | 404 / 404 | 403 `NOT_OWNER` / 404 | 404 `{"error":"not found"}` |
  | `DELETE /api/v1/links` (neither endpoint readable) | 403 / 200 `{"deleted":false}` | 200 `{"deleted":false}` / 200 `{"deleted":false}`, with the delete run for an unreadable source (#9043) | 404 `{"error":"not found"}`, nothing deleted |
  | `POST /api/v1/links` (source) | 403 / 404 | 404 `{"error":"not found"}` / same | 404 `{"error":"source memory not found","source_id":…}` |
  | `POST /api/v1/links` (substrate target) | 403 `caller cannot see the link target` / 500 | 403 `caller cannot see the link target` / 404 `{"error":"not found"}` | 404 `{"error":"not found"}`, nothing written |
  | `GET /api/v1/memories/{id}/lineage` (root) | 403 / 200 empty walk | 404 / 404 | 404 `{"error":"source memory not found","id":…}` |
  | `POST /api/v1/kg/invalidate` (source) | 403 / 404 | 404 / 404 | 404 `{"found":false,…}` |
  | `GET /api/v1/kg/timeline` (source, caller not admitted) | 403 / 404 | 403 / 404 | 404 `{"found":false,…}` |

  `POST /api/v1/kg/invalidate` keeps its answer for an agent the source row
  is addressed to (`target_agent_id` or `_inbox/<agent>`): `200` on both
  backends for a private or inbox row, and for a team-scoped row outside the
  caller's subtree `200` on SQLite and `404` on PostgreSQL, the same answers
  as before this change.
