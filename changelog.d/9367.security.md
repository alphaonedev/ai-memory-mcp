**The MCP forwarder authenticates with the per-agent key (#9367).** An
`ai-memory mcp` process with `mcp_federation_forward_url` configured now reads
`AI_MEMORY_AGENT_API_KEY_FILE` and sends that file's key as `X-API-Key` on every
forwarded write (`memory_store`, `memory_action_transition`,
`memory_signal_send`), with the explicit `AI_MEMORY_AGENT_ID` as `X-Agent-Id`,
to the configured daemon origin only: the forward client follows no redirect.

**What it costs you.** With the variable unset no key is sent and a daemon
without an api key keeps working, but one thing changes for every forward
(below). When the
variable is set but the file is missing, unreadable, not a regular file, larger
than 4096 bytes, readable by group or others, empty or not one printable-ASCII
token, or it is set without `AI_MEMORY_AGENT_ID`, the forward fails with a named
local error and no request leaves the process; it never falls back to the shared
key or to a request without a key. The lax-permission hatch
`AI_MEMORY_AGENT_API_KEY_FILE_ALLOW_LAX_PERMS` does not apply to the forwarder.
A daemon refusal of the key (its transport-auth 401 or its per-agent key binding
403) is named in the error; a 403 from another gate shows the daemon's code
instead. `ai-memory doctor` reports whether the variable is set (set or unset
only). Do not leave an enrolment or admin token exported in the variable where
an MCP process starts.

**Changed behaviour.**
- Every MCP forward, with the key variable set or unset, now follows no
  redirect: a 3xx from the daemon origin is an error and the request is not
  repeated at the redirect target.
- `memory_action_transition` with a forward URL configured refuses an action
  id that is not one path segment (empty, a `.` or `..` segment or one holding
  `..`, a character outside `[A-Za-z0-9_:.@-]`, or longer than 128 bytes) with
  a named local error before any request is sent and before the key file is
  read. Every forward now builds its path segment by segment on the configured
  base URL, and a forward URL that is not a valid base URL is a named local
  error that does not repeat the URL.
- `ai-memory agents bind-api-key` reads its token file through the same checks
  as the forwarder: it now also refuses a file that is not a regular file, a
  file larger than 4096 bytes, and a file not owned by the current user or
  root. Its permission check, its texts and its lax-permission hatch are
  otherwise unchanged.
- Both readers open the key file with `O_NOCTTY` and `O_NONBLOCK` and keep the
  key bytes in buffers that are wiped on drop. A symlink is still followed
  (mounted secrets, such as Kubernetes secret volumes, are symlinks); the
  regular-file, size, owner and mode checks apply to the file it reaches.
