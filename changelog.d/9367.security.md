**The MCP forwarder authenticates with the per-agent key (#9367).** An
`ai-memory mcp` process with `mcp_federation_forward_url` configured now reads
`AI_MEMORY_AGENT_API_KEY_FILE` and sends that file's key as `X-API-Key` on every
forwarded write (`memory_store`, `memory_action_transition`,
`memory_signal_send`), with the explicit `AI_MEMORY_AGENT_ID` as `X-Agent-Id`,
to the configured daemon origin only: the forward client follows no redirect.

**What it costs you.** Nothing while the variable is unset: the request is the
request of today and a daemon without an api key keeps working. When the
variable is set but the file is missing, unreadable, not a regular file, larger
than 4096 bytes, readable by group or others, empty or not one printable-ASCII
token, or it is set without `AI_MEMORY_AGENT_ID`, the forward fails with a named
local error and no request leaves the process; it never falls back to the shared
key or to a request without a key. The lax-permission hatch
`AI_MEMORY_AGENT_API_KEY_FILE_ALLOW_LAX_PERMS` does not apply to the forwarder.
A daemon refusal of the key (its transport-auth 401 or its per-agent key binding
403) is named in the error; a 403 from another gate shows the daemon's code
instead. `ai-memory doctor` reports whether the variable is set (set or unset
only). Do not leave an enrolment or admin token exported in the variable where
an MCP process starts.
