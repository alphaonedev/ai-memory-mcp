**Federation peer and webhook URL renderers no longer print credential bytes from an ambiguous authority (#6101, CWE-532).** When a URL's userinfo holds an unencoded `/`, `?` or `#`, `url_origin` (display only) now renders `scheme://<redacted-authority>` for any URL with an `@` after its parsed authority, and `url_origin_and_path` (also the durable peer key) does so when the parsed userinfo or the raw authority span shows the credential shape, so a legitimate `https://host/a@b` path keeps rendering. Residual, documented on `origin_and_path_is_ambiguous`: a numeric-prefixed password and a password-less username token with a delimiter cannot be told from a legitimate path there. Because those two renderings are constants, the sync daemon now refuses a peer whose URL is ambiguous or unparseable before it reads or writes `sync_state` (new `url_display::origin_and_path_is_durable_key`), so two such peers can never share one pull cursor. Regression: `url_display::tests::*_6101`, `tests/sync_state_peer_key_unique_6101.rs`.
