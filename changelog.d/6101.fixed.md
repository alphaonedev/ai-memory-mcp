**Federation peer and webhook URL renderers no longer print credential bytes from an ambiguous authority (#6101, CWE-532).** When a URL's userinfo holds an unencoded `/`, `?` or `#`, `url_origin` (display only) and `url_origin_and_path` (also the durable peer key) render `scheme://<redacted-authority>` for any URL with a literal `@` after its parsed authority (#6628 tightened the durable-key rule to exactly this; a legitimate `@` in a peer path is written `%40`). Because that rendering is a constant, the sync daemon refuses a peer whose URL has such an `@` or is unparseable before it reads or writes `sync_state` (new `url_display::origin_and_path_is_durable_key`), so two such peers can never share one pull cursor. Regression: `url_display::tests::*_6101`, `tests/sync_state_peer_key_unique_6101.rs`.
