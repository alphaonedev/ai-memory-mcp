**`ai-memory store --sign` no longer degrades silently to `claimed` (#3409).**

A local keypair whose public key was not bound in the store made the
permissive CLI gate land the row as `attest_level="claimed"` with exit 0 —
the caller asked for a signed write and got an unsigned one, and nothing
said so. `--sign` now refuses up front when no public key is bound for the
agent (and when the bound key does not match the local one), naming the
degradation, the bind command (`agents register` + `agents bind-key
--pubkey "$(identity export-pub …)"`) and the override; after stamping it
additionally refuses anything below `agent_attested`. The new
`--allow-claimed` flag states the exception deliberately: the row is stored
as `claimed` and a one-line WARN on stderr names the missing binding.
Tests: `src/cli/store.rs` (`store_sign_without_bound_key_refuses_3409`,
`store_sign_with_allow_claimed_stores_claimed_and_warns_3409`,
`store_sign_with_bound_key_is_agent_attested_3409`) and the compiled-binary
`tests/cli_store_sign_unbound_3409.rs` — the refusal cases fail on the
previous head. The CLI `store` verb is sqlite-only (`refuse_pg_store`), so
the postgres surfaces of this family are the HTTP/MCP stores.
