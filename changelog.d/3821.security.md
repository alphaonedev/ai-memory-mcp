### Security

- **[deps] rustls 0.23.38 → 0.23.45 — RUSTSEC-2026-0285 / GHSA-2mjx-qc3c-rqvc**
  ([#3821](https://github.com/alphaonedev/ai-memory-mcp/issues/3821)). Lockfile-only
  (the `Cargo.toml` range `rustls = "0.23"` already admits the first patched release);
  `cargo update -p rustls --precise 0.23.45` also moves `rustls-webpki` 0.103.13 → 0.103.15
  and, because rustls 0.23.45 requires `aws-lc-rs ^1.18`, `aws-lc-rs` 1.16.3 → 1.18.1 and
  `aws-lc-sys` 0.40.0 → 0.45.0 (both are build-script crates, so their #2635 ledger records
  are refreshed to the new checksums — inventoried, ceiling unchanged). `cargo audit` on the
  same tree: `error: 1 vulnerability found!` (exit 1) before, `warning: 1 allowed warning found`
  (exit 0, the pre-existing RUSTSEC-2026-0221 `event-listener` unsound allowance) after.
  - **Exposure, stated narrowly.** The advisory: rustls accepted a TLS 1.3 handshake message
    sent at the wrong encryption level when it followed a key change in the same record;
    the handshake transcript stays authenticated, so a network-position attacker cannot alter
    or complete a handshake — the practical effect is that a *peer* could send its own
    handshake messages in plaintext without rustls rejecting the connection (CVSS 5.3, C:L
    only). Every ai-memory TLS surface is a rustls endpoint that must run a handshake with an
    unauthenticated peer by definition — the HTTPS listener (`serve`, every bind since #3705;
    mTLS client-cert pinning and `X-Peer-Id` binding are applied at handshake end and after),
    and the rustls *clients*: federation push / sync-daemon (peer server pinned or CA-verified),
    webhook dispatch, the LLM / embedding API clients, hf-hub downloads, the postgres `sqlx`
    connection (`sslmode=verify-full`) and the optional syslog sink — but on none of them does
    the defect let the peer read or modify *our* traffic, skip certificate verification, or
    bypass any authentication step; a peer that packs its own `EncryptedExtensions` / `Certificate`
    in plaintext discloses only its own handshake data. No ai-memory deployment was exploitable
    for confidentiality or integrity of memory content; the gate red was the customer cost.
