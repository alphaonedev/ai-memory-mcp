**PostgreSQL-native backup and restore (#10021).** In a `sal-postgres` build,
`ai-memory backup` and `ai-memory restore` act on a Postgres store named by
`--store-url` (or `AI_MEMORY_STORE_URL_FILE` / `AI_MEMORY_STORE_URL`); no new verb,
MCP tool or HTTP route. The backup dumps every table of every non-system schema
(Apache AGE included) and every sequence in one read-only repeatable-read
transaction, keeping typed values, `bytea` and JSON exact, into a mode-0600
`.pgdata` file and an operator-signed `.pgmanifest.json` that records the backend,
layout version, schema version and a row count and digest per table. The restore
verifies the signature against the operator public key on the host and every
digest before the first write, refuses a non-empty target, a schema mismatch, an
unknown layout and a backup of another backend with an exact error, and loads the
rows in one transaction under exclusive locks, resetting the sequences; a failure
leaves the target empty. The artifact holds API-key hashes, the key history and
session transcripts, and the command says so. In `sal-postgres` builds the
enterprise-federation posture row "backup manifest signing" now checks the operator
keys on a postgres backend instead of reporting `N/A`. The `export` / `import` help
now states that the Portability-v2 path carries 12 record classes and is not a full
backup (offloaded blobs and the key history are omitted). A build without
`sal-postgres` keeps the #2444 refusal naming `pg_dump`.
