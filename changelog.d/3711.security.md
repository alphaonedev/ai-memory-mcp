**URLs are rendered from an allowlist at every sink — never masked (#3711, folding #3675 #3684 #3687 #3697 #3710 #3724).**
Every sink that printed a store DSN, a federation peer URL or a webhook target went
through the userinfo-only maskers (`logging::redact_url_password` /
`redact_urls_in_message`), which left `?password=`, `sslpassword=`, `sslkey=`, a
Slack/Discord path token or a query token verbatim. A masker is a denylist; it can
only hide the shapes its author enumerated.

- `src/url_display.rs` is the ONE renderer: `url_origin` (`scheme://host[:port]`),
  `url_origin_and_path` (a federation peer's durable identity), `store_url_display`
  (`scheme://host[:port]/<database>`; `sqlite://` paths verbatim). An unparseable URL
  renders its scheme token and `<unparseable>`, never its bytes.
- #3711: all ~35 DSN sites — the every-boot `info!`, `migrate --json`,
  `schema-init --json`, doctor, `backup` / `reown` / `verify-audit-trail` refusals,
  the `--db`/`--store-url` conflict, the sqlx→`StoreError` funnel's store label — now
  render through `store_url_display`; the maskers have zero production callers
  (pinned mechanically by `tests/credential_to_sink_3711.rs`).
- #3710: `reqwest::Error` (its `Display` names the full request URL) is CLASSIFIED at
  every origin into the closed `url_display::TransportFailure` vocabulary
  (`timeout` / `connect` / `http_<n>` / …) before it becomes a log line, an `anyhow`
  context or a stored DLQ record — federation `post_once` / `bulk_catchup_push` /
  catch-up, the sync-daemon pull and push, the webhook dispatcher.
- #3687: the sync-daemon logs its peer as `scheme://host[:port]/path` at INFO and WARN.
- #3675: `sync_state.peer_id` is keyed by that rendering; a row a pre-#3675 daemon
  keyed by the raw URL is moved onto the rendered key on the first cycle (cursors
  folded through the refuse-to-regress upserts, raw row deleted —
  `storage::sync_state_rekey`), so no credential survives at rest and the peer keeps
  its watermarks.
- #3697: the three webhook `warn!` lines that logged a user-registered webhook URL
  verbatim — for Slack / Discord / Teams the URL IS the credential — render
  `url_origin(url)` (`subscriptions.rs` SSRF-guard refusal, DNS-guard refusal, POST
  failure), and the POST failure's error text is the classified `TransportFailure`,
  not the `reqwest::Error` Display that would have re-named the full URL beside it.
- #3684 / #3724: the webhook dispatcher logs the target's origin only, and the stored
  `subscription_dlq.last_error` — read back by the subscriber — is the closed
  `subscriptions::dlq_reason` vocabulary (`ack_status_not_ack`, `ack_corr_mismatch`,
  `network: connect`, `http-<status>`, …); the receiver's chosen text stays in the
  operator log.
