**`ai-memory doctor` reachability probes now honour the inference-egress posture (#4121).**
The LLM and embeddings reachability sections built their own HTTP client and
sent a request, with the resolved API key as a Bearer credential, to the
configured endpoint without asking the #1963 inference-egress gate. Under
`AI_MEMORY_INFERENCE_EGRESS=deny`, `loopback-only` or `internal-only`, a doctor
run therefore contacted, with the key, an endpoint the daemon itself refuses to
build a client for. Both sections now admit the target through the same gate
the daemon and the curator section use before any client is built: on a
refusal they send nothing and report the refusal as an `inference_egress` fact;
on admission under `internal-only` the probe uses the resolve-then-pin client,
so the probed host is the admitted host. Under the default `allow` posture an
admitted target is probed as before, but an off-host plaintext `http://`
target, which the #3823 rule refuses under every posture, is now reported as
refused rather than probed. The skipped probe's note carries the actual refusal
reason instead of always naming `AI_MEMORY_INFERENCE_EGRESS`, and under `allow`
such a refusal is a warning (a misconfiguration that leaves the daemon with no
client for that endpoint), so `doctor --fail-on-warn` no longer passes it; a
refusal by a chosen restrictive posture stays informational.
