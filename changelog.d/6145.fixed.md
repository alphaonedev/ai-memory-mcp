### Fixed

- **[ci-gate] cert-expiry self-test git PATH shim now runs under `python3 -I`**
  ([#6145](https://github.com/alphaonedev/ai-memory-mcp/issues/6145)).
  The `--self-test` of `scripts/check_cert_expiry.py` wrote a `git` shim executed as a
  Python script without `-I`, the one Python entry point in the gate's path that was not
  isolated (the gate itself runs under `python3 -I` in `c8-precheck.yml`). The shim's
  interpreter line is now `<python> -I`. A `shim-isolation` self-test cell, run before
  the first shimmed gate run, plants an empty `gitshim_canary_6145.py` beside the shim
  and asserts `sys.flags.isolated` is set and the canary is not importable (the real
  import system decides, so a symlinked scratch path cannot fool it). The shim writer
  now fails closed with `GateError` when the interpreter path contains whitespace or a NUL
  byte, the interpreter line exceeds 255 bytes (the Linux kernel truncates longer shebangs
  and silently drops `-I`) or the path is not valid UTF-8, and an unexecutable shim is
  reported as a violation rather than a traceback. A `shim-interpreter` cell pins the
  refusals (whitespace, NUL, over 255 bytes, non-UTF-8) and the 255-byte boundary (255
  accepted, 256 refused) with paths sized to the literal byte counts, so changing
  `SHEBANG_MAX` is caught; `shim-interpreter-robust` and `shim-unexecutable` cells pin
  that setup failures and an unexecutable shim yield named violations. The near-PATH_MAX
  scratch is sized from `os.pathconf("PC_PATH_MAX")` (macOS 1024, Linux 4096) and built to an
  exact length, with the cell asserting the unguarded 200-byte build would overflow, so the
  self-test passes on macOS and pins the pad-before-build ordering on every checkout path;
  a `shim-deep-scratch` cell pins the builder's exact length and cleanup, and a crashing
  cell is reported as a named failure rather than a traceback.
  The `shim-interpreter` cell needs the scratch path at most 226 bytes, i.e. a checkout path
  at most 184 bytes (CI uses 44); a deeper checkout fails the self-test with a message naming
  the scratch path length and the limit. The `os.pathconf` fallback is the platform PATH_MAX
  (1024 on macOS and the BSDs, 4096 elsewhere), and `guarded()` and the fallback are pinned by
  `guarded` and `path-max-fallback` self-test cells. A `shim-deep-cap` cell pins that the
  deep-scratch targets stay inside the scratch base and PATH_MAX-1 (the cap is reached on a
  scratch 400 bytes under PATH_MAX) and that a scratch within a byte pair of PATH_MAX gets the
  named "needs room" message (the guard is `base_len + 2`, since a path cannot grow by one
  byte); a `path-max-restore` cell pins that `os.pathconf` and `sys.platform` are restored,
  with the patch list ending on a platform that is not the host's. The `path-max-restore`
  cell runs first and is the only caller of the fallback check, so its snapshot is the true
  entry state; a `path-max-diagnostic` cell pins that a dropped restore names the real host
  platform. The deep-scratch lower bound is the shared `deep_scratch_base_len`.
  Hardening of the self-test scratch directory only; not a live bypass.
