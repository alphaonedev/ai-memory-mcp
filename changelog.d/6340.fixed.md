CI concurrency groups now cancel an in-progress run only when the newer run is a pull_request run (#6340, ci.yml, coverage.yml, postgres-ignored.yml, cert-postgres-age.yml). A push to release/**, main or develop, or a merge_group run, is no longer cancelled by a later push while it is in progress. Two GitHub behaviours remain: a queued (pending) run is still replaced when a newer run queues in the same group, whatever cancel-in-progress says; and all four key the group with the event name (#6117 added it to ci.yml and coverage.yml, whose push trigger now covers chain/** carriers that are also promotion-PR heads), so a pull_request run cannot cancel an in-progress push run of the same branch; both runs complete. scripts/test/test_workflow_concurrency_6340.py pins these semantics.
