CI concurrency groups now cancel an in-progress run only when the newer run is a pull_request run (#6340, ci.yml, coverage.yml, postgres-ignored.yml, cert-postgres-age.yml). A push to release/**, main or develop, or a merge_group run, is no longer cancelled by a later push while it is in progress. Two GitHub behaviours remain: a queued (pending) run is still replaced when a newer run queues in the same group, whatever cancel-in-progress says; and ci.yml and coverage.yml key the group by branch without the event name (so an internal PR's pull_request run and its head-branch push run share one run), which means a pull_request run on the same branch can still cancel an in-progress push run there. postgres-ignored.yml and cert-postgres-age.yml include the event name and cannot. scripts/test/test_workflow_concurrency_6340.py pins these semantics.
