The sharded enterprise-fed CI suite can skip a test executable whose cargo dep-info key (own sources, local lib/bin closure, Cargo.lock, rustc and cargo versions, features, environment, Postgres server version, extensions and settings, and run-time files) equals the key recorded by the last green push to the same release/** branch on the same node and tier within 7 days. Only pull requests into release/** look the key up and pull requests never write it; the recording push to release/** runs every binary and never skips one. A documentation-only pull request is `__SKIP__` and runs no tests at all, so it never reaches the cache. A pull request that edits tests/ files (plus its changelog.d/ fragment) builds in impact mode; there the lib and every built, unchanged binary that neither scans the tree nor can read changelog.d/ hit, whichever targets the impact build compiled. A pull request that edits src/ reruns every binary (scripts/ci/test_binary_cache.py, #6384).
