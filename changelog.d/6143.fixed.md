**Carrier-branch freshness gate (#6143).** `chain/**` and `rehearsal/**` pull-request bases carry no rule requiring an up-to-date head, and GitHub does not re-run `pull_request` workflows when the base moves, so a green gate could be merged on a stale head. New `c8-precheck.yml` job `Carrier-base freshness gate (#6143)` (`scripts/check_carrier_base_fresh.py`, Python, fail-closed, 12-case self-test) refuses a merge ref that is not built on the live carrier-base tip and prints the `gh pr update-branch` remedy. The strict-required-status-checks ruleset that closes the remaining window is specified in `docs/ci/CARRIER-BRANCH-GATES.md` (a settings change; the job is in the not-required ledger until then). Pinned by `tests/carrier_base_fresh_gate_6143.rs`.
