### Security

- **[ci-trust-boundary] Structural test of the tainted-job boundary for every workflow**
  ([#9452](https://github.com/alphaonedev/ai-memory-mcp/issues/9452)). A new classifier,
  `scripts/ci/taint_boundary.py`, parses every workflow under `.github/workflows/` and the local
  composite actions and reusable workflows they call. For each job it finds the first step that runs
  pull-request code and fails when a later step holds (i) a secret, (ii) a write token, (iii) an
  output that feeds a gate decision, or (iv) persistent runner state a trusted run later reads. A
  secret under (i) is any credential the job can reach, including a credential resident on a
  self-hosted host. A write to `GITHUB_ENV` or `GITHUB_PATH` in a job holding a pull-request tree is a
  taint point, and every later step of the job, actions and cleanup included, is tainted. A
  workflow or a job it cannot classify is a failure, never clean. The thirteen known violations carry
  allow rows that name their open fix issues
  ([#9454](https://github.com/alphaonedev/ai-memory-mcp/issues/9454),
  [#9455](https://github.com/alphaonedev/ai-memory-mcp/issues/9455),
  [#9456](https://github.com/alphaonedev/ai-memory-mcp/issues/9456)); the row count is pinned and a
  stale row fails. Class (iv) also holds for every job whose `runs-on` can resolve to a runner that
  is not provably GitHub-hosted (a label, a list, a group, a matrix value, an expression or a
  reusable-workflow input) and whose workflow has a trusted trigger: such a job is a violation
  whether or not it runs pull-request code, and no environment variable, path form, cache-directory
  name or runner label clears it. An unknown `runs-on` form is a failure. The jobs `check`
  (`ci.yml`), `cert-postgres-age`, `postgres-ignored` and `lifetime-tests`
  (`session-boot-lifetime.yml`) are class (iv) at their `runs-on` and carry allow rows under #9455.
  The test is `scripts/ci/tests/test_ci_tainted_job_boundary.py`.
