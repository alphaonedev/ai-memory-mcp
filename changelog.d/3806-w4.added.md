**#3806 W4 — the consolidation merge judge: a NARROWING third gate on the one seam that deletes data.** The curator's consolidation merge (autonomy Pass-1 and its SAL successor in `curator::compaction`, before `db::consolidate`) now consults the `[decision]` provider through `AutonomyLlm::judge_merge` AFTER the two fixed gates — the Jaccard keyword pre-filter and the stored-embedding cosine gate — have admitted a cluster. The judge is asked a closed yes/no question and can only veto: it never causes a merge the fixed gates refused, and `[decision]` unset consults nobody, so the two-gate v1.0.0 predicate runs byte-identically (zero judge counters, no source label).

**Permit is the narrow case; everything else blocks.** A cluster merges only when the verdict is `yes` AND a confidence is present AND it is at or above `CONSOLIDATION_MERGE_CONFIDENCE_FLOOR` (0.80, a compiled default until the W5 calibration evidence for the `consolidation_merge` seam sets it; W6 makes it configurable), read through the one per-seam accessor `CalibrationSeam::confidence_floor` (`Some` for a destructive seam, `None` for a seam that uses verdicts as-is) so every destructive seam thresholds through the same mechanism. A `yes` with NO confidence — no logprobs, or a generative fallback — is treated as an ABSTAIN and blocks, because a permit that cannot say how sure it is is not a permit on a delete path. A `no` blocks; a decline (prose, off-vocabulary, case 3) blocks; an UNAVAILABLE decider (timeout, egress refusal, no provider, a hot-reload handle that is `None`) blocks under `fallback = "abstain"` and under `fallback = "generative"` alike — on this seam there is no old instrument to fall back to, since the `[llm]` model wrote the summary text and never judged the merge; and the stand-in is NEVER ASKED on this seam — and fails the operation under `fallback = "refuse"`.

**`DecisionProvider::judge_primary` (5-agent vote `4d3ea1c5`).** Under `fallback = "generative"` the W1c provider chain re-asks the generative `[llm]` backend whenever the primary is unavailable, BEFORE any seam sees the answer. On the merge seam that call is pure cost: memory content POSTed across the `AI_MEMORY_INFERENCE_EGRESS` boundary, on a destructive path, for an answer the seam discards by construction. The trait therefore gains a REQUIRED `judge_primary` — a leaf provider forwards to `judge`, the chain asks only its primary and returns that answer verbatim — and the merge seam calls it, so the block names the primary's own abstain (`timeout`, …) and the stand-in is not consulted. It is deliberately not defaulted: a default body of `judge` is the permissive arm, and a forwarding wrapper that forgot the override would put the stand-in back with no failing test (the `judge_merge` / `SwappableLlm` lesson one trait over); required, a forgetful wrapper is a compile error. The W2 seams (`classify_kind`, `detect_contradiction`) keep calling `judge`/`choose` and still fall back — they have a legacy instrument to fall back to. A blocked cluster is skipped with its sources untouched: no summarise, no rollback write-ahead, no persist.

**Order, and visible not silent (GOD D4 ruling).** In a REAL run the `pre_compaction` hook fires first, THEN the judge, THEN the summary — a hook Deny means the judge is never asked, a judge Block means no summary and no persist. A DRY run does not run the hook; it consults the judge as a PREVIEW so the shadow report shows what the judge would say (labelled by `DecisionSource` and block reason, not a claim the hook would permit) and still writes nothing. Both funnels carry `merge_judge` (real) or `judge_preview` (dry) — `blocked` / `permitted` / `sources` / `block_reasons` — and an unset `[decision]` carries NEITHER key (conditional omission, pinned against the v1.0.0 golden key set, self-report memory included), so unset output is byte-identical. A destructive seam whose `confidence_floor()` is `None` fails CLOSED (`no_floor`). The full hook Allow/Deny × judge yes/no/timeout × dry/real matrix is pinned (twelve cells, zero summarise/write-ahead/persist in every dry cell), as are f1's acceptance cells (a confidently-false verdict blocks; absent, NaN, infinite and out-of-range confidences all degrade to absent and block), and the seam records to the existing `consolidation_merge` series: a permit and a decided-no are `outcome="decided"`; a low-confidence or confidence-less yes is `outcome="abstained"` with `reason="unusable"`. The hot-reload `SwappableLlm` wrapper forwards the judge explicitly and maps a `None` handle to a block labelled `deterministic` — never to "no decider", which is the permissive arm — and a structural test pins that every production `impl AutonomyLlm` overrides `judge_merge` so a future wrapper cannot fall through to the trait default. RED-first pins: an unavailable decider blocks (under both fallbacks; under `generative` the stand-in is never asked — zero hits on the merge seam, with a positive control showing the same client's W2 seam does reach it), a decline blocks, a confident no blocks, a yes without confidence blocks, a yes one hundredth below the floor blocks, a yes at the floor permits, and unset `[decision]` merges with zero counters. The gate covers the two AUTONOMOUS merges only — the curator's Pass-1 and the SAL `ConsolidationPass` on both backends; the operator-explicit `memory_consolidate` / `ai-memory consolidate` / `power_consolidation` paths (the caller names the ids: tenant authoring writes) are deliberately not judged, and federation receive never consults the decider. A call-site census pins that.
