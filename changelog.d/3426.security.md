**Authorization refusals no longer disclose the owning agent id (#3426, folding #3339).**
Every cross-owner refusal on the HTTP surface — `PUT`/`DELETE`/promote on
`/api/v1/memories/{id}`, `POST`/`DELETE /api/v1/links`, `GET /api/v1/kg/timeline`,
`POST /api/v1/kg/invalidate` — used to answer `403` with the OWNING agent id in
the body (`"owner"`, or `"source_owner"`/`"target_owner"` on a link), and both
SAL owner gates (`SqliteStore` and `PostgresStore`) interpolated the owner into
`PermissionDenied.reason`, which `store_err_to_response` rendered verbatim. Any
authenticated caller who knew a row id could learn who holds it: a cross-tenant
identity oracle.

- ONE constructor, `handlers::parity::owner_gate_refusal`, now builds every
  cross-owner refusal. It takes no owner parameter, so a refusal built through
  it cannot name the owner; the body is the closed vocabulary
  `{error, code: "NOT_OWNER", caller, <the ids the caller supplied>}`.
- Both SAL gates refuse with the bare `errors::msg::CALLER_DOES_NOT_OWN_MEMORY`
  const, and the postgres error mapper renders that const through the same
  constructor, so the `error` + `code` a client matches on are byte-identical
  on either backend.
- Hide-on-write parity (#3339): a row the caller cannot READ (another agent's
  private row) now refuses a sqlite write with `404 {"error":"not found"}` —
  byte-identical to the read path and to what postgres already returned — so
  the write path no longer confirms that a hidden id exists.
- The owner is emitted only to the server-side `ai_memory::authz` WARN line,
  so operators keep full attribution.

Pinned by `tests/authz_refusal_leak_3426.rs` (both directions, both backends)
and `tests/authz_refusal_trace_3426.rs` (the trace keeps the owner). #3696
(`ConflictError.existing_id` on the store path) is a different funnel and is
not covered by this change.
