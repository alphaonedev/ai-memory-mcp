**Approved deletes and promotions execute on Postgres (#8548).** On the Postgres backend an approved `delete` pending action, and an approved tier-bump `promote`, ran under the approver's context, so the owner gate refused them and the decide answered `500 approved but execution failed` and the memory was left in place. Both arms now run as the requester, the same as the reflect arm, under the requester's owner gate: a row the requester owns executes, and another agent's row or an unstamped row is refused. The SQLite backend applies the same gate (#8564).
