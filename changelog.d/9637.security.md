### Security

- **An unreadable or invalid `hooks.toml` no longer means "no hooks"**
  ([#9637](https://github.com/alphaonedev/ai-memory-mcp/issues/9637)). The `serve` daemon, the
  `mcp` server and the `curator` (when it installs the enforcement gate) loaded the hooks file with
  the load error discarded, so a file with a TOML syntax error, a timeout over the ceiling, an
  unknown event, no read permission, a directory or a dangling symlink at the hooks path started
  the process with zero hooks and every configured deny gate silently absent. All load sites now go
  through one loader, `HookConfig::try_load_from_optional` / `HookConfig::load_for_boot`
  (`src/hooks/config.rs`): only a path that does not exist (no file and no link) means zero hooks;
  any other file that cannot be opened, is not a regular file, is larger than 1 MiB, or does not
  parse or validate stops startup with exit code 78 (`EX_CONFIG`) and the message
  `ai-memory: boot refused — hooks file <path> cannot be loaded: <reason>`. The parse reason is
  bounded and never echoes source lines. An empty file is still valid with zero hooks.
  `doctor --hooks` and `doctor --tokens --hooks` report such a file as an error and exit 2. The
  SIGHUP reload path already kept the previous hooks on a failed reload, including a reload whose
  file has disappeared; that behaviour is now pinned by a test.
  A non-UTF-8 file is refused with `not valid UTF-8`. There is no environment variable or flag that
  turns the refusal off. When no config directory resolves, startup continues with zero hooks and
  logs that once.
  **Behaviour change:** a daemon or MCP server that used to start with a broken `hooks.toml` now
  refuses to start until the file is fixed or removed. Run `ai-memory doctor --hooks` before
  restarting after the upgrade: a supervised daemon with a broken file exits 78 on every start and
  restart-loops.
  Tests: `tests/hooks_config_fail_closed_9637.rs` and the `hooks::config` lib tests.
