# In YAML a `#` PRECEDED BY WHITESPACE opens a comment, so the parsed job name
# — and therefore the check-run name GitHub actually reported, and therefore
# the string an operator copied off a PR into branch protection — stopped at
# `RQ-10`. It MATCHED, so this gate was green on a name nobody wrote. The

# #2473 CLOSES it. The workflow name is now QUOTED, this file declares the FULL
# string below, and `scripts/check-required-contexts.sh` gained rule (e):
# HARD-FAIL, never allowlistable, for ANY job in ANY workflow whose UNQUOTED
# `name:` contains whitespace-then-`#`. The class cannot re-land silently.
#
# THE LANDING ORDER FOR THIS PARTICULAR CHANGE (#2473) — it is a SWAP, not an
# addition, and its two halves pull in opposite directions:
#
#   * The OLD (truncated) context must be REMOVED from live protection BEFORE
#     the workflow rename merges. Once the rename is on the base branch, every
#     PR's cycle reports only the NEW name, so the old required context is
#     ABSENT — pending forever under `enforce_admins: true` — on every PR
#     including the one that renamed it. (Removal ⇒ protection first: the
#     REMOVAL half of the ORDER doctrine below.)
#   * The NEW (full) context must be ADDED to live protection AFTER the rename
#     merges, because until the base carries the rename no PR reports that name
#     and requiring it would wedge every open PR instead. (Addition ⇒ mirror
#     first: the ADDITION half of the doctrine.)
#
# So the sequence is: (1) protection DROPS the truncated context — 23 required;
# (2) this PR merges — mirror declares the full name, workflow reports it, and
# neither half of the swap is required, so nothing can wedge; (3) protection
# ADDS the full context — 24 required again. Step (2) between (1) and (3) is a
# short window in which the L3 gate RUNS on every PR and is visible, but is not
# REQUIRED; that is the cost, and it is strictly cheaper than the alternative
# orderings, every one of which wedges `release/v1.0.0` on an absent required
# context that `enforce_admins: true` cannot clear. Full analysis in the #2473
# PR body.
#
# (Contrast the entries that contain `(#1174 PR10)`, `(#1989)`, `(#2146)`:
# those do NOT truncate, because there the `#` is preceded by `(`, not
# whitespace. The gate's parser implements the real YAML rule and reproduces
# both outcomes — the `--self-test` clean control asserts exactly that.)
#
# FORMAT
#   * A line whose first non-space character is `#` is a comment. Blank lines
#     are ignored.
#   * Every other line is ONE required context name, verbatim.
#   * An INLINE `#` is NOT a comment — several context names legitimately
#     contain one (see the `(#1174 PR10)` entries below).
#
# HOW TO CHANGE THIS FILE
#   Adding or removing a required context is a branch-protection edit
#   (Sensitive class, `docs/AI_DEVELOPER_GOVERNANCE.md`). Land the protection
#   change and this mirror together, and state the intent — not the API
#   response — in the commit message.
#
#   ORDER, when the two halves cannot be atomic (they cannot — the mirror is a
#   PR and protection is an API call). For an ADDITION: land the mirror FIRST,
#   then add the context to protection. The gate can only prove a context sound
#   once the mirror declares it, so mirror-first means the soundness proof is
#   green in CI BEFORE the context becomes load-bearing — prove, then enforce.
#   The intermediate state (declared, not yet required) over-claims enforcement
#   for one visible, diffable window and blocks nothing, because GitHub never
#   reads this file. The reverse order produces the strictly worse state: a
#   live-required context that NO in-repo file declares, which this gate cannot
#   detect (it has no API access, by design) — so its rule coverage silently
#   narrows while it still exits 0. For a REMOVAL the order inverts for the same
#   reason: drop it from protection first, then from the mirror.
#
