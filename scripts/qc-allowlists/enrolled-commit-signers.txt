# enrolled-commit-signers.txt — the SSOT enrolled-key registry for
# `scripts/check-commit-signing-posture.sh` (#2486).
#
# ============================================================================
# HAND-ENROLLED FROM OPERATOR CUSTODY. NEVER GENERATE THIS FILE FROM A LIVE
# GITHUB API CALL (e.g. `https://github.com/<user>.keys`). A live-fetched
# registry is exactly as trustworthy as the network path fetching it, and a
# key ADD or REVOKE would become effective the moment DNS/GitHub answers
# differently — silently, with no reviewed diff. This file is the pinned-key
# discipline this repo already uses for `AI_MEMORY_WITNESS_PUBKEY` /
# `AI_MEMORY_RECORDER_PUBKEY` / `AI_MEMORY_JUDGE_PUBKEY` / etc. applied to git
# commit signing: an out-of-band enrolled key, reviewed in a PR diff on
# rotation, never trusted from an unauthenticated live fetch.
# ============================================================================
#
# FORMAT — native OpenSSH `allowed_signers`(5): one line per enrolled
# principal, `<principal> <key-type> <base64-key> [comment]`. This is the
# EXACT file format `git log --show-signature` / `%G?` consumes via
# `gpg.ssh.allowedSignersFile` (git >= 2.34), so for the principal-matching
# half of the check there is no hand-written mirror of this data anywhere:
# git reads THIS file.
#
# That native-format property is REAL but it is NOT a guarantee that nothing
# can drift (#5045). An earlier revision of this header claimed the registry
# format and the verification format "can never drift apart" with "no custom
# parser needed on either side". That is no longer true, and saying so in an
# attested registry would itself be the docs-drift defect this repo treats as
# real. Three things parse signer data now:
#
#   1. git, natively, via `gpg.ssh.allowedSignersFile` — principal matching.
#   2. `check-commit-signing-posture.sh`, which reads column 1 of this file
#      for the enrolled-principal allowlist and DERIVES each key's
#      `SHA256:` fingerprint from columns 2-3 with `ssh-keygen -lf` in order
#      to pin `%GF` (the fingerprint that actually verified). Derived, never
#      hand-copied: a typed-out fingerprint mirror would be a second place
#      for the same key to drift.
#   3. A SECOND, SEPARATE registry — `enrolled-gpg-commit-signers.txt` plus
#      its `.asc` key material — which pins OpenPGP fingerprints in a bespoke
#      format with its own parser. It exists because git dispatches signature
#      verification on the signature type carried IN THE COMMIT OBJECT, and
#      `gpg.format` does not override that dispatch: an OpenPGP-signed commit
#      is checked against the OpenPGP keyring and never against this file. On
#      a stock CI runner that keyring is empty, which is why 67 commits the
#      operator legitimately signed were refused with `%G?=E` (#5045).
#
# So the honest statement is: the SSH principal check consumes this file
# natively, the SSH fingerprint pin is derived from it mechanically, and the
# OpenPGP pin lives in a sibling registry that CAN drift from this one. What
# closes that is not a format claim but a test: the gate's `--self-test` case
# (k) asserts, on every CI run, that the shipped registries agree with the
# shipped key material and that the pinned set still carries BOTH halves, so
# losing either half fails the gate closed instead of silently narrowing or
# widening what it accepts.
#
# WHAT THIS DOES NOT CLAIM. This registry proves a commit's Ed25519 SSH
# signature was produced by the holder of THIS exact private key, and that
# the claimed committer/author principal is one this repo's control has
# pinned as account-bound. It does NOT independently prove GitHub's own
# "Verified" badge state (that is GitHub's separate web-flow / API-side
# check, not reproduced here) and it does NOT prove which GitHub *account*
# holds the key beyond the operator's own out-of-band enrollment record — an
# SSH public key carries no identity of its own. Both are the same
# ATTESTABLE-vs-OPERATIONAL boundary already documented throughout this
# repo's `AI_MEMORY_*_PUBKEY` rows: signature verification against this file
# is cryptographically enforced; WHO was enrolled here is operational trust,
# recorded via a reviewed PR diff.
#

# operator's personal bound identity and the GitHub-anonymized noreply
# alias for the SAME `alphaonedev` account, so a commit stamped with either
# is equally account-bound. Enrolling (or revoking) a key is a reviewed PR
