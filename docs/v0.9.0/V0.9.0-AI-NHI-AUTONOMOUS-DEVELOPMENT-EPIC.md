## Dependency-Ordered Execution Sequence

The autonomous loop fans tasks out in phases. A task is eligible only when **all** its `Deps` are merged-green **and** the phase-level gates below are satisfied. Two cross-cutting ordering laws from the sequencing spec are non-negotiable correctness gates (not preferences): **shadow-before-live** (#1706 → #1707) and **attest-before-enforce** (a measured/attested substrate must precede anything that acts on it). The shape is **Phase 0 carryover → foundational → primitives → backends/integration → higher-integration → gates/release.**

**Phase 0 — Carryover, tracker hygiene, and the BLOCKING vector gate (start immediately, no foundational deps).**
- **`FILE-ISSUE-B7`** first — #1853 requires the epic to start on a clean tracker; the three core §11.5 features are otherwise invisible to burndown, and every B7 build task references its filed issue#.
- **`B7-CO-2` (#1854)**, **`B7-CO-3` (#1855)** — land on the already-open PR #1857; they harden the audit-test and postgres-parity CI the rest of the epic relies on for its green bar.

### 2. Decision-Point Protocol — 2 Waves × 5 Adversarial Voters

Because there is no human to backstop a single wave's groupthink, every non-trivial fork runs a **two-wave, ten-voter** crossroads vote. This extends — does not replace — the canonical single-round 5-agent standard (`4d3ea1c5`); it institutionalizes the operator's own 2-round elevation precedent (`d36797f5`) as the v0.9 default.

#### 2.1 Trigger conditions (mechanical — no judgment-by-feel)

Run the vote **before acting** whenever any inherited trigger holds:

- **T1** public-contract shape change with ≥2 viable forms (a SAL `MemoryStore`/`VectorIndex` trait method; a public field crossing a module boundary; a new MCP tool / HTTP route / CLI subcommand; a wire/JSON or DB-schema migration shape).
- **T2** a sync↔async boundary decision.
- **T3** a security/governance posture (fail-open vs fail-closed; a new or relaxed gate/auth/visibility/encryption boundary).
- **T4** a hard-to-reverse representation (on-disk format, persisted/attested/signed-bytes layout, any back-compat obligation once shipped).
- **T5** deviation from a written spec / acceptance criterion.
- **T6** ≥2 mutually-exclusive paths with no single clear precedent to copy.

**Pre-declared v0.9 crossroads that always vote:** every `#1005 VectorIndex` trait signature, the 3-backend factory contract (`--index=auto|sqlite-vec|vectorlite|builtin`), the `signed_events` index-event extension, the `migration_state`/`embedder_registry` on-disk layout, and any §23.0 recall-regression accept/reject; each `#1822–#1828` gap design call; the G29 secrets-screen write-path shape and the G30 forget-true-erasure shape; the `#1840` portable-vs-eBPF path; every `#1829–#1839` v0.9-vs-v1.0 deferral-boundary call; and (per §25.4) the `epoch_manifest` schema, `SignableEpochManifest` byte layout, `epoch.manifest_applied` event, `EpochAdvance` binding, and every FED-RQ authority-write — **before `git add`/commit**.

**Exempt — decide-and-build, no vote** (record inline in the commit): internal-only refactors with no public-surface change; naming/comments/error-wording/test structure; mechanical edits dictated by an existing precedent; single-correct-answer bug fixes; no-op/idempotent semantics. **Precedent-copy rule:** copying a clear precedent IS the decision, so T6 does not fire. When in doubt between exempt and T6, **fail closed and vote.**

#### 2.2 Wave construction and prompting (identical for both waves)

A wave is exactly **5 concurrent Agent subagents**, spawned in one batch so they run in parallel, **isolated** (no subagent sees another's output within its own wave — no cross-talk, no shared scratch, no hand-off). Each is prompted as a **default-to-reject skeptic**: the burden of proof is on the *proposal*; absent an affirmative, evidence-backed case the correct ballot is **REJECT**. Each is handed the fork statement, the labelled options A/B/C…, the matched trigger code(s) Tn, the codegraph/ROADMAP/issue anchors, and its **assigned lens**. Every claim must be grounded in `file:line` / symbol / issue# via `codegraph_explore` against the project path; an unevidenced ballot is downgraded to REJECT at tally.

**Lens diversity (mandatory anti-groupthink).** The 5 lenses in a wave must be distinct and fork-fitted, drawn from: (1) precedent/consistency, (2) blast-radius/impact, (3) security/governance posture, (4) spec-literalism, (5) testability/verifiability, (6) sync/async correctness, (7) reversibility/migration-safety. **The Claims-Discipline lens is always seated in at least one wave** and default-REJECTs any option whose framing requires a banned-until-gated claim or a perma-banned grandeur term.

**Ballot schema (fixed, every subagent, both waves):** `VERDICT ∈ {ACCEPT, REJECT}` (or, for multi-option forks, a RANKING of A/B/C plus ACCEPT/REJECT on the top option proceeding at all); `CONFIDENCE` 0–100; `RATIONALE` (anchored); `TOP_RISK`; `KILLER_OBJECTION`.

#### 2.3 Per-wave majority (fail-closed on ambiguity)

A wave returns **ACCEPT iff ≥3 of 5 ballots are ACCEPT**; otherwise REJECT. **Normalization before tally:** any ballot that is abstain / timeout / unparseable / missing a field / unevidenced is counted as **REJECT**, never dropped — the denominator stays 5. A subagent crash therefore moves the wave toward REJECT, never toward a spurious PROCEED. For multi-option forks, the winner is the option ranked first by a majority; no ≥3 first-rank majority = REJECT. A wave that returns fewer than 5 accountable ballots is treated as REJECT.

#### 2.4 Wave-2 (independent confirm-or-overturn over a visible Wave-1)

Wave-2 runs strictly **after** Wave-1 completes and is recorded. Each of Wave-2's 5 fresh isolated skeptics is shown the **full Wave-1 record** (all 5 ballots, the verdict, the synthesized rationale) and is tasked to **red-team it**: steelman the opposite conclusion, hunt for what Wave-1 missed, and check for groupthink or a shared blind spot. Wave-2 voters are isolated **from each other** but deliberately **not** from Wave-1's output — seeing it is the point. They then ballot under the same §2.3 schema and majority rule, producing a confirm-or-overturn verdict.

#### 2.5 Two-wave reconciliation (asymmetric, fail-closed-favoring)

| Wave-1 | Wave-2 | Result |
|---|---|---|
| ACCEPT | ACCEPT | **PROCEED** — both waves independently cleared it |
| REJECT | REJECT | **BLOCK** |
| ACCEPT | REJECT | **BLOCK** — overturning *down* (toward fail-closed) is cheap and always honored |
| REJECT | ACCEPT | **PROCEED only if** Wave-2's ACCEPT is a **supermajority ≥4/5** *and* its ballots cite the **specific Wave-1 error/blind-spot** corrected; **otherwise BLOCK** |

The asymmetry is the core safety property: it is structurally easy to stop and structurally hard to proceed against a prior skeptical wave.

#### 2.6 Tie-break (one rule, no ambiguity)

**DEFAULT-TO-REJECT / FAIL-CLOSED ALWAYS WINS.** Any unresolved state — a wave that cannot reach a clear majority, a reconciliation cell not explicitly PROCEED, a deadlock, an R→A overturn that misses the §2.5 bar, an infra failure preventing either wave from completing, or any disagreement about whether a fork even triggered — resolves to **BLOCK**. There is no 11th tie-breaking voter and no in-band operator escalation; the fail-closed default *is* the tie-breaker. A BLOCK is a safe, recorded outcome, not a failure of the loop.

#### 2.7 Record-to-memory with vote id (before implementing — non-negotiable ordering)

Mint **one fresh `vote-id`** (UUIDv4) per invocation — the join key across the memory record, the commit trailer, and the issue comment. The instant reconciliation resolves and **before any `git add`/write**, `memory_store` one decision memory: `kind=decision`; `tier=long` for tag/scope-boundary forks else `mid`; `priority` 9–10; namespace `ai-memory` (project) or `global` (process); title `2x5-wave vote (<vote-id>) — <fork> DECISION: <chosen pathway>`; tags include `2x5-wave`, `<vote-id>`, `4d3ea1c5`, the issue#, and the Tn code(s). Content MUST capture, in full: (a) fork statement + Tn + anchors; (b) the option set; (c) **all 10 ballots** verbatim in the 5-field schema (or a faithful `3 OPTION_C (conf 82/88/95) + 2 OPTION_A (80/80)`-style tally preserving every VERDICT/CONFIDENCE); (d) both wave verdicts; (e) the reconciliation cell applied and, for R→A, the cited Wave-1 error; (f) the chosen pathway and synthesized why; (g) the **verbatim dissent** — every REJECT rationale and KILLER_OBJECTION from the prevailing side, word-for-word. `memory_link` to the protocol record and to `4d3ea1c5`. Implementation begins **only** after the store returns an id. The commit/issue audit trailer is mandatory and machine-greppable: `2x5-wave vote (<vote-id>)`. Shipping a trigger-matching change without a recorded vote is a self-flagged process violation — store a `kind=incident` memory and surface it.

**A BLOCK never idles the loop.** On BLOCK, do exactly one of, in priority order, and record which: (1) **defer with rationale** — file/append the appropriate tracking issue, write the rationale, mark DONE-via-recorded-deferral (the `#1840`/W6 precedent, `cf2cbfb7`: `BLOCKS_RELEASE=no`); (2) **re-scope and re-vote** — if a specific KILLER_OBJECTION is neutralized by a narrower option, mint a **new** vote-id and run a fresh 2×5-wave on the narrowed option (never silently proceed on the un-voted variant); (3) **route to the next task**. Under no circumstance does a BLOCK cause unilateral implementation of the blocked path or an idle spin. A re-surfaced deferred fork does **not** auto-reverse — it requires a fresh full 2×5-wave with a new vote-id; if implementing a PROCEED reveals a *new* fork (a second Tn fires), pause and vote that fork separately — one vote-id governs one fork.

#### 3.1 What GREEN means

**A ROUND** is the full ordered check sequence run end-to-end against the live target. **GREEN = every check passes with its asserted value**; a single failed/missing/timed-out check makes the whole round **RED**. **3 consecutive** means three in a row with no intervening RED **on the same SHA**; a RED at round 2 discards rounds 1–2 and restarts at round 1. The counter is **per-gate AND per-droplet-shape** (PG16 and PG18 each maintain their own 3-streak); the loop persists streak state in `mcp__memory` keyed by `SHA+shape` so a restart resumes rather than double-counts. Any commit to `src/`, `infra/do-hive/`, `migrations/`, or the schema files **resets both gates' counters to 0**; docs-only diffs do not.

**Build preconditions, re-pinned on any code change:**
- Binary built with `--features sal-postgres` (the default `sqlite-bundled` build cannot serve the postgres+AGE path and is invalid for Gate A). The postgres legs run over HTTP (SSH-tunnelled to the loopback daemon); MCP-stdio is sqlite-only by design.
- **Pin the embedder to the column dimension before any store:** `AI_MEMORY_EMBED_MODEL=all-MiniLM-L6-v2` (384-d) to match `vector(384)`. A 768-vs-384 mismatch 503s every store — assert this in pre-flight, never discover it mid-round.
- Record the exact git SHA in every evidence-doc header; all 3 rounds run against the same SHA.
- **Read the v0.9 migration-head schema_version and assert it on both backends** (the `postgres_schema_parity` invariant) — do **not** hardcode 71; v0.9 adds the §23.2 vector-index tables so the stamp will be `> 71`.

### 4. Guardrails & Risk Register

These guardrails bind the swarm with **no human in the loop**. Authority precedence (highest first): **operator-signed L1 RuleEngine > these guardrails > the EPIC task table > an agent's local plan.** When any rule here conflicts with a task instruction, the rule wins and the agent **HALTs-and-logs**, never proceeds. An agent may never elect itself an exception.

#### 4.1 The DO-NOT list (violation = immediate halt of that agent + escalation event)

- **DO-NOT touch protected branches.** Never commit, force-push, rebase, amend, reset, `git clean`, or `git gc --prune` against `main` or any `release/*`. All work lands on a fresh topic branch; integration is PR-only. Branch-cleanup automation may delete **only** merged topic branches it created, matched by an explicit prefix allowlist — never a branch it did not create, never `release/*`, never `main`.
- **DO-NOT bypass signing or branch protection.** Every commit signed; the tag GPG-signed. If a protection rule is temporarily relaxed for an automated merge, restore the **exact** prior protection state in the same run — **wrapped so RESTORE runs even on push failure** (trap/`finally` semantics). A run that cannot restore protection **fails closed and escalates** rather than leaving protection weakened; a loop that lifts protection and dies with it lifted is a critical incident — `memory_signal_send` an alert and refuse the next task until protection is confirmed restored. **NEVER leave `main` unprotected across a sleep interval.**
- **DO-NOT bypass, disable, no-op, or weaken governance to make a task pass.** The L1 law is operator-signed and read-only (`enforced_rule_passes` requires an operator Ed25519 signature, `src/governance/rules_store.rs:205`; the RuleEngine is never programmatically mutated, `src/governance/agent_action.rs:782`). Respect seed rules R001–R004 wherever signed/enabled. Do not edit `governance_rules`, re-sign with a non-operator key, or route writes around `check_agent_action`/`GOVERNANCE_PRE_WRITE`/`GOVERNANCE_PRE_ACTION`. The MCP egress gate is fail-closed as of `#1685` — do not reintroduce a fail-open path.
- **DO-NOT delete or destructively mutate data without a verified snapshot first** (`#1576`: forward-only migration, snapshot-restore IS the only rollback). Before any schema-mutating migration, take the `VACUUM INTO` pre-migration snapshot via `snapshot_before_migration` to `<db-file>.pre-migration-v<FROM>-to-v<TO>-<token>.bak`; the migration MUST refuse to mutate if the snapshot fails. Do not delete the `.archive/` retained `instant-distance` state (kept one release cycle, §23.3) or any `.bak` within the release window.
- **DO-NOT overclaim** — the §1.5 banned/perma-banned vocabulary is binding in code comments, CHANGELOG, release notes, capabilities JSON, landing pages, and commit messages.
- **DO-NOT mark a gap SHIPPED/RESOLVED without §23.8 / per-issue DoD evidence** (real code + passing test). Distinguish DONE / PARTIAL / MISSING in every status; never report PARTIAL as DONE.
- **DO-NOT violate the §1.1 ordering gates** — they are correctness gates, not preferences (enforce on CLAIMED metadata = security theater; shadow before live; postgres parity before per-cycle decorrelation; `policy_version`+`model_family` before the epoch consumer).
- **DO-NOT self-merge a T1+T4 crossroads without the cited §2 vote.** The epoch schema stays git-UNTRACKED with zero `src/` consumer until the fork is resolved; fabricating or skipping the vote cite is a halt-class violation.
- **DO-NOT phone home.** No outbound call to any destination the operator did not explicitly configure (federation mTLS allowlist, opt-in HuggingFace fetch, opt-in Ollama endpoint). Spans carry operation metadata only, never memory content.
- **DO-NOT break SQLite↔PostgreSQL parity.** Any schema or write-path change ships in **both** backends in the same change set, in lockstep. A sqlite-only landing of a parity-bearing change is prohibited.

#### 4.2 Anti-scope-creep boundary (the REFUSE list — decline, do not silently attempt)

A candidate is IN v0.9 **only if** it (a) sits on the `v0.9` milestone OR is a named §11.5/§23/§25.3-P0 deliverable, **and** (b) strengthens one of the seven §2 properties. Everything else is OUT:

- **§16 confirmed-cut:** Plugin SDK Python/TypeScript (MCP is the SDK); any backend beyond SQLite + Postgres-AGE; full mobile SDK wrappers; cloud-hosted storage; web UI (→ `ai-memory-viewer` sibling); agent runtime/orchestration; general-purpose subagent spawning (only the bounded compaction subagent); real-time WebSocket viewer; mature schema-change methodology (→ `ai-memory-schema-tools` sibling); cognitive-state/affect modeling.
- **§25.5 eternity-cut:** full RQGM / population genetics in `src/`; governance auto-mutation without an operator-signed pack; epoch panel as MCP tools; a `--rqgm` flag; `enforce` on CLAIMED metadata; cross-node raw utility leaderboards. The L3 engine stays permanently external in `ai-memory-rqgm` (v0.9.1+) and **never** enters the v0.9.0 tag — `rg -i 'rqgm|epoch_manifest|red.?queen' src/` MUST stay `0` as a CI gate.
- **§23.7 vector out-of-scope:** quantization backends (RaBitQ-IVF, TurboQuant, residual VQ — pluggable via the `VectorIndex` trait but **not shipped**); GPU acceleration; per-namespace HNSW shards (the §23.2 namespace pre-filter is the v0.9 answer); asymmetric distance computation; streaming consistency under data-dependent quantization. Building the trait seam is in scope; populating these backends is not.
- **v1.0 deferral boundary:** the 17 P2 TRACT gaps `#1829–#1839` (G15…G31) are milestone v1.0 — do not pull forward. Federation maturity (mDNS, E2E encryption beyond mTLS, MVCC strict-consistency, OTel, semver freeze, Memory Portability Spec v2, the public third-party security audit, the API-stability guarantee) is v1.0. **Refusal protocol:** when a task, an emergent "improvement," or a tempting adjacency lands on any refuse list — even if it looks "easy" — (a) do **not** implement it, (b) log a structured scope-refusal event naming the list + clause, (c) if it appears genuinely load-bearing, file an issue for the appropriate milestone for human triage. Pulling a v1.0/§23.7 item forward requires an operator-recorded §2-class vote; absent that, file it and move on. Conversely, any **untracked** defect the loop discovers is a §24 obligation to **file** (not silently fix-and-forget) before it can count toward closure.

#### 4.3 Rollback / snapshot safety (the loop's only reverse gear)

The substrate is forward-only by design (`#1576`); there is no migration downgrade path, so snapshot integrity is load-bearing for the entire loop.

- **Pre-mutation:** every schema-mutating step auto-snapshots via `VACUUM INTO` (transactionally consistent, folds pending WAL, inherits SQLCipher keying) to the `.pre-migration-bak`; the migration aborts if the snapshot write fails.
- **Rollback recipe (verbatim):** stop the daemon → reinstall the previous binary → copy the matching `.pre-migration-bak` over the live DB file, removing stale `-wal`/`-shm` siblings → start. **Verify** the daemon comes up healthy (`ai-memory doctor` + V08-PE-8 `verify-audit-trail` chain-walk) **after** restore before declaring rollback complete.
- **Vector-index reverse gear:** the old `instant-distance` state in `<db_dir>/.archive/` is retained one release cycle — do not purge within the v0.9 window.
- **Retention invariant:** no automated cleanup may delete `.bak` pre-migration snapshots or `.archive/` index state during the release window — add this as a CI ratchet.
- **Checkpoint discipline:** before any high-blast-radius batch (index migration over a large corpus, bulk forget fanout), record a resumable `migration_state` checkpoint so the loop restarts idempotently rather than re-runs destructively.

#### 4.4 Top risk register (trigger → mechanism → mitigation → hard stop)

- **R1 — Migration data-loss on a large corpus (HIGHEST).** *Trigger:* an index/schema migration interrupted mid-run on a multi-hundred-k-vector corpus. *Mechanism:* a non-idempotent/non-restartable migration partially writes the index; forward-only design means no downgrade. *Mitigation:* migrations are idempotent + restartable with a `migration_state` table tracking `last_completed_memory_id` + `target_backend`; mandatory `ai-memory migrate-index --dry-run` before any live run; the `VACUUM INTO` snapshot is the recovery anchor; an `IndexMigrationCompleted` signed event marks true completion. **Hard stop:** any dry-run anomaly, a failed snapshot, or an inconsistent `migration_state` on restart → HALT and escalate; do not force the migration.
- **R2 — Schema lockstep drift sqlite↔postgres (HIGH).** *Trigger:* a v0.9 migration (e.g. §23.2 `embedding_dim`/`embedder_version` columns, `embedder_registry`, the index-event types) lands in one backend's ladder but not the other. *Mitigation:* every parity-bearing change ships both backends in the same PR; a version-parity invariant test asserts equal `CURRENT_SCHEMA_VERSION`; the `#1855` nightly postgres-parity fleet must be green; the ship-gate runs against both backends. **Hard stop:** any backend-version mismatch or parity-test failure blocks the tag — drift is never a "fix in a follow-up."
- **R3 — Federation erasure incorrectness / resurrection (HIGH, data-privacy).** *Trigger:* a forgotten memory re-appears. *Mechanism (G30):* a hard forget historically deleted the relational row but left content in `federation_push_dlq` cleartext, as a live in-RAM HNSW vector, and with no persisted tombstone so a peer LWW re-push resurrected it. *Mitigation:* v0.8.1 W2 makes single-node forget a true erasure (purges DLQ + `transcript_line_dedup` hash-oracle in-tx on both backends, synchronously invalidates the HNSW vector, writes a signed v71 `forget_tombstones` entry checked on receive; archive-restore is tombstone-gated, `#1848`). The v0.9 residual is the cross-mesh tombstone-propagation + owner-authz layer (`#1823`/`#1852`) — and the vector migration must wire `forget`/`idx.remove` into the `VectorIndex` trait so erasure stays synchronous across all three backends. **Hard stop:** ship-gate Phase-2 federation + the `#1845` forensic-egress redaction regression must prove no resurrection and no forgotten content in any export before tag.
- **R4 — Vector-rebuild incorrectness (HIGH).** *Trigger:* `VectorIndex::rebuild()` produces a stale/partial/silently-wrong index, or reads during rebuild return wrong results. *Mitigation:* rebuild is contributed to all three backends with eventually-correct reads during rebuild and signed `IndexRebuilt` events at batch boundaries; the §23.0 BLOCKING pre-flight is the recall guarantee (sqlite-vec/f32 exact, int8 ≤0.5 pt R@5, vectorlite ≤1.0 pt @100k/1M); the §23.4 ship-gate runs all three backends + int8 (4 runs) with the 12-variant LongMemEval disclosure; V08-PE-8 is extended with index-drift/embedder-violation/rebuild-status checks; the audit-chain write is serialized to avoid the hash race. **Hard stop:** if pre-flight recall regresses beyond the stated points, the decision is NO-GO and the loop does not proceed to foundation work; any backend that fails the gate ships **disabled, never silently degraded.**
- **R5 — Audit-chain integrity break (HIGH; attestation is the most-shipped property).** *Trigger:* an index event written without an Ed25519 signature, out of monotonic sequence, or a truncated chain tail. *Mitigation:* index events are first-class in `signed_events`, signed through the trait; V08-PE-8 walks them end-to-end; the `#1850` anchor guards tail-truncation. **Hard stop:** any `verify-audit-trail` failure blocks the tag and triggers escalation.
- **R6 — Extension-blocked / build-download failure / platform coverage / operator backend confusion (MEDIUM).** *Mitigation:* the pure-Rust `hnsw_rs` builtin fallback covers environments where SQLite extension loading is disabled; the `--index=auto|sqlite-vec|vectorlite|builtin` factory + Capabilities-v3 reports the **active** backend, storage type, and scale regime; build artifacts bundle both shared libs per platform (no run-time download). **Hard stop:** a platform that cannot load any of the three backends must **fail loud with the builtin fallback active**, never start with a silently-absent index.
- **R7 — Governance fail-open regression / secret leakage (MEDIUM-HIGH, data-privacy).** *Trigger:* a change re-opens the MCP egress gate (`#1685`) or routes a write around the G29 credential screen. *Mitigation:* `tests/mcp_governance_pre_action_1685.rs` pins fail-closed egress; the G29 fail-closed write-path screen (default `AI_MEMORY_SECRET_SCREEN_MODE=refuse`, both backends, also at forensic-bundle egress) stays on all caller-origin write paths. **Hard stop:** any test in this fleet red blocks merge.

#### 4.5 Loop-level stop conditions and escalation (the safety net)

**HALT-and-escalate (do not auto-proceed) on any of:** a §17 quality-gate failure; a coverage regression below the 92 floor (93.84% baseline); a snapshot failure; an audit-chain verify failure; a backend-parity mismatch; a pre-flight recall NO-GO; a governance/secret-screen test red; or any attempt that would require touching a refuse-list item or a protected branch. Every release must declare its §2-property contribution in CHANGELOG (v0.9 strengthens §2.1 persistent endpoint-resident index, §2.4 rebuild primitive, §2.5 index events in the signed chain); a release strengthening none must be re-evaluated against the §3 scope test before merge — the loop may not tag it. **Provenance discipline:** every status, claim, and SHIPPED/PARTIAL/MISSING verdict the loop emits carries a code anchor (`file:line` / symbol) or issue#; an unsourced claim is an overclaim and is itself a §4.1 violation. Single-evaluator strategic claims are not procurement-defensible — the heterogeneous `#1171` panel reviews any strategic-layer claim (decorrelation, attestation, ASI-durability) before tag, and every contested crossroads is decided by the cited §2 vote, not a single agent.
