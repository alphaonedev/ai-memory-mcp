## 2. RPO per durability class (§0.2 row 3; classes from `src/write_receipt.rs`)

Loss is counted in ACKNOWLEDGED operations (op-ids present in a receipt) missing from the
recovered state INSIDE the receipt's declared class, verified by the harness digest of
the bytes sent against a read through a different surface — never by HTTP 200 alone.

| `durability_class` | Posture it requires | Declared RPO | Miss disposition |
|---|---|---|---|
| `local-only` under the certified SQLite posture (`AI_MEMORY_DB_SYNCHRONOUS=FULL` or `asi-hard`) | `doctor --posture` attests `synchronous=FULL` (N26) | **0 acknowledged operations lost** on process crash, SIGKILL and power interruption — the after-commit boundary is pinned in software (`tests/power_loss_durability.rs`, `AI_MEMORY_TEST_ABORT_AFTER_COMMIT`); the power-cut half rests on fsync honesty of the qualification host's storage (N20, #3561) and is NOT YET EVIDENCED until that run | any loss = CERT-VOID |
| `local-only` under `synchronous=NORMAL` (the compiled default, inside the envelope only under this class) | the node declares NORMAL | 0 acknowledged operations lost on process crash / SIGKILL; **on power interruption: up to the WAL tail not yet checkpoint-fsynced** — declared as EXPOSURE, bounded by the WAL autocheckpoint (1000 pages) and stated in the receipt's class | loss on crash/SIGKILL = CERT-VOID; loss on power cut inside the WAL tail = published exposure, never upgraded |
| `quorum W-of-N` (`quorum_acks > 1`, `quorum_required ≤ quorum_acks ≤ quorum_n`) | federation with `AI_MEMORY_FED_REQUIRE_SIG=1`, `_NONCE=1`, `_PEER_ENROLLMENT=1` | **0 acknowledged operations lost while at least W acknowledging nodes survive**; with fewer than W survivors the class degrades to the surviving nodes' `local-only` rows above | any loss with ≥ W survivors = CERT-VOID |
| `replicated+backup` (`quorum_acks > 1` AND `AI_MEMORY_BACKUP_POSTURE_ATTESTATION=attested`, #3555) | the quorum row's posture plus an OPERATOR-ATTESTED backup cadence | 0 acknowledged operations lost with ≥ 1 acknowledging node surviving; with total node loss, **≤ 24 h** of acknowledged operations (the declared backup cadence the attestation vouches for — the attestation is a posture assertion, not evidence, per the #3555 row of the env table) | loss with ≥ 1 survivor = CERT-VOID; loss inside the 24 h window with total node loss = published exposure |

Today no receipt is emitted by every write funnel (N29, #3555 landed the receipt type;
funnel coverage is item 1c). A write with no receipt is OUTSIDE every class above and its
loss is published as exposure — it cannot void a certificate it was never inside, and it
cannot be counted as durable.

### 4.1 Growth budget per table, per 24 h, per 10⁶ resident rows in `memories`

Measured by the N20 growth ledger (#3561) as the delta of `SELECT count(*)` and of
on-disk bytes per table over each 24 h window of the soak, normalised to 10⁶ resident
`memories` rows, under the soak's declared write rate (the `AI_MEMORY_MAX_MEMORIES_PER_DAY`
default, 1000/day/agent, × the declared agent count).

| Table (both backends) | Budget per 24 h per 10⁶ rows | Provenance |
|---|---|---|
| `memories` | the declared write rate itself (workload, not maintenance) — **no orphaned growth**: a row count that rises faster than acknowledged stores | §0.4 |
| `memories_fts` / `tsv` GIN | proportional to `memories` (derived index) — ≤ 3× the `memories` byte delta | FTS5 external-content + trigram overhead |
| `recall_observations` | ≤ (recalls per 24 h) rows, and the table's total bounded by the 7-day `AI_MEMORY_OBSERVATIONS_TTL_DAYS` default (row #42) — a total above 7 × the daily recall count is a miss | #886 / #2358: pruned at every `gc` chokepoint |
| `signed_events` | ≤ 1 row per governed write + 1 anchor per 64 appends (`WATERMARK_INTERVAL`) | audit spine; retention declared in §5 preconditions of the standard (days) |
| `archived_memories` (+ `archived_memory_links`) | ≤ the `gc` eviction count per 24 h; purge cadence declared by the operator | archive-on-gc default |
| `memory_revisions` (append-only spine, `AI_MEMORY_APPEND_ONLY=1`) | ≤ 1 leaf per supersede / erase / consolidate source | #1823 / #1859 |
| `federation_push_dlq` | ≤ the failed-push count; a quarantine count that grows without an operator remedy is a miss | #1544 edge-triggered WARN at 1000 |
| **`signals`, `actions` (+ `action_edges`, `leases`), `checkpoints`, `routine_runs` — the #3011 tables** | **EXCLUDED from the per-10⁶-rows budget for v1.0.0.** Only caller-declared-ephemeral (expired) signals are reaped today (`signals::prune_expired` at the `gc` chokepoint); acknowledged signals, actions, checkpoints and routine runs are never pruned (#3011 open). Their absolute growth is PUBLISHED per soak window as exposure; a retention policy lands with #3011 and enters this budget at revision 2 of this file, with the dated reason line §5 requires | §0.1 NOT YET EVIDENCED: "coordination-plane retention (#3011)" |
| `kg_projection_outbox` (postgres, `deferred` mode only) | ≤ the link-write count per 24 h and drained to 0 pending within the window | #1735 |
| `transcript_line_dedup` | ≤ the captured-turn count per 24 h | #1389 L4 |

Cost ceiling: the maintenance work of one 24 h window (gc + fold + backfill + FTS
integrity + gauge refresh) consumes ≤ 5 % of one core-hour per 10⁶ resident rows on the
qualification host; above it is FAIL of G5 even when every foreground target passes.
