# cert-3607 evidence sanitization (re-bind after #3204; first re-issue after #3549 / #3553 / #3199)

These files are **recorded artifacts** of the enterprise-federation
certification re-bind run against the chain-10 candidate tip named in the
provenance line below (gated by push gate v3 reds=0 and published to `origin/release/v1.0.0`
in the same push). They are **not** regenerated by CI. Host: a Linux build host; the certified
PostgreSQL 18 + AGE + pgvector tier over TLS (`sslmode=verify-full`); an
exclusive throwaway live database created for this run (never an operator
or shared database); release-built binaries of the same tip (one default,
one `--features sqlcipher`) for the four §5.4(2) posture legs.

Provenance: posture captures recorded at tip `ab6f2175077afd47e0a0ac65d5121db97e1d22d5` on 2026-09-12 (UTC); rewritten by scripts/recapture-cert-3607-posture.py on every recapture.

That provenance line is the only place this file names a tip or a date. A recapture
(`scripts/recapture-cert-3607-posture.py`) rewrites it in staging to the full HEAD sha and the
UTC date of the run, so the published `MANIFEST.sha256` covers the updated file; the recapture
refuses a `SANITIZATION.md` that does not hold exactly one such line. A recapture rewrites the
four posture captures, `posture-legs-exit-codes.txt`, the two peer files, this provenance line
and the manifest. It does **not** rewrite `test-results.txt` or `named-tests.txt`: those two were
recorded by the cargo run of the certification and stay as recorded.

## What was sanitized / omitted

- Cargo progress bars, compiler warnings, and absolute `CARGO_TARGET_DIR`
  paths were **not** copied. Only the `test result:` / `test <name>` lines.
- Absolute checkout, fixture and home paths in the posture captures are
  collapsed to `<repo-root>` / `<home>`.
- The live DSN (including the postgres role password), the fixture
  database passphrase and the fixture key material were process-env /
  fixture-file only and do **not** appear in these files.
- No API keys, passphrases, PEM blocks, peer IDs from production, internal
  host names, ports or shared database names.

## How the posture captures are redacted (read this before trusting a capture)

- **Every occurrence, longest value first.** The sensitive values are the per-child homes, the
  fixtures root, the repo root and HOME, each as given and as its realpath. For each one the
  recapture replaces every occurrence of the raw text, the JSON-escaped text (with and without
  the `\/` slash escape, once and twice) and the percent-encoded text (upper and lower hex,
  with and without an encoded slash), longest value first. There is no delimiter allowlist.
- **Over-redaction is the rule, not a defect.** A longer path that shares a prefix with a
  sensitive value (`/home/a` inside `/home/ab`) is over-redacted (`<home>b`). The evidence may
  lose detail; it never keeps a sensitive value. Do not "repair" an over-redacted line by hand:
  the manifest and the recapture will not accept an edited capture.
- **The redaction is not claimed to be complete; the detector is the guarantee.** After redaction
  the recapture builds decoded views of every capture: repeated case-insensitive percent decoding,
  JSON `\u` and `\/` unescaping, `html.unescape`, and the text joined across line wraps (with
  and without the indentation of the next line) with the wrap characters and ANSI sequences removed,
  and `//` and `/./` segments collapsed. If a sensitive value appears in **any** decoded view, the
  run refuses to publish, exits non-zero and names the capture and the form (never the value).
  Every input is therefore either redacted or refused; none passes through.
- **Trust anchor.** The recapture reads `MANIFEST.sha256` as committed in git HEAD
  (`git show HEAD:<path>`), never the file on disk, and refuses unless the working-tree manifest
  is byte-identical to it, the set of every file and directory under this directory equals the
  manifest set exactly (an extra, missing or unlisted file or subdirectory, or any symlink,
  refuses) and every listed digest matches. Commit the evidence directory after a recapture
  before running the next one.
