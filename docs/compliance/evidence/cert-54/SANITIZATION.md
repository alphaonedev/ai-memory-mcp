# cert-54 evidence sanitization (2026-08-12 recorded artifacts)

These files are **recorded artifacts** of the 2026-08-12 §5.4(2)/(5)
localhost runs that the certification cites. They were copied from the
operator node's gitignored `.local-runs/cert-54-evidence/` into this
committed directory so the evidence chain is verifiable at the re-issue
SHA (finding F5). They are **not** regenerated by CI.

## What was sanitized

| Pattern | Replacement | Files |
|---|---|---|
| Absolute local repo path of the operator checkout | `<repo-root>` | 2 posture legs (`posture-hardened-env.out`, `posture-sqlcipher-pass.out`) — the `AI_MEMORY_FED_PEER_FINGERPRINTS` `actual:` line originally named the gitignored source path; 12 per-control `removal-*-{broken,restored}.out` cargo `Compiling ai-memory v1.0.0 (…)` banners |

No other substitutions. Byte-identical to the source run where the
source contained no host path.

## Inspected and left unchanged

| File | Why it stays |
|---|---|
| `peer-attestation.json` | Synthetic fixture: peer id `peer-a`, agent `agent-a`, namespaces `team-x/ops` + `team-x/shared`. No real hostnames, no keys, no secrets. |
| `peer-fingerprints.txt` | Synthetic fixture: host `peer-a.fleet.example` + a 64-char hex of all `1`s (not a real cert fingerprint). |
| `posture-bare-env.out` | No host path. 6 `[FAIL]` / 10 `[PASS]` of 16. |
| `removal-proof-full.log` | No host path. First-pass harness log against the *pre-remap* control map; ends `overall: CERT-RED`. Retained as the rigor trail, **not** the final proof. |

## What was NOT present (and therefore not redacted)

- No API keys, passphrases, PEM blocks, or `AI_MEMORY_DB_PASSPHRASE` values.
- No operator home directory beyond the repo path already substituted.
- No live droplet / LAN IPs (those live only in the campaign docs this
  bundle does not include).

## First-pass vs final-map disclosure (F5)

No full-harness `overall: PASS` log exists for the **final** corrected
control map. The per-control `removal-*-{broken,restored}.out` pairs
are the proof artifacts. `removal-proof-full.log` (11:02, ending
`CERT-RED`) is the superseded first-pass record: it still maps
`require_push_namespace_scope_enabled` and
`authorize_remote_checkpoint_resolution` to the tests that did **not**
exercise them decisively, and it treats `peer_enrolled_in_allowlist` as
a standalone row (broken→rc=0 — behaviorally masked). The remapped
per-control pairs for the five load-bearing controls are RED→GREEN;
the `peer_enrolled_in_allowlist` pair remains broken→rc=0 (see cert
doc §4 row 6 and #2912).
