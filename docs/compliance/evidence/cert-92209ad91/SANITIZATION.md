# cert-92209ad91 evidence sanitization (2026-09-22 re-issue after 2 §7-watched federation-wire files changed since `f32c18dad`)

These files are **recorded artifacts** of the enterprise-federation
certification re-issue run on 2026-09-22 against the promotion-2 rehearsal tip
`92209ad91054e5e354499e383f403dd091f4d88d`. They are **not** regenerated by CI.
Host: a Linux build host; release-built binaries of this exact tip (one default
/ non-sqlcipher, one `--no-default-features --features sqlcipher,sal`) for the
four §5.4(2) posture legs; the §5.4(4)/(7) acceptance battery run under default
features on the same tip. The §5.4(3) Postgres+AGE tier and the self-hosted
federation lanes are cited from CI on PR #3903, whose merge commit carries this
exact tree — not re-run on the host.

**Why this re-issue exists.** The §7 trigger fired on a **comment-only** diff:
22 changed lines across `src/handlers/federation_receive.rs` and
`src/handlers/federation_signing_check.rs`, **0 of them code**. With comments
stripped both files hash identical to `f32c18dad`, the `AI_MEMORY_FED_*`
identifier set is identical, and `src/federation/**` has no diff. §7 carries no
comment-only carve-out, and the amendment-without-re-mint route was closed by
#3556, so the trigger was discharged by a full re-issue with §5.4(2)–(5)
**re-measured** rather than carried forward.

## Provenance note — the `@ d5c596a69` in the exit-codes header

`posture-legs-exit-codes.txt` carries a header ending `@ d5c596a69`, which is
the recapture script's own `git rev-parse --short HEAD` of the worktree it ran
in, recorded verbatim. The banner and this document bind the certification to
`92209ad91`. Both are correct and the difference is not a discrepancy:

`git diff 92209ad91 d5c596a69 -- . ':!tests'` is **empty** — the two commits
differ only under `tests/` (the macOS config-redirect fix), so the release
binaries built for the posture legs are built from the `92209ad91` source tree
exactly. The generated header is left as the script emitted it rather than
edited, because a provenance line that records what actually ran is worth more
than one that has been tidied to match the banner.

## Sanitization

No secret material is recorded here.

- The Ed25519 key pair and the operator key used by the posture legs are
  **throwaway**, generated into a scratch fixture directory outside this bundle
  and not committed.
- The leg-4 SQLCipher passphrase is randomly generated per run and appears in
  no artifact.
- `peer-fingerprints.txt` carries a **placeholder** fingerprint (a constant
  repeated digit), not a real peer key.
- The posture outputs render an operator public-key **sha256 prefix** only,
  which is a fingerprint, not key material.
- Scanned before commit for `passphrase` / `PRIVATE KEY` / `api_key` shapes and
  for base64/hex blobs: no hits other than the placeholder fingerprint above.

## Reproducing

`scripts/recapture-cert-9220-posture.sh` (committed alongside this bundle) is
the retargeted sibling of `scripts/recapture-cert-f32c-posture.sh` and drives
the four legs. It needs `DEFAULT_BIN` and `SQLCIPHER_BIN` pointing at the two
release binaries described above, `umask 022`, `XDG_CONFIG_HOME` unset, and a
`TMPDIR` off `$HOME`.
