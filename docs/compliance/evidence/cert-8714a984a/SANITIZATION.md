## Provenance note — the header of `posture-legs-exit-codes.txt`

The header reads `2026-09-11 #3607 re-issue recapture (22 checks) @ 8714a984a`.
Its date, 2026-09-11, is the recapture script's template date, not the run
date: these legs ran on 2026-10-04. The hardened and certified `.out` files
name the fixture path `<repo-root>/.local-runs/cert-3607-fixtures/`. The header
and that path are both FIXED strings of the
recapture script (its header line and its path-redaction label), which was
retargeted in `OUT` / `FIX` only; the `@ 8714a984a` is the script's
`git rev-parse --short HEAD` of the worktree it ran in, recorded verbatim,
and it equals the bound SHA. They are left as the script emitted them: a
provenance line that records what actually ran is worth more than one tidied
to match the banner.

## Sanitization

No secret material is recorded here.

- The Ed25519 key pair and the operator key used by the posture legs are
  **throwaway**, generated into a scratch fixture directory outside this bundle
  and not committed.
- The leg-4 SQLCipher passphrase is randomly generated per run and appears in
  no artifact.
- `peer-fingerprints.txt` carries a **placeholder** fingerprint and
  `peer-attestation.json` a placeholder peer; neither names a real host.
- Cargo progress bars, compiler warnings, absolute `CARGO_TARGET_DIR` /
  worktree paths and the host name were NOT captured into any file here: the
  four `.out` files are the `doctor --posture` renderings only,
  `test-results.txt` carries the `test result:` summary lines only, and
  `removal-proof-full.log` is the #4503 header plus the proof harness's
  per-control verdict lines. Verified by grep for the scratch, mount, home and
  host-name prefixes across the bundle (the bundle builder refuses on a hit):
  zero hits in every captured file, with exactly two disclosed exceptions.
  (1) The `CERT-PROOF:` header line in `removal-proof-full.log` carries
  `worktree=<absolute path of the cert worktree>`. The proof script prints
  that one header twice, byte-identical: as the log's first line and again
  directly above the `overall:` verdict. It is kept VERBATIM because
  the header is a measurement printed by `scripts/check-cert-removal-proof.sh`
  (the #4503 tip binding) and the cert's RUN-RECORD copies it unedited.
  Rewriting it would turn that measurement into an assertion (GOD ruling
  7a4e20b5: disclose, never rewrite; builder defect #4555). It is a known mount-prefix hit and it is
  run provenance, not leaked run output: the cert worktree the proof ran in, a
  local checkout directory, not a secret. The builder tolerates it ONLY on that
  exact line (in exactly those two positions) and ONLY when the line also names the tip, `dirty=0` and
  `controls=15`. Any other path anywhere in the log still refuses the bundle.
  (2) `recapture-posture.sh`, whose `DEFAULT_BIN` / `SQLCIPHER_BIN` fallback paths
  are copied verbatim from the shipped `scripts/recapture-cert-3607-posture.sh`
  (repository content, not run output; the run passed both binaries
  explicitly), as in the `cert-385da3a05` bundle.
