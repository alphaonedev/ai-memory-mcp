## 3. Master findings catalog

Findings use stable IDs from Wave 1 with Wave-2 confirmations. Wave-3 adjudicator ranking is authoritative for priority.

### 3.1 P0 — must-fix correctness / integrity

#### W1A1-02 — `agent_attested` survives content/title mutation  
**Status:** CONFIRMED (W2) · **Severity:** P0  
**Evidence:** `SignableWrite` binds `sha256(content)` at stamp (`src/identity/attest.rs`); update reuses existing metadata when not patched (`src/storage/mod.rs` ~2558); HTTP update re-embeds only (`src/handlers/memories.rs` ~549); `IMMUTABLE_PROVENANCE_KEYS` does not include `attest_level` / `write_signature`.  
**Impact:** Consumers that trust `metadata.attest_level=agent_attested` as “current content is author-signed” are wrong after unsigned edit. Federation re-verify of stored `write_signature` can disagree with content.  
**Fix direction:** On content/title/kind mutation without a fresh valid signature, clear/downgrade attest (mirror model-family fail-safe).

#### W1A2-01 / W1A2-02 — Federation Ack = HTTP 2xx, not “applied”  
**Status:** CONFIRMED (W2) · **Severity:** P0 (authority lane)  
**Evidence:** `post_once` → any `status.is_success()` → `AckOutcome::Ack` (`src/federation/sync.rs` ~184–200); never reads `skipped` or `unsupported_on_postgres`. Postgres funnel returns 200 with `unsupported_on_postgres` tally for archives/restores/pendings/checkpoints (`src/handlers/federation_signing_check.rs` ~604–831). Tests pin 200+unsupported (`tests/cov_ga2_pg_federation.rs`).  
**Impact:** W-of-N / DLQ “peer has the write” over-claims. Authority-lane checkpoints on postgres peers are especially load-bearing.  
**Classification:** Receiver residual documented; end-to-end Ack contract is a **defect relative to W-of-N semantics**.  
**Fix direction:** Non-Ack when authority items skipped/unsupported; or non-2xx when entire payload unsupported.

#### W1A5-02 — MCP has no fold loop  
**Status:** CONFIRMED (W2) · **Severity:** P0 (MCP-primary topologies)  
**Evidence:** Fold loops spawned only from `bootstrap_serve` (`src/daemon_runtime.rs` ~5870+); `src/mcp/**` has zero fold spawn. Access ladders only run on fold.  
**Impact:** MCP sessions never update `access_count`, TTL floor-extend, mid→long promotion, priority decade, confidence decay from pure recall.

#### W1A5-01 — `gc_if_needed` without fold-before-GC  
**Status:** CONFIRMED (W2) · **Severity:** P0 (compounds W1A5-02)  
**Evidence:** `gc_if_needed` → direct `gc()` (`src/storage/mod.rs` ~11397–11410); callers include MCP recall (`src/mcp/tools/recall.rs:981`), CLI recall/store/list/io; MCP `memory_gc` also bare `gc`. Contrast: daemon GC + CLI `gc` + HTTP admin GC fold first.  
**Impact:** Under pure recall, TTL extension lives only in unfolded `recall_observations`. Opportunistic GC can archive/delete short/mid rows that fold would have floor-extended.  
**Compound:** W1A5-01 + W1A5-02 = double kill for MCP-only dogfood.

#### W1A6-09 — R40 signed-approval HTTP gap + escalate queue dead  
**Status:** CONFIRMED (W2) · **Severity:** P0  
**Evidence:** MCP `memory_pending_approve` runs `verify_quorum_from_env` (`src/mcp/tools/pending.rs` ~367–407). HTTP approve body is HMAC-only (`src/handlers/approvals.rs`). `route_escalation_to_approval_gate` has **no production callers** (tests only). Live `Decision::Escalate` → fail-closed `Err` without queue (`src/daemon_runtime.rs` ~4222–4238).  
**Impact:** “Human-key-signed approval” story is MCP-partial; escalate does not auto-enter R40 queue.

### 3.2 P1 — isolation, validation, archive, tools, residual multi-tenant

#### W1A2-04 — GET-by-id does not hide `quarantined`  
**Status:** CONFIRMED · **Severity:** P1  
**Evidence:** List/search/recall/export/fed egress use `lifecycle_visible_clause`; `db::get` / SAL `get` / HTTP get do not. Quarantine is opt-in (`AI_MEMORY_FED_QUARANTINE_UNATTRIBUTED` default off).  
**Impact:** When quarantine is enabled, UUID-known rows remain readable by id.

#### W1A4-08 — `RequestValidator` not on MCP/CLI store  
**Status:** CONFIRMED · **Severity:** P1  
**Evidence:** HTTP uses `RequestValidator::validate_create`; MCP/CLI use free-fns. `reject_reserved_write_namespace` only on `validate_create` → reserved ns hole on MCP/CLI.  
**Impact:** Dual-path drift; reserved namespace enforceable on HTTP only.

#### W1A6-03 — `PreGovernanceDecision` never fired  
**Status:** CONFIRMED · **Severity:** P1  
**Evidence:** Enum TODO at `src/hooks/events.rs` ~149–156; `enforce_governance` has no hook dispatch; zero production fire sites. Eligible for PE-1 / listed in asi-hard template.  
**Impact:** Presence enforcement for that event is theater.

#### W1A1-01 — Advisory HTTP identity residual (H1/M1 class under shared key)  
**Status:** CONFIRMED · **Severity:** P1 (ops residual; RBD soak rung)  
**Evidence:** Default `HttpIdentityMode::Advisory` (`src/config.rs`); Claimed named principals WARN-only on sensitive gates; inert if no per-agent keys enrolled.  
**Impact:** Multi-tenant shared-`api_key` deployments must set `enforce` + enroll per-agent keys.

#### W1A3-02 — `kind_provenance` dropped on archive→restore  
**Status:** CONFIRMED · **Severity:** P1  
**Evidence:** Column only on live `memories` (v79); not on `archived_memories`; archive/restore INSERT lists omit it. Metadata may still carry a copy.  
**Impact:** Denormalized queryable provenance lost after archive restore.

#### W1A4-01 — Phantom `memory_recover_previous_session` MCP tool  
**Status:** CONFIRMED · **Severity:** P1  
**Evidence:** Claimed in `docs/CLI_REFERENCE.md`, `ROADMAP.md`, `src/daemon_runtime.rs` comments; **no** `src/mcp/tools/recover_previous_session.rs`; not in registry. CLI `recover-previous-session` exists.  
**Impact:** Agents following docs will call a non-existent MCP tool.

#### W1A3-05 — Postgres federation unsupported subcollections  
**Status:** CONFIRMED · **Severity:** P1–P0 when combined with false Ack  
**Evidence:** archives/restores/pendings/namespace_meta/checkpoints counted `unsupported_on_postgres` but still 200.  
**Impact:** Heterogeneous sqlite↔postgres fleets diverge on authority/archive lanes.

#### W1A3-06 — Skills + governance_rules SQLite-only behind version stamps  
**Status:** CONFIRMED · **Severity:** P1  
**Evidence:** `migrate_v82` / `migrate_v66` postgres no-ops; skills handlers use `app.db` rusqlite even under postgres serve (W3 residual: side-car split + retire/delete 501 on PG).  
**Impact:** Schema tip 86 ≠ product parity.

#### W1A4-09 — `memory_recall_observations` MCP free-fn vs HTTP SAL  
**Status:** CONFIRMED · **Severity:** P1 (semantic fork under frozen name)  
**Evidence:** MCP → sqlite `observations::list_observations`; HTTP → `MemoryStore::list_recall_observations`.

#### W3 — `record_stop` fence incomplete  
**Status:** NEW residual from Wave-3 · **Severity:** P1  
**Evidence:** `gate_record_stop` on store/update/delete/link/consolidate/merge but **missing** on forget, archive_by_ids, archive_restore, archive_purge, dequarantine, bind_agent_pubkey/api_key, append_lineage.  
**Impact:** Record-stop claim incomplete for those mutators.

#### W3 — Skills on postgres mislabeled supported  
**Status:** NEW residual · **Severity:** P1  
**Evidence:** postgres_gate allowlists skill routes; handlers use side-car sqlite; no skills table on PG; retire/delete not allowlisted → 501 asymmetry.
