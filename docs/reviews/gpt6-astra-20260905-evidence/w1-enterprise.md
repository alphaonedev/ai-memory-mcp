## Grand-slam pass criteria (proposal, not observed SLOs)

1. One reproducible application-level acceptance run on SQLite+MCP and Postgres+HTTP covering store, restart, hybrid recall, signed lineage, checkpoint, deletion propagation and negative tenant controls; backend-specific refusal must be machine-discoverable before the agent attempts a workflow.
2. Three isolated nodes with distinct stores: repeated partition, crash-after-local-commit, peer recovery, reordering, duplicate replay, delete/restore race. Require zero lost acknowledged local writes and zero unauthorized cross-namespace applications; report convergence and quarantine behavior, not just HTTP success.
3. Benchmark at stated corpus/agent concurrency and model configuration; publish p50/p95/p99, RAM, embedding cost, queue age and recall effectiveness against files+search and bare Postgres/pgvector. Acceptance should require useful-task completion or fewer repeated mistakes with equal context/token budgets, not merely higher retrieval throughput.
4. Expose a compact per-request provenance/freshness/completeness receipt: which backend and retrieval mode answered, projection/catchup lag where relevant, truncated/budget-exceeded status, and acknowledged durability. Existing typed gates are a foundation; certify their agreement across transport/profile/backend combinations.
5. Run application-level projection recovery and quarantine repair drills. Extension RETURN 1 plus zero backlog is insufficient to certify them. Fail the release claim if promised operations are unavailable or silently downgraded.
