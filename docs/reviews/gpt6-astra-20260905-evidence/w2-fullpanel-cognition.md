## Required test-plan refinements before my final approval

**E2-1 — distinguish information-retention benefit from reasoning benefit.** The no-cross-session-memory arm will necessarily lose a task whose answer is a unique random fact deliberately made inaccessible after reset. That is a legitimate continuity demonstration, but a mechanical information-access advantage cannot establish better reasoning or supremacy over other persistent stores. Stratify (a) retention-required missions and (b) matched-information reasoning/use-time tasks, where each arm has equivalent authorized task-relevant information available through its declared interface. Report these separately. Files and ordinary retrieval remain necessary competent persistent baselines. Do not leak the answer directly into the no-memory arm merely to force equality; construct a separate controlled cohort.

**E2-2 — isolate roadmap mechanisms.** The current core-versus-full arms measure a bundle. Add preregistered baseline, individual-mechanism and combined-mechanism ablations for advisories/skills, compact metadata, valid-time defaults, feedback dampening and corroboration/containment where implemented. Hold all other knobs and input state fixed and publish interactions. A full-stack improvement does not establish that a particular default flip is beneficial.

**E2-3 — remove ambiguous calibration wording.** Replace “do not select the held-out dataset until memory reliably loses” with “Never select or tune held-out cases to force memory to win or lose.” The assessment's longer paragraph already gives the intended correct meaning; make the test plan equally unambiguous.

Optional tightening: include the boundary comparator's mixed known axes (same session/different source and different session/same source) in the explicit truth table alongside all-equal/all-different/unknown. This tests the exact ambiguity in the roadmap without treating the future comparator as a current runtime defect.
