| Question | Answer |
|----------|--------|
| Does v0.8.0 **implement** RQGM? | **No.** `rg 'epoch_manifest\|Agent-as-Judge\|co-evolv\|RQGM\|evolutionary\|genetic\|fitness' src/` → **0 production hits.** The substrate stores, gates, attests; RQGM searches and evolves. |

| Honest substrate-readiness | **~15%** for the RQGM *optimization* spine (measurement plumbing present; computation + loop absent); **~5%** for §2.6 cognitive-family verification (Ed25519 attests the *agent key*, never the *model family*). |

**Overall:** ai-memory v0.8.0 is **RQGM-principles-aligned substrate (~15% optimization-readiness)**, **not an RQGM implementation (~0%)**. The paper validates the **direction of the v0.9 roadmap** more than it validates v0.8.0 as a finished system.

**Claims discipline (binding):** never say "implements RQGM", "co-evolving evaluators shipped", "decorrelation enforce shipped", or "self-improving agent framework" at v0.8.0.

## What RQGM claims

RQGM targets recursive self-improvement when the **evaluation criterion is non-stationary** — the Red Queen problem: agents and their evaluators must co-evolve, because a fixed verifier goes stale against an improving policy.

| Mechanism | Paper intent |
|-----------|--------------|
| **Epoch-bound utilities** | The scorer is **frozen within an epoch**; the utility may change only at epoch boundaries. |
| **Co-evolving evaluators** | Graders/reviewers evolve alongside writers/coders — a population, not a single judge. |
| **Agent-as-Judge** | A cheaper complementary signal (code review, paper review) layered atop verifiable tests. |
| **Adversarial objectives** | Search discovers evaluators that fix *systematic grader bias* (e.g. over-accepting AI-authored papers). |
| **Empirical refutation** | Each epoch commits to measurable outcomes (pass/acceptance/grading-accuracy), not static-benchmark worship. |

**RQGM optimizes AGENTS. ai-memory governs the GOVERNED PERSISTENCE of what agents write.** That category boundary is the spine of this assessment — and it is the reason the algorithm belongs *outside* the substrate.

## The placement model (validated)

```
L3 — ai-memory-rqgm / operator runner    (EXTERNAL, hard line)
      utility evolution · evaluator-population search · adversarial objectives
      READS substrate telemetry · WRITES one signed epoch artifact only
            │  operator/quorum Ed25519 signature
            ▼
L2 — ai-memory curator (IN REPO, separate process)
      verify signed epoch artifact → V-4 epoch.manifest_applied row
      epoch tick · stamp metadata.epoch_id · decorrelation EVERY cycle
            │  SAL / MCP tools / hooks
            ▼
L1 — ai-memory substrate (MCP / HTTP / CLI)
      persist · gate · attest · bounded reflect · N≥3 quorum · ledger · governance · V-4 chain · federation checkpoints
```

**21/21 lenses agree:** the evolutionary SEARCH is EXTERNAL (L3); only verification + consumption + attestation live in-repo (L1+L2). This is the moonshot §0 "verifies rather than trusts" line drawn through the code.

## Mechanism-by-mechanism map

### 1. Non-stationary / epoch-bound utilities

**RQGM:** Utility evolves only at epoch boundaries; within-epoch guarantees hold.

**v0.8.0 reality:**

| Surface | Behavior | RQGM fit | Evidence |
|---------|----------|----------|----------|
| `effective_max_reflection_depth` | Static per-namespace cap (default 3) | Fixed utility, not epoch-evolving | `src/models/namespace.rs:963-970` |
| `RuleEngine::evaluate` | Read-only first-refusal-wins over an immutable loaded snapshot | Fixed evaluator | `src/governance/agent_action.rs:782` |
| `ReflectDecorrelationMode::Enforce` | **INERT** — degrades to advisory at v0.8.0 | Loop dormant | `src/curator/decorrelation_probe.rs:272-281` |
| Coordination `Checkpoint` | Ed25519-attested conditional gate, fail-closed resolution | Epoch *infrastructure*, not a utility scheduler | `src/models/checkpoint.rs:106-128` |
| `epoch_manifest.schema.json` | JSON Schema; `utility.frozen_within_epoch` const `true` | Contract spec only — **git-untracked, zero `src/` consumer** | `docs/contracts/epoch_manifest.schema.json` |

**Verdict:** Epoch *infrastructure* exists (checkpoints, actions, signed events); the **controlled utility-evolution loop is absent**. The schema encodes the right invariant (`frozen_within_epoch=true`) but is an uncommitted file with no deserialization target or verifier in `src/`.

> **Opus refinement (Lens 10 — diverges from prior Grok review).** The proposed net-new `epoch_manifest.json` **partially duplicates an existing primitive**: the attested-checkpoint (`src/models/checkpoint.rs:106-128`) is already a signed, frozen, fail-closed, federated, auditable gate. The epoch boundary should arguably **bind to a Checkpoint row** (e.g. a `ConditionType::EpochAdvance`) rather than introduce a parallel JSON artifact. This is a real architectural fork the v0.9 design must resolve, not assume.

### 2. Co-evolving agents + evaluators

**RQGM:** Writers and graders co-evolve; evaluator-panel diversity is the whole point.

**v0.8.0:** The closest analogue is the decorrelation probe — explicitly **visibility-only**:

- The curator's LLM judge is a **single stationary** `AutonomyLlm`: `build_curator_llm` has 3 production callers, each constructing **one** `OllamaClient`; every other `AutonomyLlm` impl is a test stub (`src/cli/curator.rs:114`; `src/autonomy.rs:96,125`).
- `run_decorrelation_probe` has **exactly one production caller** — `run_reflect` only, via `run_decorrelation_probe_step` (`src/curator/decorrelation_probe.rs:254` → `src/cli/curator.rs:818,807,786`). It does **not** run in `run_once` or `store_backed_reflection_sweep`. There is no "decorrelation every cycle" today.
- Distinctness is **CLAIMED, not ATTESTED**: `producer_signal()` ranks on free strings, falling back `model_family → agent_id → source` (`src/curator/decorrelation_probe.rs:99-117`), so one model writing under two agent_ids reads as two producers. The probe carries its own CLAIMED-not-ATTESTED caveat (`:68-74`).

**Verdict:** The substrate **names** the monoculture risk RQGM solves and ships **honest non-enforcement**. Co-evolution is a v0.9+ story gated on attested model-family provenance (#1719 / #1171).

### 3. Agent-as-Judge signal

**RQGM:** A cheap judge signal complementary to verifiable tests; a panel for reviewing.

**v0.8.0:**

| Judge-like path | Role | Composed into a loop? | Evidence |
|-----------------|------|-----------------------|----------|
| `AutonomyLlm` / curator reflection pass | Proposes reflections | Opt-in; reflection requires explicit `--reflect`, bails without it | `src/cli/curator.rs:194` |
| `RuleEngine::evaluate` | Static policy judge | Read-only, never mutates rules | `src/governance/agent_action.rs:782` |
| `reflect_with_hooks` + `PreReflect` | Veto before reflect | **Unreachable on the MCP path** — see §5 | `src/mcp/tools/reflect.rs:496` |

**Verdict:** Judge **primitives exist**; they are **not composed** into an RQGM search with empirical utility updates, and the single judge is a monoculture.

### 4. Adversarial objectives (fixing evaluator bias)

**RQGM:** An adversarial objective discovers reviewers equally strict on AI vs human work.

**v0.8.0:** Governance `Decision::Escalate` → human review (fail-closed, `src/governance/agent_action.rs:796-803`); decorrelation dominance → advisory WARN; `contradicts` links store conflict. **None evolves a counter-evaluator.** Fail-closed governance: yes. Adversarial evaluator evolution: no.

### 5. Empirical utility / feedback surveillance

**RQGM:** Utility is measured empirically each epoch.

**v0.8.0** — the strongest alignment, and the most honestly bounded:

- `record_recall` / `record_recall_with_identity` write one ledger row per recall candidate (`src/observations/mod.rs:65,144`). The **record** side is surfaced on MCP + HTTP; the **consume** side (`mark_consumed`/`mark_recall_consumed`) has SAL **backend twins** on sqlite `:894` + postgres `:14176` (refuting Grok F-53's "MCP-sqlite-only") **but is wired to ZERO production surfaces** — no MCP tool / HTTP route / CLI subcommand sets `consumed`; it is a **dead capability** (test-only callers). See correction **C-1** / defect **D-OPUS-6** above.
- The ledger is **write-only telemetry**: `src/reranker.rs` reads neither `consumed` nor the observations table; no code aggregates `consumed` into a pass/acceptance rate. **#1706 shadow-utility sweep does not exist in `src/`** (0 references; contract-only).
- **`access_count` is already a silent live fitness proxy** *on the recall hot path*: it is part of the blended score `MIN(access_count,50)*0.1` and drives auto-promotion + priority-bump (`src/storage/mod.rs:1461,3688,4244,10269`). Optimizing the ledger directly would double-count an already-live proxy (Goodhart exposure).
- **#1707 live recall wire is correctly DEFERRED** behind #1706 (shadow-before-live).

**Verdict:** ~70% of the *measurement plumbing* exists; the *measurement computation* and the *optimization loop that consumes it* do not.

### 6. Bounded-RSI safety (where the substrate is strongest)

- Reflection depth is checked **before any transaction opens** — `DepthExceeded` returns and a signed audit row is written *before* `BEGIN IMMEDIATE` (`src/storage/reflect.rs:413,454,531`). Runaway recursion is genuinely refused; `Some(0)` is a kill-switch.
- Refusal is **typed data**, not silent failure: `ReflectError::{DepthExceeded, HookVeto}` distinct (`src/storage/reflect.rs:43-55`).
- The V-4 chain is real: `prev_hash` SHA-256 + monotonic `UNIQUE sequence`, atomic IMMEDIATE-tx append, fail-closed `verify_chain`/`verify_audit_trail` (`src/signed_events.rs:333-366,518-680,867-939`).

## Honest procurement framing

**Allowed today:**

> ai-memory v0.8.0 ships **bounded recursive-refinement** (depth-capped, refusal-as-data), **operator-signed static governance**, **a recall-consumption observation ledger** (full three-surface / dual-backend consume-parity), **a tamper-evident V-4 audit chain**, **Ed25519-attested coordination checkpoints**, and **an advisory, visibility-only decorrelation probe** — the measurement + attestation scaffolding an external RQGM-style outer loop could orchestrate, with explicit refusal of unbounded recursion and honest CLAIMED-vs-ATTESTED limits. A signed epoch-boundary contract **spec** exists for a future hybrid L3-external / L2-internal deployment.

**Banned today:** "implements RQGM" · "co-evolving evaluators shipped" · "decorrelation enforce shipped" (it is INERT) · "attests model family / cognition diversity" (it is CLAIMED) · "epoch closure shipped" (no V-4 writer; schema untracked) · "self-improving agent framework".

## Bottom line

The paper validates the **direction** of the v0.9 roadmap (panel, attestation, shadow utility, epoch discipline) far more than it validates v0.8.0 as a finished RSI system. ai-memory is the **audit trail and gatekeeper** RQGM would need; **RQGM is the evolutionary engine you build around it, on the far side of a signed wire** — never inside `src/`.
