## Executive summary

Two independent AI NHIs — **Fable 5** and **Grok 4.5** — each ran a 3-wave × 7-agent full-spectrum audit of ai-memory v1.0.0 at `8f025225`, both wired into the live substrate (Grok as the configured MCP LLM `x-ai/grok-4.5`; Fable as the orchestrating Claude Code agent dogfooding the substrate this session). Fable then ran a **2-round × 5-lens adversarial comparison** that re-verified every Grok finding against HEAD and mapped it to Fable's set.

**Convergent verdict:** the v1.0.0 core (store / recall / delete / attest / integer SSOTs) is credible GA for a single-operator MCP/CLI long-tier corpus. It is **not yet** "defaults cannot lie + MCP pure-recall is safe + multi-node ack means applied + attestation tracks current content." The two audits independently converged on the same load-bearing clusters (pure-recall fold/GC hole; attestation-survives-mutation; archive→restore provenance loss), which raises confidence that these are real, not artifacts of one reviewer's bias.

- **Fable 3×7:** 55 raw confirmed findings (7 refuted by adversarial verifiers) → **34 canonical defects** after cross-round dedup.
- **Grok 2×5 comparison:** of Grok's ~28 catalogued findings, **21 kept** (15 net-new to Fable + 6 merge into Fable clusters) and **7 dropped** (refuted at HEAD or genuine residual-by-design).
- **Merged union to fix 1:1:** **~48 GitHub issues**, all under the 100% fix policy.

### Highest-leverage defects (both audits agree)

1. **Pure-recall data loss on MCP/CLI** — MCP spawns no fold loop, and `gc_if_needed` / MCP `memory_gc` reap before folding, so short/mid rows lose their recall-driven TTL floor-extension and can be evicted. (Fable **FBL-04** ≡ Grok **W1A5-01/02**.)
2. **`agent_attested` survives unsigned content/title mutation** — update funnels (both backends) carry `attest_level`/`write_signature` verbatim over mutated content; a strict receiver then refuses the legitimately-edited row as forged. (Fable **FBL-32** ≡ Grok **W1A1-02**.)
3. **Federation ack = HTTP 2xx ≠ "applied"** — the sender counts any 2xx toward W-of-N quorum and retires the push-DLQ row, even when the postgres peer returned `unsupported_on_postgres` (archives/restores/pendings/checkpoints) or the sqlite peer `skipped` on validation failure. (Grok **W1A2-01/02**, net-new to Fable.)
4. **`memory_update {tier:"long"}` keeps a stale short/mid `expires_at`** and GC is tier-blind → a row promoted to the documented-permanent tier is silently reaped (crypto-erased when `archive_on_gc=false`). (Fable **FBL-01**; the postgres twin #1626 fix never landed on sqlite/MCP.)
5. **Human gate hollow on escalate** — R40 signed-approval quorum is enforced on MCP only; both HTTP approve surfaces bypass it, and `Decision::Escalate` fails closed with no pending queue. (Grok **W1A6-09**, net-new to Fable.)

## Anti-findings (what is solid — both audits agree)

- Integer SSOTs lockstep + invariant-tested: schema 86, 103 MCP tools, 93/79 routes, 89/91 CLI, 30 Memory fields.
- #1953 pure recall: no sync-touch; ledger-only write (this is also the *root* of the FBL-04/W1A5 fold gap — the pure-recall contract is correct; the fold plumbing on MCP is the defect).
- #2167 `embedding_space`: hybrid path fail-closes rather than score across spaces.
- Federation pure authz: enrolled-key verify; forged signatures rejected even under `require_sig=false`.
- Secret-screen dual path: refuse caller-origin, redact storage-funnel (CRDT-safe).
- v1.0.0 secure-default flips are real (`FED_REQUIRE_WRITE_SIG`/`SIGNAL_SIG`/`CHECKPOINT_SIG`=1), which is why Grok's "soft-defaults catalog" was dropped.
- CLI dogfood core path (store/get/recall hybrid+rerank/delete) green on v1.0.0.
