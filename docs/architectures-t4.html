Tier 4 · the PostgreSQL tier

A data-center swarm on PostgreSQL.

Several racks of ai-memory daemons, each built with sal-postgres and started with a postgres:// store URL, keep their memories in an operator-run PostgreSQL 18 deployment with pgvector and, when installed, Apache AGE. The daemons federate across racks with signed W-of-N quorum writes. Agents never connect to PostgreSQL: every request terminates at a daemon.

PostgreSQL 18 + pgvector Apache AGE when installed 76 of the 89 unique paths served rack-spread W-of-N quorum wake-hub per host
Architecture

Daemons in every rack, one PostgreSQL deployment underneath.

Each host runs its agents, one daemon and one same-host wake hub. The daemons are first-class federation peers across racks. The PostgreSQL primary, its streaming replicas and the connection pooler are run by you: ai-memory does not know the replication topology and treats its configured --store-url as authoritative.

memory read/write · federation wake hint PostgreSQL replication (operator) operator-run component

What is ai-memory and what is yours. The daemons, the federation mesh and the wake hubs are ai-memory; the pooler, primary and replicas are PostgreSQL, configured per the enterprise deployment guide. MCP over stdio is SQLite-only, so agents on this tier use HTTPS. Sources: src/daemon_runtime.rs (--store-url), src/store/postgres_schema.sql, src/store/postgres.rs, src/federation/sync.rs, src/wake_hub/server.rs.

Request path

A route gate that fails closed.

On PostgreSQL the daemon puts postgres_route_gate in front of every handler. It checks the method and path against an explicit allowlist: a supported path reaches the PostgreSQL storage layer, a registered path that is not yet supported answers a uniform 501 NOT IMPLEMENTED, and an unregistered path answers 404. No request ever reads or writes the wrong database.

Graph walks. At boot the PostgreSQL store checks whether the AGE extension is installed; with it, knowledge-graph walks use a Cypher projection, without it they fall back to a recursive CTE. memory_links is the source of truth either way. Sources: src/handlers/postgres_gate.rs, src/store/postgres.rs; guide: graph backend fallback.

Walkthrough

One write, one recall.

Write

Commit in PostgreSQL, then replicate

  1. An agent in rack A sends POST /api/v1/memories with its X-Agent-Id to the daemon on its host.
  2. The route gate admits the path; identity and the namespace governance gate run as on every tier.
  3. The row commits in PostgreSQL (MVCC, so concurrent writers from other daemons do not serialize on a file lock).
  4. The daemon signs the body and fans it out to its --quorum-peers in the other racks; W acknowledgements in time acknowledge the write, a miss answers 202 with quorum_met:false and the row stays committed.
  5. PostgreSQL streams the WAL to the replicas: that is your database, not ai-memory's replication.
Recall

Keyword, vector and graph in one database

  1. An agent in rack B sends POST /api/v1/recall to its local daemon.
  2. Scope visibility filters what the caller may see, from its namespace position.
  3. Keyword search runs on tsvector, semantic search on a pgvector column, graph walks on AGE or the CTE fallback.
  4. The result returns over HTTPS; nothing about the recall path is exposed as a PostgreSQL connection to the agent.
Deployment recipe

One daemon per host, every flag real.

Build with the sal-postgres feature. --store-url and --db are mutually exclusive; keep the URL out of argv with AI_MEMORY_STORE_URL_FILE. A non-loopback bind also needs api_key set in config.toml, and every listener is TLS. serve and curator run against PostgreSQL; the tenant-facing CLI read/write verbs and MCP over stdio are SQLite-only; the admin verbs schema-init, keys, reown, verify-audit-trail, agents bind-api-key, identity hub-cache and doctor take a per-run --store-url target.

# ai-memory, on each host (rack A host 1 shown)
cargo build --release --features sal-postgres

AI_MEMORY_STORE_URL_FILE=/etc/ai-memory/store-url \
ai-memory serve \
  --host 0.0.0.0 --port 9077 \
  --tls-cert /etc/ai-memory/tls.crt --tls-key /etc/ai-memory/tls.key \
  --mtls-allowlist /etc/ai-memory/mtls-allow.txt \
  --quorum-writes 2 \
  --quorum-peers https://rack-b-1:9077,https://rack-c-1:9077 \
  --quorum-timeout-ms 2000 \
  --quorum-client-cert /etc/ai-memory/fed.crt --quorum-client-key /etc/ai-memory/fed.key \
  --quorum-ca-cert /etc/ai-memory/fed-ca.crt \
  --catchup-interval-secs 30

# the same host's wake plane (Unix socket, same host only)
ai-memory wake-hub --socket /run/ai-memory-hub/wake-hub.sock \
  --hub-id rack-a-1 --allowlist /run/ai-memory-hub/hub-allow.json

# health, locally and across the fleet; doctor --json reads the local SQLite --db
# unless AI_MEMORY_STORE_URL / AI_MEMORY_STORE_URL_FILE points it at PostgreSQL
AI_MEMORY_STORE_URL_FILE=/etc/ai-memory/store-url ai-memory doctor --json
ai-memory doctor --remote https://rack-b-1:9077 --api-key-file /etc/ai-memory/api.key

# PostgreSQL side: OPERATOR configuration, not ai-memory
#   primary + streaming replicas, a pooler in transaction mode,
#   pg_basebackup + WAL archive for backups, TLS (sslmode=verify-full),
#   a role allowed to create the vector extension (and age, optionally)

Flags: src/daemon_runtime.rs (ServeArgs, DoctorCliArgs), src/cli/wake_hub.rs. Enrol each peer's transport certificate pin and Ed25519 signing key before the first push: see federation. ai-memory backup refuses non-SQLite stores, so PostgreSQL backups are yours.

Wiring

Governance, wake and attestation at T4.

Governance

Same gate, now on PostgreSQL

Namespace standards, Allow / Deny / Pending decisions and the pending-action queue are enforced on PostgreSQL. The rule inspection API (memory_rule_list, memory_check_agent_action) is in the fail-closed set; enforcement itself is not.

Wake plane

One hub per host

A notify commits the inbox row in PostgreSQL, then wakes the host's hub. A recipient on another host learns of the row through federation, and its daemon publishes a local wake only for a fresh apply. Clients keep a backstop poll of at most a minute.

Attestation

Signed, enrolled, scoped

Cross-rack pushes carry an Ed25519 X-Memory-Sig bound to an X-Memory-Nonce; receivers refuse unsigned, replayed and unenrolled pushes and check the sender's namespace scope.

At rest

Operator-attested

The enterprise posture check verifies the TLS store URL and requires an explicit operator attestation (AI_MEMORY_PG_AT_REST_ATTESTED) that volume encryption is on. It does not probe the disk; SQLCipher and application content encryption are separate controls.
