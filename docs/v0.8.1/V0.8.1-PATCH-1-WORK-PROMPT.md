## 3. Work items (W1–W7)

Each item: **the defect → the anchors → the fix shape → SAL parity → the regression test → acceptance.** Anchors are from `release/v0.8.0`; **re-verify each with CodeGraph before editing** (the index may have drifted; per the prime directive, probe a freshly-built binary before claiming any behavior).

### W1 — G29 · Secrets / credentials in memory have **no write-path screen** · CodeGraph-verified live defect · **MUST-FIX**

- **Defect.** Every store surface (`memory_store` MCP, `POST /api/v1/memories`, CLI) accepts caller content with **zero credential screening**. `validate.rs` checks shape + length only (`validate_content` `src/validate.rs:165`, `validate_create` `:917`). A pasted private key / API token / passphrase is persisted, FTS-indexed, embedded, federated, and surfaced verbatim on recall + forensic export + federation push. The substrate classifies its *own* env vars as `secret` (CLAUDE.md env table) yet screens nothing the caller writes.
- **Fix shape.** A **fail-closed pre-write secret-screen** on the SAL write path so SQLite + Postgres behave identically:
  - **W1.1** A screening predicate (entropy + key-pattern + denylist): PEM blocks (`-----BEGIN … PRIVATE KEY-----`), `AKIA[0-9A-Z]{16}`, `xai-…`, `sk-…`, `ghp_…`/`github_pat_…`, JWT shape, `Bearer <token>`, high-Shannon-entropy spans. Land it as a reusable `crate::validate` (or `crate::governance`) function with a hardcoded-literal-free pattern table (CLAUDE.md pm-v3.1 — patterns as named consts, not scattered literals).
  - **W1.2** A per-namespace policy knob `REDACT | REFUSE | OFF` (default **REFUSE** on write; OFF is an explicit opt-out, mirroring the secure-default convention of `AI_MEMORY_REQUIRE_AGENT_ATTESTATION`). Wire it through `AppConfig` + an `AI_MEMORY_SECRET_SCREEN_MODE` env var; add the env var to the CLAUDE.md env table AND `tests/config_precedence.rs` (mandatory per CLAUDE.md).
  - **W1.3** Defense-in-depth at egress: the same screen runs on the forensic-bundle writer (`src/forensic/bundle.rs`) and the federation-emit path, so a pre-existing secret can't leak through export even if it predates the screen.
- **SAL parity.** The screen lives on the `MemoryStore` write trait method (or the validation layer both adapters call) — verify with a Postgres run (`infra/lan-parity-test/`) that a secret is refused identically on both backends.
- **Regression test.** `tests/secret_screen_g29.rs`: (a) each credential pattern is refused on `memory_store` + `POST /memories` + CLI; (b) REDACT mode stores a redacted span + a `secret.redacted` audit row; (c) OFF mode is byte-identical to pre-patch; (d) a benign high-entropy-but-not-credential string (e.g. a UUID, a base64 image thumbnail) is NOT a false-positive (tune the entropy gate). (e) forensic-export of a pre-existing secret is screened.
- **Acceptance.** A credential cannot land in durable storage under default config on any surface or backend; benign content is unaffected; the env var is precedence-tested; CodeGraph shows the screen on the write path for both adapters.

### W2 — G30 · Erasure is incomplete — **data remanence on `forget`** · CodeGraph-verified live defect · **MUST-FIX**

- **Defect (3 confirmed leaks).** Bulk `db::forget` (`src/storage/mod.rs:2852`, behind HTTP `forget_memories` `src/handlers/memories_query.rs` + MCP `handle_forget` `src/mcp/mod.rs`) correctly purges the row + FTS + embedding columns + `recall_observations`/`memory_links` cascades, but **does not** fan out to three derived channels:
  1. **Federation push-DLQ retains cleartext.** `federation_push_dlq.payload_json` holds the full serialized body with a deliberately **non-FK** `memory_id` (`migrations/sqlite/0041_v07_federation_push_dlq.sql:15-37`); `forget` never purges it.
  2. **No federated tombstone → resurrection.** Bulk forget never calls `broadcast_delete_quorum` (the sole caller is the *per-row* path `src/handlers/memories.rs:967`); `src/handlers/federation_receive.rs:446-450` confirms "simple remove (no tombstone row)" → a re-sync from a peer that still holds the row revives it via LWW `insert_if_newer`.
  3. **HNSW vector survives in RAM.** Bulk forget never calls `idx.remove` (cf. the scrubbing sites `src/handlers/memories.rs:548`, `src/handlers/federation_receive.rs:395/1145/1746`); the embedding still answers nearest-neighbour recall until the next rebuild.
- **Fix shape.** Make `forget` a **true erasure** with a fanout that reaches every derived store:
  - **W2.1** Purge matching `federation_push_dlq` rows by `memory_id` inside the same `forget` transaction.
  - **W2.2** Evict the vector from BOTH the `active` and `warming` HNSW graphs synchronously on bulk forget (reuse the existing `idx.remove` path the per-row update uses).
  - **W2.3** Emit + **persist a signed FORGET tombstone** that federation `/sync/push` receive checks *before* accepting an inbound write, so a re-pushed forgotten row is rejected, not resurrected. (This is the same tombstone primitive G6.2 needs — build it minimally here; do NOT pull the full G6 append-only refactor, which is v0.9.x.) **This is a T4 hard-to-reverse representation (a new persisted/wire shape) → 5-agent vote required before committing the tombstone schema.**
- **SAL parity.** All three on the `MemoryStore` trait; verify on Postgres (`infra/lan-parity-test/`) that forget purges DLQ + tombstones identically.
- **Regression test.** `tests/erasure_fanout_g30.rs`: (a) after bulk forget, `federation_push_dlq` has no row for that `memory_id`; (b) the HNSW index returns the forgotten id in **zero** semantic-recall results immediately (no rebuild wait); (c) a simulated peer re-push of the forgotten row is **rejected by the tombstone** (not resurrected); (d) the parts that already worked (row, FTS, recall_observations cascade) still work. Add a remanence-probe test that asserts the cleartext content appears in **no** queryable store after forget.
- **Acceptance.** `forget` leaves **no recoverable copy** of content in DLQ, HNSW, or via peer re-sync, on both backends; banned-claim "complete erasure / right-to-be-forgotten" can be lifted only when this is green.

### W3 — G12 / §26.3 · Durability reported as a **503**, not a success-with-status · API-semantics bug · **MUST-FIX**

- **Defect.** On a W-of-N quorum miss the local row already **persisted** (ADR-0001, never rolled back, `src/handlers/create.rs:941-966`) yet the handler returns `503 quorum_not_met` via `quorum_not_met_response` (`src/handlers/parity.rs:48`; call sites `create.rs:667/672/1018`, `memories.rs:568`, and the rest of the 11-handler set). It misreports a **locally-durable** write as a service failure.
- **Fix shape.** Decouple the HTTP success code from the replication outcome: after a durable local write, return **201 Created** (create) / **200 OK** (update) — or **202 Accepted** at most — carrying replication state as **body metadata** (`{ "quorum_met": false, "acks": <got>, "needed": <n>, "pending_peers": [...] }`). **Never 5xx** when the local write succeeded. The under-replication is surfaced as data; the sync daemon already drives convergence (`parity.rs:62-64`). Change the `quorum_not_met_response` contract + its call sites.
- **Regression test.** `tests/durability_status_g12.rs`: on a forced quorum miss, the create/update returns 201/200/202 (NOT 503) with the quorum-state body; the row is durably present locally; a genuine *local* write failure still returns the correct error (5xx only when the local write actually failed).
- **Acceptance.** No 5xx is ever returned for a write that committed locally; the body honestly reports replication state; banned-claim "durability guaranteed / quorum-durable writes" framing is corrected.

### W4 — #1685 · Governance **fail-open on the MCP surface** · security gap · **VERIFY-THEN-FIX**

- **First, verify it is still open** (per prime directive: probe a freshly-built binary, don't trust the doc). Per ROADMAP §11.3.1: `GOVERNANCE_PRE_ACTION` (`wire_check::check`) is installed on the HTTP daemon only — `run_mcp_server` installs only `GOVERNANCE_PRE_WRITE`, so the four egress sinks (skill export, federation sync, hooks executor, LLM HTTP) **fail-open on the MCP surface** (the primary NHI interface).
- **Fix shape.** Install `GOVERNANCE_PRE_ACTION` in `run_mcp_server` so the MCP surface enforces the same egress gate as HTTP. **T3 governance-posture change → 5-agent vote.**
- **Regression test.** `tests/mcp_governance_pre_action_1685.rs`: a policy-denied egress action is refused on the MCP surface, not just HTTP.
- **Acceptance.** Egress governance is enforced identically on MCP and HTTP; `gh issue close 1685` with retest evidence.

### W5 — #1693 · Postgres-backed daemons do **not** rehydrate from host transcripts (L2) · parity gap · **VERIFY-THEN-FIX**

- **Verify open first.** Per §11.3.1: L2 `recover-previous-session` is **sqlite-only** — no SAL `recover_turn_idempotent`, so postgres-backed daemons skip cross-session rehydration.
- **Fix shape.** Add the `recover_turn_idempotent` (and any `capture_turn_idempotent` parity) to the `MemoryStore` trait + the `PostgresStore` adapter, so postgres daemons rehydrate identically. Verify against a live PG (`infra/lan-parity-test/`).
- **Regression test.** `tests/postgres_l2_rehydration_1693.rs`: a transcript replay produces identical idempotent memories on sqlite and postgres.
- **Acceptance.** L2 rehydration is backend-blind; `gh issue close 1693`.

### W6 — V08-PE-3 · Subprocess-chain visibility (eBPF / dtrace) · explicit "defer-to-v0.8.1" item · **STRETCH (platform-gated)**

- ROADMAP line 1100: "Defer to v0.8.1 if substrate slips: V08-PE-3 subprocess-chain visibility (eBPF/dtrace work has platform-specific risk)." This is the one *feature* deferral that the ROADMAP assigns to v0.8.1.

- **Acceptance.** Either shipped behind a documented feature flag with tests, or a recorded 5-agent-vote deferral with rationale.

## 4. Workflow discipline (CLAUDE.md, non-negotiable)

1. **Branch.** Create `release/v0.8.1` **from `release/v0.8.0`** (`git checkout -b release/v0.8.1 release/v0.8.0`). All v0.8.1 work lands there. Do not work on `main`.
2. **Four gates per change** before any commit: `cargo fmt --check` · `cargo clippy -- -D warnings -D clippy::all -D clippy::pedantic` · `AI_MEMORY_NO_CONFIG=1 cargo test` · `cargo audit`. Plus the three script gates (`scripts/check-hardcoded-literals.sh`, `scripts/qc-codegraph-precheck.sh`, `scripts/check-vendor-literals.sh --self-test`).
3. **Signed commits.** Repo-local signing is configured (`id_ed25519`, `commit.gpgsign=true`). Every commit must be signed (`git log -1 --format=%G?` = `G`) and end with `Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>`. Commit per work item (one `fix(...)` per defect), not one mega-commit.
4. **5-agent vote** at every `T1–T6` crossroads (W1, W2, W4, W6 are pre-flagged). `memory_store` the decision; cite `5-agent vote (4d3ea1c5)` in the commit.
5. **Scratch only under `.local-runs/`** — never `/tmp`, `/var/tmp`, `/private/tmp` (CLAUDE.md hard rule).
6. **Push** to `origin/release/v0.8.1` is pre-approved for the campaign; **never force-push**; **never push to `main`**. The v0.8.1 → main merge + tag-cut is operator-gated.
7. **Verify-before-claiming (pm-v3.3).** For any behavioral claim about the daemon, probe a freshly-built binary (`cargo build --release && printf <JSON-RPC> | ./target/release/ai-memory mcp …`), not the operator's running process.

## 5. Testing protocol — 100% (functional + operational + dogfood)

A work item is **not done** until ALL of these are green for it.

### 5.1 Functional (local)
- The four cargo gates + three script gates pass on `release/v0.8.1`.
- The per-item regression test (`tests/secret_screen_g29.rs`, `tests/erasure_fanout_g30.rs`, `tests/durability_status_g12.rs`, etc.) passes and **pins the fix** (verify it FAILS on the pre-fix binary, PASSES on the post-fix binary).
- **SAL parity:** run `infra/lan-parity-test/run-parity-tests.sh` (sqlite ↔ postgres+AGE) — W1/W2/W5 must behave identically on both backends.

### 5.2 Operational — DigitalOcean (`infra/do-hive/`)
- Provision a DO droplet pair with `infra/do-hive/spawn.sh` (memory node + agent node via the `cloud-init-*.yaml.tpl` templates; `main.tf`). **This spends operator $$ — confirm the operator has authorized the DO spend before `spawn.sh`** (CLAUDE.md cost-gating). If not yet authorized, STOP at this step and surface it; do not provision.
- Deploy the `release/v0.8.1` binary to the droplets. Run **operational** verification on real infra (not just unit tests):
  - **W1:** over the HTTP API on the droplet, attempt to store each credential pattern → confirm `REFUSE`; confirm a benign secret-shaped-but-not-credential payload stores; confirm forensic-export screens.
  - **W2:** store → federate to the peer droplet → `forget` → confirm the content is gone from the DLQ, returns zero semantic-recall hits, and a peer re-sync does **not** resurrect it.
  - **W3:** force a quorum miss (stop the peer) → confirm `POST /memories` returns 201 + `{quorum_met:false,…}`, NOT 503, and the row is locally durable.
  - **W4/W5:** confirm MCP-surface governance enforcement + postgres L2 rehydration on the droplet.
- Capture the operational evidence (status codes, recall results, DLQ state) into `docs/v0.8.1/operational-evidence-do.md`. **Tear down with `infra/do-hive/teardown.sh`** when done (stop the $$).

### 5.3 AI-NHI dogfood (real MCP session)
- `scripts/dogfood-rebuild.sh` to repoint the live `ai-memory` binary to the `release/v0.8.1` build (it backs up the DB + dry-runs migrations first).
- Drive the substrate as the **actual memory layer for an AI-NHI agent session** (MCP stdio) and verify the defects are fixed *in real use*, not just in tests:
  - Ask the agent to `memory_store` a fake API key → it must be **refused/redacted** (W1).
  - `memory_store` something, then `memory_forget` it → `memory_recall` must return **nothing**, and a forensic-bundle export must not contain it (W2).
  - Exercise a federated write under a partition → the agent sees a **success + pending-replication**, not a 503 error (W3).
- Record the dogfood transcript evidence into `docs/v0.8.1/dogfood-evidence.md`. Revert with `brew link --overwrite ai-memory` when done.
